# minifia

## What This Is

친구들이 점심시간에 각자 폰으로 같은 방에 들어와 5~10분 안에 한 판 끝내는 마피아 게임이다. 4~8명이 각자 다른 곳에서 앱만으로 하는 비대면 게임이다. 토론은 앱 안의 빠른 메시지와 이모티콘으로 하고, 앱이 사회자가 되어 역할 배정, 단계 진행과 타이머, 밤 행동과 투표 집계, 결과 발표를 맡는다. 앱 설치나 로그인 없이 공유받은 링크나 4자리 코드로 들어온다. 화면은 세로 폰 폭 기준이다.

`미니피아(minifia)` 는 개발 코드명이다. 정식 이름은 출시 전 상표 확인 후 정한다.

## Core Value

링크 하나로 모인 친구들이 설명 없이 정통 마피아 한 판(6~10분)을 끝까지 마치는 것. 다른 것이 부족해도 "방 만들기·참가 → 역할 확인 → 밤 → 낮 토론·투표 → 최후 변론 → 결과" 흐름이 각자 폰에서 끊기지 않고 돌아가야 한다.

**개발자 성공 지표**: 친구 4명 이상이 각자 폰으로 배포된 주소에 들어와 한 판(6~10분)을 끝까지 마치고, 다시 하고 싶어 한다.

- [ ] 방장이 방을 만들고(4자리 코드·링크 공유) 4~8명이 닉네임만으로 들어온다 (ROOM)

- [ ] 마피아·경찰·의사·시민 역할이 배정되고, 다른 사람의 역할은 서버가 클라이언트로 보내지 않는다 (ROLE)
- [ ] 밤 행동(지목·조사·보호)이 정체를 드러내지 않는 같은 모양의 화면으로 진행되고 아침에 결과가 발표된다 (NIGHT, ELIM)
- [ ] 낮 토론, 처형 투표, 최후 변론, 찬반 투표, 처형을 거쳐 승패가 나고 모든 역할이 공개된다 (DAY, VOTE, END)
- [ ] 낮 동안 빠른 메시지(대상·직업을 고르는 템플릿)와 이모티콘으로 의심·주장·변론을 주고받는다 (COMM)
- [ ] 무거운 분위기의 화면과 외형이 다른 캐릭터, 세로 폰 화면에서 설명 없이 따라올 수 있는 안내 문구 (LOOK, CHAR, UX)
- [ ] Cloudflare 에 배포된 주소에서 실제 친구들이 한 판을 끝까지 한다 (DEPLOY, PLAY)

## Context

- 4~8명이 각자 다른 곳에서 쓰는 비대면 게임이다 (결정 0005). 음성 통화 없이 앱 안에서만 소통한다. 사람마다 폰(또는 PC 브라우저)이 한 대씩이다.
- 진행은 정통 마피아 그대로이고 분위기는 무겁게 간다. 캐릭터는 단순하지만 외형과 성격이 드러나게 만든다. MVP 에서는 외형만 쓰고 게임 능력 차이는 없다.
- 규칙 수치(타이머, 역할 구성)는 초안이다. 플레이테스트 후 조정한다.
- 기획 원천은 `docs/product.md`(기획서)와 `docs/architecture.md`(설계서), 결정 기록은 `docs/decisions/` 다. 요구사항·로드맵·진행 상태의 기준은 `.planning/` 이고, 둘이 어긋나면 `.planning/` 에 맞춘다 (ADR-0004).
- Mac 과 집 Windows PC 를 오가며 작업한다. 작업을 마칠 때마다 `HANDOFF.md` 를 갱신하고 push 한다. 페이즈마다 PR 을 만들어 병합한다 (`/gsd-ship`).
- 코드는 아직 없다. 패키지와 버전은 1페이즈 구현 계획에서 확정한다.
- 디자인 참고 자료는 고정 폴더가 없다. 디자인이 걸린 단계에서 사용자가 경로를 주면 따르고, 없으면 자체 판단으로 진행한다 (`design/references/` 는 보관 위치로 쓸 수 있다).
- 열린 질문(상세는 STATE.md): 사운드 출력 위치, 캐릭터 수·성격·선택 방식, 애니메이션 라이브러리(Rive 또는 Lottie), 이탈 플레이어 처리, 투표 결과 공개 방식, 수익화.

## Constraints

- **Tech stack**: 클라이언트는 React + TypeScript + Vite 의 PWA. 서버는 Cloudflare Workers + Durable Objects 이고, 방 하나가 Durable Object 하나다. 정적 파일도 Workers 정적 에셋으로 같은 곳에서 배포한다 — 링크로 바로 참가하고 방 상태를 한 곳에 두어 동시 투표·타이머 경합을 없애기 위해 (ADR-0001, ADR-0002)
- **저장소**: 한 저장소에 웹과 서버를 두고 공통 타입(메시지, 게임 상태)을 함께 쓴다 — 메시지 계약이 어긋나지 않게
- **서버 기준 판정**: 게임 규칙과 판정은 방 Durable Object 안에서만 한다. 클라이언트는 받은 상태를 보여 주고 행동만 보낸다 — 클라이언트를 조작해도 결과를 바꿀 수 없게 (ADR-0002)
- **상태 공개 원칙**: 서버는 플레이어마다 다른 상태를 보낸다. 다른 사람의 역할은 보내지 않는다. 마피아는 서로의 정체를, 경찰은 자기 조사 결과만 받는다. 전체 역할은 게임이 끝났을 때(와 v2 의 관전 화면)에만 보낸다. 화면에서 숨기는 것으로 대신하지 않는다 — 네트워크 메시지만 봐도 정체를 알 수 없게
- **서버 기준 타이머**: 서버가 단계 전환과 타이머의 기준이다. 클라이언트는 서버가 보낸 마감 시각으로 표시만 한다 — 폰마다 시계가 달라도 같은 순간에 넘어가게
- **WebSocket Hibernation**: Durable Object 의 Hibernation API 를 써서 대기 중 비용을 줄인다
- **이른 배포**: 1페이즈부터 `wrangler deploy` 한 번으로 URL 이 바뀌지 않고 갱신된다. 이후 페이즈 검증은 배포본으로 한다. 개발 중에는 PC 브라우저 탭 여러 개로 4~8명을 흉내 내고, 같은 Wi-Fi 의 폰으로 로컬 서버에 접속해 확인한다
- **iOS Safari**: 화면이 꺼지거나 다른 앱으로 가면 WebSocket 이 끊기므로 재접속이 필수다. Vibration API 는 동작하지 않는다. 소리는 사용자가 한 번 누른 뒤에만 재생된다. Screen Wake Lock 은 지원할 때만 쓴다
- **출시 경로**: 웹(PWA)으로 플레이테스트한 뒤, 정식 출시 때 같은 코드를 Capacitor 로 감싸 Android·iOS 에 낸다. 웹 링크 참가는 앱 출시 후에도 유지한다. iOS 심사에 대비해 출시 단계에서 진동·공유 시트·알림 같은 기기 기능을 붙인다. 무거운 3D·고급 그래픽은 어렵고 2D 캐릭터·애니메이션 범위는 문제없다
- **작업 방식**: GSD Core + gsd-addons. 산출물과 응답은 한국어, 작은 MVP, 1페이즈 Cloudflare 배포 (ADR-0004)

## 잠긴 결정 (ADR, locked)

아래 결정은 채택되어 잠겨 있다. 바꾸려면 `docs/decisions/` 에 새 번호로 결정을 추가한다. 로드맵·계획·구현은 이 결정과 어긋나면 안 된다.

### ADR-0001 웹앱 먼저, 출시 때 같은 코드로 앱 감싸기 (locked, 2026-10-21)
- 원문: `docs/decisions/0001-web-first.md`
- 결정: React + TypeScript 웹앱(PWA)으로 먼저 만든다. 정식 출시 때 같은 코드를 Capacitor 로 감싸 Android·iOS 앱으로 낸다. 웹 링크 참가는 앱 출시 후에도 유지한다.
- 따라야 할 것: 플레이테스트는 웹 URL 공유로 한다. iOS 심사에서 웹을 감싼 앱으로 거절되지 않도록 출시 단계에서 기기 기능을 붙인다.

### ADR-0002 실시간 서버는 Cloudflare Durable Objects (locked, 2026-10-21)
- 원문: `docs/decisions/0002-cloudflare-durable-objects.md`
- 결정: Cloudflare Workers + Durable Objects. 방 하나가 Durable Object 하나이고 WebSocket 으로 연결한다. 게임 규칙과 판정은 Durable Object 안에서만 한다.
- 따라야 할 것: 클라이언트는 받은 상태를 보여 주고 행동만 보낸다. 다른 사람의 역할은 서버가 보내지 않는다. 웹 정적 파일도 Workers 에서 함께 배포한다. Cloudflare 계정과 `wrangler` CLI 가 필요하다.

### ADR-0003 정통 마피아 진행, 무거운 분위기, 특색 있는 캐릭터 (locked, 2026-10-21)
- 원문: `docs/decisions/0003-classic-rules-dark-mood.md`
- 결정: 진행은 정통 마피아 그대로("밤이 되었습니다", 마피아 지목, 처형 투표). 배경과 연출은 무거운 분위기. 캐릭터는 단순하지만 각자 외형·성격이 드러나게 만든다.
- 따라야 할 것: 디자인 참고 자료는 무거운 분위기 배경과 특색 있는 캐릭터 위주로 모은다. 캐릭터 성격은 MVP 에서 외형·소개 문구에만 쓰고 게임 능력에는 영향을 주지 않는다.

### ADR-0004 개발 진행은 GSD Core 와 gsd-addons 로 한다 (locked, 2026-10-21)
- 원문: `docs/decisions/0004-gsd-workflow.md`
- 결정: GSD Core 를 수정 없이 쓰고 개인 확장은 gsd-addons 로 더한다. MVP 는 핵심 흐름(방 만들기·참가 → 역할 확인 → 밤 → 낮 토론·투표 → 최후 변론 → 결과)만 넣고, 만든 뒤 친구들과 해 보며 피드백으로 확장·개선한다. 1페이즈(걷는 뼈대) 성공 기준에 Cloudflare 배포를 넣어 폰 여러 대로 같은 방에 들어갈 수 있게 한다.
- 따라야 할 것: 요구사항·로드맵·진행 상태의 원천은 `.planning/` 이다. 페이즈마다 PR 을 만들어 병합한다(`/gsd-ship`). 디자인 참고 자료는 디자인 단계에서 받은 경로를 따르고, 없으면 자체 판단으로 진행한다.

### ADR-0005 비대면 게임, 소통은 빠른 메시지와 이모티콘으로 시작 (locked, 2026-10-21)
- 원문: `docs/decisions/0005-remote-play.md`
- 결정: 각자 다른 곳에서 음성 통화 없이 앱만으로 한다. v1 소통은 대상·직업을 골라 채우는 빠른 메시지와 이모티콘이고, 낮 토론·찬반 투표 중 생존자만 보낸다(최후 변론은 후보만 변론 메시지). 서버는 템플릿 ID 와 값만 받아 검증하고 자유 텍스트는 받지 않는다. 자유 채팅은 플레이테스트 피드백으로 정한다. 화면은 세로 폰 폭 기준, 참가는 링크 공유와 4자리 코드(QR 없음).
- 따라야 할 것: "말로 토론·변론" 을 전제로 한 설계를 하지 않는다. 밤 화면은 역할과 관계없이 같은 구성으로 둔다.

## Evolution

이 문서는 페이즈 전환과 마일스톤 종료 때 갱신한다.

**페이즈가 끝날 때마다:**
1. 무효가 된 요구사항 → Out of Scope 로 옮기고 이유를 적는다
2. 검증된 요구사항 → Validated 로 옮기고 페이즈를 적는다
3. 새로 생긴 요구사항 → Active 에 추가한다
4. 남길 결정 → Key Decisions 에 추가한다
5. "What This Is" 가 아직 맞는지 확인한다

**마일스톤이 끝날 때마다:**
1. 모든 섹션을 훑어본다
2. Core Value 가 아직 맞는 우선순위인지 확인한다
3. Out of Scope 의 이유가 아직 유효한지 확인한다
4. Context 를 현재 상태(플레이테스트 피드백 등)로 갱신한다
