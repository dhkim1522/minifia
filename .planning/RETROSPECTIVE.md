# Project Retrospective

*마일스톤마다 갱신하는 회고. 배운 점을 다음 계획에 넘긴다.*

## Milestone: v1.0 — MVP

**Shipped:** 2026-10-30
**Phases:** 6 (1·2·3·3.1·4·5, 6 삭제) | **Plans:** 107 | **Sessions:** 기록 없음

### What Was Built
- 방 Durable Object 가 규칙·판정·타이머를 맡고, 플레이어별 허용 목록 뷰로 역할이 네트워크에도 나가지 않는 실시간 마피아 한 판
- 방 만들기·링크 참가·재접속 → 역할 확인 → 순차 직업 주장·빠른 메시지 토론 → 처형 투표·변론·처형 → 밤·아침 → 승패
- 2.5D 고정 테이블·캐릭터 8종·장면 배경, 단계별 안내 문장, 실제 브라우저 E2E·배포본 smoke/uat·테스트 방 봇

### What Worked
- 1페이즈부터 실제 주소에 배포하고 이후 검증을 배포본으로 한 것. 배포에서만 나는 결함(빌드 CSS 접두, 알람 경로)을 일찍 잡았다.
- 누출 검사를 단계마다 "허용 경로" 방식 전수 검사로 고정한 것. 단계가 14개로 늘어도 역할 비노출이 깨지지 않았다.
- 결정 기록(0001~0043)과 6KB HANDOFF 로 두 PC·여러 세션을 이어 간 것.
- 시안을 캔버스로 먼저 승인받고 `design/` 사본을 기준으로 구현한 것.

### What Was Inefficient
- 사람과 함께 하는 실게임 테스트가 마지막(6페이즈)에 있었다. 10일 개발 뒤에야 "이대로는 출시가 어렵다"는 판단이 나왔다.
- 실기기 확인이 개발 끝으로 몰려 화면 결함 보완 계획(gap closure)이 많았다(1페이즈 5개, 2페이즈 7개, 4페이즈 35개 계획).
- 같은 화면을 여러 차례 다시 설계했다(테이블 원근 → 고정, 이름표 반전 → 말풍선 등). 앞선 시안 단계에서 실제 폰 크기·글자 밀도를 덜 봤다.

### Patterns Established
- 서버만 규칙을 정하고 클라이언트는 보여 주기만 한다. 와이어 변경은 결정 기록으로 계약을 먼저 적는다(0016·0020·0036).
- 서버와 화면은 함께 배포한다(0036-15). 배포 전 계정 자동 확인(0042).
- E2E 기준 수치와 승인 완화 목록은 낮추지 않는다. 결함은 코드로 고친다.

### Key Lessons
1. v2.0 은 기획 단계에서 사람과 하는 짧은 플레이 테스트(종이·시안·프로토타입)를 앞에 둔다. 재미와 출시 가능성은 끝에서 처음 확인하지 않는다.
2. 화면이 바뀌는 페이즈마다 실제 폰 크기 시안을 먼저 보고, 실기기 확인을 페이즈 안에서 끝낸다.
3. 이미 검증된 서버·동기화·테스트 도구는 v2.0 에서 다시 쓴다. 새로 만드는 것은 게임 경험(기획·화면·에셋)에 집중한다.

### Cost Observations
- Model mix: 기록 없음
- Sessions: 기록 없음
- Notable: 검증·보안·테스트 빈틈 점검을 병렬 에이전트로 돌려 마무리 기간을 줄였다.

## Milestone: v2.0 — 같은 공간

**Completed:** 2026-11-07 (main 반영은 v3.0 실테스트 뒤)
**Phases:** 9 (6·7·8·9·9.1·9.1.1·10·11·12) | **Plans:** 172

### What Was Built
- three 3D 맵 이동(재즈 바·광장), 자유 채팅 채널, 지목→변론→찬반 처형과 유령, 밤 마피아 이동·아침 흔적
- 정치 장치, 동작·의상 캐릭터, 결과 시상·다시 하기, 합성 소리 56개

### What Worked
- 순수 모듈 + TDD(카메라·구간 이동·audience)로 서버·폰이 같은 출처를 쓰게 해 누설·불일치가 적었다
- 배포 가드(`deploy-target.mjs`)로 v1.0 주소를 건드리지 않고 별도 Worker 에 반복 배포했다

### What Was Inefficient
- 표현(맵·연출·장치)을 많이 얹었지만 "처음 하는 사람이 무엇을 하나"를 팀 테스트로 늦게 확인했다
- 실기기 확인을 계속 미뤄 페이즈 검증이 `human_needed`·stale 로 쌓였다
- 6종 E2E 전체 회귀를 자주 돌려 시간이 많이 들었다(바뀐 흐름만 돌리는 규칙으로 바꿈)

### Patterns Established
- 단계별 audience 한 함수로 전송 범위를 고정하고 누설 시험을 신분별로 넓힌다
- 기능은 지우지 않고 설정으로 끈다(v3.0 기본판에서 정치 장치를 끄는 방식)

### Key Lessons
- 장치를 늘리는 것보다 "확인할 수 있는 사실"과 "지금 할 일"을 주는 것이 몰입에 먼저다
- 팀 모의 플레이는 기능이 다 붙기 전, 한 판이 도는 시점에 해야 방향을 싸게 고친다

### Cost Observations
- Sessions: 다수(밤샘 위임 포함)
- Notable: 계획 172개 — 페이즈당 계획이 많아 실행기 컨텍스트를 가볍게 유지하는 규칙이 생겼다

2. 서버가 보내는 범위를 한 함수로 묶으면 기능이 늘어도 누설 검사가 버틴다
