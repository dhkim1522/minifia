## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

화면 E2E 갱신(UI-SPEC 15)의 **검사 쪽 앞부분**이다: 투표·인트로·후보 선택·공개 화면의 합격 기준을 DOM 없이 판정하는 순수 함수로 만들고 단위 시험으로 고정한다. 브라우저에서 값을 읽는 일(04-31)과 흐름 조립(04-32~33)이 이 함수들을 쓴다. 배포하지 않는다(D-26).

## Claude 재량 결정

- **스냅숏 계약 한 곳:** `readVerdict(page)`(04-31)가 만들 값의 모양(`VerdictSnap`)을 이 계획이 `lib.mjs` 머리 주석에 적는다. 04-30 이 나머지 필드를 같은 주석에 더한다. 검사 함수는 필드가 없으면 `측정값 없음(…)` 으로 실패한다(기존 검사와 같은 규칙).
- **기준을 낮추지 않는다.** 새 완화는 `APPROVED_RELAXATIONS` 에 한 줄씩(04-30 의 `P-PANEL-236` 하나). 이 계획은 완화를 더하지 않는다.
- 검사 ID 는 UI-SPEC 15.3 의 `P1`~`P10` 을 그대로 쓴다(기존 ID 와 겹치지 않는다).
- 진홍 판정은 토큰 색값 목록(`crimsonColors`, 브라우저에서 토큰을 읽어 rgb 로 정규화한 문자열 배열)을 입력으로 받아 비교한다 — lib 에 색 값을 하드코딩하지 않는다.
