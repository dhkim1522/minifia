## 페이즈 목표

화면이 무거운 분위기로 바뀌고, 플레이어마다 외형이 다른 캐릭터를 받으며, 세로 폰 화면에서 처음 하는 사람도 설명 없이 지금 할 일을 알 수 있다 (ROADMAP 5페이즈).

이 계획은 페이즈의 **첫 계획이자 트레이서**다. UX-01 의 빈 칸 두 곳(낮 시작 하단·낮 토론 안내)을 상수 → 장면 → DOM 계약(`data-guide`) → 방 화면 렌더 시험까지 한 번에 꿰고, 나머지 모든 단계 화면에 같은 DOM 계약을 붙여 14단계 × 시점 점검표를 시험으로 고정한다. 05-06 의 E2E 검사 `UX1` 이 이 계약(`[data-guide]`)을 그대로 읽는다.

## Claude 재량 결정

- **안내 요소 표(DOM 계약):** 각 단계 화면에서 `data-guide` 를 붙이는 요소를 아래 표 하나로 정한다. 부품이 늘 그 화면의 주 안내인 곳(`NightPanel`·`ClaimPanel`·`ExecVotePanel`·`DefenseChips` 의 제목 `h2`, `TurnPanel`·`DefensePanel` 상태 줄 `.stat b`)은 부품 안에서 항상 붙이고, 같은 부품이 보조 줄로도 쓰이는 곳(`PhaseBar` 안내줄, `ReadOnlyRow`)은 `guide` 불리언 prop 으로 장면이 켠다. 그래서 한 화면에 `[data-guide]` 가 정확히 하나다.

  | 단계 | viewer | `data-guide` 요소 |
  |---|---|---|
  | lobby | 방장·손님 | `.mf-lobby__guide` |
  | assigning | 모두 | 가운데 `h2` `직업을 배정하고 있습니다…` |
  | roleReveal | 모두 | `.mf-reveal__hint` |
  | dayAnnounce | 모두(탈락 포함) | 하단 `NightPanel` 제목 `낮이 되었어요` |
  | claim | 내 차례 / 남의 차례 / 탈락 | `ClaimPanel` 제목 / `TurnPanel` `.stat b` / `ReadOnlyRow`(guide) |
  | discussion | 생존 / 탈락 | `PhaseBar` 안내줄(guide) / `ReadOnlyRow`(guide) |
  | night | 마피아 / 경찰·의사·시민 / 탈락 | `PhaseBar` 안내줄(guide) / `NightPanel` 제목 / `ReadOnlyRow`(guide) |
  | morning | 모두 | `NightPanel` 제목 |
  | execVote | 생존·관전 | `ExecVotePanel` 제목 `h2`(관전 알약 `ReadOnlyRow` 에는 붙이지 않음) |
  | candidateVote · candidateVoteReveal · execution | 모두 | `NightPanel` 제목 |
  | defense | 후보 본인 / 생존 / 관전 / 후보 없음(서버 이상) | `DefenseChips` 제목 / `DefensePanel` `.stat b` / `DefensePanel` 의 `ReadOnlyRow`(guide) / `NightPanel` 제목 |
  | ended | 모두 | `.mf-result__banner-title` |
- **TIMELESS_PHASES 에 assigning 포함(P5-5 기본값, 확인 대기):** 3초 연출 단계라 카운트다운이 읽히기 전에 끝난다. 05-08 이 결정 0038 에 "바뀔 수 있는 기본값" 으로 적는다.
- **낮 시작 하단은 관전자에게도 같은 두 줄**(아침 하단과 같은 규칙, UI-SPEC 7.2). 그래서 dayAnnounce 분기를 `meDead` 분기보다 앞에 둔다.
