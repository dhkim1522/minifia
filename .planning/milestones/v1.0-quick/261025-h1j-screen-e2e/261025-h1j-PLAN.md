## 목표

지금까지 서버 규칙은 봇 시나리오 스크립트(`scripts/uat-*.mjs`)로 자동 확인되지만, 화면(배치·겹침·잘림·반응)은 사람이 폰으로 봐야 했다. 사용자의 요청은 "직접 할 수 있는 건 모두 자동 테스트로" 다. 헤드리스 Chrome 으로 배포본(또는 `--url` 로컬)을 열고, 테스트 방(결정 0022)과 서버 봇(결정 0024)으로 원하는 단계·직업·인원을 만든 뒤 실제 화면 좌표를 검사하는 `npm run e2e` 를 만든다. 테스트 도구라 시안은 만들지 않는다. 화면 결함을 찾으면 기록만 하고 앱 코드는 고치지 않는다.

## 사용자 결정 (이번 요청 — 바꾸지 않는다)

- **U-01 도구**: `playwright-core` 를 devDependencies 에 정확한 버전(`^` 없음)으로 넣고 브라우저는 내려받지 않는다. 실행기는 이미 설치된 시스템 Chrome 을 환경 변수 `CHROME_PATH` 로 띄운다(기본값 macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, Windows·Linux 기본 경로도 찾는다). 찾지 못하면 분명한 안내를 찍고 종료 코드 2. 앱 번들·배포에 들어가지 않는다(scripts/ 전용). `npm run e2e`(= `node scripts/e2e/run.mjs`)를 더하고 HANDOFF 에 적는다. 설치 명령은 `npm install --save-dev --save-exact playwright-core@<현재 안정판>` 이고 package.json·package-lock.json 을 커밋한다.
- **U-02 실행기 인자·출력**: `node scripts/e2e/run.mjs [--url https://minifia.dhplay.workers.dev | http://localhost:5173] [--only <시나리오 부분 문자열>] [--shots] [--sizes 360x640,390x664,430x932]`. 기본 주소 = scripts/prod-url.txt, 기본 크기 = 위 셋. 기기 배율은 좌표 검사에 1, `--shots` 일 때만 2. 결과 표(시나리오 | 크기 | 항목 | 결과 | 내용), 모두 통과 0 · 실패 1 · 중단 2. 화면 사진은 `--shots` 일 때만 `scripts/e2e/out/` 에(.gitignore 에 추가).
- **U-03 방 준비**: 스크립트는 HTTP 로 테스트 방을 만들고(POST /api/rooms, testMode true) 토큰을 찍지 않는다. 페이지를 열기 전에 앱 주소의 localStorage `minifia:session` = JSON {code, token} 을 심어 **브라우저 페이지가 방장**이 되게 한다 — 스크립트와 페이지가 둘 다 방장 소켓을 쥐면 앱이 앞 소켓을 4001 로 대체한다. 방장 동작(testRole·testBots·시작·testSkip)은 실제 [테스트] 시트 버튼을 눌러 한다(테스트 도구 화면도 함께 검사된다). 밤 30초처럼 단계가 흘러가므로 검사 직전에 [다음 단계로 넘기기] 를 누른다. 시나리오 하나는 약 60초 안, 크기별로 서로 다른 방을 병렬로(동시에 최대 3개 — 속도 제한 회피).
- **U-04 시나리오**(각각 360x640·390x664·430x932): (1) 대기실(테스트 방 방장): [테스트] 가 보이고 다른 조작과 겹치지 않음, 봇 줄 [−]/[+] 누를 수 있음, [5명 채우기] 동작(인원 글자) (2) 직업 공개·경찰 방장: 위쪽 제목이 한 줄(오늘의 버그: [수사 기록][내 역할] 옆에서 '직업 공개' 제목이 3줄로 접힘 — 제목 높이 ≤ 1.6 × 줄 높이) (3) 4·5·8명 낮 토론: 가로 스크롤 없음, 모든 이름표가 장면 안에 다 있고 하단 패널에 가리지 않음(사각형 교차 또는 elementsFromPoint), 이름표가 다른 자리의 얼굴(캐릭터 상자 위 45%)을 가리지 않음, [테스트] 버튼이 어떤 캐릭터 상자와도 겹치지 않음(오늘 직업 공개에서 알려진 버그) (4) 경찰·마피아·의사·시민 밤(testRole): 역할별 하단, 자리를 누르면 선택 링(시민은 반응 없음), 마피아는 자신·동료를 누를 수 없음, 위쪽 제목 한 줄 (5) 아침: 카드가 보이고 허용 범위를 넘어 가리지 않음, 하단 문구 '곧 낮 토론이 시작돼요' (6) 경찰 수사 기록: 선택한 밤 뒤 [수사 기록] 점이 켜지고 시트에 '마피아' 또는 '마피아 아님' 줄(봇 선택이 무작위라 결과가 아니라 구조를 본다, 재시도 허용) (7) ^ 버튼의 채팅 내역 모달이 열리고 닫힘 (8) 테스트 시트가 열리고 닫힘.
- **U-05 알려진 결함**: 제목 줄바꿈·[테스트] 겹침 단언은 평범한 단언이다. 오늘 실패가 예상되고, 계획은 그렇게 적으며, 단언을 약하게 만들지 않는다. SUMMARY 에 찾은 결함으로 보고한다. 이 계획에서 앱 코드를 고치지 않는다.
- **U-06 공통 검사**(모든 검사 상태): 가로 스크롤 없음(documentElement.scrollWidth ≤ 폭), 장식이 아닌 요소가 가로로 화면 밖에 없음, 누르는 요소(button, [role=button])는 폭·높이 44 이상(허용 목록은 이유와 함께만), 콘솔 오류 없음(console error·pageerror), 실패한 요청 없음.
- **U-07 보안**: 토큰은 찍지 않는다. 스크립트는 주어진 주소하고만 통신한다. 실행기는 prod-url.txt·localhost 가 아닌 주소는 `--url` 로 명시했을 때만 쓴다.
- **U-08 마지막 과제**: 배포본으로 한 번 돌려 정확한 결과 표를 SUMMARY 와 HANDOFF 에 적는다(예상된 실패 포함). HANDOFF 에 `npm run e2e` 실행법, CHROME_PATH, 검사 범위, 아직 사람이 봐야 하는 것(실제 iPhone Safari·Android Chrome 느낌, 애니메이션 부드러움, 여러 기기 타이밍)을 적고, 커밋하고 SSH 로 push 한다(실행자가 자기가 커밋한 코드·문서를 push 한다).

## Claude 재량 결정 (계획에서 정함)

- **단계·직업은 페이지가 받은 프레임으로 안다**: `page.on("websocket")` → `framereceived` 만 구독해 state 프레임의 view 를 추적기에 둔다(phase·phaseEndsAt·me.role·me.seat·me.allies·me.records·me.pick·me.testBots·me.testRole·players). 두 번째 소켓 없이 단계 도달을 정확히 기다리기 위해서다. 보낸 프레임(hello 에 토큰이 있다)은 구독하지 않고, 받은 프레임 원문도 찍지 않는다.
- **흐름 묶기**: 시나리오 8개를 크기마다 흐름(방) 다섯 개로 묶어 15개 작업으로 돈다(아래 "흐름 설계"). 같은 방에서 직업 공개 → 토론 → 밤 → 아침을 이어 보면 방 수와 시간이 줄고, 단계가 바뀌어도 테이블이 그대로인지(D7)도 볼 수 있다.
- **사람 실기기 목록 중 자동으로 볼 수 있는 것 더하기**: HANDOFF 의 2·3페이즈 실기기 목록에서 좌표로 판정되는 항목을 검사로 더한다 — 세로 스크롤 없음(D5), 하단 패널 높이 157(D6), 단계가 바뀌어도 테이블 면 그대로(D7), 위쪽 바 버튼 한 줄(D8), 4명 이름표 서로 안 겹침(D9), 밤 하단 안내 2줄 이하·패널 안(N4), 8명판에서도 모든 대상 자리를 누를 수 있음(N5), 방장 화면에 연장·넘기기 없음(C3). 수치 출처는 `design/screens/day-v3/SPEC.md`·`night-v1/SPEC.md`.
- **결과 표 모양**: 한 줄 형식은 정확히 `시나리오 | 크기 | 항목 | 결과 | 내용` 이고 시나리오 칸은 `흐름/상태`(예 `police5/claim`), 항목 칸은 `ID 이름`(예 `D1 위쪽 제목이 한 줄`), 결과 칸은 `통과`·`실패`(기존 uat 스크립트와 같은 말). 공통 검사 G1~G6 은 상태마다 한 줄 `G 공통 검사` 로 묶고 내용 칸에 실패한 하위 ID 와 근거를 적는다(약 570줄 → 줄 수를 줄인다). 끝에 `## 요약`(흐름·크기별 통과/전체 15줄)과 `## 실패`(실패 줄만, 같은 형식) 두 표, `걸린 시간 N초`, 마지막 줄 `E2E OK` · `E2E FAIL: N개 실패` · `중단: …`. SUMMARY 에는 전체 표를, HANDOFF 에는 요약·실패 표를 그대로 옮긴다(HANDOFF 는 세션마다 교체되는 문서라 길게 두지 않는다).
- **휴대폰 흉내**: 브라우저 컨텍스트는 viewport = 크기, `isMobile: true`, `hasTouch: true`, `locale: "ko-KR"`. 모바일 흉내에서는 넘친 내용 때문에 layout viewport 가 커질 수 있으므로 가로 검사는 `innerWidth` 가 아니라 **설정한 폭** 과 비교한다.
- **글꼴**: 앱은 index.html 에서 Google Fonts(Gowun Dodum)를 불러온다. 글꼴이 다르면 줄바꿈 판정이 달라지므로 두 글꼴 호스트만 요청 가드의 허용 목록에 두고, 검사 전에 `document.fonts.ready` 를 기다리며 `document.fonts.check('24px "Gowun Dodum"')` 를 준비 검사 S2 로 적는다.
- **방장 닉네임** `화면검사기`(5자 — 가장 긴 이름표로 잘림을 본다). 봇 이름은 서버 고정 목록(3자).
