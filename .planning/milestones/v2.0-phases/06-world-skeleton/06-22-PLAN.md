## Phase Goal

친구들이 `minifia-v2` 주소로 들어와 로비 맵에서 서로의 캐릭터가 걷는 모습을 보고, 이 렌더링 방식이 실제 폰에서 버틴다는 것이 숫자로 확인된다.

이 계획은 UAT 테스트 4 에서 나온 갭 G-06-4 를 닫는다. 진단(`.planning/debug/nametag-overlap-clip.md`)이 밝힌 원인은 코드 버그가 아니라 UI-SPEC 계약 문장이 서로 모순이었다는 것이다: 면 80% 반투명 + "맨 앞은 전부 읽힌다" + "밀지 않는다". 사용자가 2026-11-01 에 좁힌 범위대로 (1) 내 이름표를 맨 위로, (2) 겹친 이름표 중 맨 앞 하나만 면을 짙게 하고, (3) 계약과 E2E 판정을 거기에 맞춘다. 가장자리 잘림·[테스트]/알림 겹침은 수용하므로 건드리지 않는다.

<objective>
`writeTags` 의 이름표 순위에 "내 이름표 맨 위" 를 더하고, 겹친 이름표 중 맨 앞 하나에 `data-front="true"` 를 붙여 CSS 가 면을 `overlay-ink-strong` 으로 바꾸게 한다. 순위·겹침 판정은 순수 함수 `rankTags` 로 뽑아 단위 테스트로 고정한다. E2E NT3 를 같은 규칙으로 확장하고, 06-UI-SPEC 과 화면 지도를 맞춘다.

Purpose: 8명이 한 점에 모여도 '(나)' 가 가려지거나 비쳐 보이지 않게 한다(MAP-07 "이름표가 읽힌다", MAP-01 "서로의 닉네임을 본다"). 새 CSS 토큰은 만들지 않는다 — 승인 토큰 `overlay-ink-strong` 을 쓴다.

</objective>
