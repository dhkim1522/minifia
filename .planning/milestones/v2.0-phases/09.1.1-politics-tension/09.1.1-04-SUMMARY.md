### 동작 사실(화면 09.1.1-14·봇 05 가 기대해도 되는 것)
- 흐름: 지목 끝 알림 마감 → `runoff` step 0(`phaseDurationMs` 1000) → 1(5000) → 2(1500) → `defense`(candidate = 많이 받은 후보, `day.candidate`·그날 `voteLog` 줄의 `cand.candidate` 가 채워짐) 또는 `night`(동점, `noExecution.reason` 은 `tie`, 그날 줄에 candidate 없음). 단계 id 는 하나(`runoff`)이고 세부는 `day.runoff.step`.
- 후보는 낮은 좌석 → 높은 좌석 순(`cand[0] < cand[1]`), `tally` 도 이 순서.
- 첫 표는 모든 소켓이 state 를 받아 `day.runoff.voted` 가 갱신(좌석 오름차순, 값 없음), 같은 사람이 바꾸면 그 소켓만 state(me.ballot 갱신), 같은 값은 프레임 0. 마감을 당기지 않는다(모두 던져도 5초 다 채움).
- `me.ballot` 은 step 1·2, 산 유권자 본인이 던졌을 때만. 후보·유령·미투표자 view 에는 키 없음. 기권(안 던짐)은 표로 세지 않는다.
- 거절: 앞머리·결과·마감 뒤 WRONG_PHASE, 후보 본인·후보 밖 대상·유령·모르는 행위자 BAD_MESSAGE. 검사 순서 = 단계 → 행위자 → 후보 본인 → 창 → 대상 (그래서 앞머리의 후보 시도도 BAD_MESSAGE).
- 지도(걷기)·채팅 단계 집합에 `runoff` 가 들었다(채널 all, 산 사람 걷기 금지·유령 자유). `PHASE_SCENE.runoff = "dusk"`.
