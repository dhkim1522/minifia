## 참고 자료 (design-refs)

- 화면: `design/screens/*.png` — 직접 열어 보고 따른다. 색·간격 값은 그림에서 읽지 말고 토큰을 쓴다.
- 인물: `public/characters/table/fig{1..8}_*_default@2x.png`(`@4x` 는 srcset), 직업 `public/characters/roles/{mafia,police,doctor,citizen}_default@2x.png`, 유령 `public/characters/ghost/`(1페이즈 미사용). 원본·규격 `design/characters/`.
- 배경: `public/backgrounds/bg_{game,entry}_{lobby,night,day,verdict}.svg`(A_cute). 원본·규격 `design/backgrounds/`.
- `design/references/` 의 이미지는 방향 참고용이다. 1차본에서 정리한 쓰지 않을 것(보라·파랑·분홍 그라데이션과 네온 광택, 의미 없는 유리 패널, 이모지 아이콘, 3D 라이브러리)은 그대로다.

디자인 방향 한 줄: "어둡지만 경쾌한 밤" — 달빛 마을 광장 그림 위 원근 테이블에 세트 C 인물이 둘러앉고, 진홍은 위험하거나 확정된 순간에만 나온다.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — 직접 만든 React 부품 + 일반 CSS. 참고 구현은 `design/design-system/components/` |
| Icon library | none — 인라인 SVG(디자인 시스템 `Icon` 의 경로를 옮겨 쓴다: 뒤로, 공유, 카드, 닫기, 복사). 이모지·아이콘 폰트 금지 |
| Font | 시스템 글꼴 `--font-ui`. 웹 폰트 내려받기 없음 |

shadcn 을 쓰지 않는 이유는 1차본과 같다: 새 패키지 설치 없음(T-01-SC), 화면의 중심이 일반 UI 키트에 없는 2.5D 테이블·카드다.

스타일 규칙
- 색·간격·크기·모션 값은 `tokens.css` 변수로만 쓴다. 화면 CSS 에 hex 를 직접 쓰지 않는다. 토큰이 모자라면 `design/tokens.json` 에 더하고 `npm run tokens` 로 다시 만든다(디자인 시스템 아티팩트에도 같은 값을 넣도록 HANDOFF 에 적는다).
- 애니메이션은 `transform`·`opacity`(그리고 인물 상태의 `filter`)만.
- 사용자 문자열(닉네임)은 React 텍스트와 `title` 로만 그린다.
- 그림 경로는 `public/` 기준 절대 경로(`/characters/...`, `/backgrounds/...`).

## Spacing Scale

4의 배수. `--space-*` 토큰.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 점·아이콘 사이, 이름표 안쪽 세로 여백 |
| sm | 8px | 버튼 안 요소 사이, 라벨과 입력칸 사이, 인접 버튼 사이 |
| md | 16px | 기본 간격, 게임 화면 좌우 여백, 입력칸 안쪽 가로 여백 |
| lg | 24px | 입장 화면 좌우 여백, 시트 안쪽 여백, 구역 사이 |
| xl | 32px | 큰 구역 사이 |
| 2xl | 48px | 입장 화면 위쪽 여백 |
| 3xl | 64px | 드묾 |

예외(레이아웃 치수이며 간격이 아니다)
- 누르기 영역 최소 44px(`--tap-min`). 작게 보이는 대상도 투명 영역으로 44×44 이상.
- 컨트롤 높이: 입력칸 48(`--control-input`), 버튼 52(`--control-button`), 작은 버튼(아이콘 버튼·[내 역할]·[참가])은 44 이상.
- 재접속 띠 높이 52.
- 테이블 장면 안(자리·판·조명)은 장면 폭 대비 퍼센트 좌표(`seatLayout`).

화면 틀(설계서 `02_Common.png` "화면 구조"): 기준 390×844, 폭 360~430 에서 같은 구조. `#root` 폭 최대 430px 가운데. 게임 화면은 위쪽 바(단계 이름·[내 역할]·타이머) → 장면 → 하단 시트(안내·버튼). 좌우 여백 입장 화면 24, 게임 화면 16. 위·아래 여백에 `env(safe-area-inset-*)` 를 더한다. 게임 화면(S-03~S-06)은 360×640 에서도 세로 스크롤이 없다(`100dvh`, 장면이 줄어든다). 입장 화면은 키보드가 올라오면 스크롤을 허용한다.

## Typography

크기 4개(14/16/24/36), 굵기 2개(400/700). 설계서의 6단계는 이 조합이다.

| Role | Size | Weight | Line Height | 쓰는 곳 |
|------|------|--------|-------------|---------|
| display | 36px | 700 | 1.2 | 화면당 하나: 서비스 이름 "미니피아", 방 코드, "방 4827", "낮이 되었습니다", 카드 앞면 역할 이름 |
| heading | 24px | 700 | 1.2 | 화면 제목("역할 확인"), 시트 제목, 타이머 숫자, "직업을 배정하고 있습니다…", "1일차" |
| body-strong | 16px | 700 | 1.5 | 버튼 글자, 하단 시트의 강조 안내 |
| body | 16px | 400 | 1.5 | 안내 문장, 입력칸 글자(16 미만이면 iOS 확대), 카드 한 줄 설명 |
| label-strong | 14px | 700 | 1.4 | 이름표 — 자리 크기와 관계없이 항상 14px |
| label | 14px | 400 | 1.4 | 입력 라벨, 보조 설명, 상태·오류 문장, 인원 표시, 버전 |

- 한글은 `word-break: keep-all`. 닉네임·코드는 `break-all` 허용.
- 방 코드는 글자 사이를 띄운다(`letter-spacing: 0.12em`, 보정 `padding-left: 0.12em`), `tabular-nums`.
- 타이머 숫자는 `m:ss`(예 `0:15`), heading, `tabular-nums`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--night-900` #0E1326 | 앱 바탕. 폰 열 바깥(PC)·배정 막은 `--night-950` |
| Secondary (30%) | `--night-800` #151C36, `--night-700` #1E2847, `--gray-800` #2B2F38, `--gray-700` #3A3F4B | 입력칸·시트·입력 카드 면(`--night-800`), 재접속 띠·눌림 면(`--night-700`), 보조 버튼 면(`--gray-800`), 구분선·타이머 트랙(`--gray-700`) |
| Accent (10%) | 진홍 `--crimson-300/400/500` | 아래 "진홍 예약" 에 적힌 곳뿐 |
| Destructive | 진홍 없음 | 1페이즈 확인 시트의 파괴 동작은 `--gray-800` 면(진홍은 처형·탈락 발표에 남긴다) |

글자: 제목 `--gray-50`, 본문 `--gray-100`, 보조 `--gray-300`. **`--gray-500` 은 글자에 쓰지 않는다**(UI 경계 전용). 주 버튼 `--gray-100` 면 + `--night-900` 글자. 보조 버튼 `--gray-800` 면 + `--gray-50` 글자. 포커스 링 `--gray-100` 2px, 오프셋 2px.

**진홍 예약(설계서 공통 규칙 "진홍은 여섯 곳에만" 가운데 1페이즈 해당분)**
1. 타이머 마지막 5초: 숫자 `--crimson-400`, 막대 `--crimson-500`
2. 역할 카드 뒷면 마름모 문양 `--crimson-500`(모두 같은 뒷면 — 역할 정보가 아니다)
3. 마피아 동료 링·문양 `--crimson-400`(테이블. 1페이즈 화면에는 동료가 보이는 테이블이 없지만 Table 부품은 지원한다)
4. 마피아 카드·내 역할 시트의 동료 줄 `--crimson-300`(작은 글자)
5. 입력 오류 문장 `--crimson-300`, 오류 입력칸 테두리 2px `--crimson-300`

진홍을 쓰지 않는 곳: 버튼 면, 포커스 링, 방장 배지, 토스트, 재접속 띠, 링크, 아이콘, 장식.

배경 그림 위 글자: 장면 위에 바로 놓는 글자(이름표, 입장 화면 소개 문구, 낮 발표)는 `--shadow-text` 를 쓴다. 이름표는 반투명 `--night-900` 알약 위에 둔다(디자인 시스템 `Figure` 이름표).

| 화면 | 배경 | 비고 |
|------|------|------|
| S-01, S-02 | `bg_entry_lobby.svg`(입장 구도, 달이 크다) | 아래 40% 위에 입력 카드 |
| S-03 | `bg_game_lobby.svg` | 테이블은 높이 36% 아래부터 |
| S-04 | `bg_game_lobby.svg` + 테이블 + `--night-950` 90% 막 | 테이블이 흐릿하게 비친다 |
| S-05 | `bg_game_lobby.svg` + 어두운 막 | 테이블은 그리지 않는다(설계서 그림) |

## 화면·부품 계약

공통: 세로 한 열, 폭 360~430. 가로 모드는 설계하지 않는다.

### S-01 첫 화면 — `/`
- 배경 입장 구도. 위쪽 가운데: 소개 "친구들과 한 판, 점심시간 마피아"(label, `--gray-100`, 글자 그림자) → 서비스 이름 "미니피아"(display, `--gray-50`).
- 아래쪽 입력 카드(면 `--night-800` 반투명, `--radius-lg`, 안쪽 여백 lg): "닉네임" 라벨 + 입력칸(48) → [방 만들기](주 버튼 52, 전체 폭) → 구분선 + "또는" → "방 코드" 라벨 + 한 줄: 코드 입력칸(placeholder "4자리 숫자", `inputMode="numeric"`) + [참가](보조 버튼, 높이 48). 카드 아래 `v{버전}`(label `--gray-300`, 배포 확인용).
- 닉네임: 1~8자, 마지막으로 쓴 닉네임을 미리 채운다(D-06). 닉네임이 유효하지 않으면 [방 만들기]·[참가] 둘 다 꺼진다. 한 번이라도 입력한 뒤 비우거나 쓸 수 없는 글자를 넣으면 칸 아래에 오류 문장. 코드가 4자리 미만이면 [참가]만 꺼진다.
- 서버 거절(코드 참가): 해당 칸 아래 오류 문장 + 칸 테두리 2px `--crimson-300`. 한 번에 하나. 입력한 닉네임·코드는 지우지 않는다. 칸을 고치면 오류가 사라진다. 방 상태 오류(없는 방·정원·시작됨)는 코드 칸 아래, 같은 이름은 닉네임 칸 아래.
- 네트워크 오류·방 만들기 한도는 화면 아래 토스트.
- 요청 중에는 두 버튼 모두 꺼진다.
- 재접속: 이 브라우저에 진행 중인 방의 입장 정보가 있으면 이 화면을 건너뛰고 그 방의 현재 단계 화면으로 간다. 방이 없어졌으면 입장 정보를 지우고 첫 화면을 보여 준다.

### S-02 링크 참가 — `/r/{code}`
- 배경 입장 구도. 위쪽: "미니피아에 초대받았어요"(label) → "방 {코드}"(display).
- 가운데(광장): 먼저 앉은 사람들 — 인물과 이름표를 한 줄로(자리 순서, 최대 8). 아래 "{n} / 8명이 모였어요"(label-strong).
- 아래 입력 카드: "닉네임" 라벨 + 입력칸(placeholder "1~8자로 입력", 열리자마자 포커스, 미리 채운 닉네임은 전체 선택) → [참가하기](주 버튼, 닉네임이 유효하면 켜짐) → [다른 방 코드로 참가](텍스트 버튼, `/` 로 이동).
- 미리보기는 열 때 받고, 이 화면에 있는 동안 10초마다·화면 복귀 때 다시 받는다(설계서 "인원 표시는 방의 현재 상태를 따라"). 서버 `GET /api/rooms/{code}` 미리보기에 `players: {seat, nickname}[]` 를 더한다(역할·토큰 없음).
- 불러오는 동안: 입력 카드 자리에 "방 정보를 불러오는 중…"(body `--gray-300`).
- 들어갈 수 없는 방: 입력 카드 대신 사유 한 문장(heading) + [처음으로](주 버튼). 같은 이름은 닉네임 칸 아래 오류 문장.
- 그 방의 입장 정보(토큰)가 있으면 이 화면 없이 바로 방으로 들어간다(D-07, CONN-01).

### S-03 대기실
- 위쪽 바: 왼쪽 [뒤로] 아이콘 버튼(44×44, `aria-label="나가기"`) / 가운데 "방 코드"(label `--gray-300`) 아래 코드(display, 글자 사이 띄움) / 오른쪽 [공유] 아이콘 버튼(44×44, `aria-label="공유"`, C-03 을 연다).

  - 첫 줄: 안내(body-strong `--gray-50`) + 오른쪽 인원 "{연결된 인원} / 8명"(label `--gray-300`).
  - 방장: [게임 시작](주 버튼 52, 전체 폭).
  - 참가자: 아래 줄 "친구가 더 오면 링크를 다시 보낼 수 있어요"(label `--gray-300`) + [링크 공유](보조 버튼, 공유 아이콘, C-03 을 연다).

- 안내 문구: 방장 4명 미만 "4명부터 시작할 수 있어요", 4명 이상 "모두 모였으면 시작하세요". 참가자 "방장이 시작하길 기다리는 중이에요", 방장이 끊겼으면 "방장 연결을 기다리는 중이에요". 자리가 8개 다 차면 인원 표시가 "8 / 8명 · 가득 찼어요"(자리 수 기준, 끊긴 사람 포함).
- 토스트(결정 0012): 새 참가자가 앉으면 "{닉네임}님이 들어왔어요", 방장이 바뀌면 모두에게 "{닉네임}님이 새 방장이 되었어요". 화면 위쪽(방 코드 아래) 가운데, 2초. 처음 화면을 열 때(재접속 포함) 이미 있던 사람에게는 띄우지 않는다. 나에 대한 입장 토스트는 띄우지 않는다.

- 게임이 시작되면 모든 폰이 S-04 로 간다.

### C-02 연결 끊김 · 재접속
- 방 화면에서 `status` 가 `connecting`·`reconnecting` 이고 `view` 가 이미 있으면 화면 맨 위에 띠: 높이 52, 면 `--night-700`, "연결이 끊겼어요 · 다시 연결하는 중"(label `--gray-100`). 띠는 내용을 아래로 민다(게임 화면은 장면이 그만큼 줄어든다).
- 끊긴 동안 마지막 화면을 그대로 두고 서버로 가는 입력은 꺼진다([게임 시작], 내보내기, [뒤로]). 카드 뒤집기·[내 역할] 시트처럼 화면 안에서 끝나는 동작은 된다. 카운트다운은 마감 시각 기준으로 계속 그린다.
- 다시 연결되면 띠가 "다시 연결됐어요" 로 2초 바뀌었다가 사라지고, 서버의 현재 단계 화면을 그린다.
- 재연결이 30초 넘게 실패하면(가정) 전체 화면 "연결할 수 없어요" + [다시 시도](주 버튼) + [처음으로](보조 버튼).
- `view` 가 아직 없으면 전체 화면 "연결 중…".
- 다른 창에서 같은 자리로 들어가면(01-02 기존) "다른 창에서 이 방에 들어갔어요" + [다시 연결] / [처음으로].

### Timer
- 입력 `endsAt`, `durationMs`, `offset` 뿐(단계 이름을 모른다). 막대(높이 8, `--radius-sm`, 트랙 `--gray-700`, 채움 `--gray-100`) + 오른쪽 숫자(heading, `m:ss`, `tabular-nums`).

## 접근성·상호작용 규칙

- 누르기 영역 44px 이상, 인접 대상 사이 8px 이상.
- 키보드: 모든 버튼·입력칸에 `:focus-visible` 링. 카드는 Space/Enter 로 뒤집힌다. 시트는 Esc 로 닫힌다.
- 입력칸: 글자 16px, 닉네임 `autocomplete="off" autocapitalize="off" autocorrect="off" spellcheck="false"`, 코드 `inputMode="numeric" pattern="[0-9]*"`, 4자리 넘으면 자른다. `<label>` 연결. 오류 문장은 `role="alert"` 이고 `aria-describedby` 로 칸과 잇는다, 오류 칸은 `aria-invalid="true"`.
- 아이콘 버튼은 `aria-label`(나가기·공유·닫기).
- 상태 안내: 보이지 않는 `aria-live="polite"` 영역 하나가 단계가 바뀔 때만 읽는다("직업을 배정하고 있습니다", "역할 확인", "낮이 되었습니다"). 토스트는 `role="status"`.
- 제출 중복 방지: 요청 중 버튼 꺼짐, 시작 버튼 2초 잠금.
- 역할 비노출: 역할을 보기 전 화면(S-04, 카드 뒷면, [내 역할] 버튼, S-06)은 역할과 무관하게 같은 마크업이다. 다른 점은 마피아 본인 화면의 동료 정보뿐이다. 서버가 다른 사람의 역할을 보내지 않는다(화면에서 숨기는 것으로 대신하지 않는다). 화면 캡처는 막을 수 없고 수용한다.
- 대비: 본문 글자 4.5:1 이상(`--gray-300` 이상), 큰 글자·UI 경계 3:1 이상. 배경 그림 위 글자는 그림자나 알약 면으로 대비를 확보한다.

## Copywriting Contract

말투는 해요체("~어요"), 짧게, 문장 끝 마침표 없음(두 문장 이상인 오류 문장은 첫 문장 뒤 마침표). 진행 중은 말줄임표 `…`. 이모지·느낌표 없음.

| Element | Copy |
|---------|------|
| 서비스 이름 · 소개 | 미니피아 / 친구들과 한 판, 점심시간 마피아 |
| Primary CTA (첫 화면) | 방 만들기 |
| Primary CTA (링크 참가) | 참가하기 |
| Primary CTA (방장, 대기실) | 게임 시작 |

## UI Considerations

> 1차본의 상태 점검 표(요소 13개, 75항목)를 개정 2 기준으로 고쳤다. 바뀐 항목만 적고, 적지 않은 항목은 1차본 판단 그대로다(빈 의자 관련 항목은 "빈 자리는 비워 둔다" 로 읽는다).
> 상태 표기: ✅ resolved · 🧪 backstop(01-10 실기기·폭 360px 확인) · — dismissed · ⚠ assumption.

| 요소 | 항목 | 상태 | 해결 |
|------|------|------|------|
| E1 첫 화면 | empty | ✅ | 닉네임이 유효하지 않으면 두 버튼 꺼짐. 처음 열 때는 오류 문장 없음, 한 번 입력한 뒤부터 칸 아래 오류 |
| E1 | error | ✅ | 코드 참가 거절은 코드 칸 아래(테두리 2px `--crimson-300`), 같은 이름은 닉네임 칸 아래, 네트워크·한도는 아래 토스트 |
| E1 | partial | ✅ | 코드가 4자리 미만이면 [참가]만 꺼짐 |
| E1 | resume | ✅ | 진행 중인 방의 입장 정보가 있으면 첫 화면을 건너뛰고 그 방으로 |
| E2 링크 참가 | populated | ✅ | 먼저 앉은 사람의 인물·이름표 한 줄과 "{n} / 8명이 모였어요". 10초마다·화면 복귀 때 다시 받는다 |
| E2 | error | ✅ | 없는 방·정원·시작됨은 입력 카드 대신 사유 + [처음으로], 같은 이름은 칸 아래 |
| E2 | overflow | 🧪 | 8명이 한 줄에 들어가는지 폭 360px 로 확인(넘치면 인물 크기를 줄인다) |
