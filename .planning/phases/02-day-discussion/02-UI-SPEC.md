## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — 직접 만든 React 부품 + 일반 CSS. 참고 구현은 `design/design-system/components/` |
| Icon library | none — 인라인 SVG(`src/components/Icon.tsx`). 이 페이즈에서 아이콘 11개 추가(아래 "아이콘 추가 목록"). 이모지·아이콘 폰트 금지 |
| Font | 시스템 글꼴 `--font-ui`. 웹 폰트 내려받기 없음 |

shadcn 을 쓰지 않는 이유는 1페이즈와 같다(새 패키지 없음, 화면의 중심이 일반 UI 키트에 없는 2.5D 테이블). 이 페이즈도 새 패키지를 설치하지 않는다.

스타일 규칙(1페이즈 규칙 그대로)
- 색·간격·크기·모션 값은 `tokens.css` 변수로만. 화면 CSS 에 hex 를 쓰지 않는다. 새 토큰은 필요 없다.
- 애니메이션은 `transform`·`opacity`(그리고 인물 상태의 `filter`)만.
- 닉네임은 React 텍스트와 `title` 로만 그린다. 메시지 문장은 클라이언트가 템플릿 ID 로 만든다(서버는 문장을 보내지 않는다).
- 이 페이즈의 토큰에 없는 길이·크기는 부품 안 지역 상수(R18 방식): 주장 공개 팝 360ms, 흔들림 400ms, 공개 유지 2000ms, 말풍선 유지 3000ms, 이모티콘 유지 2000ms, 전송 쿨다운 2000ms, 반응 원 36px, 말풍선 최대 폭 140px, 낮 시작 발표 2000ms.

## Spacing Scale

1페이즈와 같다. 4의 배수, `--space-*` 토큰.

| Token | Value | Usage (이 페이즈) |
|-------|-------|-------------------|
| xs | 4px | 로그 줄 사이, 칩 안 체크 아이콘과 글자 사이, 주장 알약 안 요소 사이 |
| sm | 8px | 칩 사이(가로·세로), 버튼 사이, 로그 안쪽 세로 여백, 완료 알약 안쪽 가로 여백 |
| md | 16px | 위쪽 바 좌우 여백, 패널 안 구역 사이, 로그 안쪽 가로 여백 |
| lg | 24px | 하단 패널·시트 안쪽 좌우 여백 |
| xl | 32px | 사용하지 않음 |
| 2xl | 48px | 사용하지 않음 |
| 3xl | 64px | 낮 시작 발표의 아래 여백(1페이즈 그대로) |

예외(레이아웃 치수, 간격이 아니다)
- 누르기 영역 최소 44px(`--tap-min`): 칩 높이 44, 방장 줄 버튼 44, 이모티콘 칸 높이 52.
- 컨트롤 높이: [빠른 메시지]·[보내기] 52(`--control-button`), [이모티콘] 52×52.
- 반응 원 지름 36, 반응 안 아이콘 22(디자인 시스템 값). 말풍선 최대 폭 140.
- 메시지 로그 높이는 3줄 고정: `calc(3 * 1.4 * 14px + 2 * var(--space-xs) + 2 * var(--space-sm))`(약 83px). 줄이 적어도 높이를 줄이지 않는다(화면이 출렁이지 않게).
- 테이블 장면 안(자리·이름표·주장 알약·말풍선)은 장면 폭 대비 퍼센트 좌표(`seatLayout`).

화면 틀·폭·여백·`dvh`·안전 영역은 1페이즈와 같다. **직업 공개·낮 토론 화면은 360×640 에서도 세로 스크롤이 없다**(장면이 줄어든다, 아래 높이 계산).

높이 계산(360×640 기준, 장면이 남는 높이를 쓴다)

| 화면 | 위쪽 바 | 하단 패널 | 장면에 남는 높이 |
|------|---------|-----------|------------------|
| 직업 공개 | 약 118 | 약 240(손잡이 12 + 제목 29 + 안내 2줄 40 + 칩 2줄 96 + 간격·여백 약 60) | 약 280 → 4:5 장면 폭 약 224, 자리 폭 약 45 |
| 낮 토론(방장) | 약 118 | 약 240(손잡이 12 + 로그 83 + 방장 줄 44 + 버튼 줄 52 + 간격·여백 약 50) | 약 280 |
| 낮 토론(방장 아님) | 약 118 | 약 188 | 약 330 |

장면이 이보다 작아져 자리가 40px 이하가 되면 패널 안쪽 여백(`--space-lg` → `--space-md`)을 먼저 줄이고, 그래도 모자라면 안내 문장을 한 줄로 줄인다(스크롤을 만들지 않는다). 실기기 확인 항목이다(UI Considerations).

1. 타이머 마지막 5초(직업 공개 15초의 끝, 낮 토론 90초의 끝, 연장 뒤에도 같음): 숫자 `--crimson-400`, 막대 `--crimson-500`

진홍을 쓰지 않는 곳(이 페이즈 전부): "말 바꿈", "완료", 주장 알약, 말풍선, 이모티콘, 방장 줄 버튼, 오류·안내 문장, 토스트. **"말 바꿈"을 위험 신호처럼 진홍으로 칠하지 않는다** — 거짓 주장이 아니라 바꿔 말했다는 사실만 보여 주는 것이다.

### S-06b 직업 공개 (15초, 서버 단계 `claim`)
위쪽 바(PhaseBar): 제목 "낮 · 직업 공개"(heading), 안내 "{N}일차"(label `--gray-300`), 오른쪽 [내 역할](1페이즈와 같은 한 가지 마크업), 아래 `Timer`(15초, 마지막 5초 진홍).

장면: 낮 장면 + 테이블 + 전원 자리. 각 자리 이름표는 1페이즈 규칙(항상 14px, 한 줄 말줄임, "(나)").

완료 알약(`ClaimDone`): 누군가가 이번 낮에 **직접 칩을 눌러 고르면** 그 사람 캐릭터 머리 위(말풍선 자리)에 "완료"(label-strong, 면 `--gray-100`, 글자 `--night-900`, `--radius-pill`, 가로 여백 `--space-sm`)가 뜬다. 등장 180ms(scale .6→1, opacity). 한 번 뜨면 마감까지 유지된다(바꿔도 사라지지 않음, D-03). 무엇을 골랐는지는 서버가 마감 전에 다른 사람에게 보내지 않으므로 화면에 나타나지 않는다(D-01). **2일차 이후 어제 선택이 미리 선택돼 있어도 직접 누르기 전에는 완료 알약이 뜨지 않는다**(전원이 완료로 보이면 알약이 의미를 잃는다 — 가정, 아래 "확인 필요"). 내 자리 알약도 같은 규칙.

하단 패널(`ClaimPanel`, `<dialog>` 가 아니라 화면 안 패널 — 1페이즈 대기실 하단 시트와 같은 틀: 면 `--night-800`, 위 모서리 `--radius-lg`, 손잡이 막대, 안쪽 여백 `sm lg lg`, 아래에 `env(safe-area-inset-bottom)`):
- 제목 "주장할 직업을 고르세요"(heading `--gray-50`)
- 안내(label `--gray-300`, 두 문장이라 첫 문장 뒤 마침표): 1일차 "거짓말도 괜찮아요. 시간이 끝나면 모두에게 한꺼번에 공개돼요" / 2일차 이후 "거짓말도 괜찮아요. 바꾸지 않으면 어제 선택이 그대로 공개돼요"
- 칩 줄(`role="group"`, `aria-label="주장할 직업"`): 마피아 · 경찰 · 의사 · 시민 · 말 안 함 순서. **이번 판 구성에 없는 직업은 그리지 않는다**(4명판은 의사 없음 → 4칩). 칩은 줄바꿈한다(5칩이면 첫 줄 4개 + 둘째 줄 말 안 함, 보드 그림 그대로. 칩 줄 가로 스크롤은 쓰지 않는다 — 디자인 시스템 Chip README 의 "가로로 밀어 본다"는 이 화면에서 설계서 그림이 이긴다).
- 칩(`Chip`): 높이 44, 가로 여백 `--space-md`, label-strong 글자, 면 `--night-700`, 테두리 1px `--night-600`, `--radius-pill`. 선택되면 면 `--gray-100`·글자 `--night-900`·테두리 `--gray-100` + 앞에 체크 아이콘 18px(`aria-pressed="true"`). 누를 때 scale .96(180ms). 포커스 링 `--gray-100` 2px.
- 누르면 바로 서버로 보낸다(별도 [확인] 없음). 마감 전까지 다른 칩을 눌러 바꿀 수 있고 마지막 선택이 공개된다(D-03). 이미 선택된 칩을 다시 눌러도 아무 일 없다(선택 해제 없음).
- 처음 상태: 1일차는 선택된 칩이 없다. 2일차 이후는 어제 선택 칩이 선택된 상태(체크)로 시작한다(D-09).
- 내 선택은 내 폰에만 보인다. 서버는 내 선택을 내 뷰(`me`)에만 싣고 다른 사람 뷰에는 "완료 여부"만 싣는다. 재접속하면 내 선택이 복원된다.
- 끊긴 동안(재접속 띠가 떠 있는 동안)과 공개 연출 중 칩은 꺼진다(opacity .6).
- 시간이 넘도록 아무것도 고르지 못한 사람: 서버가 말 안 함으로 처리한다(D-05). 2일차 이후 직접 고르지 않은 연결된 사람은 미리 선택돼 있던 어제 선택이 공개된다(화면이 거짓말하지 않게 — "확인 필요" 2번).

### S-06c 주장 공개 연출 (약 2초, 서버 단계 `claimReveal`)
- 마감 순간 모든 사람의 주장이 한꺼번에 공개된다. 모든 캐릭터 머리 위에 주장 말풍선(`.mf-bubble` 모양: 면 `--gray-100`, 글자 `--night-900`, label-strong, `--radius-md`, `--shadow-card`)이 동시에 뜬다. 내용은 직업 이름 하나("경찰") 또는 "말 안 함". **말 안 함 말풍선은 흐릿하게**(opacity .6).
- 모션: 팝 360ms(`--ease-out`, scale .6→1.1→1, opacity 0→1) 직후 흔들림 400ms(translateX 0 → -3px → 3px → -2px → 2px → 0 한 번). 전원 동시(시차 없음). 말풍선은 공개 시작부터 2000ms 머물고 마지막 180ms 에 사라진다.
- 같은 순간 이름표 아래 주장 알약이 나타나 이후 낮 토론 내내 유지된다(D-06). 완료 알약은 말풍선으로 대체돼 사라진다.
- "말 바꿈": 직전 낮과 다른 **직업**을 고른 사람의 주장 알약 안에 "· 말 바꿈"이 함께 나타난다(주장 알약 모양은 아래 `ClaimTag`). 말풍선에는 "말 바꿈"을 넣지 않는다. 이전 주장 이력은 보이지 않는다(D-08). 어제 말 안 함 → 오늘 직업은 말 바꿈으로 치지 않고 처음 주장으로 본다(권장안, Claude 재량 D-08). 어제 직업 → 오늘 말 안 함은 말 바꿈 표시 없이 "말 안 함"만 보인다(가정 — 직업을 "바꿔 말한" 것이 아니므로).
- 위쪽 바: 제목 "낮 · 직업 공개" 그대로, 안내 "{N}일차" 그대로, 타이머는 0:00 과 빈 막대로 머문다. 하단 패널은 높이를 유지한 채 제목 "주장이 공개됐어요", 안내 "곧 토론이 시작돼요", 칩 줄은 내 선택이 표시된 채 꺼져 있다(레이아웃이 출렁이지 않게).
- 이 동안 메시지·이모티콘은 서버가 거부한다(성공 기준 5). 화면에 보내기 버튼이 없다.
- 재접속해서 공개 연출 도중에 들어온 사람: 말풍선 애니메이션을 다시 돌리지 않고 주장 알약만 보인다.
- `prefers-reduced-motion: reduce`: 팝·흔들림 없이 말풍선이 나타나고 2초 뒤 사라진다(상태 변화는 그대로).

### S-07 낮 토론 (90초, 서버 단계 `discussion`)
위쪽 바: 제목 "낮 · 토론"(heading), 안내 "{N}일차"(label), [내 역할], `Timer` 90초(`1:30`부터). +30초 연장하면 타이머가 새 `endsAt`·`durationMs`(120초)로 다시 그려진다(막대 비율이 커지며, 마지막 5초 진홍 상태가 풀릴 수 있다).

장면: 테이블 + 전원 자리 + 이름표 + **주장 알약**(`ClaimTag`) + 말풍선·이모티콘 층.

`ClaimTag`(이름표 바로 아래 줄, 방장 배지가 있으면 그 아래): 알약 면 `--night-800`, 테두리 1px `--night-600`, `--radius-pill`, 안쪽 가로 여백 `--space-sm`, 직업 글자 label-strong `--gray-50`("경찰", "말 안 함"), 말 바꿈일 때 같은 알약 안 `--space-xs` 간격으로 "· 말 바꿈"(label 400, 색 `--gray-300`). 한 줄, 최대 폭 112px. 낮 토론 내내 유지되고 다음 낮 공개 때 새로 계산된다. 접근성: 자리 그룹 `aria-label` 에 ", 직업 주장 {직업}" 과 말 바꿈이면 ", 말 바꿈"을 더한다.

말풍선·이모티콘 층(`SeatFloat`):
- 자리마다 **한 번에 하나**만 뜬다. 같은 사람이 3초 안에 새 말풍선·이모티콘을 보내면 새 것이 이전 것을 바꾼다.
- 위치: 보낸 사람 머리 위. 앞쪽 자리 `headTop - 1%`, 뒤쪽 자리 `headTop - 8%`(디자인 시스템 값). 가로는 장면 안에 가둔다: `left: clamp(70px, {x}%, calc(100% - 70px))`(말풍선 최대 폭 140 의 절반).
- 말풍선: 위 "주장 공개 연출"과 같은 `.mf-bubble` 모양, 내용은 완성된 문장("하윤 의심돼요"), 최대 폭 140, 3초 유지. 등장 180ms(opacity 0→1, translateY 6px→0, scale .8→1), 퇴장 180ms 페이드. 꼬리 없음.
- 이모티콘: 지름 36 원(`.mf-react`: 면 `--gray-100`, 아이콘 `--night-900` 22px, `--shadow-card`), 2초 유지. 등장·퇴장 말풍선과 같은 모션.
- 동시에 여러 사람이 보내면 겹쳐도 된다. 나중에 온 것이 위(`z-index` 증가), 이름표보다는 항상 위층.
- 스크린 리더: 말풍선·이모티콘 층은 `aria-hidden`. 메시지는 로그가, 이모티콘은 보이지 않는 `aria-live="polite"` 줄("{닉네임}: {이모티콘 이름}", 가장 최근 하나)이 읽는다.

하단 패널(`DiscussionControls` + `MessageLog`, 면 `--night-800`, 틀은 직업 공개 패널과 같음):
1. **최근 메시지**(`MessageLog`, 디자인 시스템 `.mf-log` 옮김): 면 `--night-700`, 반경 `--radius-md`, 안쪽 여백 `sm md`(디자인 시스템 `.mf-log` 의 `--night-800` 은 패널과 같은 면이라 경계가 사라지므로 한 단계 올린다). 3줄 높이 고정(위 "Spacing" 예외), 줄 하나는 한 줄(label 14px): 앞에 보낸 사람 구분 점(8px 원, `--seat-{자리+1}` 토큰) + 보낸 사람 이름(label-strong; 나는 "나") + 문장(label). 마지막 줄(가장 최근)은 `--gray-100`, 이전 줄은 `--gray-300`. 줄은 한 줄 말줄임. 위로 밀면 이전 메시지(서버 보관 최대 약 20개)가 나온다. 새 메시지가 오면 맨 아래로 자동 스크롤하되 사용자가 위로 밀어 둔 동안은 그대로 둔다. 새 줄은 180ms 페이드. `role="log"`, `aria-live="polite"`, `aria-relevant="additions"`.
   - 빈 상태: 줄 하나에 "아직 메시지가 없어요"(label `--gray-300`), 높이는 그대로.
2. **방장 전용 줄**(방장에게만 그린다. 방장이 아닌 사람에게는 이 줄이 **없다**, 서버도 NOT_HOST 로 거부): 보조 버튼(compact, 높이 44) 둘이 같은 폭으로 가로(간격 `--space-sm`): [+30초 연장](앞에 `plus` 아이콘) · [넘기기](앞에 `skip` 아이콘).
   - [+30초 연장]은 낮 토론마다 1회. 쓰고 나면 꺼지고(opacity .6) 글자가 "이미 연장했어요"로 바뀐다. 다음 낮에 다시 1회. 누르면 모두에게 토스트 "방장이 30초를 늘렸어요"(2초, 화면 위쪽 타이머 줄 아래).
   - [넘기기]는 확인 없이 즉시 실행(D-18). 누르면 두 버튼이 꺼지고(요청 중, 화면은 서버의 다음 단계로 넘어갈 때까지 기다린다).
   - 방장이 끊겨 있으면 조작할 사람이 없고 타이머대로 넘어간다(중대하지 않음).
3. **말하기 줄**: [빠른 메시지](주 버튼 52, `chat` 아이콘, 남는 폭) + [이모티콘](보조 버튼 52×52, `smile` 아이콘, `aria-label="이모티콘"`). 둘 다 누르면 해당 시트가 열린다. **보낸 직후 두 버튼은 2초 동안 꺼진다**(opacity .6, 연타 방지 D-14). 끊긴 동안도 꺼진다.

화면 단계 전환: 90초가 끝나거나 방장이 넘기면 서버가 일차 +1 로 다음 낮 시작 발표(S-06a)로 돌린다(임시 루프, D-19). 열려 있던 시트는 자동으로 닫힌다(고른 내용은 버린다, 알림 없음).

### S-08a 빠른 메시지 시트
`Sheet` 틀(`showClose`, `aria-label="빠른 메시지"`). 위쪽부터:
1. 제목 "빠른 메시지"(heading)
2. 라벨 "무슨 말을 할까요?"(label `--gray-100`) + 문구 칩 5개(줄바꿈, 순서 고정): "[○○] 의심돼요" · "[○○] 믿어요" · "저 아니에요" · "[○○]는 [직업]이었어요" · "[○○] 투표해요". 설계서 그림의 순서(의심돼요 · 믿어요 · 저는… · …이었어요 · 저 아니에요 · 투표해요)에서 "저는 [직업]이에요"만 뺀 것이다. **시트가 열릴 때 첫 칩("[○○] 의심돼요")이 미리 선택돼 있다**(설계서 그림). 선택을 해제할 수 없다.
3. "누구에게?" 라벨 + 대상 칩: **나를 뺀 생존자**의 닉네임, 서버 seat 오름차순. 선택되면 체크. 끊긴 사람도 목록에 있다(연결 끊김은 칩에 표시하지 않는다). "저 아니에요"를 고르면 이 줄이 사라진다.
4. 문구가 "[○○]는 [직업]이었어요"일 때만 "무슨 직업이었나요?" 라벨 + 직업 칩(이번 판 직업, 마피아·경찰·의사·시민 순, 말 안 함 없음)이 대상 줄 아래에 나타난다(D-12). 대상을 먼저 고르고 직업을 고른다.
5. "미리보기"(label) + 완성 문장 알약(`.mf-bubble` 모양을 시트 폭까지 허용): 예 "하윤 의심돼요". 칸이 비어 있으면 그 자리는 "[○○]"·"[직업]" 글자 그대로, 알약의 `--night-900` 글자 불투명도 .6 으로 보인다(`--gray-500` 은 글자에 쓰지 않는다).
6. [보내기](주 버튼 52, 전체 폭). 필요한 칸(대상·직업)이 모두 채워지면 켜진다. "저 아니에요"는 칸이 없어 바로 켜진다. 누르면 서버로 보내고 시트가 닫힌다(240ms). 서버가 받으면 모든 폰에 보낸 사람 말풍선과 로그 줄이 뜬다.

닫기: [닫기] 아이콘, 막 누르기, 아래로 끌기, Esc. **닫으면 고른 내용을 버린다**(다시 열면 첫 칩이 다시 선택된 상태). 1페이즈 시트 규칙(`Sheet`)을 그대로 따른다. 키패드는 없다(입력칸 없음).

**문장 만들기 규칙(클라이언트, 템플릿 ID + seat + 직업으로만 만든다)**

| 템플릿 | 문장 | 비고 |
|--------|------|------|
| `suspect` | "{닉네임} 의심돼요" | |
| `trust` | "{닉네임} 믿어요" | |
| `claimed` | "{닉네임}{은/는} {직업}{이었어요/였어요}" | 은/는: 닉네임 마지막 글자가 받침 있는 한글이면 "은", 없으면 "는". 한글이 아닌 글자(영문·숫자 등)는 "는"으로 둔다(가정). 직업: 마피아였어요 · 경찰이었어요 · 의사였어요 · 시민이었어요 |

### S-08b 이모티콘 트레이
`Sheet` 틀(`showClose`, `aria-label="이모티콘"`). 제목 "이모티콘"(heading). 4열 × 2행 격자(간격 `--space-sm`): 칸 8개(웃음 · 크게 · 놀람 · 의심 / 화남 · 슬픔 · 좋아요 · 느낌표). 칸: 높이 52, 면 `--night-700`, 테두리 1px `--night-600`, `--radius-md`, 위에 아이콘 22px(`--gray-100`) 아래 글자 label(`--gray-100`)(화면 읽기용 이름은 "크게 웃음"). 아래에 "2초에 한 번 보낼 수 있어요"(label `--gray-300`).
- 칸을 누르면 **바로 보낸다**(확인 없음). 보내면 8칸이 모두 2초 동안 꺼진다(opacity .6). **트레이는 닫히지 않는다** — 쿨다운 뒤 연달아 다른 걸 보낼 수 있다(설계서). 보낸 사람 머리 위에 원형 이모티콘이 2초 뜬다(모든 폰, 내 폰 포함).
- 이모티콘은 로그에 남지 않고 서버가 보관하지 않는다(재접속 때 복원 없음).

### 오류·거부 처리 (서버 → 화면)

| 서버 코드 | 상황 | 화면 |
|-----------|------|------|
| `RATE_LIMITED` | 2초 안 재전송(클라이언트 쿨다운을 우회한 경우) | 아무 표시 없음. 두 버튼을 지금부터 2초 다시 꺼 둔다 |

## 접근성·상호작용 규칙

1페이즈 규칙(44px, 인접 8px, `:focus-visible` 링, 시트 Esc, 시트 밖 포커스 이동 금지)을 따르고 아래를 더한다.

- 칩은 `aria-pressed` 토글 버튼(디자인 시스템 Chip 규칙)이고, 칩 줄은 `role="group"` + `aria-label`("주장할 직업", "문구", "대상", "직업"). 선택은 색만이 아니라 체크 아이콘 + 면 반전으로 표시한다.
- 직업 공개 시작·단계 전환 안내(`aria-live="polite"` 영역, 1페이즈 `PHASE_ANNOUNCE` 확장): `dayAnnounce` "{N}일차 낮이 되었습니다", `claim` "직업 공개. 주장할 직업을 고르세요", `claimReveal` "직업이 공개되었습니다", `discussion` "낮 토론".
- 공개 연출 뒤에는 자리 그룹 `aria-label` 이 "{닉네임}, 직업 주장 {직업}, 말 바꿈"을 읽어 준다(말풍선은 `aria-hidden`). 직업 공개 중 자리 `aria-label` 은 완료한 사람에게 ", 선택 완료"를 더한다.
- 메시지 로그 `role="log"`, 새 메시지 한 줄씩 읽는다("{보낸 사람} {문장}"). 이모티콘은 가장 최근 하나만 보이지 않는 live 줄이 읽는다.
- 꺼진 버튼은 `disabled`(쿨다운·끊김·연장 사용). 꺼진 이유가 쿨다운이면 별도 설명은 없다(2초).
- 시트가 열린 동안 단계 타이머는 계속 간다. 시트를 연 채로 단계가 바뀌면 시트는 닫히고 고른 내용은 버려진다(1페이즈 [내 역할] 시트와 달리 이 시트는 단계에 묶여 있다).
- 역할 비노출: 이 페이즈의 새 화면은 모두 역할과 무관한 같은 마크업이다(직업 칩 목록도 이번 판 구성이라 모두 같다). 내 선택은 내 폰에만 있고, 공개 전까지 서버는 남의 선택을 보내지 않는다(화면에서 숨기는 것으로 대신하지 않는다). 공개된 주장은 거짓일 수 있다는 점을 화면 문구가 알려 준다("거짓말도 괜찮아요").
- 대비: 칩 글자 `--gray-100`/`--night-700` 및 선택 `--night-900`/`--gray-100`, 로그 `--gray-300` 이상, 말풍선 `--night-900` on `--gray-100` — 모두 4.5:1 이상.

## 화면이 서버 뷰에서 필요로 하는 값 (형식은 계획이 정한다)

UI 가 동작하기 위해 서버 뷰·이벤트가 실어야 하는 것의 목록이다. 이름·스키마는 정하지 않는다(CONTEXT "Claude's Discretion" 의 서버 메시지 형식·방 상태 스키마).

- 단계: `dayAnnounce`, `claim`, `claimReveal`, `discussion` (계획이 단계 이름과 `claimReveal` 을 별도 서버 단계로 둘지 정한다 — "확인 필요" 3번). 일차 `day`.
- 이번 판 직업 목록(공개 정보, 서버 구성표 한 곳에서). 칩·직업 선택지·검증이 같은 목록을 쓴다.
- 자리별 공개 값: `claimDone`(직접 고른 적이 있는가), 공개 뒤 `claim`(직업 또는 말 안 함)과 `changed`. **마감 전에는 다른 사람의 선택을 보내지 않는다.**
- 내 값: 현재 선택(`me.claim`, 직업 공개 중에만 의미).
- 낮 토론: `extendUsed`(이번 낮 연장 사용 여부), 최근 메시지 목록 `{ seat, template, targetSeat?, role?, at }`(최대 약 20개, 서버 시각), `phaseEndsAt`·`phaseDurationMs` 는 연장되면 바뀐다.
- 이벤트: 새 메시지(방 전체), 새 이모티콘 `{ seat, icon }`(방 전체, 저장 안 함).
- 3페이즈 이후를 위해 대상 후보는 `isAlive` 공용 함수로 계산한다.

## 확인 필요 (1·2·4 는 2026-10-24 사용자 확정, 3 만 계획이 정한다)

1. **[확정: 이 문구만 4번 허용] "[○○]는 [직업]이었어요" 4번 누름**: 성공 기준 6 은 템플릿 → 대상·직업 → 보내기(3번)를 말한다. 대상과 직업이 둘 다 필요한 이 문구는 4번이다. 허용할지, 성공 기준 문구를 "대상·직업을 한 줄에 합친 문구"로 고칠지 정해야 한다.
2. **[확정] 2일차 이후 어제 선택**: D-09(미리 선택)와 D-05(고르지 못하면 말 안 함)를 이 문서는 "연결된 사람은 어제 선택 유지, 끊긴 사람은 말 안 함"으로 풀었다. 맞는지 확인.
3. **공개 연출 단계**: `claimReveal` 을 서버 단계로 분리하는 안(권장, 모든 폰이 같은 시각에 시작·종료)과 낮 토론 시작 후 2초 동안 연출만 보여 주는 안 중 하나를 계획에서 정한다.
4. **[확정: "는"으로 둠] 조사**: "[○○]는 [직업]이었어요" 의 은/는 에서 닉네임 끝 글자가 한글이 아니면 "는"으로 둔다(가정). 어색해도 괜찮은지 확인.
5. **표기**: 템플릿 빈칸은 설계서와 REQUIREMENTS 의 "[○○]"(흰 동그라미)를 쓴다. CONTEXT 는 "[OO]" 로 적었는데 같은 뜻이다.
