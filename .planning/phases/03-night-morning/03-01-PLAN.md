## 페이즈 목표

낮 다음 밤이 되면 각 폰이 역할에 맞는 선택 화면을 보이고(마피아는 전용 채팅 포함), 마피아·경찰·의사의 행동이 서로 모르게 처리되어 아침에 결과가 발표된다.

이 계획은 3페이즈의 트레이서다. 서버 단계 표에 밤 30초·아침 5초를 더해 낮 토론 → 밤 → 아침 → 다음 낮 루프를 서버(순수 tick)·워커(알람)·화면(방 화면 라우팅)까지 한 줄로 잇고, 와이어 계약의 타입을 한 번에 정한다. 판정 규칙(03-03), 뷰 값 채우기(03-05), 워커 행동 배선(03-07), 화면(03-08·03-10·03-11)은 이 계약 위에 얹는다.

범위 밖(한 줄): 밤 행동·판정·채팅·화면 내용. 이 계획이 끝난 뒤 밤 화면은 아직 낮 장면의 제목을 쓴다(03-08 이 바꾼다). 4페이즈 전까지 승패가 없어 판이 끝나지 않는 것은 의도된 상태다(RESEARCH Pitfall 9).

## Claude 재량 결정

- **루프 순서:** `discussion → night → morning → dayAnnounce`. 아침 다음은 다음 낮(직업 공개 앞 발표)이다 — ROADMAP Phase 3 Notes("4페이즈가 생기기 전까지는 낮 토론 다음 바로 밤, 아침 다음 다시 낮"), CONTEXT Claude's Discretion(단계 표·진입 훅 구조는 결정 0016).
- **난수 주입:** `tick(state, now, randInt = NO_RANDOM)`. `NO_RANDOM` 은 불리면 `Error` 를 던진다 — 낮만 도는 기존 테스트는 영향이 없고, 난수가 필요한 진입(03-03 의 아침 판정)을 난수 없이 부르면 즉시 드러난다(RESEARCH Pattern 1).
- **`MORNING_PHRASE_COUNT = 8` 은 와이어 상수로 `shared/protocol.ts` 에 둔다.** 서버(문구 번호 선택, 03-03)와 화면(문장 표, 03-10)이 같은 값을 읽는다.
- **아침 단계 안내 문구는 03-10 이 정한다.** 이 계획은 PHASE_ANNOUNCE 의 morning 항목을 빈 문자열로 두고(대기실과 같은 "읽을 것 없음"), 03-10 이 카드 제목까지 붙인다.
- **이 계획은 밤 진입 훅을 아직 두지 않는다.** night·morning 은 시간으로만 넘어가는 단계다. 진입 훅(선택 비우기·판정)은 03-03 이 같은 ON_ENTER 표에 행을 더한다.
