이 계획은 03.1 의 트레이서 첫 조각이다: 서버 규칙(순수 함수)만으로 "방장이 고르고 나머지는 시간 초과 → 낮 토론" 이 흐르는 것을 먼저 증명하고, 와이어 계약(protocol)·뷰까지 한 번에 정한다. 워커 배선·봇·결정 기록(03.1-02), 화면(03.1-03 이후)은 이 계약 위에 얹는다. **이 계획이 끝난 시점에 `src/`·`worker/` 는 아직 옛 계약을 쓰므로 전체 `npm run typecheck` 는 03.1-02·03.1-03 이 닫는다. 이 계획의 타입 검사는 `shared/`·`test/unit/` 범위로 좁혀 본다.**

## Claude 재량 결정

- **차례 상태는 방 상태 필드로 둔다:** `claimOrder`(차례 순서 seat 목록), `claimIdx`(지금 차례 위치), `claimStart`(직전 시작 자리), `claimPick`(지금 차례의 고른 값, 차례가 끝나면 지운다), `claimLog`(공개 주장 기록). 모두 optional 이라 옛 저장 방도 읽힌다. `RoomState` 는 서버 전용이고 view 는 허용 목록으로만 만든다.
- **단계 표(PHASE_DEFS)만으로는 "같은 단계에 머물기" 를 표현할 수 없다.** 그래서 tick.ts 에 진입 훅 표(ON_ENTER)와 짝인 **마감 훅 표(ON_DEADLINE)** 를 더한다. 훅은 `{ state, stay }` 를 돌려주고 stay 면 같은 단계에서 마감만 `이전 마감 + 단계 길이` 로 옮긴다. 결정 0016-2 의 "단계 전이는 tick 루프 안에서만" 원칙은 그대로다.
- **일찍 고르기 = 마감 당기기.** selectClaim 은 `claimPick` 을 적고 `phaseEndsAt` 을 `now` 로 당기기만 한다(결정 0022 의 skipPhase 와 같은 방식). 다음 차례로 넘기는 일은 호출하는 쪽(워커)이 `tick(state, now, randInt)` 를 부르면 ON_DEADLINE 이 한다. claim.ts 가 tick.ts 를 import 하지 않아 순환이 없다.
- **공개 연출 단계 삭제(D-07):** 주장 줄이 차례가 끝나는 순간 채팅에 올라오고 팝·흔들림이 삭제되므로(UI-SPEC C1) 2초 대기는 의미가 없다. 한 판 시간만 늘린다.
- **차례가 아닌 사람의 claim 은 WRONG_PHASE:** "지금은 그 사람이 할 때가 아니다" 라는 시간 문제이고 클라이언트는 어느 코드든 error + 최신 state 로 서버 값으로 돌아간다(기존 sendRejection 규칙).
- **주장 채팅 줄 문장은 서버가 만들지 않는다.** 서버는 `claimLog` 의 직업 키만 보내고 문장은 화면이 만든다(UI-SPEC "스타일 규칙"). 표시용 템플릿 ID 는 03.1-07 이 더한다.
