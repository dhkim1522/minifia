# Phase 3.1 Plan 01: 순차 주장 서버 규칙 Summary

직업 주장을 "한 명씩 8초" 순서로 돌리는 서버 순수 규칙을 tick 의 새 마감 훅(ON_DEADLINE)으로 넣었다. 방장이 한 번 고르고 나머지가 시간 초과하면 tick 만으로 낮 토론까지 흐르고, 뷰에는 지금 차례(`day.turn`)와 공개 기록(`day.claimLog`)만 모든 viewer 에게 같게 실린다. 끝나지 않은 차례의 선택(`claimPick`)은 어떤 view 키로도 나가지 않는다는 것을 4~8명 × 시드 3 전수 검사로 고정했다.

## 한 일

**Task 1 (트레이서)**: `scripts/tsc-scoped.mjs`(범위 좁힌 타입 검사 게이트)와 규칙 테스트 10건, `CLAIM_TURN_MS` 8000, claim.ts 새 규칙(`claimOptions`·`currentClaimSeat`·`enterClaim`·`selectClaim`·`resolveClaimTurn`), tick.ts `ON_DEADLINE`, view.ts `turn`·`claimLog`, protocol.ts 새 타입. 방장 한 번 선택 + 나머지 시간 초과 → 낮 토론, 알람이 늦어도 tick 한 번이 따라잡고 마감은 이전 마감 + 8000 으로 연쇄되는 것을 증명했다.

**Task 2 (규칙 전 경로)**: 시작 자리 이동(0 → 1 → … → 0), 탈락자 건너뜀, 방장 탈락 시 첫 생존 seat, 생존자 1명·0명, 검사 순서 여섯 가지 거부, `none` 허용, 끊긴 사람의 차례, 이월 없음, 일차 누적 순서. `normalizeStoredRoom` 이 옛 공개 연출 단계(→ discussion + 90000)·차례 상태 없는 claim 방(→ enterClaim + 8000)·옛 Player 주장 필드 넷을 옮기고 해당 없으면 같은 객체를 돌려준다. chat.ts `senderOf` 가 허용 단계를 받아 emote 만 claim 에서 허용한다.

**Task 3 (뷰 계약·전수 누출)**: view.test.ts 를 새 계약으로 재작성했다. 허용 경로는 `me.role`·`day.roles[]`·`day.claimLog[].claim`, claim 중 day 키는 정확히 `claimLog,n,roles,turn`, 고른 직후(tick 전) 상태의 view 가 고르기 전과 마감 시각만 다름을 모든 viewer 에서 확인한다.
