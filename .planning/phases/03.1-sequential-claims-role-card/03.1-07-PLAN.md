## 페이즈 목표

직업 주장을 한 명씩 차례로 평문 채팅으로 하고(결정 0023), 역할 카드의 활동 기록 탭에서 역할별 일지(수사·암살·치료)를 본다(결정 0026). 실제 폰 화면에서 겹침과 줄바꿈 없이 읽힌다.

이 계획은 순차 주장 화면의 앞 절반이다: 주장 채팅 줄, 남의 차례 하단 완성형, 차례 강조 연결. 낮 캐릭터 탭 → 유저 기록 카드는 03.1-08 이 한다(같은 DayScene 을 이어서 고치므로 순서가 있다).

## Claude 재량 결정

- **주장 줄은 `claimLog` 에서 화면이 만든다.** 합성 `ChatLine`(`template` = 표시 전용 ID `claimRole`/`claimNone`, `seq` = 오늘 줄 개수에서 거꾸로 센 음수)으로 만들어 기존 `MessageLog`·`ChatHistorySheet`·`ChatLineItem` 을 그대로 쓴다. 음수 seq 는 실제 채팅 번호(≥ 1)와 겹치지 않아 React key 가 안전하다. 주장 줄은 항상 받은 채팅 줄보다 앞이다(주장 단계가 토론보다 먼저).
- **표시 전용 템플릿 ID 를 `TEMPLATE_IDS` 끝에 더하고 별도 상수 `DISPLAY_ONLY_TEMPLATE_IDS = ["claimRole","claimNone"]` 로 구별한다.** 서버는 이 ID 를 chat 프레임으로 보내지 않고 `say` 로도 받지 않는다(`when: "claim"` 이라 `say` 의 때 검사에서 BAD_MESSAGE, claim 단계 say 는 WRONG_PHASE). `shared/schemas.ts` 의 `z.enum(TEMPLATE_IDS)` 는 고치지 않는다 — 파싱을 통과해도 `say()` 가 상태·방송 없이 거부한다. 빠른 메시지 칩 순서 목록(`TEMPLATE_ORDER`·`NIGHT_TEMPLATE_ORDER`)은 바뀌지 않는다. 결정 0027-7 에 기록되어 있다.
- **쿨다운은 훅으로 뽑는다.** `DiscussionControls` 안의 "보낸 순간 + 2초 잠금 + RATE_LIMITED 재잠금 + 언마운트 정리" 로직을 `useSendLock` 으로 옮겨 `TurnPanel` 이 같은 규칙을 쓴다(합산 쿨다운은 서버 규칙이라 두 곳의 동작이 같아야 한다). `DiscussionControls` 의 외부 동작은 바뀌지 않는다.
- **이모티콘 수집 단계를 넓힌다:** 말한 사람 반전·이모티콘 말풍선은 claim·discussion·night 에서 모으고, 채팅 줄 수집은 discussion·night 로 그대로 둔다(claim 의 `chat` 이벤트는 오지 않는다).
