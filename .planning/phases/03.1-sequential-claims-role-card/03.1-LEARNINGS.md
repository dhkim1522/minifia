# Phase 3.1 Learnings: 순차 주장과 역할 카드

## Decisions

### 일찍 고르기는 "선택 기록 + 마감 당기기"이고, 차례 넘김은 tick 이 한다
`selectClaim` 은 `claimPick` 만 적고 `phaseEndsAt` 을 `now` 로 당긴다. 다음 차례로 넘기는 일은 호출하는 쪽의 `tick` 이 하며 `claim.ts` 는 `tick.ts` 를 import 하지 않는다. 마감 훅 표 `ON_DEADLINE`(claim → `resolveClaimTurn`)은 같은 단계에 머물며 마감을 이전 마감 + 8000 으로 연쇄해 알람이 늦어도 tick 한 번이 따라잡는다.

**Rationale:** 순수 규칙 모듈 사이의 순환 의존을 막고, 늦은 알람에도 차례가 밀리지 않게 한다.
**Source:** 03.1-01-SUMMARY.md, 03.1-02-SUMMARY.md

### 끝나지 않은 차례의 선택과 차례 순서는 서버 전용 키로 두고 view 에 싣지 않는다
`claimPick`·`claimOrder`·`claimIdx`·`claimStart` 는 서버 상태에만 있다. 전원에게는 `day.turn = {seat}` 과 공개 `day.claimLog = {n,seat,claim}` 만 간다. `worker/room.ts applyClaim` 은 `selectClaim` 직후 같은 호출에서 `tick` 해서 pending pick 이 저장·방송될 틈이 없다.

**Rationale:** 비공개 정보 경계가 이 페이즈의 핵심 위험(결정 0002, 허용 목록 view). 화면에서 숨기는 것으로 대신하지 않는다.
**Source:** 03.1-VERIFICATION.md, 03.1-SECURITY.md (T-03.1-01, T-03.1-06)

### 역할별 일지(`me.records`)는 본인 역할의 것 하나만, 줄은 숫자·불리언으로만 보낸다
경찰 `{n,target,isMafia}`, 마피아 `{n,target,died}`, 의사 `{n,target}`. 줄 안에 직업 문자열을 넣지 않고, 의사 줄에는 구출 여부(`died`)를 싣지 않으며, 마피아의 `died` 는 공개 아침과 같은 정보라서 새 정보가 아니다. 탈락한 시민 관전자에게도 `records` 키가 없다.

**Rationale:** 일지 한 줄이 다른 역할이나 구출 사실을 암시하지 않게 한다(결정 0026-4).
**Source:** 03.1-04-SUMMARY.md, 03.1-SECURITY.md (T-03.1-11, T-03.1-12, T-03.1-13), 03.1-VERIFICATION.md

### 일지 SVG 9종은 역할과 무관하게 전부 미리 받는다
`src/net/assets.ts` 가 세 직업 × (cover, page, icon) 을 모두 프리로드해 `rolePreloadList` 가 7 → 16 개가 됐다.

**Rationale:** 요청 패턴으로 내 역할이 드러나는 것을 막는다(T-03.1-18). 그림 교체는 `journalArt(role, slot)` 한 곳만 고치면 된다(D-13).
**Source:** 03.1-06-SUMMARY.md, 03.1-SECURITY.md, 03.1-CONTEXT.md

### 읽은 일지 개수만 폰에 저장한다
`minifia:records:{방코드}` 키 하나에 0 이상 정수 문자열만 둔다(`parseCount` 가 위조값 방어). 기록 내용·토큰은 저장하지 않는다. 다른 기기에서는 점이 다시 보일 수 있음을 수용했다.

**Rationale:** 비공개 정보를 브라우저 저장소에 남기지 않으면서 앰버 점 읽음 처리를 구현한다.
**Source:** 03.1-CONTEXT.md (D-11), 03.1-SECURITY.md (T-03.1-32, T-03.1-33), 03.1-11-SUMMARY.md

### E2E 기준 수치는 낮추지 않고, 사용자가 승인한 완화 3건(M1, D3a/D3b, D4)만 허용한다
`OVERLAP_EPS=0.5`, `ONE_LINE_FACTOR=1.6`, `FACE_RATIO=0.45`, `TAP_MIN=44`, `PANEL_H=157` 은 그대로 두고, 12px 글자 허용 목록 `TEXT_SIZE_ALLOW` 는 `.mf-journal__new` 와 `.mf-tt-sheet__list small` 둘뿐이다. 단위 테스트가 그 밖 선택자와 기준 수치 변경을 거부한다.

**Rationale:** 검사를 통과시키려고 검사를 약화하는 것을 구조적으로 막는다.
**Source:** 03.1-VERIFICATION.md, 03.1-09-SUMMARY.md, 03.1-12-SUMMARY.md, 03.1-SECURITY.md (T-03.1-36)

## Lessons

### 계획 시점에 계산되지 않은 상호 겹침은 E2E 가 찾는다
밤 끝 알림이 360 폭에서 [테스트] 버튼 가운데 점을 1.8px 덮어 `elementFromPoint` 눌림이 실패했다. UI-SPEC 는 알림이 얼굴 가림 규칙 대상이 아니라고만 했고 [테스트] 와의 관계는 계산돼 있지 않았다. D4 를 완화하지 않고(사용자 결정 C) 폭 < 390 에서만 여백 16 → 8, 간격 8 → 4 로 앱을 고쳤다(UI-SPEC 예외 S13).

**Context:** 03.1-12 에서 폭 3종 × 6 흐름 E2E 전체 실행 중 발견.
**Source:** 03.1-12-SUMMARY.md

### 대소문자를 구분하지 않는 파일 시스템에서는 새 테스트 파일명을 먼저 확인한다
계획의 `test/client/rolecard.test.tsx` 가 macOS 와 Windows 에서 기존 `roleCard.test.tsx` 와 같은 파일이라 기존 내용을 덮어썼다. `git checkout` 으로 되돌리고 `roleCardSheet.test.tsx` 로 옮겼다. 후속 계획 03.1-11 의 verify 명령에도 같은 이름이 있어 고쳐 실행해야 했다.

**Context:** 사용자가 Mac 과 집 Windows PC 를 오가며 작업하는 환경.
**Source:** 03.1-06-SUMMARY.md

### 설계 계약이 바뀌면 옛 테스트를 지우는 것이 아니라 새 계약의 단언으로 옮긴다
공개 연출 단계 삭제, 주장 말 바꿈 폐지, 이름표 아랫줄 삭제로 파일 목록에 없던 client 테스트 여러 개(discussion·morning·nightChat·nightScene)가 깨졌다. 매번 임계값을 낮추거나 단언을 지우지 않고 새 값으로 바꿨으며, 삭제한 테스트는 의도가 폐지된 이유(결정 0023)를 SUMMARY 에 적었다.

**Context:** 계획의 `files_modified` 와 grep 기준선이 직접 참조만 세어 영향 범위를 놓친 사례가 반복됐다.
**Source:** 03.1-01-SUMMARY.md, 03.1-03-SUMMARY.md, 03.1-05-SUMMARY.md, 03.1-08-SUMMARY.md

### 타이밍 시험은 즉시 지나가는 차례가 아니라 8초 시간 초과 창에서 한다
방장 차례는 바로 넘어가 거부·이모티콘 시험이 경쟁 상태가 된다. 스모크는 `clients[3]` 한 명을 일부러 안 고르게 두어 그 창 안에서 시험하고, uat-night 은 2일차 첫 차례를 탈락자 claim 시험이 끝날 때까지 붙든다(그러지 않으면 거부 코드가 `BAD_MESSAGE` 가 아니라 `WRONG_PHASE` 가 된다).

**Context:** 03.1-13 에서 소켓 스크립트를 새 계약에 맞출 때.
**Source:** 03.1-13-SUMMARY.md

### 개발 서버에서는 스모크의 마지막 캐시 헤더 단언이 항상 실패한다
vite 개발 서버는 `public/_headers` 를 적용하지 않아 `Cache-Control: max-age=86400` 단언이 `no-cache` 로 실패한다. 단언을 느슨하게 하지 않고 저장소 밖 스크래치에 그 줄만 끈 사본으로 변경이 맞는지 확인했으며, 진짜 확인은 배포본에서 한다.

**Context:** 계획의 "로컬에서 `SMOKE OK full`" 가정이 거짓이었다. 02-11 SUMMARY 와 HANDOFF 에 알려진 한계로 이미 기록돼 있었다.
**Source:** 03.1-13-SUMMARY.md

### 헤더가 붐빌 때 보인 D1 실패는 옛 [수사 기록] 버튼이 함께 있던 시점의 흔적이었다
03.1-09 가 본 경찰 헤더 제목 2줄·D7 실패는 03.1-11 이 옛 버튼을 지운 뒤 재현되지 않았다. 앱 결함이 아니라 중간 상태를 찍은 것이다. 다만 옛 빌드를 다시 돌려 확인하지는 않았다.

**Context:** 결함을 고치기 전에 현재 HEAD 에서 재현되는지 먼저 본다.
**Source:** 03.1-12-SUMMARY.md

## Patterns

### 마감 훅 표(ON_DEADLINE)와 진입 훅 표(ON_ENTER)의 쌍
훅이 `{ state, stay }` 를 돌려주고 `stay` 면 같은 단계에 머물며 마감만 이전 마감 + 단계 길이로 옮긴다.

**When to use:** 한 단계 안에서 같은 종류의 구간(차례, 라운드)을 반복해야 하고 알람이 늦을 수 있을 때.
**Source:** 03.1-01-SUMMARY.md

### 변이 확인(mutation check)으로 RED 없는 테스트의 감도를 증명한다
구현이 이미 끝나 테스트가 처음부터 통과하는 경우, 구현을 임시로 변형해(`>` → `>=`, view 에 `claimPick` 싣기, 의사 줄에 `died` 섞기, 시민에게 `records` 주기) 테스트가 실패하는지 본 뒤 원복하고 `git diff` 가 비어 있음을 확인한다.

**When to use:** 부정 단언이나 누출 검사처럼 구현이 없어도 참이 되기 쉬운 테스트.
**Source:** 03.1-01-SUMMARY.md, 03.1-02-SUMMARY.md, 03.1-04-SUMMARY.md

### 전수 누출 검사는 "허용 경로 최소화 + 서버 전용 키 부재"로 쓴다
`leak.test.ts` 가 모든 프레임 경로에서 서버 전용 키가 없고, `.view.me.records` 는 받아야 할 소켓 집합(경찰·마피아·의사)에만 있으며 실제로 받았는지도 확인한다. `smoke.mjs` 와 `uat-test-bots.mjs` 의 `LEAK_NEEDLES` 도 같은 방식이다.

**When to use:** 비공개 정보를 다루는 view 나 프로토콜 변경이 있을 때.
**Source:** 03.1-04-SUMMARY.md, 03.1-13-SUMMARY.md, 03.1-SECURITY.md

### 범위를 좁힌 타입 검사 게이트와 단일 판정 함수
`scripts/tsc-scoped.mjs` 의 `evaluate` 가 grep 파이프 대신 한 곳에서 판정한다(상태 0 통과, 상태 1·2 는 모든 오류 줄이 경로 형식이고 범위 안 0 개일 때만 통과). 순수 함수 + CLI 로 테스트가 가능하다.

**When to use:** 큰 변경 도중 아직 고치지 않은 영역의 타입 오류와 지금 고친 영역을 구분해 게이트를 걸어야 할 때.
**Source:** 03.1-01-SUMMARY.md

### 읽는 쪽이 정하지 못하는 조건은 한 곳에서만 계산한다
`roleArt` 는 `meDead ? view.spectate : undefined` 한 곳에서만 만들고, 합성 채팅 줄은 `when:"claim"` 로 서버가 만든다(say 로는 `BAD_MESSAGE`, claim 단계 say 는 `WRONG_PHASE`). 화면은 `day.turn.seat === me.seat` 일 때만 패널을 열고 어긋나도 서버가 막는다.

**When to use:** 화면이 서버 규칙을 복제하다 어긋나면 비공개 정보가 새거나 위조될 수 있는 곳.
**Source:** 03.1-VERIFICATION.md, 03.1-SECURITY.md (T-03.1-09, T-03.1-25, T-03.1-29)

### 새 선택 props 는 기본값을 두어 기존 호출부 테스트를 건드리지 않는다
`DayScene` 의 `roleCardOpen = false`, `onOpenActivity?` 를 선택 props 로 두었고 실제 호출부 `RoomScreen` 만 명시해 넘긴다. CSS 규약 테스트가 서로 충돌하면 테스트를 약화하지 않고 규칙을 새 파일(`rolecard-toast.css`)로 나눈다.

**When to use:** 여러 테스트가 같은 컴포넌트를 직접 그리는 점진적 UI 교체.
**Source:** 03.1-11-SUMMARY.md

## Surprises

### 규칙 테스트 일부가 RED 단계에서 이미 통과했다
03.1-01 Task 1 구현이 시작 자리·거부 순서·이월 없음·테스트 방 넘기기까지 이미 덮어 Task 2 RED 에서 일부가 통과했고, 03.1-02·04 에서도 같은 일이 있었다. 이미 통과한 테스트가 진짜 검사를 하는지는 변이 확인으로 보강해야 했다.

**Impact:** RED/GREEN 커밋 쌍이 계획대로 나오지 않는 경우가 있어 기록으로 설명해야 했다.
**Source:** 03.1-01-SUMMARY.md, 03.1-02-SUMMARY.md, 03.1-04-SUMMARY.md

### 일찍 고르기 후 새 마감은 이전 마감보다 늦다
계획은 "이전 마감보다 앞당겨진다"고 적었으나 새 마감 `now + 8000` 은 호출 시각이 이미 지난 마감 뒤라면 이전 마감보다 항상 뒤다. 실제 의미는 "원래 일정(이전 마감 + 8000)보다 앞섬"이라 단언을 `호출 시각 + 8000 ≤ 마감 ≤ 응답 시각 + 8000` 과 `마감 < 이전 마감 + 8000` 으로 더 정확히 옮겼고 결정 0027-4 에 적었다.

**Impact:** 단언이 느슨해진 것이 아니라 정확해졌다.
**Source:** 03.1-02-SUMMARY.md

### 아침 카드가 5초 동안 뒷자리 얼굴을 가리고, 7·8명판 이름표도 일부 가려진다
이름표를 캐릭터 아래 층으로 내리는 선택의 대가로 7명 50%·8명 55% 까지 가려지는 것을 수용했다(F7). [테스트] 버튼이 5명판에서 자리 2 가장자리와 1.5px 겹치는 것도 수용했다. 이 항목들은 실기기 확인 대기 목록에 남았다.

**Impact:** 자동 검사로 판정할 수 없는 가독성 판단이 사람 확인으로 넘어갔다(정식 확인은 6페이즈 몫이었으나 이후 6페이즈는 삭제됨, 결정 0041).
**Source:** 03.1-VERIFICATION.md, 03.1-CONTEXT.md

### 구현한 밤 끝 알림은 이후 결정으로 삭제됐다
이 페이즈에서 "눌러서 활동 기록 탭으로 가는 4초 알림"(D-12)을 만들고 360 폭 겹침까지 고쳤으나, 결정 0028-1 이 알림 자체를 삭제했다(보안 감사에는 T-03.1-34 완화로 기록).

**Impact:** 알림 전용 CSS·테스트 투자의 일부가 쓰이지 않게 됐다. 실기기 피드백이 설계를 단순화한 사례다.
**Source:** 03.1-SECURITY.md (T-03.1-34, T-03.1-35), 03.1-11-SUMMARY.md, 03.1-12-SUMMARY.md

### 페이즈 말미에 배포본 E2E 출력이 로컬에 남지 않았다
`scripts/e2e/out/last-run.txt` 는 3.1 이전 72건 실패 기록으로 남은 오래된 파일이었고, 배포본 E2E·봇 UAT 결과는 SUMMARY 보고만 근거였다. 검증자는 같은 코드(배포본 = HEAD)를 로컬 서버에서 직접 돌려 18/18 로 보완했다. 또 `uat-test-bots` 통과 개수가 로컬 41/41, 배포본 42/42 로 한 개 달랐고 원인 줄을 추적하지 않았다.

**Impact:** 배포본 검증의 독립 확인이 약해졌다.
**Source:** 03.1-VERIFICATION.md, 03.1-14-SUMMARY.md
