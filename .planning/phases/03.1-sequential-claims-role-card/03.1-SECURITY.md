# Phase 3.1 — Security (순차 주장과 역할 카드)

> 페이즈 보안 계약: 위협 등록부, 수용한 위험, 감사 기록. 검증 기준은 ASVS L1(완화 장치가 인용한 파일에 실제로 있는지 확인), `block_on: high`. 등록부는 14개 계획(03.1-01 ~ 03.1-14)의 `<threat_model>` 을 모아 중복 ID 를 합친 것이다(T-03.1-SC 는 한 줄). 근거는 2026-10-30 현재 코드 기준이다.
> 이 페이즈의 위험은 비공개 정보 경계다: 끝나지 않은 차례의 선택, 역할별 일지(`me.records`), 살아 있는 사람 화면의 남의 직업 그림. 이후 페이즈가 바꾼 부분은 현재의 동등한 통제를 완화 장치로 센다(결정 0021·0027·0036, `test/worker/leak.test.ts`).

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| 클라이언트 claim 메시지 → 서버 규칙 | 신원은 소켓 첨부의 playerId 뿐. 단계·차례·값 검증은 서버 | claim 값 |
| 서버 방 상태 → 플레이어별 view | 한 사람에게 갈 값만 허용 목록으로. 끝나지 않은 차례의 선택은 싣지 않는다 | 직업, 일지, 관전 정보 |
| 서버 방 상태 → 전원 방송 state | 공개 주장 기록과 지금 차례 seat 만 | day.turn, day.claimLog |
| 서버 봇 → 사람과 같은 본체 | 봇은 특권이 없다 | 봇 claim |
| 저장된 옛 방 → 새 코드 | 옛 단계 이름·필드를 정규화 | 저장된 방 상태 |
| 서버 view → 화면 / 닉네임 → DOM | 화면은 서버 값만 믿고, 닉네임은 다른 플레이어가 정한 문자열 | 닉네임, roleArt 입력 |
| 정적 에셋(SVG) → 화면 | 저장소의 정적 파일 | 일지 SVG 9종 |
| 폰 저장소 → 읽은 일지 개수 | 사용자가 바꿀 수 있는 값 | 숫자 문자열 하나 |
| E2E·UAT·smoke 스크립트 → 서버 | 토큰이 출력에 남으면 안 된다 | 플레이어 토큰, 프레임 |
| 이 PC → Cloudflare / GitHub | 개인 계정과 개인 SSH 원격만 | 배포 계정, 원격 |
