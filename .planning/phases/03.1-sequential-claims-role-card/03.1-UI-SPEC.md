# Phase 3.1 — UI Design Contract (순차 주장과 역할 카드)

> 화면·상호작용 계약서. 요구사항 DAY-02(차례 주장), NIGHT-04(역할별 화면: 일지), ELIM-01(관전)의 화면 몫이고, 성공 기준 4(실제 폰 화면에서 겹침·줄바꿈 없음)의 **수치 계약**이다.
>
> **시각 디자인은 사용자가 승인한 시안이다(`design/screens/claim-turns-v1/`, `design/screens/role-card-v1/`).** 이 문서는 새 모양을 만들지 않고 시안을 토큰·부품·상태표·좌표로 옮긴다. 시안이 정하지 않은 곳(탭 모양, 배치 규칙, 좌표)과 시안과 **달라지는 곳**은 "시안과 달라지는 곳"과 "확인 필요"에 모았다. 달라지는 곳은 모두 **계산으로 이유를 댄다**(승인 시안대로는 E2E 결함이 남기 때문).
> 1·2·3페이즈 계약(`../01-walking-skeleton/01-UI-SPEC.md`, `../02-day-discussion/02-UI-SPEC.md`, `../03-night-morning/03-UI-SPEC.md`)의 토큰·글자·간격·접근성 규칙을 그대로 물려받고, 이 문서에 적힌 것만 덮어쓴다.

shadcn 을 쓰지 않는 이유는 1~3페이즈와 같다(새 패키지 없음, 중심 화면이 2.5D 테이블). `components.json` 없음(확인: `ls components.json` → 없음, 2026-10-25). 이 페이즈도 새 패키지를 설치하지 않는다.

스타일 규칙(이전 그대로)
- 색·간격·크기·모션 값은 `tokens.css` 변수로만. 화면 CSS 에 hex 를 쓰지 않는다. 이 페이즈의 새 색은 아래 "새 토큰"에서 토큰으로 먼저 만든다.
- 애니메이션은 `transform`·`opacity` 만.
- 닉네임·문구는 React 텍스트로만 그린다. 주장 문구는 서버가 보낸 값(직업 키)에서 화면이 문장을 만든다(문장표는 `src/game/roleText.ts` 한 곳).
- 서버 view 에 없는 값(남의 역할 등)을 화면이 추측하지 않는다. 일지는 `me.records`(본인에게만)에서만 그린다.

## 화면 기하 (수치 계약의 기준)

모든 좌표는 `src/game/dayTable.ts` 와 같은 공식으로 계산했다. 자리 `k`(나 = 0, 시계 방향), 인원 `n`: `θ = π/2 + 2πk/n`, 발 위치 `x = cx + rx·cosθ`, `y = cy + ry·sinθ`, 깊이 `d = (sinθ+1)/2`, 배율 `s = 0.8 + 0.2d`, 캐릭터 상자(배율 적용 후) 폭 `72s`·높이 `96s`, 왼쪽 `x − 36s`, 위 `y − 96s`. **얼굴 영역 = 상자 위 45%**(E2E `FACE_RATIO`). 테이블 인물 8종 PNG 의 알파 경계를 재 보니 머리는 가로 8~92%, 세로 6~16%에서 44% 에 있어 이 영역이 머리를 거의 정확히 덮는다(투명 여백이 아니다).

|--------|------|--------------------|---------------|-------------------|-----------------------|----------------------|

## 화면·부품 계약

### A. 헤더 (D1 해소)

- 구성: 윗줄 = 왼쪽 열(제목 24px + 안내 14px) · 오른쪽 **[역할 카드] 버튼 하나**. 아랫줄 = 진행 막대 + 남은 시간. 높이 119.2(위 표).
- 제목 `h1` 과 안내 `p` 는 `white-space: nowrap`, 윗줄 `min-height: 50.4px`. 제목 열이 줄어들 일이 없도록 폭을 계산해 둔다: 360폭에서 윗줄 가용 328(= 360 − 32), 버튼 최대 폭 **120**(14px 굵게: 테두리 1 + 여백 12 + 아이콘 20 + 간격 8(S5) + 글자 "역할 카드"(4자 ≈ 60) + 여백 12 + 테두리 1 ≈ 114), 간격 8 → 제목 열 ≥ **198**. 가장 긴 제목 `낮 · 직업 공개` ≈ 150, 가장 긴 안내 `N일차 · 함께 지목하세요` ≈ 150. 둘 다 여유 50.
- 단계별 제목·안내: claim `낮 · 직업 공개` / `N일차`, discussion `낮 · 토론` / `N일차`, night `밤` / `N일차`(살아 있는 마피아는 `N일차 · 함께 지목하세요`), morning `아침` / `N+1일차`.
- 헤더 타이머: **claim 에서는 지금 차례의 남은 시간**(8초 → 0, 막대 채움 = 남은/8, 차례가 바뀌면 다시 가득). 숫자는 하단의 `N초`와 같은 값. (시안 K1·K2 의 막대 퍼센트는 예시다.)
- 버튼 접근성: `aria-label` = 안 읽은 기록이 있으면 `역할 카드, 새 기록`, 없으면 `역할 카드`. 점은 `aria-hidden`.

### B. 순차 주장 (K1·K2·K4)

규칙(서버가 정하고 화면은 받은 값만 그린다): 차례는 살아 있는 사람 중 자리 순서 시계 방향, 시작 자리는 날마다 한 칸 이동, 한 명 8초, 일찍 고르면 바로 다음, 시간 초과 = `말 안 함`, 어제 주장 이월 없음. 화면이 받는 것: **지금 차례 seat**, **차례 마감 시각**, 이번 판 직업 목록(`view.day.roles`), 지금까지의 공개 주장. 와이어 이름은 계획이 정한다(결정 0020 방식으로 기록).

**테이블**
- 차례 자리: 발밑 링 `.mf-dt__spot`(폭 140%, 높이 24%, `bottom:-4px`, `translate(-50%, 50%)`, 3px gray-50 + 빛), 머리 위 말풍선 배지 `.mf-dt__turn`(28px 원, gray-50 면, `--night-900` 말풍선 아이콘 16px, 위 -24px, 가운데), 이름표 윗줄 반전(`.mf-dt__tag--turn`: `--spoke` 와 같은 반전). 차례가 없는 단계(토론·밤·아침)에는 없다. 한 번에 한 자리만.

  - 빈 상태: 목록 면은 그대로 두고 한 줄(14px/20 gray-300, 안쪽 8 0) — 수사 `아직 조사한 사람이 없어요`, 암살 `아직 지목한 사람이 없어요`, 치료 `아직 보호한 사람이 없어요`.
  - 용어: 밤 마피아의 살해 = **암살**, 낮 투표의 탈락 = **처형**(4페이즈). 이 페이즈 화면에 `처형` 글자는 나오지 않는다.
  - 탈락한 경찰·마피아·의사도 같은 탭을 본다.
- **안 읽음 규칙**: 읽은 개수는 폰 메모리 `minifia:records:{방코드}`(3페이즈 03-11 의 키와 같다). 안 읽은 수 = `me.records.length − 읽은 개수`. 활동 기록 탭이 **보이는 순간** 읽은 개수를 현재 길이로 올려 버튼 점·탭 점이 함께 사라진다. 그 시트를 닫을 때까지는 이번에 새로 본 줄에 `NEW` 가 남고, 닫으면 사라진다. 탭이 열려 있는 동안 새 기록이 오면 즉시 읽음 처리하고 `NEW` 를 단다. `내 역할` 탭만 열었을 때는 읽음 처리하지 않는다. 기록 내용·토큰은 저장하지 않는다.
- **밤 끝 알림**(R6): 같은 접속(epoch)에서 `me.records` 길이가 늘 때만, 역할이 경찰·마피아·의사일 때만, 시트가 닫혀 있을 때만 띄운다(재접속·처음 마운트·길이 불변에는 없음). 문구 `수사일지가 추가됐어요 · 눌러서 보기`(경찰) / `암살일지가…`(마피아) / `치료일지가…`(의사). 알약 모양(모서리 pill, 면 night-900 94%, 테두리 1px gray-100, 그림자), **누르는 버튼**: 높이 ≥ 44(안쪽 위아래 12·좌우 16), 일지 아이콘 16 + 간격 8 + 글자 14px 굵게 gray-50 `white-space: nowrap`, `max-width: calc(100% - 32px)`, 위치 헤더 아래(`top: 127px` = 119.2 + 8), 수명 **4초**(아침 5초 안에 사라짐), 누르면 사라지고 시트가 `활동 기록` 탭으로 열린다. 내용은 `role="status"`. 이 알림은 일시적이라 얼굴 가림 규칙(D4·M1)의 대상이 아니다.

### E. [테스트] 버튼 배치 (D4 해소)

- 낮 장면(`DayScene`)에서 [테스트] 는 **장면 상자의 왼쪽 아래**에 둔다: `.mf-tt-anchor` = 높이 0 인 닻을 장면 상자 맨 아래에 놓고 버튼을 `position:absolute; left:0; bottom:8px` 로 올린다. 모양(점선 1px, 모서리 14, 높이 44, 글자 14px 굵게, 렌치 18)은 승인 시안 T1 그대로이고 너비 ≈ 87.7(E2E 실측), **상한 92**.
- 근거(계산): 맨 아래 왼쪽 사각형 `[0,92] × [장면높이−52, 장면높이−8]` 는 어떤 인원(4~8)·세 크기에서도 캐릭터 상자와 겹치지 않고 한 줄 이름표와 최소 9.1px 떨어진다(가장 빡빡한 곳: 360×640 · 8명판 · 자리 1 이름표 y 280.7~302.7 vs 버튼 위 311.8). 맨 위 왼쪽은 5명판(자리 2 상자 위 50.5, 버튼 아래 52)과 7명판(자리 3 상자 왼쪽 93.0 vs 버튼 오른쪽 92)에서 닿으므로 쓰지 않는다.
- 규칙: [테스트] 는 (1) 어떤 자리의 캐릭터 상자와도 겹치지 않고(허용 0.5px), (2) 한 줄 이름표와 8px 이상 떨어지고, (3) 하단 패널과 8px 간격이다. 관전자(이름표 둘째 줄이 있는) 8명판 360×640 에서는 자리 1·7 의 **둘째 줄 이름표**와 겹칠 수 있다(얼굴·캐릭터 상자는 아님, 상자는 31px 이상 떨어짐) — 테스트 방 방장이 탈락했을 때만 생기는 알려진 예외.
- 대기실·낮 시작 발표(`Day`)에서는 지금 위치 그대로다(이 계약 밖).

## 확인 필요

시안이 없거나 계산으로 시안과 달라진 곳이다. 아래는 계약이 정한 기본값이며 사용자가 다르게 정하면 해당 항목만 고친다.

1. **6~8명판 D3(이름표 ↔ 이웃 얼굴)는 한 줄 이름표로 0 이 되지 않는다.** 4·5명판은 0(간격 0 적용). 6~8명판은 결정 0017-1 이 받아들인 겹침이고 승인 시안 K4 도 같다. 기본값: E2E 는 허용 쌍 목록으로 회귀만 막는다. **해소안(시안 없음, 계산으로 검증됨)**: 이름표를 **발 아래 대신 머리 위**(상자 위 − 이름표 높이 − 1)에 두는 자리를 인원별로 정한다 — 6명: 슬롯 {2, 4}, 7명: {2, 3, 4, 5}, 8명: {2, 3, 5, 6}(나 = 0 기준). 이 규칙으로 4~8명판 · 세 크기 모두 얼굴 겹침 0 · 이름표끼리 겹침 0 · 장면 안(폭 100·70 둘 다 확인). 단점: 머리 위에 이름표가 오면 차례 배지(-24)·이모티콘(-36)과 위치가 겹쳐 둘의 위쪽 이동 규칙이 더 필요하다. 채택하려면 Design 캔버스 시안이 먼저다.
2. **아침 카드를 패널 안으로 옮긴 것**(D-a)은 시안 M1 과 다르다. 8명판에서 테이블 위 어디에도 카드가 들어가지 않는다는 계산이 근거다. 사용자가 테이블 위 카드를 고수하면 8명판은 "카드가 뒷자리 얼굴을 가리는 것을 허용"하는 길뿐이다(M1 은 8명판에서 영구 실패).
3. **헤더 실측 119.2**(시안·SPEC 100)를 기준으로 삼았다. 장면이 시안(407)보다 19.2 짧다. 헤더를 100 으로 줄이면 장면이 늘지만 `PhaseBar` 의 간격·여백을 시안 값으로 바꾸는 일이다 — 이 계약은 하지 않는다.
4. **[테스트] 위치**를 장면 아래 왼쪽으로 옮겼다(시안 T1 은 왼쪽 위). 관전자(둘째 줄 이름표) 8명판 360×640 에서 이름표 둘째 줄과 겹칠 수 있는 예외가 있다(테스트 방 방장이 탈락한 경우만).
5. **관전자 이름표 둘째 줄(실제 직업)은 유지**한다. 결정 0023 의 "이름 한 줄"은 살아 있는 사람 화면의 규칙으로 읽었다(실제 직업을 보여 줄 다른 자리가 시안에 없다). 이 줄은 D3 계산 밖이다(관전자 흐름은 E2E 가 다루지 않음).
6. **탭 줄 모양**은 시안에 CSS 가 없어(`.tabs__b` 정의 없음) 이 문서가 정했다(선택 night-700 + gray-300 테두리, 안 선택 night-800 + night-600 테두리).
7. **시민의 `내 역할` 본문**: "기존 시트"를 "탭 줄 없는 같은 구조"로 읽어 모든 역할이 같은 `.mf-rolecard__body`(128×160 액자)를 쓴다.
8. **작은 빨간 글자는 crimson-300**: 03 계약은 수사 기록 `마피아`를 crimson-400 으로 정했으나 14px 에서 3.61:1 이라 4.5:1 미달(C9).
9. **알림은 눌리는 버튼**이 되어 시안(높이 36, 2초)보다 커지고 길어진다(D-f). 얼굴 가림 규칙의 대상이 아니다.
10. **말풍선 배지 -24px**(시안 -28px, D-b), **이름표 간격 0**(시안 3, D-c).
11. **430×932 에서 테이블 아래 약 297px 가 비어 있다.** 이 페이즈는 `cy = 210` 고정을 바꾸지 않는다(결정 0017). 큰 화면에서 테이블을 세로 가운데로 옮길지는 따로 정한다.
