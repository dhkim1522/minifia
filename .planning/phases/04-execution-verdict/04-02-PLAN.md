## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

이 계획은 04-01 트레이서가 남긴 빨강을 닫는다: 새 `PhaseId` 가 타입 오류로 강제하는 화면 쪽 단계 표 세 곳(타입 검사를 초록으로 유지하는 데 꼭 필요한 곳뿐)과 discussion → night 직결을 전제로 한 기존 회귀. 트레이서 계획의 컨텍스트 예산을 지키려고 04-01 에서 떼어 냈다. 화면 부품·`renderPhase`·`seatFloats`·`PHASE_INTRO` 는 건드리지 않는다(시안 승인 → `/gsd-ui-phase 4` 뒤 Add more plans 로 화면 계획). 배포하지 않는다(D-26). 같은 웨이브의 04-03(결정 0036 문서)과 파일이 겹치지 않는다. 이 계획은 push 하지 않는다 — 앱 타입 검사·옛 테스트 이전이 초록임을 확인만 하고, 웨이브 1·2·3 의 push 는 웨이브 3 의 마지막 번호 계획 04-05 가 이 계획의 SUMMARY 와 초록을 확인한 뒤 한다.
