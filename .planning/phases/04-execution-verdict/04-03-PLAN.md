## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

이 계획은 서버·공유 로직 웨이브의 순수 규칙 첫 확장이다: 04-01 트레이서가 연 후보 선택 경로를 후보 선택 → 공개(서버 순서) → 변론 → 처형까지 규칙으로 채운다. 승패·종료는 04-05, 소켓 배선은 04-06, 변론 메시지 규칙은 04-04 가 맡는다. 화면은 이 묶음에 없다(시안 승인 → `/gsd-ui-phase 4` 뒤 Add more plans). 배포하지 않는다(D-26).

## Claude 재량 결정

- **모듈 나눔:** 투표 수신·집계(castCandidateVote·tallyCandidateVote)는 vote.ts, 단계 진입·마감 훅(enterCandidateVoteReveal·routeAfterCandidateVote·enterExecution)은 새 execution.ts. 승패·종료(04-05)는 별도 win.ts·endgame.ts 라 이 파일과 겹치지 않는다.
- **후보 선택 집계는 공개 구간 진입 훅에서 한 번에**(RESEARCH Pattern 2). 셔플에 난수가 필요한데 마감 훅에는 난수 인자가 없다.
- **공개 진입 때 개인 후보 선택 키(Player.candidateVote)를 지운다.** 같은 내용이 공개 기록(voteLog.cand.votes)으로 남으므로 서버 전용 필드를 끌고 갈 이유가 없다.
- **그날 줄 갱신:** voteLog 의 그날(n === 현재 일차) 줄에 cand 를 더한다. 그 줄은 여부 투표 마감 훅이 항상 만든다. 줄이 없으면(도달할 수 없는 경로) voteLog 는 그대로 두고 verdict 만 갱신한다.
- **처형 문구는 아침 문구와 따로 센다**(lastExecPhrase). 처형 단계 진입 훅에서 한 번 추첨한다.
- **처형 무효 이유(D-34)는 새 상태 필드 없이 공개 기록에서 파생한다.** `noExecutionOf(state)` 가 밤 단계에서 그날(n === 일차) voteLog 줄을 읽어 이유를 정한다: 여부 미통과면 던진 표 0 → noVotes, 아니면 notMajority(동률 포함 — "찬성이 과반이 아니에요"), 여부 통과·후보 없음이면 cand.votes 가 비면 noVotes, 아니면 tie. 후보가 있었으면(처형이 이뤄짐) 없음. 단계가 night 일 때만 view 에 실으므로 아침으로 가면 저절로 사라지고 지울 상태가 없다. 공개 투표 기록만 읽어 새 정보가 생기지 않는다. 여부 동률을 notMajority 로 묶은 것은 0036 의 바뀔 수 있는 기본값이다.
