## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

이 계획은 한 판이 **끝나게** 한다: 승패 판정, 종료 단계, 종료 방 정리, 결과·판 요약 view. 결과 화면 부품과 [처음으로] 처리는 화면 계획(시안 승인 → `/gsd-ui-phase 4` 뒤 Add more plans)이 만든다. 배포하지 않는다(D-26).

## Claude 재량 결정

- **판정은 마감 훅에서**(진입 훅이 아니라): 아침 진입 때 판정하면 암살 발표 5초가 끊긴다(D-10). execution·morning 의 ON_DEADLINE 이 checkWinner 가 null 이 아니면 next "ended" 를 돌려준다.
- **승리 값 변환은 한 곳**(enterEnded): 내부 checkWinner 는 "citizen"·"mafia", 상태·와이어는 `GameWinner`("citizenWin"·"mafiaWin" — 역할 단어와 겹치지 않아 누출 검사의 역할 단어 경로 규칙과 충돌하지 않는다, Pitfall 10).
- **종료 방 정리는 새 타이머 없이** 만료(expiresAt)를 앞당긴다. nextWakeAt 이 이미 만료를 알람으로 쓰고, 만료되면 DO 가 room_closed 로 소켓을 닫는다(Pitfall 18 — 결과 화면 중 닫힘 처리는 화면 계획).
- **판 요약은 view 가 ended 에서만 buildSummary 를 부른다.** 공개 기록(voteLog)과 서버 전용 밤 기록(nightLog)을 필드별로 합친다. nightLog 는 판 중 어떤 view 에도 실리지 않는다(결정 0020-3: 게임 중에는 의사 구출이 지목 없음과 구별되지 않아야 한다).
- **새 모듈 두 개**: win.ts(역할을 읽지만 팀 문자열 하나만 돌려준다)와 endgame.ts. 04-03 의 execution.ts 는 건드리지 않는다.
