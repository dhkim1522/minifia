## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

이 계획은 04-03~04-05 의 순수 규칙을 방 Durable Object 에 배선하고 실제 소켓으로 증명한다: 후보 선택 메시지(투표자에게만), 공개·변론·처형 프레임, 두 종료 경로와 30분 정리. 봇·테스트 도구는 04-07, 전수 누출 검사는 04-08 이다. 화면은 이 묶음에 없다(시안 승인 → `/gsd-ui-phase 4` 뒤 Add more plans). 배포하지 않는다(D-26).

## Claude 재량 결정

- **후보 선택 수신자:** pick 과 같은 "받는 사람에게만" 규칙의 가장 좁은 형태 — 투표자 본인 한 명(관전자도 아님, A7). 전원 방송은 "누가 언제 골랐는지" 타이밍을 흘린다(Pitfall 7).
- **변론 메시지 전달은 기존 applySay 경로 그대로**(밤이 아니면 전원 방송). 후보 검사는 순수 규칙(04-04)이 한다. DO 코드 변경이 필요 없음을 소켓 테스트로 확인한다.
- **종료는 DO 변경 없이** 돌아야 한다(tick 이 ended 로 가고 enterEnded 가 만료를 앞당기면 advance → reschedule 이 알람을 옮긴다). 테스트가 빠진 곳을 찾으면 그 자리만 고치고 SUMMARY 에 적는다.
- **소켓 도우미는 helpers.ts 로 모은다:** night.test.ts 의 지역 도우미(actorsOf·lastView·settle·mark·summary)와 같은 모양을 helpers.ts 에 내보내고, 투표로 단계를 넘기는 `voteExec(code, actors, agreeBySeat)`·`voteCandidate(code, actors, targetBySeat)` 를 더한다. night.test.ts 는 건드리지 않는다.
