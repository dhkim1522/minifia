## 페이즈 목표

낮 토론 뒤 처형 여부 투표, 후보 선택 투표, 최후 변론, 처형을 거치고 승패가 나면 모든 역할이 공개되는 결과 화면으로 가서, 한 판이 끝까지 돌아간다 (결정 0034).

이 계획은 테스트 방 도구(결정 0022·0024)가 새 단계를 따르게 한다: 서버 봇의 투표·변론, 넘기기의 투표 단계 처리, 대기실 복귀의 새 필드 정리. 봇이 투표하지 않으면 테스트 방 한 판이 처형에 닿지 않는다(Pitfall 20). 화면은 이 묶음에 없다(시안 승인 → `/gsd-ui-phase 4` 뒤 Add more plans). 배포하지 않는다(D-26).

## Claude 재량 결정

- **봇 투표 확률·지연(이름 붙인 상수, 파일 상단):** 여부 투표 찬성 70%(`EXEC_YES_PERCENT`) — 테스트 방에서 처형 경로가 자주 열리게. 지연은 여부 `1000 + [0, 6000)`ms, 후보 선택 `1000 + [0, 9000)`ms, 변론 `1000 + [0, 4000)`ms(모두 단계 길이 − 0.5초 안). 0036 의 바뀔 수 있는 기본값이다.
- **후보 대상:** 자기 자신을 뺀 살아 있는 사람 seat 오름차순에서 randInt(길이). 역할을 보지 않는다(봇이 마피아를 아는 척하지 않는다).
- **변론 봇 템플릿:** 대상·직업이 필요 없는 셋(defNotMe·defCitizen·defPlead) 중 randInt(3). 후보가 아닌 봇은 변론 중 아무것도 하지 않는다.
- **봇 난수 호출 순서(봇 하나당):** execVote = randInt(100) → randInt(지연 폭), candidateVote = (후보가 있으면) randInt(후보 수) → randInt(지연 폭), defense(후보 봇만) = randInt(3) → randInt(지연 폭). 봇은 seat 오름차순으로 호출한다(기존 planBotSteps 규칙).
- **botsVoteNow** 는 넘기기 직전에만 부르고, 계획과 같은 결정 함수(찬성 여부·후보 대상)를 쓰되 지연 난수는 부르지 않는다. 그래서 넘기기 경로의 난수 순서는 봇 하나당 execVote = randInt(100), candidateVote = randInt(후보 수) 다.
