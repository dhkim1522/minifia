### 2.2 장면 매핑(PHASE_SCENE)

`src/game/scenes.ts` 의 두 행을 바꾼다. `Record<PhaseId, SceneId>` 라 행이 빠지면 타입 오류가 알려 준다.

| PhaseId | 현재 | **이 문서** |
|---|---|---|
| `execVote` · `candidateVote` · `candidateVoteReveal` · `defense` · `execution` | `verdictDusk` | **`dusk`** `[제안(확인 대기) P-1]` |
| `ended` | `lobby`(임시) | **`night`** `[제안(확인 대기) P-2]` |

P-1 근거(직접 확인): `public/backgrounds/bg_game_verdict_dusk.webp` 를 열어 보면 **위에서 떨어지는 원뿔 조명과 마루 위 타원 조명이 그림에 구워져 있다**(`design/backgrounds/BACKGROUND_SPEC.md` "verdict: 위에서 떨어지는 조명 기둥과 바닥 조명 타원", v5 README "투표·처형은 위가 좁은 원뿔 스포트라이트"). D-29 는 "배경 그림 자체에는 스포트라이트를 두지 않는다 — 구워진 연출이 있으면 쓰지 않고 해당 연출이 없는 그림을 고르라"고 했고, 시안은 `.cone` 한 층만으로 빛을 낸다. `bg_game_dusk.webp`(같은 창·같은 방, 조명 없음)가 그 조건을 만족한다. 투표 세 단계도 같은 그림이어야 낮 → 해질녘 크로스페이드가 한 번이고 변론에서 배경이 바뀌지 않는다. D-14 가 이름 `verdictDusk` 를 적었지만 의도는 "해질녘 배경"이므로 **`dusk` 파일을 쓰는 것이 D-14·D-29 를 함께 지킨다.** 바뀌는 곳: `scenes.ts` 표·머리 주석, `test/unit/scenes.test.ts` 의 장면 표 단언, `scripts/e2e/lib.mjs` `EXPECTED_SCENE`. `verdictDusk` 장면 등록은 지우지 않는다(어떤 단계도 가리키지 않는 등록만, 이전 `dusk` 와 같은 처지). 사용자가 `verdictDusk` 를 원하면 그림에서 조명을 지운 새 WebP(디자인 세션)가 먼저다.

P-2 근거: `bg_game_lobby.webp` 와 `bg_game_night.webp` 는 **바이트가 같다**(md5 동일) — 보이는 차이가 없다. 결과 화면은 대기실이 아니라 "밤 같은 조용한 방" 이고 크로스페이드 대상(`dusk`·`morning` → 종료)이 어두운 쪽이면 충분하다. 그림 변경 없음 → `ASSET_VERSION` 은 올리지 않는다.

배경 프리로드 `[제안(확인 대기) P-17]`: `dusk` 는 처음 쓰일 때 불러오면 1.2초 상한(`SCENE_IMAGE_WAIT_MS`) 안에 크로스페이드가 늦을 수 있다. 낮 토론(`discussion`) 진입 시 `backdropUrl("game","dusk")` 하나(약 25KB)를 `preload` 한다. 어떤 역할이든 같은 요청이라 요청 패턴이 역할을 드러내지 않는다(Pitfall 20).

### 6.1 색 의미 분리(D-33)

- **앰버 = 낮의 공개 투표.** 예약 목록(전부):
  1. "처형 투표" 인트로 카드(테두리·띠·제목 번짐·바탕 갈색 그라데이션)와 화살표 셰브런
  2. 공개 화살표(직선, 삼각 머리)
  3. 방금 닿은 대상의 표수 칩(`pop`)과 캐릭터 윤곽 후광(`halo-amber`)
  4. 최다 득표 후보의 칩(`lead`)·후광 — 유일한 최다일 때만(§8.3)
  5. 처형 단계 문구 카드의 테두리·띠(처형은 낮의 공개 재판, D-33 확정)
- **진홍 = 마피아의 밤 암살·마피아 팀.** 이 페이즈에서 진홍이 나오는 곳은 **① 결과 화면의 마피아 팀 승리 배너(띠·글자·상단 번짐 `crimson-700`)와 역할 카드의 `마피아` 글자(`crimson-300`), ② 기존 "마피아 동료 표시"(D-33 이 진홍으로 명시: 마피아 viewer·관전자 화면의 동료 마름모와 진홍 후광, 투표 장면에서도 그대로 유지 — 마피아가 투표 중에도 동료를 알아야 한다)뿐**이다. 이 페이즈가 새로 그리는 투표·변론·처형 요소(카드·화살표·칩·후광·처형 카드)에는 진홍이 없어야 한다(E2E 검사 P4·P6: 허용 진홍은 `.mf-dt__mark`·`mf-figure--halo-crimson` 뿐).

### 8.1 `execVote` — 처형 여부 투표 (D-02, D-14, D-23, D-30)

- 장면: 낮 테이블 그대로(같은 `DayScene`, 같은 자리·이름표·z). 배경 `dusk`. 이름표·캐릭터 아래·머리 위에 투표 표시 **없음**.

  - 이 단계 화면에는 말하기·이모티콘 입구가 없다(승인 시안 Main 과 같음). 서버는 `execVote` 중 say/emoji 를 계속 허용하지만(결정 0036 §6) 화면이 보내지 않는다. CONTEXT D-12 개정(2026-10-28).

- 집계 숫자가 바뀌면 숫자에 `scale 1.15 → 1` 180ms 팝(축소 모션: 없음). 값은 서버가 방송한 `execTally` 그대로이며 화면이 계산하는 것은 `아직 k명` 하나뿐.

### 8.3 `candidateVoteReveal` — 선택 공개 (D-07, D-20, D-21, D-22, D-31, D-32, 결정 0036 §5)

- 장면: 같은 테이블(어둡게 없음). 하단은 NightPanel 모양 제목+안내. **좌석 탭은 비활성**(공개 4초 동안 연출에 집중, 기록 카드 없음).
- **순서**: `voteLog[n].cand.votes` 배열 순서 그대로(서버가 셔플해 보냄) — 클라이언트는 다시 섞지 않는다. 무효표는 줄이 없으므로 화살표도 없다.
- **화살표(D-32 직선+삼각 머리, 한 번에 하나)**: SVG 층 하나(`z 40`, 이름표·캐릭터 위). 선 두 겹: 아래 `night-950` 55% 불투명 9px, 위 `amber-400` 5px, 둥근 끝, 끝에 삼각 머리(시안 `marker` 5×5, `refX 7`), 바깥 `drop-shadow(0 0 7px amber .9)`.
  - 시작점 = 투표자 몸 중심 + 32px × 대상 방향, 끝점 = 대상 몸 중심 − 26px × 투표자 방향. 몸 중심 = (발 x, 발 y − 48 × 배율). (시안 RA2: 지호(80.7, 380, .95) → 도윤(195, 230, .8) 의 (98.9, 306.2) → (174.4, 207).)
  - 선이 자라는 동안 머리가 끝을 따라가야 하므로 **CSS dash 가 아니라 `requestAnimationFrame` 으로 끝점(x2, y2)을 보간**한다(dash 로는 머리가 처음부터 끝에 있다). 한 번에 화살표는 1개뿐(쌓지 않음, D-20).
- **표수 칩**: 대상 위 `min-width 28, 높이 24, 모서리 7, 16px 700, gray-100 바탕·night-900 글자, 그림자 0 4px 10px`. 위치 = 대상 머리 위 가운데, 아래끝이 머리 위 8px(`headTop = 발 y − 96×배율`). **위쪽이 장면 위(헤더 타이머 영역)로 나가지 않게 `chipTop = max(4, headTop − 8 − 24)`** `[P-14]`(앞줄이 낮은 높이의 폰에서 맨 뒤 자리 칩이 타이머를 가리지 않게). 칩이 머리 위 일부를 덮는 것은 허용(연출 중 일시적). **`[04-32 Rule-1]` 다른 자리 이름표를 덮지 않는다**: 앞줄 자리의 이름표가 뒷줄 자리의 머리 위로 올라와 있어 기본 자리가 겹치면(E2E P10) `chipPlacement` 가 캐릭터 폭 안에서 칩을 옆으로(그래도 안 되면 위로) 옮긴다. 이름표 폭은 최악 100, 높이 26, 팝 여유 4px 로 본다.
  - 닿는 순간 `pop`: 앰버 바탕으로 팝 `scale 1 → 1.25 → 1` 220ms, 다음 투표자로 넘어가면 `gray-100` 로 돌아간다. 단 **유일한 최다 득표 후보**의 칩은 앰버를 유지(`lead`, D-31 ②).
- **캐릭터 후광(D-31)**: ① 방금 닿은 대상 = **앰버 후광**(닿은 시점~다음 화살표 시작까지, 약 slot 시간). ② **유일한** 최다 득표 후보 = 앰버 후광 유지(동률 선두는 후광을 켜지 않는다 `[P-14]` — 동률 4명이 켜지면 후광 3개 상한을 넘는다). 한 화면 후광 동시 최대 **3개**(결정 0030); 이 화면에서는 ①(1) + ②(1) 최대 2개에 마피아 동료 진홍 후광(마피아 viewer 1, 관전자 최대 2)이 더해질 수 있어 합이 3 을 넘으면 §12.4 우선순위(흰 > 앰버 > 진홍)로 진홍부터 끈다.
- **두근(D-31 ③)**: `clinchedTarget(counts, remaining)` — 남은 공개 표를 전부 받아도 2위가 역전할 수 없을 때(`c₁ > c₂ + remaining`, c₂ = 1위 외 최대). 확정 순간 **그 후보의 캐릭터와 칩**이 크기 변화: 캐릭터 `1 → 1.12 → 1` ×2회, 칩 `1 → 1.3 → 1` ×2회, 약 0.7초(`dk-c`·`dk-chip`, 시안 `f.css` 키프레임 그대로), 앰버 후광이 0.7초 동안 3px/18px 로 밝아졌다 돌아온다(`dk-halo`). 이후 공개가 끝날 때까지 느린 박동: 캐릭터 `1 → 1.04 → 1`, 칩 `1 → 1.1 → 1`, 주기 약 2.2초(시안 값; CONTEXT 는 "약 1.2초 주기"라고 했으나 시안 `dk-slow 2.2s` 가 승인본이다 — 어긋나면 CONTEXT 가 이기므로 **주기 1.2초 + 진폭 작게**로 구현하고 시안 값은 참고 `[P-14]`).
- `navigator.vibrate`: 확정 순간 `vibrate(30)` 한 번을 지원 기기에서 허용(구현 재량, 실패는 무시).
- **끝 상태(RA4)**: 유일한 최다 후보 칩은 `big`(24px·높이 32·외곽선, 앰버) + 앰버 후광 + 느린 박동, 나머지 칩은 일반(1표 등). 하단은 §7.2 끝 문구. 동률·0표는 앰버 후광·큰 칩 없이 칩만 남고 하단이 해당 문구.
- 타이밍은 §13.2. 재접속·중간 입장은 **현재 시각의 상태로 건너뛴다**(지난 화살표 재생 없음).

### 8.4 `defense` — 최후 변론 (D-13, D-15, D-16, D-29)

- 후보(`day.candidate`) 캐릭터가 **테이블 가운데**로 이동·확대, 나머지(배경·다른 캐릭터·이름표)는 어두워지고 3px 흐려진다, 빛은 **원뿔 층 하나**뿐(배경 그림에는 조명이 없다, §2.2).
  - 후보 위치(장면 좌표): 가운데 x = `cx`, 발 y = `min(cy + 80, sceneH − 34)`, 배율 **1.7**(72×96 → 122.4×163.2), 이름표는 발 y + 8, 높이 22. (시안 DB: 발 410 → 장면 290.8 ≈ `cy 210 + 80`. 시안 DC 는 400 으로 10px 위 — 236 패널이 장면을 줄이는 경우의 보정이라 **단일 공식 `min(cy+80, sceneH−34)` 로 통일**하고 짧은 폰에서 이름표 아래끝이 패널에 닿지 않게 한다 `[P-15]`.)
  - 이동: 좌석 위치 → 가운데, **600ms ease-in-out**(`left`·`top`·`transform` 전이, 대기실 `mf-dt--slide` 와 같은 방식), 같은 시각에 어둡게 층 400ms 페이드인, 원뿔은 200ms 뒤 500ms 페이드인. 후보 좌석이 떠난 자리는 비운다(그 자리 이름표도 후보와 함께 이동).
  - 층(§12): 어둡게+흐림 z 30 → 원뿔 z 30(DOM 뒤) → 후보 좌석 z 31 → 후보 이름표 z 32 → 이모티콘 z 60+.
  - 후보 후광: **흰 후광**(기존 흰, 시안 DB). 후광 1개.
- 원뿔: 장면 가운데 x, 아래끝 = 후보 발 y + 8, 위 = 아래끝 − 340(헤더 영역으로 올라가도 된다 — 헤더가 위에 있다). 헤더 글씨 대비는 E2E H1(`.mf-timer__num` 은 오른쪽, 제목은 왼쪽이라 위쪽 54px 폭 꼭대기와 겹치지 않는다).

### 8.5 `execution` — 처형 (D-06, D-09, D-11, D-16, D-33)

- 변론의 위치·어둡게·원뿔을 **그대로 이어 간다**(이동 연출 없음, D-16). 처형 진입 시 후보는 서버가 `alive false` 로 만든다 → 화면은 같은 자리에서 **유령으로 바뀐다**: 사람 그림이 400ms 에 걸쳐 사라지고(`opacity 1 → 0.35`) 유령 그림(`ghostSrc`)이 `opacity 0 → .9` + 위로 18px 떠오른다(시안 EX 의 두 층). 후광(흰)은 유령에도 유지. 이름표는 탈락 표시(기존 `mf-dt__tag--dead`, gray-500 글자 — 기존 승인 예외).
- **처형 문구 카드**(앰버, D-33): `MorningCard` `tone="amber"` — 폭 252, 장면 위 + 8px(시안 top 128 − 119.2 = 8.8 → 8), 가운데, 모서리 16, 바탕 `night-900` 94%, 테두리 1px `amber-400`, 위 띠 8px `amber-400`, 그림자 `0 10px 28px shadow` + `0 0 24px amber 30%`, 제목 24 700, 부제 14 `처형이 집행됐어요`. 등장 팝(scale .92→1, opacity, 300ms), 퇴장은 단계 마감 300ms 전부터 페이드(`exitDelayOf`, 아침 카드와 같은 규칙). 터치 통과. 제목이 3줄이면(5자 이름) 후보 머리를 일부 덮는 것을 허용(카드가 위).
- 직업·역할 이름·`roles/*` 그림은 **어디에도 쓰지 않는다**(D-09). 처형된 사람이 나라면: 같은 프레임에 `spectate` 가 와서 남의 자리가 직업 그림으로 바뀌는 것은 기존 관전 규칙(결정 0021)이며 허용.
- 처형된 사람이 나인 경우 이 5초 동안 하단은 `NightPanel` 문구 그대로(탈락 안내 별도 없음 — `ended`/`night` 에서 기존 관전 하단이 이어진다).
- 하단: 제목 `처형이 끝났어요` + 안내 `곧 다음으로 넘어가요`(P-10). 이모티콘·메시지 없음(서버가 거부).
- 5초 뒤: 승패가 나면 `ended`(결과 화면, D-37), 아니면 `night`.

## 12. 층(z-index)·구현 규칙

### 12.1 DayTable 안(루트 `isolation`, 기존 규칙 불변): 이름표 1~11 · 캐릭터 12~22 · 화살표 40 · 표수 칩 46 · **어둡게+흐림 30 · 원뿔 30(DOM 순서로 어둡게 위) · 후보 좌석 31 · 후보 이름표 32** · 이모티콘 60+.

> 어둡게 층과 화살표·칩은 같은 단계에 있지 않다: 어둡게+원뿔은 변론·처형에만, 화살표·칩은 공개에만 나온다. 순서만 위처럼 지킨다(공개 40·46 은 기존 어둡게 30 보다 위).

### 12.2 `.mf-dayscene` 안(DayTable 컨텍스트 밖): **헤더(`PhaseBar` 래퍼)와 하단 패널은 `position: relative; z-index: 3` 으로 DayTable 보다 위**. 어둡게 층이 헤더·패널 영역 뒤까지 번져야 해서 (`top: −(헤더 119.2)`, `bottom: −(패널 높이)`, 좌우 `−var(--mf-scene-pad)`; `.mf-dayscene` 는 `overflow: hidden` 이라 잘린다) 위쪽 창 그림과 장면이 이어서 어두워지고 흐려진다. 카드(인트로·무효·처형)는 `z 70`(기존 `MorningCard` 와 같음), `SceneIntro` 는 `z 40`(기존).

### 12.3 위험·대체
- `backdrop-filter` 가 배경(Backdrop 층)을 흐리게 하지 못하면(iOS Safari 등 조상의 `isolation`·`opacity` 애니메이션 때문), 대체: 흐림을 `Backdrop` 에 `filter: blur(3px)` 클래스(`mf-backdrop--blur`)로 주고 좌석 `img`·이름표에 같은 filter 를 준다(후광 filter 와 겹치면 `grayscale/halo` 합성 순서 유지). 실기기에서 먼저 확인한다(D-38 의 실기기 확인과 같은 시점).
- 후광은 한 화면 최대 3개(`HALO_MAX_SIMULTANEOUS`)이고 흐림 층 위의 필터와 합쳐 렌더 비용이 커질 수 있다 — 8명판에서 프레임 드랍이 보이면 어둡게 층의 `backdrop-filter` 를 `blur` 없이 어둡게만 쓰는 폴백(상수 `VERDICT_BLUR_PX = 0`)을 쓴다.

### 13.2 공개 시간표 (`revealPlan(votes, startMs)` 순수 함수)

- 슬롯 `slotMs = floor(min(REVEAL_SLOT_MAX_MS, REVEAL_BUDGET_MS / n))`, n = `votes.length`(0이면 연출 없음, 끝 문구만). n=8 → 450ms, n=7 → 500ms(3500 ≤ 3600), n ≤ 7 → 500ms.
- 투표자 `k`(0부터)의 시작 = `단계시작 + 200 + k × slotMs`. 단계시작 = `phaseEndsAt − phaseDurationMs`(서버 시각) → `connection.offset` 로 로컬 보정(모든 폰이 같은 순서·같은 시각에 본다).
- 슬롯 안: 0–280ms 화살표가 자란다(`ease-out`) → **280ms 에 닿음**: 칩 +1 팝(앰버, 220ms)·대상 앰버 후광 켜짐·화살표 120ms 페이드아웃 → 슬롯 끝까지 정지(다음 화살표가 시작하면 이전 대상의 `pop` 해제 — 후광은 유일한 최다일 때만 남음).
- 마지막 슬롯 끝(`200 + n × slotMs ≤ 3800`) → 끝 상태(§8.3 RA4)를 4초 마감까지 유지.
- 중간 합류(재접속): 시작 시각이 지난 투표자는 **즉시 적용된 상태**(칩 수·후광·두근 판정)로 그리고, 지금 슬롯의 화살표만 남은 시간으로 이어서 그린다.
