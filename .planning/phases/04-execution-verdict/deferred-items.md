# 4페이즈 미룬 항목

## 04-08 에서 발견 (범위 밖이라 고치지 않음)

- `scripts/uat-test-bots.mjs` 와 `scripts/e2e/browser.mjs` 는 봇이 낀 테스트 방에서 `testSkip` 으로 낮을 건너 `night` 에 닿는다고 가정한다.
  04-08 부터 넘기기가 여부 투표·후보 선택 단계에서 안 던진 봇 표를 먼저 채우므로, 봇 표가 통과하면 후보 선택·변론·처형을 지나고
  방장이 처형되거나 판이 `ended` 로 끝날 수 있다(무작위). 이 스크립트들은 배포본을 대상으로 하는 수동·E2E 용이라 이번 계획에서 돌리지 않았다.
  화면 웨이브 계획에서 E2E 를 4페이즈 흐름에 맞출 때 같이 고친다(여부 투표에서 방장이 반대 표를 먼저 던지거나, 처형을 단계 진행으로 받아들이게).
- 같은 이유로 워커 테스트 `test/worker/bots.test.ts` 의 밤 두 테스트는 `skipDayToNight` 로 고쳐 결정적으로 만들었다(아래 SUMMARY 편차 1).

## 04-31 에서 발견 (범위 밖이라 고치지 않음)

- **P10 이 실제 화면에서 실패한다(칩이 다른 자리 이름표와 겹침).** 후보 선택 공개 단계에서 선두 칩(`lead`)이 앞줄 자리의 이름표와 겹친다.
  5명판 세 폭(360·390·430)에서 칩(자리 1)↔이름표(자리 2), 8명판 360·390·430 에서 칩(자리 1)↔이름표(자리 3)가 정지 상태로 겹쳤다
  (예: 390 폭 8명판 칩 [74,267–110,299] 와 이름표 [45,258–139,284]; 애니메이션 중 일시 겹침이 아니다). `placementChecks`(P10)와 `readVerdict` 의
  측정이 틀린 것이 아니라 화면 배치(`chipAnchor` 머리 위 8px)가 UI-SPEC 15.3 P10 `칩·카드가 이름표와 겹치지 않음` 을 지키지 못하는 것이다.
  04-32 의 `vote5` reveal 상태가 P10 에서 실패하므로, 04-32 전에 칩 위치를 고치거나(`src/game/verdict.ts chipAnchor`) 사용자 승인을 받아 P10 의 기준을 바꿔야 한다.
- **`haloChecks`(K4)를 공개 단계의 앰버 후광에 그대로 쓰면 실패한다.** 앰버 후광 filter 는 박동 애니메이션 중이라 `drop-shadow(rgba(115, 87, 36, .97) 0 0 2.46px) drop-shadow(oklab(…) 0 0 13.1px)`
  처럼 고정 9px 이 아니고 색도 oklab 이다(`collectSnapshot` 이 `finish()` 하는 것은 CSS 전환뿐이라 애니메이션은 그대로). 공개 단계의 후광은 종류·개수(`readVerdict().dt.haloImgs`, P4)로 보고
  K4 의 `9px` 규칙은 흰·진홍(정지 상태) 후광에만 적용한다.
