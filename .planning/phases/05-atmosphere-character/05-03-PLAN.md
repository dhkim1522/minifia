## 페이즈 목표

화면이 무거운 분위기로 바뀌고, 플레이어마다 외형이 다른 캐릭터를 받으며, 세로 폰 화면에서 처음 하는 사람도 설명 없이 지금 할 일을 알 수 있다 (ROADMAP 5페이즈). 성공 기준 1: 밤·아침·처형 같은 단계가 바뀔 때 분위기가 눈에 띄게 달라진다.

UI-SPEC §9.2 단계별 전환 점검표의 결론대로 **밋밋한 두 전환(처형 → 밤, 밤 → 아침)** 만 보강한다. 방 그림은 장면마다 같고 창문만 바뀌므로(§9.1 측정), 밤은 가장자리를 어둡게, 아침은 장면 상자 안을 밝게 한다. 둘 다 CSS 그라데이션 한 층이다.

## Claude 재량 결정

- **비네팅은 배경 층 안에 둔다:** `Backdrop` 의 장면 그림 층(`.mf-backdrop__art`)이 `night` 장면일 때 그 층 안에 자식 `div.mf-backdrop__vignette` 를 둔다. 층이 이미 0.8초 크로스페이드로 켜지고 꺼지므로 비네팅이 같은 박자로 따라오고(UI-SPEC "밤 배경 크로스페이드와 같은 박자"), 재접속(instant)은 한 층이라 바로 켜진 상태다. 그림 층은 콘텐츠 아래(`z-index: -1`, `isolation: isolate` 의 `.mf-backdrop` 안)라 인물·글자는 어두워지지 않는다. `Backdrop` 에 선택 prop `vignette?: boolean` 을 더하고 `DayScene` 만 켠다 — 같은 `night` 그림을 쓰는 결과 화면(`ended`)에는 생기지 않는다.
- **그라데이션 값은 인라인 CSS 변수로:** `--mf-scrim` 선례처럼 `--mf-vignette`·`--mf-glow` 변수에 함수 결과 문자열을 싣고 CSS 가 `background: var(--mf-…)` 로 읽는다(happy-dom 이 인라인 `color-mix()` 값을 버리는 문제 회피, 02-07 선례). 상승 시간도 `--mf-glow-rise-ms` 로 상수에서 싣는다.
- **밝아짐 층 위치:** `.mf-dayscene__scene` 의 첫 자식(DayTable 앞), `position: absolute; inset: 0; z-index: -1`. `.mf-dayscene__scene` 는 쌓임 맥락을 만들지 않으므로 이 층은 `.mf-backdrop` 의 쌓임 맥락에서 그림 층 다음·콘텐츠 아래로 그려진다. 실제 층 순서(인물·이름표가 위)는 05-06 의 E2E `AT2`(elementFromPoint)가 배포본에서 확인한다.
- **CSS 짝 선언 금지:** `backdrop-filter`·접두 선언을 쓰지 않는다(04-35 교훈). 이 계획의 층은 `background`·`opacity`·`animation` 만 쓴다.
