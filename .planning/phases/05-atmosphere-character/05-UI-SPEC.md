## 8. UX-01 안내 문장 점검표 (D-08)

**방법.** 코드(`Lobby.tsx`·`Assigning.tsx`·`RoleReveal.tsx`·`DayScene.tsx`·`verdictScene.tsx`·`NightPanel.tsx`·`TurnPanel.tsx`·`ClaimPanel.tsx`·`DiscussionControls.tsx`·`ResultScreen.tsx`)를 읽고, 배포본에서 테스트 방 방장으로 마피아·경찰·의사·시민 4역할과 탈락 관전자(6명·8명 방)를 따로 걸어 각 단계의 헤더 글자·하단 패널 글자·타이머를 읽었다(14단계 전부, 360×640 기준). `—` 는 그 viewer 가 그 단계에 있을 수 없음.

### 8.1 점검표 — 역할 공통 단계

"생존자" 열은 마피아·경찰·의사·시민에게 같은 글자다(밤은 §8.2).

| PhaseId (시간) | 생존자의 지금 할 일 한 문장 (위치) | 관전자(탈락)의 문장 (위치) | 남은 시간 | 판정 |
|---|---|---|---|---|

### 9.3 보강 1 — 밤 비네팅 `[시안 먼저 P5-1 — 사용자 확인 2026-10-29: 시안을 보고 값 확정]`

가장자리를 어둡게 해 밤을 무겁게 한다. 값은 모두 `src/game/scenes.ts` **한 곳**(D-05).

| 상수(제안) | 값 | 뜻 |
|---|---|---|
| `NIGHT_VIGNETTE_ELLIPSE` | `70% 60% at 50% 44%` | 방사형 타원의 반지름(가로·세로)과 중심(화면 가로 가운데, 세로 44%) |
| `NIGHT_VIGNETTE_STOPS` | `[[0, 0], [45, 0], [75, 0.40], [100, 0.72]]` | `[타원 위 위치 %, night-950 알파]`. 중심~45% 는 그대로, 좌우 가장자리 중간은 약 0.35, 모서리는 0.72 |
| `NIGHT_VIGNETTE_FADE_MS` | `SCENE_FADE_MS`(800) | 켜지고 꺼지는 시간. 밤 배경 크로스페이드와 같은 박자 |

`nightVignetteGradient()` 는 `radial-gradient(ellipse ${ELLIPSE}, color-mix(in srgb, var(--night-950) A%, transparent) P%, …)` 문자열을 만든다(`headerScrimGradient()` 와 같은 방식, `#` 색 값 없음).

- **언제**: `view.phase === "night"` 인 `DayScene` 에서만. 처형 → 밤 도착 때 800ms 로 나타나 밤 내내 유지, 아침으로 가면 800ms 로 사라진다. **재접속(instant)은 연출 없이 바로 켜진 상태.** 처형 무효로 온 밤(회색 카드)도 같다.
- **어디에 안 쓰는가**: 대기실·배정·역할 확인·낮·투표 구간·결과(`ended` 는 장면 `night` 를 쓰지만 `ResultScreen` 이라 그리지 않는다. 결과의 분위기는 4페이즈 승인대로).
- **층 규칙**: 배경 그림 **위**, 캐릭터·이름표·테이블 면·하단 패널·헤더 글씨 **아래**(`z-index: -1` 로 `Backdrop` 안에 들어가 `DayTable` 이 위에 그려진다). 즉 **인물과 글자는 어두워지지 않고** 그림의 가장자리(커튼·카펫 모서리·창문 모서리)만 어두워진다. 탭을 막지 않는다(`pointer-events: none`), `aria-hidden`.
- **색 규칙(D-07)**: `night-950` 한 색뿐. 앰버·진홍·후광 3개 상한과 무관(후광이 아님).
- **대비**: 배경만 어두워져 헤더 글씨 대비(H1)는 같거나 올라간다.
- **모션 줄이기(D-06)**: 켜짐·꺼짐이 즉시다 — 비네팅은 움직임이 없는 정적 상태이고, `base.css` 의 전역 규칙(`transition-duration: 0.01ms !important`)이 이미 전환을 즉시로 만든다. 별도 CSS 분기 불필요.

- **언제**: `view.phase === "morning"` 에서만, **밤 → 아침을 같은 접속에서 직접 본 렌더**(`sawNightToMorning` 와 같은 조건)에서만 오른다. 재접속·중간 입장은 연출 없이 최대치 상태로 시작해 남은 시간만큼 보이고 사라진다(아침 카드와 같은 규칙).
- **층 규칙**: 장면 상자(`.mf-dayscene__scene`) 안, **`DayTable` 뒤**(`z-index: -1`)에 둔다. 글자·이름표·캐릭터 위로 올리지 않는다(`dawn` 은 "글자 바탕으로 쓰지 않는다"). 헤더 영역에는 닿지 않는다 → **헤더 글씨 대비(H1·`backdropContrast.test.ts`) 불변.** 타원이 장면 상자 위쪽 경계에서 알파 약 0.03 이라 헤더와 이어지는 줄이 생기지 않는다.
- **주의(미리 알림)**: 아침에는 4페이즈의 어둡게 층(`night-900` 45%, 탈락자 강조)이 `DayTable` 안 위쪽에 이미 있다 → 밝아짐은 그 층 **뒤**라 약해진다(대략 장면 상자 배경 휘도 26 → 45 정도의 상승). 효과가 미묘할 수 있어 **사용자 확인을 권한다.** 약하면 `MORNING_GLOW_ALPHA` 를 올리거나(헤더를 건드리지 않아 대비 걱정 없음) 층을 `DayTable` 위로 옮기는 안을 쓴다(그 경우 글자·이름표 위가 되므로 알파를 0.20 이하로).
- **색**: `--dawn`(대안 `--morning`). 앰버·진홍 아님(D-07).
- **모션 줄이기**: 전역 규칙이 애니메이션 길이를 0.01ms 로 만들므로 올라가는 모션은 없고 **켜진 정적 상태로 아침 내내 보이다 퇴장 지연 뒤 사라진다.** 한 번의 낮은 변화라 깜박임 기준(초당 3회 이하) 해당 없음.
- 한 화면 후광 3개 상한·글자 크기·간격과 무관.

### 9.5 범위 밖으로 둔 것(요청 시에만)

낮·투표 구간의 방 전체 톤 변화(§9.1 표 — 방이 장면마다 같다는 사실의 연장), 전환 진동(앱 전환 때, D-05), 소리·파티클(D-06). 어느 것도 이 문서가 넣지 않았다.

## 12. CONN-03 Wake Lock (D-12, D-13) — 보이지 않는 동작

**화면 변경·문구·토스트·아이콘 없음.** 오류를 사용자에게 보이지 않는다.

| 항목 | 계약 |
|---|---|
| 훅 | `src/net/useWakeLock.ts` 의 `useWakeLock(active: boolean)`. `RoomScreen` 에서 한 줄로 부른다 |
| `active` | `view !== null` 이고 `view.phase !== "ended"` 이고 연결 화면 상태가 방을 보여 주는 중(`replaced`·`failed`·`removed` 아님). **대기실을 포함한다**(제안: 대기실에서 화면이 꺼지면 소켓이 끊겨 친구가 "나갔다" 로 보이므로 `[제안(확인 대기) P5-7]`, 구현이 정한다는 D-12 의 범위 안) |
| 요청 | `active` 가 참이 되면 `navigator.wakeLock.request("screen")`. 이미 살아 있는 sentinel 이 있으면 다시 요청하지 않는다(중복 없음) |
| 재요청 | `document.visibilitychange` 가 `visible` 이고 `active` 이고 sentinel 이 없거나 해제됐으면 다시 요청. **그 밖에서 재시도 루프를 돌지 않는다**(sentinel 의 `release` 이벤트로는 즉시 재요청하지 않는다 — 저전력 모드가 반복 거부하는 루프를 막는다) |
| 해제 | `active` 가 거짓(결과 화면 진입·쫓겨남·연결 포기)이 되거나 언마운트될 때 `sentinel.release()`, `visibilitychange` 리스너 제거 |
| 생략(조용히) | `navigator.wakeLock` 이 없음(iOS 구버전·HTTP 비보안 맥락), `request` 가 동기 예외를 던지거나 거부됨(`NotAllowedError`, 저전력 모드) → 아무것도 하지 않는다. `console.error`·`console.warn`·토스트·재시도 안내 없음(E2E G4 "콘솔 오류" 가 지킨다) |
| 서버·와이어 | 불변(클라이언트 전용) |

수용 기준(D-13):
- **단위 테스트**(`navigator.wakeLock` 모의 4갈래): ① 있음 → 요청 1회, `active` 유지 중 리렌더에 재요청 없음 ② 없음 → 예외 없이 생략 ③ 거부(reject) → 생략, 상태 유지, `console.error` 호출 0 ④ `visibilitychange` hidden → visible 에서 재요청, `active` 거짓이면 재요청 안 함, `ended` 진입 시 `release` 1회.
- **E2E**: 미지원 환경(`addInitScript` 로 `navigator.wakeLock` 삭제)에서 대기실 → 낮 한 단계가 정상 진행되고 G4(콘솔 오류) 통과. 지원 환경은 `request` 호출만 스파이로 확인(실제 화면 꺼짐 동작은 실기기 일괄 확인, D 보류 항목).
