## Phase Goal

친구들이 `minifia-v2` 주소로 들어와 로비 맵에서 서로의 캐릭터가 걷는 모습을 보고, 이 렌더링 방식이 실제 폰에서 버틴다는 것이 숫자로 확인된다.

이 계획은 페이즈의 첫 슬라이스다: **v2 배포 대상 한 경로**(단일 출처 → 설정 → 빌드 산출물 → 배포 스크립트)를 끝까지 잇고, 모든 검사 스크립트가 v1.0 주소를 거부하게 만든다. 이 계획이 끝나기 전에는 어떤 배포도 하지 않는다(HANDOFF 경고, STATE Blockers).

<objective>
`scripts/deploy-target.mjs` 를 배포 대상의 유일한 출처로 만들고, 빌드 산출물(`dist/worker/wrangler.json`)을 검사하는 게이트를 `npm run deploy` 의 빌드와 배포 사이에 넣는다. `wrangler.jsonc`·`scripts/prod-url.txt` 를 같은 커밋 흐름에서 v2 로 바꾸고, E2E·smoke·bots·uat·gallery 스크립트가 v1.0 주소를 네트워크 요청 전에 거부하게 한다.

Purpose: DEPLOY-02 — v2 배포가 v1.0 을 덮어쓰거나 검사하지 않는다. 결정 0043-3·0044-24("배포 설정과 검사 스크립트의 기본 주소를 같은 커밋에서 바꾸고 v1.0 을 덮어쓰지 않게 막은 뒤 첫 배포"). 첫 배포 자체는 06-07 이 한다.
Output: 가드 모듈·게이트 CLI·node:test 한 파일, 바뀐 설정 3개, v1 을 거부하는 스크립트 10개.
</objective>
