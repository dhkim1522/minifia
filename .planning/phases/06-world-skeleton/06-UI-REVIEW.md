## Top 3 Priority Fixes

1. **[WARNING] 이름표가 겹치면 앞 이름표가 읽히지 않는다** — 계약("맨 앞 이름표는 전부 읽힌다", 읽힘 게이트)이 직접 걸린 항목이다. `world-stack-360x640.png` 에서 내 이름표 "손님이름여덟글자 (나)" 의 "(나)" 가 아래 이름표와 겹쳐 "·)" 로 보인다. 원인은 `--overlay-ink` 80% 반투명 면 위에 다른 이름표가 비쳐 보이는 것. 수정: 이름표 면을 겹침 순서가 위인 것만 불투명에 가깝게(예: 위쪽 순위 이름표의 면 알파를 0.92 이상) 하거나, `HeadStack` 에 `backdrop` 없이도 가려지도록 `isolation` + 뒤 이름표 `opacity` 를 낮추는 규칙을 둔다. 8명 한 점 스크린샷을 `scripts/e2e` 에 추가해 고정한다.
2. **[WARNING] 작은 폰(360×560·360×640)에서 알림·[테스트]·가장자리 이름표가 서로 겹치거나 잘린다** — `lobby-8-360x560.png` 에서 "봇… 님 입장" 알림(top 88)이 [테스트] 버튼(top 70, 높이 44)과 겹쳐 버튼 오른쪽을 가리고, 오른쪽 이름표 "…챠챠카타파하" 가 화면 밖으로 잘린다(계약: 걸을 수 있는 모든 점에서 캐릭터·이름표가 스테이지 사각형 안). 수정: 테스트 방에서는 [테스트] 를 헤더 줄 안(공유 버튼 옆이 아니라 나가기 아래 대신 알림 아래 y≥134)으로 옮기거나 알림 위치를 [테스트] 가 있을 때 아래로 민다. 이름표는 `clampTarget` 한계와 별개로 투영 좌표를 스테이지 사각형 폭 안으로 클램프(이름표 반폭 기준)한다.
3. **[WARNING] 기본 구도가 비어 있고 어둡다** — `interactive-dpr2-x4-run1.png`(첫 입장)에서 스테이지 사각형 아래 약 1/3(y 약 1000~1500 @2x)이 아무 내용 없는 어두운 바닥·바닥 가장자리 선·연장 판이고, 캐릭터(남색 코트·갈색 머리)가 어두운 바닥에 묻힌다. 계약("스테이지 사각형 안 빈 배경 없음", "캐릭터와 무대 둘레가 항상 읽혀야", 위험 1번 "보드와 같은 밝기") 미달 징후. 수정: 입장 지점이 맵 가장자리일 때 `clampTarget` 한계를 줄여 빈 바닥을 덜 보이게 하고, `LIGHT_TUNE` 에서 캐릭터 림 라이트(또는 반구광 +10~15%)를 올려 보드(390×844)와 나란히 다시 맞춘다(낮은 명도는 유지, 대비만).

추가 권고(우선순위 낮음)

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- 계약 문구 일치 확인: 헤더 `PhaseHeader title="대기실" hint="바닥을 눌러 걸어요"`(`Lobby.tsx`), 행동 줄 "시작"/"방장을 기다리는 중…", 알림 `방장 · {닉네임}`(crown)·`{닉네임} 님 입장/퇴장`(`roomDiff.ts` 43~47행), "4명부터 시작해요". 해요체·마침표 없음·느낌표 없음·이모지 없음 모두 지킴. 대기실에서 읽어야 하는 글은 제목 + 2.5초 한 줄 + 버튼 라벨뿐이라 결정 0051 에 부합한다. (Lobby 에서 `HINT_MS` 2500 후 접힘.)
- 감점 1: 접근성 이름("게임 시작, 5명 모임, 4명부터 시작할 수 있어요")은 낭독용으로만 있고 화면에는 이유가 없다 → 위 권고 4.
- 감점 2: 같은 화면에서 "{닉네임} 님"(알림)과 "{닉네임}님을"(내보내기 시트, `Lobby.tsx` kick title)이 섞인다. 계약이 시트는 v1.0 그대로로 정했으나 사용자에게는 표기 불일치다. 문구만 `님` 띄어쓰기를 통일하면 된다.
- 감점 3: 공유 시트 문장 분량(위 권고 6).
- 맵 상태 카드 문구(`status.ts` `MAP_STATUS_COPY`)는 계약 표와 일치(제목 + 한 줄 본문 + 한 단어 버튼).

### Pillar 2: Visuals (2/4)
- 좋은 점: 헤더 좌 [나가기]·우 [공유] 44×44, 가운데 제목, 위 가림막으로 제목 대비 확보. 내 이름표만 1.5px 테두리 + "(나)" 로 초점이 분명(`interactive-dpr2-x4-run1.png`). 캐릭터는 3D 조립 인물이고 발밑 그림자·재즈 바 소품(무대 놋쇠 전구·촛불·병 선반)이 읽힌다. 아이콘 단독 버튼에는 `aria-label` 있음("나가기"·"공유").
- 결함 A(이름표 겹침): 위 우선순위 1. `tune-after-talk.png` 의 8명 모임에서는 이름표가 캐릭터 얼굴을 가리고(예: "수상한손님"·"고양이탐정"이 머리·모자 위에 걸침) 겹친 이름표가 서로 비친다.
- 결함 B(가장자리 잘림·충돌): 우선순위 2. `lobby-8-360x560.png`.
- 결함 C(구도): 우선순위 3. 첫 입장 화면에서 시선이 갈 곳이 이름표 하나뿐이고 아래쪽 큰 면이 비어 있다. 바닥 가장자리 대각선이 선명하게 보여 "맵 끝" 느낌이 난다(연장 판은 있으나 가장자리가 안개로 충분히 녹지 않음).
- 비활성 [시작] 이 평평해 보여 패널이 "비어 있는 곳"처럼 읽힌다. 점 8개는 숫자 대신 쓰는 좋은 장치(0051)이나 4번째 기준선이 없다.

### Pillar 3: Color (3/4)
- 하드코딩 색 검사: CSS(`world.css`·`lobby.css`·`v2.css`)에 hex·rgb 없음(0건). 색은 모두 토큰·`color-mix` 로 쓰임. 3D 색은 `world/palette.ts` 에 모여 있고 토큰과 같은 4색은 테스트로 고정됨. 진홍·놋쇠·앰버를 UI 에 쓰지 않음, 따뜻한 빛은 장면 안에서만(캡처 확인). 이름표 점 `seat-1~8` 은 구분색으로 계약대로.
- 60/30/10: 화면 거의 전체가 night 계열(60%+), 패널·이름표 면 30% 안팎, accent(`gray-100`)는 [시작] 활성 면·내 이름표 테두리·링으로 한정 → 분배는 계약대로. 오히려 accent 가 너무 적어 로비 첫인상이 한 덩어리 어둠이다.
- 감점: ① 장면 대비 부족(우선순위 3) — 낮은 명도 규칙은 지키되 "캐릭터와 무대 둘레가 읽혀야" 는 약하다. ② `inactive` 면(`night-700` 0.45)에 `gray-100` 글자 → 실효 대비가 4.5:1 미만으로 보인다(캡처 `world-stack-360x640.png`의 "시작"). E2E H(헤더 글씨 4.5:1)는 헤더만 대상이라 이 버튼은 검사되지 않는다.
- 끊김 표시는 이름표 불투명도 0.55 + 점 `gray-700` 뿐이라, 색·투명도에만 의존한다(접근성 목록에는 "연결 끊김" 이 있어 낭독은 해결).

### Pillar 4: Typography (4/4)
- `v2.css` 의 글자 규칙: 이름표 14px/700, 제목 24px/700, 안내 14px/400, 알림·버튼 16px/700, 링 숫자 16px. 4크기(14·16·24·36)·2굵기(400·700) 안에서만 쓰임. `world.css`·`lobby.css` 에 `font-size` 직접 지정 없음. 이름표 말줄임 없음(`white-space: nowrap`, 8자 + "(나)" 가 360 폭에서 잘리지 않음 — `lobby-8-360x560.png`). 한글 `keep-all` 계약. 결함 없음.
- 참고(결함 아님): 이름표 크기가 항상 14px 이라 8명이 모이면 글자가 캐릭터보다 지배적이다 — 위 이름표 겹침 문제로 이어진다.

### Pillar 5: Spacing (3/4)
- 헤더(18/16/44→62)·패널(`14px 16px 22px`, 간격 10, 높이 88)·행동 줄(52, 반경 14, 간격 8)·재접속 띠(top 72)·알림(top 88)·[테스트](top 70) 값이 계약 예외 목록과 일치. 임의 `[..px]` 값 없음.
- 감점: 값이 계약대로여도 쌓인 결과가 충돌한다 — `.mf-lobby__test`(top 70, 높이 44 → 114)와 `TopToast`(top 88)가 같은 가로 띠에서 겹침(`lobby-8-360x560.png`), 재접속 띠(top 72)도 [테스트] 와 겹칠 수 있다(테스트 방 + 끊김). 이는 UI-SPEC 쪽 위치 값의 설계 결함이므로 계약서와 구현을 함께 고쳐야 한다.
- `PX_PER_UNIT` 고정으로 작은 폰은 보이는 맵이 줄어든다(계약 의도). 360×560 은 스테이지 410px 이라 이름표 8개가 들어서면 빽빽하다.

### Pillar 6: Experience Design (3/4)
- 커버리지(계약 표 대비 코드·캡처 확인): 맵 로딩("맵을 불러오는 중…" 카드, night-950 가림막), 불러오기 실패(다시 시도), WebGL 불가(나가기), 컨텍스트 소실(40% 가림막 + 작은 카드)·복구 실패(새로 고침) — `MapStatusCard.tsx`·`status.ts`. 혼자일 때 빈 화면 없음(내 캐릭터 + [시작] 흐림). 재접속 띠는 흐름을 밀지 않고 위에 얹음. 헤더 [나가기]·[공유] 는 맵 가림막 위(z-index 맵 격리)라 로딩 중에도 눌린다. `disabled={!canSend}` 로 끊김 중 나가기 잠금, 시작 2초 잠금, 방장 이양 알림, 입장·퇴장 연출(reduced-motion 분기) 모두 있음.
- 성능 게이트: 조건 B 모든 칸 통과, 조건 A(CriOS)는 일부 항목만 측정되고 결정 0057 로 통과 판정(`06-PERF-RESULTS.md`). 계약의 "iPhone Safari" 가 아니라 iOS용 Chrome 으로 잰 점, 발열·LTE 3초·WebGL 복구(A)·하단 채팅 확인표(iPhone)가 미확인인 점은 UI 계약 대비 미완이다(WARNING, 사용자가 건너뜀을 기록해 둠).
- 감점: ① 방장 내보내기 진입점 발견성(권고 5). ② 첫 방문 손짓 링(`WalkCue`, `runtime.ts`)이 있으나 UI 쪽(헤더 안내 2.5초)과 달리 시각 증거를 이번 감사에서 확인하지 못했다(캡처 없음 — 코드 존재만 확인). ③ 방장이 끊긴 사람을 내보낸 직후 피드백은 시트 닫힘뿐이다(토스트는 퇴장 알림에 의존, 서버 이벤트가 늦으면 반응이 없어 보임). ④ 비활성 [시작] 의 이유 노출(권고 4).
