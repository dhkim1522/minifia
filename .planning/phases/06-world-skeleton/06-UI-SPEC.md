# Phase 6 — UI Design Contract (월드 뼈대)

> 화면·상호작용 계약서. 요구사항 DEPLOY-02, MAP-01, MAP-02, MAP-03, MAP-05, CONN-04 의 화면 몫과 렌더 성능 게이트(로드맵 성공 기준 4)의 화면 쪽 판정 기준.
> 범위는 **`minifia-v2` 주소의 방 만들기·참가, 로비 맵(캐릭터·이름표·터치 이동·카메라 따라가기), 연결 끊김·복귀 상태, 렌더 성능 스파이크, 7페이즈 입력용 하단 채팅 레이아웃 확인**이다. 시작 이후 한 판은 v1.0 흐름과 화면 그대로이고 이 문서가 다시 정하지 않는다.
> 이 문서의 숫자와 문구는 **자리표시 그림 단계**(결정 0006: 각 페이즈는 자기 구간의 이펙트·액션을 기본형으로 만든다) 기준이다. 실제 리그 캐릭터는 10페이즈에서 같은 자리에 끼운다.

## 임시 기준 경고

- v2.0 디자인 시스템과 화면설계서(로비·채팅창·동작 목록 등)는 **아직 승인 전**이다(STATE 블로커, HANDOFF 다음 할 일 1번). 그래서 이 문서는 ① 승인된 v2.0 맵·캐릭터 시안(결정 0046) ② v1.0 승인 디자인 시스템 토큰(`design/tokens.json`) ③ 이 문서가 정하는 값 세 층으로 쓴다.
- 아래 "v2.0 디자인 시스템이 바꿀 수 있는 값" 표의 항목은 디자인 시스템 승인 때 다시 확인한다. 값이 바뀌면 `design/tokens.json` 을 고치고 `npm run tokens` 로 다시 만든 뒤 이 문서를 맞춘다.

| 항목 | 지금 값 | 바뀔 수 있는 이유 |

| 헤더 높이 119.2 | v1.0 | v2.0 화면설계서의 맵 위 헤더 |

- 애니메이션은 `transform`·`opacity`(끊김 표현의 `filter`)만. `prefers-reduced-motion` 이면 움직임을 끄고 상태 변화는 그대로 둔다(`src/net/useReducedMotion.ts`).
- 사용자 문자열(닉네임)은 React 텍스트·`title`·`aria-label` 로만 그린다. 캔버스에 글자를 그리지 않는다.
- 그림 경로는 `public/` 기준 절대 경로.

## 화면 틀과 레이아웃

모든 대기실 화면은 **캔버스 한 장이 화면 전체를 채우고**(`position: absolute; inset: 0`) 헤더와 하단 시트가 그 위에 얹힌다. 캔버스는 헤더·시트 때문에 크기가 줄지 않는다(크기 변화는 WebGL 재할당이라 끊김의 원인이다).

- **캐릭터·이름표 크기는 폰 폭·높이와 무관하게 고정**이다(v1.0 의 짧은 폰 배율 압축 `f` 는 쓰지 않는다). 카메라 배율(월드 1단위당 화면 px)도 상수이고, 폰이 작으면 **보이는 맵 영역만** 줄어든다. 이름표 글자는 항상 14px.
- 내 캐릭터는 스테이지 사각형 가운데(가로 50%, 발끝 세로 58%)에 둔다. 맵 가장자리에서는 카메라가 멈추고 내 캐릭터가 가운데에서 벗어난다. **어떤 경우에도 내 캐릭터(이름표 포함)는 스테이지 사각형 안에 보인다**(카메라 이동 한계는 아래 "카메라" 참고).
- 입력창은 이 화면에 없다. 키보드가 열리는 일이 없으므로 캔버스는 크기를 바꾸지 않는다. 주소창이 접히거나 펴져 `resize` 가 오면 150ms 디바운스 뒤 한 번만 다시 잰다.
- PC: 가운데에 폰 폭(최대 430) 한 열로 서고 바깥은 `night-950`. 캔버스도 그 열 안에 있다.
- 세로 화면만 지원한다. 가로 화면 대응은 하지 않는다(v1.0 과 같음).
- 캔버스 위 터치: `touch-action: none`, 더블탭 확대·핀치 확대·길게 눌러 메뉴(`-webkit-touch-callout: none`)·글자 선택(`user-select: none`)·당겨서 새로 고침(`overscroll-behavior: none`) 모두 막는다.

Accent reserved for:
1. 주 버튼 [게임 시작] 면(`gray-100` + `night-900` 글자)
2. 목적지 링(`gray-50` 선)
3. 내 이름표 테두리(`gray-100`, 2px)
4. 포커스 링(`gray-100` 2px, 오프셋 2px)

추가 규칙
- 이름표 점의 `seat-1`~`seat-8` 은 의미 없는 구분색이다(accent 아님).
- **진홍(`crimson-*`)과 앰버(`amber-*`)는 이 페이즈에서 쓰지 않는다**(예약 목록에 로비·연결 상태가 없다). 끊김·오류에도 진홍을 쓰지 않는다.
- 이름표 면은 `night-900` 80%(신규 토큰 `plate-bg`), 글자는 `gray-50`(대비 16.5:1). 끊긴 사람 이름표 글자는 `gray-100`(흑백 처리와 함께).
- 맵 팔레트 규칙(결정 0046-4·7, 승인 시안 `TIMES`·`tune`): 가장 밝은 낮도 흐린 보랏빛 회색(쨍한 빛·순백·선명한 색 없음). 밤 분위기는 조명과 안개로 만들고 화면 전체를 어둡게 덮지 않는다. **따뜻한 실내등은 응접실 맵 안에서만** 허용되고 UI(헤더·시트·알약)에는 따뜻한 색을 쓰지 않는다. 광장은 차가운 흰빛 가로등만 쓰고 네온은 없다.
- 시안의 조명 세기(`ek`·`lk`·`gk`, 반구광, 노출)는 three r128 기준이다. 현재 three 에서는 같은 값이 다르게 보이므로 **시안 스크린샷과 나란히 놓고 캐릭터·모이는 자리·바닥이 같은 밝기로 읽힐 때까지** 값을 다시 맞춘다. 값을 맞추는 기준은 시안이지 숫자가 아니다.
- 끊긴 캐릭터: `grayscale(1)` + 불투명도 60%(승인 시안 Turn). 색만으로 구분하지 않고 이름표에 끊김 아이콘(`Icon` `disconnected`, 16px)을 함께 둔다. 흑백을 먼저 적용한다.

## 맵과 시간대

| 항목 | 6페이즈 계약 |
|------|--------------|
| 로비 맵 | **A 달빛 응접실**. 가운데 크림 대리석 원탁과 의자 8개가 모이는 자리 |
| 시간대 | **저녁(`night`) 고정**. 로비는 실내등(샹들리에·벽등·벽난로)이 모두 켜진 상태. 맵 코드는 `timeId` 를 입력으로 받아 5개 시간대를 모두 그릴 수 있게 만들지만 6페이즈 화면은 저녁만 쓴다 |
| 광장(B) | 제품 화면에 쓰지 않는다. **스파이크에서만** 잰다(8·9페이즈 입력) |
| 맵 크기 | 화면보다 크고 빈 배경이 보이지 않는다(바닥이 화면 밖까지 이어짐, 0046-3). 앞쪽(화면 아래)에는 시야를 가리는 높은 물체를 두지 않는다 |
| 카메라 | 정사영, 시안의 각도·`view` 값(응접실 8.4, 광장 9.6)을 시작값으로. 가운데 크기는 아래 "카메라" |
| 안개·빛망울 | 시안의 안개와 `motes`(떠다니는 빛망울)를 그대로. 배경 장식이라 접근성 도구에는 숨김 |

모이는 링(원탁 둘레)
- 중심 `[0,0]`, 반지름 1.9 월드 단위(시안 `pawnR`).
- **입장 위치**: 서버가 정한 자리 번호 `s`(0~7)마다 링 위 각도 `s/8 · 2π + 0.2` 라디안인 지점(시안 의자 배치와 같다). 한 사람이 한 지점이라 처음 들어올 때 서로 겹치지 않는다.
- 로비에서는 아무도 링에 묶이지 않는다(맵 전체를 자유롭게 걷는다, MAP-04 는 8페이즈). 지목 때 모이는 것도 8페이즈다.

이동 가능 영역
- 서버가 정한 영역 안에서만 걷는다. 원탁·의자·가구·벽 안쪽·맵 바깥으로는 걸어 들어가지 않고 **돌아서 간다**(캐릭터가 가구를 뚫고 지나가는 화면은 허용하지 않는다). 데이터 형식은 리서치가 정한다.
- 가구나 막힌 곳을 눌렀을 때: 서버가 가장 가까운 걸을 수 있는 지점으로 보정하고, 목적지 링은 **보정된 지점으로 미끄러져 간다**(180ms). 오류 문구는 없다.
- 영역 밖(벽·맵 바깥)을 눌렀을 때도 같다.

가림: **캐릭터는 3D 물체(가구·벽)에 가려지지 않는다.** 가구 뒤를 걸어도 항상 보인다(맵 위에 그려진 것처럼 항상 맨 위). 캐릭터끼리는 발끝 화면 y 가 큰 쪽(아래쪽)이 앞이다. 이 규칙은 빌보드·DOM 겹치기 어느 쪽으로 구현해도 같다.

`WorldCharacter` 는 그림을 모른 채 `{ 위치, 이동 방향, 상태(서 있음·걷는 중·끊김), 의상 }` 만 받는다. 10페이즈가 승인 시안의 리그로 바꿀 때 지키는 값을 지금 못 박는다.

- 리그 크기 80×83(여백 포함 `viewBox -20 0 160 166`), 그림은 앞·옆·뒤 3벌, 왼쪽은 옆 그림 반전, 옆 걷기 4프레임·앞뒤 걷기 2프레임, 동작은 앞 그림으로만(결정 0046-5).

- 걷기 프레임 시간은 6페이즈의 `dur-step`(300ms) 단계에 맞춘다(옆 4프레임 = 2단계씩).

### 눌러서 하는 일

- 연결이 끊긴 **다른 사람** 캐릭터를 방장이 누르면 `ConfirmSheet` "{닉네임}님을 내보낼까요?"(v1.0 D-16 그대로). 누르기 영역은 캐릭터 그림 위 최소 44×44(그림이 작아 보이면 투명 영역을 늘린다).
- 그 밖의 캐릭터를 누르면 **바닥을 누른 것과 같다**(그 지점으로 걷기 시작). 유저 기록 카드는 로비에서 열지 않는다.

## 상호작용 계약

### 터치해서 걷기 (MAP-02)

| 순서 | 동작 | 기준 |
|------|------|------|
| 1 | 터치 판정 | 손가락이 10px 이상 움직이거나 350ms 넘게 누르면 탭이 아니다(아무 일도 없다). 두 번째 손가락은 무시. 마우스 클릭도 같다 |
| 2 | 즉시 표시 | 누른 지점에 **목적지 링**이 100ms 안에 나타난다. 캐릭터는 아직 움직이지 않는다(위치는 서버 구간이 와야 정해진다) |
| 3 | 보정 | 서버가 지점을 보정하면 링이 보정된 지점으로 180ms 미끄러져 간다 |
| 4 | 출발 | 서버 구간을 받으면 내 캐릭터가 출발한다. 보통 300ms 안, 최대 500ms(통신 포함 기준값) |
| 5 | 걷는 중 | 링은 도착할 때까지 남는다. 중간에 새로 누르면 새 목적지로 즉시 갈아타고 이전 링은 120ms 에 사라진다 |
| 6 | 도착 | 캐릭터가 서고 링이 180ms 에 사라진다 |
| 7 | 응답 없음 | 1.5초 안에 구간을 못 받으면 링이 사라지고 토스트 "연결이 불안정해요. 다시 시도해 주세요"(기존 문구) 한 번 |

- 탭 간격이 150ms 보다 짧으면 뒤 탭은 무시한다(서버 속도 제한은 보이지 않게 둔다. 서버가 막은 탭에는 문구를 띄우지 않는다).
- **걷는 속도(시작값)**: 2.2 월드 단위/초, 응접실 한 끝에서 반대 끝(약 8 단위)이 약 4초. 이 값은 서버 상수이고 스파이크·팀 확인 뒤 조정한다. 모든 폰에서 같은 속도다.
- **두 폰에서 같아 보이는 기준**: 같은 캐릭터의 월드 좌표 차이가 어느 시점에서도 0.3 단위(약 20px) 이하(E2E 가 검사한다, 아래 "검사 가능하게 둘 것").
- 연결이 끊긴 동안(`canSend` false)에는 탭을 무시한다. 링도 띄우지 않고 대기열에 쌓지 않는다. 안내는 재접속 띠가 한다.
- 터치 대상: 맵 전체가 입력이고, 이름표·시트·헤더 버튼이 있는 곳은 그쪽이 먼저 받는다(헤더·시트는 캔버스 위 DOM 이라 자연히 그렇다).

### 목적지 링(`DestinationRing`)

- 바닥에 놓인 납작한 타원(아이소메트릭에 맞춰 가로:세로 약 2:1), 바깥 지름 40.

- 맥박: 크기 1 → 1.15 → 1, `dur-ring`(600ms) 반복. `prefers-reduced-motion` 이면 맥박을 끄고 고정 표시.
- 겹침 층에서 캐릭터보다 아래(내 캐릭터가 링 위를 걸어도 링이 얼굴을 덮지 않는다).

### 카메라 (MAP-03)

- 내 캐릭터를 따라간다. 부드럽게: 거리의 약 90%를 350ms 에 줄이는 감쇠(시간 상수), 도착 후 멈춘다. `prefers-reduced-motion` 이면 따라가기는 하되 감쇠 없이 즉시 붙는다(카메라 이동은 상태 변화라 끄지 않는다).
- 카메라 중심 이동 한계(월드 단위): 응접실 **3.2**, 광장 **3.6**(승인 시안 `pan`). 이 한계 안에서는 화면에 빈 배경이 보이지 않아야 한다.
- 한계에 걸리면 카메라는 멈추고 캐릭터가 가운데를 벗어나 움직인다. 가장자리에 서 있어도 캐릭터와 이름표는 스테이지 사각형 안에 보인다.
- **손으로 끌어서 둘러보기는 6페이즈에 없다**(시안 페이지에는 있었지만 탭과 끌기가 겹치지 않게 뺀다). 맵 전체 보기·핀치 확대도 없다.
- 처음 들어오거나 새로 고치거나 재접속했을 때 카메라는 날아가지 않고 **내 캐릭터 위치에 바로 붙는다**.
- 크기 변화(주소창 접힘 등) 뒤에는 카메라 중심을 180ms 에 다시 맞춘다.

## 렌더 성능 게이트 (로드맵 성공 기준 4, 결정 0046 결과)

화면 쪽 합격선. 시나리오와 기기를 고정해 숫자로 판정하고, 결과는 결정 기록(다음 번호, 예: 0047)과 6페이즈 SUMMARY 에 남긴다.

### 스파이크 장면(제품 화면과 별도, `?perf=1`)

- 맵: 응접실·광장 각각. 시간대는 가장 무거운 **저녁**(조명 전부 켜짐)과 가장 밝은 **낮**.
- 캐릭터 8명: 승인 시안의 **2D 리그**(`design/v2.0/characters/`)로 만든 시험용. 폭 80. 사람처럼 3~6초마다 무작위 지점으로 걷는다(모두 가구를 돌아서 간다).
- 동작 2개를 번갈아 5초마다 한 명씩: 손사래·박수(승인 시안의 2종). 동작은 앞 그림으로만.
- 카메라는 한 명(내 캐릭터)을 따라간다. 탭 이동 입력도 1분에 한 번 이상 누른다.
- 이름표 8개는 DOM 으로 같이 그린다(DOM 겹치기 방식이면 투영 좌표 갱신 비용이 포함된다).
- 스파이크의 리그는 **버리는 시험용**이다. 제품 로비에는 이 그림을 쓰지 않고(자리표시 사용), 10페이즈에서 다시 같은 기준으로 잰다.

| 평균 프레임 | 5분 평균 55fps 이상 | 로드맵 기준. 가장 무거운 조합 1개로 기기마다 5분, 나머지 조합은 1분 |
| 끊김 | 한 프레임이 50ms 를 넘는 일이 5분에 5회 이하 | "카메라 이동 끊김 없음"을 수치화한 보조값 |
| 반응 | 탭 → 링 100ms 이내, 탭 → 내 캐릭터 출발 500ms 이내, 방 입장 → 맵 조작 가능 3초 이내(LTE, 처음 방문) | "로비 조작 3초" 기준 |
| 발열 | 5분 뒤 기기를 만졌을 때 "뜨겁다"가 아니다(미지근까지) | 사람이 기록 |
| 메모리 | 탭이 다시 불러와지거나 경고가 뜨면 미달. 맵 열고 닫기 5회 뒤 메모리 증가가 눈에 띄지 않을 것 | iOS 탭 재로딩, Android 메모리 경고 |
| WebGL 복구 | iOS 에서 앱 전환·화면 잠금 뒤 돌아와 캔버스가 5초 안에 복구되거나 복구 실패 카드가 뜬다. 흰 화면·검은 화면이 남으면 미달 | "연결·복귀 상태" 표 |
| 읽힘 | 8명이 모였을 때 모든 캐릭터와 이름표가 읽힌다(360폭), 저녁에도 캐릭터와 모이는 자리가 어둠에 묻히지 않는다 | 시안과 나란히 스크린샷 |

기기(모두 실기기): 저가 Android(램 3GB 이하) Chrome, 같은 기기의 **카카오톡 인앱 브라우저**, 구형 iPhone(A11~A13급) Safari, 같은 기기의 카카오톡 인앱, 삼성 인터넷(갤럭시). 각 기기의 모델·OS·브라우저 버전을 결과 표에 적는다.

### 미달 때 줄이는 순서(화면에 남겨야 할 것)

앞 단계부터 하고, 한 단계마다 다시 잰다.

| 단계 | 줄이는 것 | 눈에 띄는 변화 |
|------|-----------|----------------|
| 1 | 그리는 배율 `min(devicePixelRatio, 2)` → 1.5 → 1.25 | 거의 없음 |
| 2 | 그림자 맵 2048 → 1024 → 512(부드러운 그림자 → 기본) | 그림자 가장자리가 거칠어짐 |
| 3 | 점광원 수: 샹들리에와 모이는 자리 주변만 남기고 벽등·벽난로·스탠드는 밝기를 재질에 미리 넣음 | 벽 쪽 빛 번짐이 줄어듦 |
| 4 | 건물·소품 수: 먼 것부터(광장은 먼 건물), 모이는 자리·창·샹들리에·원탁은 유지 | 배경이 단순해짐 |
| 5 | 안개 두께·빛망울 끄기 | 공기감이 줄어듦 |
| 6 | 맵을 시간대별 **미리 구운 이미지**로 바꿈(캐릭터 2D 는 그대로) | 맵이 움직이지 않음 |

반드시 지키는 것(어느 단계에서도): 캐릭터·모이는 자리가 읽힘, 이름표는 DOM, 화면 좌표 ↔ 바닥 좌표 대응(탭 이동이 맞아야 함), 이동 가능 영역이 어디인지 시각적으로 헷갈리지 않음, 맵 가장자리에 빈 배경이 보이지 않음.

- **미리 구운 이미지**로 갈 때: 같은 카메라 각도와 이동 한계, 같은 스테이지 사각형 배치, 같은 모이는 링 위치를 쓰고 시간대별로 5장(광장은 필요한 시간대만). 탭 좌표 변환은 이미지 기준으로 다시 만든다.
- **자동 강등(권장)**: 10초 평균이 45fps 미만이면 위 1~3단계를 한 단계씩 내린다(되돌리지 않음, 안내 문구 없음). 단계 5 이상은 사람이 결정한다.
- 그래픽 사양이 안 되는 기기(WebGL 불가): `MapStatusCard` 오류 상태(문구 계약). **v1.0 `DayTable` 로비로 몰래 대체하지 않는다.** 대체 로비를 둘지는 스파이크의 실패율을 본 뒤 정한다("확정 필요·위험" 6번).

## 하단 채팅 레이아웃 확인 (7페이즈 입력)

6페이즈는 채팅을 만들지 않는다. **iOS 키보드가 열린 상태의 하단 채팅 배치가 가능한지**만 실기기로 확인하고 결과를 7페이즈로 넘긴다. 시안 페이지(`?chat-mock=1`)는 제품 화면이 아니다.

시안 구성(7페이즈가 쓸 후보 배치)
- 위: 기존 헤더(119.2).
- 가운데: 맵 캔버스(크기 고정, 키보드가 열려도 줄이지 않는다).
- 아래 채팅 독: 메시지 3줄(14px, 줄 높이 1.4 → 약 59) + 입력 줄(입력칸 높이 `control-input` 48 + [보내기] 44×44 이상 누르기 영역). 면 `night-800`, 위 모서리 `radius-lg`, 안전 영역 포함.
- 입력칸 글자는 16px(iOS 가 16px 미만이면 확대한다).
- 키보드가 열리면 채팅 독이 키보드 바로 위에 붙고(`visualViewport` 기준), **캔버스는 재할당하지 않으며** 카메라 중심을 남은 영역 가운데로 옮겨 내 캐릭터가 계속 보이게 한다.

## 접근성·모션·입력

- **읽기 전용 목록**: 겹침 층 안에 보이지 않는 목록 `<ul aria-label="방에 있는 사람 {N}명">` 을 둔다. 항목은 "{닉네임}님", 해당되면 ", 방장" · ", 나" · ", 연결 끊김". 캔버스·캐릭터·이름표·링은 `aria-hidden`.
- 맵은 장식이 아니라 위치 정보를 주지만, 6페이즈에서 맵 위 위치가 게임 판단에 쓰이지 않으므로 위치를 말로 풀어 읽어 주지 않는다(8페이즈 지목·모이기부터 다시 검토).
- 입장·퇴장 알림은 기존 토스트(`role="status"`)가 읽어 준다.
- 안내 알약 `role="status"`, 재접속 띠 `role="status"`(기존).
- 모션: `prefers-reduced-motion` 이면 목적지 링 맥박·입장 낙하·페이드·카메라 감쇠·빛망울 이동을 끈다. 캐릭터 이동(상태 변화)과 걷기 흔들림은 둔다. 입장 연출은 불투명도 0→1 의 즉시 전환으로 줄인다.
- 누르기 대상은 최소 44px(`tap-min`): 헤더 버튼, [게임 시작], 끊긴 사람 내보내기 영역.
- 키보드 사용자: 헤더 버튼·시트 버튼은 기존대로 탭 이동이 된다. 캔버스는 포커스를 받지 않는다(맵 이동은 포인터 전용, 이 페이즈 범위).
- 포커스 링: `gray-100` 2px, 오프셋 2px(기존).
- 온라인 기준(결정 0018): 옆 사람 화면 훔쳐보기·캡처는 설계 제약으로 두지 않는다.

### 검사 가능하게 둘 것(E2E 규칙)

- 겹침 층 루트에 `data-world-stage`, 캐릭터마다 `data-seat`·`data-wx`·`data-wz`(월드 좌표, 소수 둘째 자리)를 달고 **초당 4회 이하**로 갱신한다(두 폰의 위치 비교용).
- 걷는 중에는 캐릭터에 `data-walking="1"`, 목적지 링에 `data-ring`.
- 기존 자동 검사 묶음 중 G(글자 14px 이상·누르기 44px·가로 넘침 없음·콘솔 오류 없음·다른 출처 요청 없음)와 H(헤더 글씨 대비 4.5:1)를 대기실 맵 화면에도 적용한다. H 는 위쪽 가림막 위에서 잰다. 폰 폭 3종 이상(360×640, 390×664, 430×932)과 짧은 폰 360×560 에서 확인한다.
- 대기실 화면의 `data-guide` 검사(화면당 안내 문장 하나)는 하단 시트 안내 하나만 센다.
- **다른 출처 요청 없음**: three 는 번들에 들어가고 CDN 요청이 없어야 한다(글꼴은 기존 예외).

- 맵 위 글자(이름표·안내를 캔버스에 그리기), 말풍선에 채팅 내용(채팅은 하단 채팅창만, 7페이즈).

- 캐릭터 상세 소개·성격 문구(`CHARX-01` 은 다음 마일스톤 후보).
