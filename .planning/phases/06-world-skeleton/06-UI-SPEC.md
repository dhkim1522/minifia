# Phase 6 — UI Design Contract (월드 뼈대)

> 화면·상호작용 계약서. 요구사항 DEPLOY-02, MAP-01, MAP-02, MAP-03, MAP-05, CONN-04, MAP-07 의 화면 몫과 렌더 성능 게이트(로드맵 성공 기준 4)의 화면 쪽 판정 기준.
> 범위는 **`minifia-v2` 주소의 방 만들기·참가, 지하 재즈 바 로비(3D 캐릭터·이름표·터치 이동·카메라 따라가기), 연결 끊김·복귀 상태, 렌더 성능 스파이크, 7페이즈 입력용 하단 채팅 레이아웃 확인**이다. 시작 이후 한 판은 v1.0 흐름과 화면 그대로이고 이 문서가 다시 정하지 않는다.
> **이 문서는 이전 판(2D·DOM 겹침 캐릭터, 달빛 응접실 저녁 고정, v1.0 토큰 임시 기준)을 버리고 다시 썼다.** 이전 판에서 살아남은 것은 연결·복귀 상태, WebGL 불가·복구 카드, 배포 표식, 탭 → 걷기 → 목적지 링 흐름, 성능 HUD, 카메라 따라가기 규칙이다(모두 3D 기준으로 다시 맞췄다).
> **가장 중요한 규칙(결정 0051, CLAUDE.md)**: 글은 최소로, 보고 누르는 조작 중심. 정보는 장면·아이콘·숫자·점으로 먼저, 읽을 글은 단계 이름과 한 줄 이하(3초 규칙), 행동은 대상을 직접 누른다. 아래 모든 문구 행과 요소가 이것을 먼저 따른다.

2. 보드는 `[꾸미기]`(의상·맵 시트)와 채팅 기록·입력줄을 보여 주지만 6페이즈 범위 밖이다(10·11·7페이즈). 해당 자리를 어떻게 비우는지는 "로비 보드 요소 대응표".
3. 보드의 바닥 탭 이동은 **직선·즉시 계산**의 시연이다. 제품은 서버가 가구를 돌아가는 경로를 정하고 클라이언트는 받은 구간만 따른다(0044-17).
4. 보드의 장면 프레임 30fps 상한과 자동 동작(`nextEmote`)은 시안 한정이다. 제품은 30fps 로 묶지 않고, 로비에서 캐릭터가 혼자 동작하지 않는다(동작은 10페이즈에 사용자가 고른 것만).
5. 보드의 방장 이양 "걸어 나가며 희미해짐"은 11페이즈(CONNX-01)에 두고, 6페이즈의 퇴장은 한 가지 연출(아래)로 한다.

디자인 방향 한 줄: "같은 공간의 스산한 밤" 그대로 — 영업 중인 지하 재즈 바(촛불·벽등 따뜻한 빛)에서 조립 인물 8명이 돌아다닌다. 따뜻한 색은 **맵 안 빛에서만** 쓰고 UI(헤더·이름표·패널·버튼)에는 쓰지 않는다. 진홍·놋쇠는 이 페이즈 UI 에 없다.

- 애니메이션은 DOM 에서 `transform`·`opacity`(·`filter`)만. `prefers-reduced-motion` 이면 움직임을 끄고 상태 변화는 그대로 둔다(`src/net/useReducedMotion.ts`).
- 사용자 문자열(닉네임)은 React 텍스트·`aria-label` 로만 그린다. 캔버스에 글자를 그리지 않는다.
- 그림 경로는 `public/` 기준 절대 경로. 앱용 캐릭터는 이미지가 아니라 코드(`MFChar`)로 조립하므로 로비에 `public/characters/table/*.png` 를 쓰지 않는다.

- 3D 월드 단위(걷는 속도, 링 반지름, 입장 낙하 높이)와 카메라 픽셀 배율 58.2 는 간격이 아니다.
- 그 밖에는 없다.

- 이름표 점의 `seat-1`~`seat-8` 은 의미 없는 구분색이다(accent 아님). 자리 색은 서버가 준 자리 번호로 정해진다.

- 맵 팔레트(결정 0046·0050, 디자인 시스템 3D 공간): 낮이든 밤이든 스산하게. 로비는 영업 중인 바(`talk` 조명: 촛불·벽등 `light-lamp`, 약한 달빛 방향광 `light-moon`)이고 캐릭터와 가운데 무대 둘레가 항상 읽혀야 한다. 화면 전체를 어둡게 덮지 않는다.
- 시안의 조명 세기(보드 `PHASE.talk`: 반구광 0.42, 달빛 0.35, 노출 1.0, 점광원 `lamp(...)`)는 three r128 기준이다. 0.186.1 에서는 같은 수치가 다르게 보이므로 **보드 스크린샷(390×844)과 나란히 놓고 캐릭터·무대 둘레·바닥이 같은 밝기로 읽힐 때까지** 값을 다시 맞춘다. 맞추는 기준은 숫자가 아니라 시안이다.
- 끊긴 사람: 이름표는 `is-away`(불투명도 0.55, 점 `gray-700`), 3D 캐릭터는 채도 0 + 밝기 ×0.6(보드 `setDim` 방식의 재질 색 조정. **투명하게 만들지 않는다** — 반투명은 유령(8페이즈) 표현이라 구별한다). 색만으로 구분하지 않도록 접근성 목록에 "연결 끊김"을 함께 적는다.

**입장 위치**: 서버가 정한 자리 번호 `s`(0~7)마다 재즈 바 `ctx.talk[s]` 지점이다(보드 로비의 8명 배치와 같다: `(3.6,0.4)·(0.4,3.6)·(5.4,2.2)·(−4.2,−1.2)·(3.4,−2.6)·(−2.6,3.4)·(−4.2,0.2)·(2.2,5.4)`). 한 사람이 한 지점이라 처음 들어올 때 서로 겹치지 않는다. 지점에 `yaw` 가 있으면 그 방향, 없으면 카메라 쪽(`π/4`)을 본다. 로비에서는 아무도 서는 자리(놋쇠 8개)에 묶이지 않는다(맵 전체를 자유롭게 걷는다, 지목 때 모이기는 8페이즈 MAP-04).

**이동 가능 영역**
- 서버가 정한 영역 안에서만 걷는다. 바 카운터·스툴·피아노·탁자·의자·무대·벽·맵 바깥으로는 걸어 들어가지 않고 **돌아서 간다**(캐릭터가 가구를 뚫고 지나가는 화면은 허용하지 않는다). 바깥 한계는 승인 보드의 ±5.8 이고 데이터 형식은 리서치(ASCII 격자 마스크 + 서버 A*)가 정한다.
- **가려짐 방지**: 걸을 수 있는 모든 격자점에서 캐릭터 머리 꼭대기가 카메라에서 가구·벽에 가려지지 않아야 한다(바 카운터 뒤 통로처럼 카메라 쪽 물체 뒤로 완전히 숨는 자리는 막는다). 몸이 일부 가려지는 것은 허용한다. 검사는 마스크 단위 테스트로 한다("확정 필요" 9번).
- 가구나 막힌 곳을 눌렀을 때 서버가 가장 가까운 걸을 수 있는 지점으로 보정하고 목적지 링이 **보정된 지점으로 미끄러져 간다**(180ms). 영역 밖을 눌러도 같다. 오류 문구는 없다.

**가림**: 캐릭터는 3D 라서 맵 소품이 앞에 있으면 부분적으로 가려진다(깊이 판정). 가려지지 않는 것은 **이름표**(DOM 층이 캔버스 위)와 목적지 링의 가림은 3D 와 같이 처리된다(링도 가구 뒤에서는 가려진다). 캐릭터끼리는 3D 깊이로 앞뒤가 정해지고, 이름표는 발 y 가 큰(화면 아래쪽) 쪽이 위(`z-tags` + 순위)다.

### 눌러서 하는 일

- 연결이 끊긴 **다른 사람**의 이름표를 **방장이** 누르면 `ConfirmSheet` "{닉네임}님을 내보낼까요?"(v1.0 D-16 그대로, 판정은 서버가 다시 한다). 이 이름표만 `pointer-events: auto` 이고 누르기 영역이 44×44 이상이다. `aria-label="{닉네임} 님 내보내기"`. 8자 닉네임이면 시트 제목이 두 줄이 될 수 있고 `keep-all` 로 줄바꿈한다.
- 그 밖의 이름표·캐릭터를 누르면 **바닥을 누른 것과 같다**(`pointer-events: none` 이라 아래 캔버스가 받는다). 유저 기록 카드는 로비에서 열지 않는다.

## 상호작용 계약

### 터치해서 걷기 (MAP-02)

| 순서 | 동작 | 기준 |
|------|------|------|
| 1 | 터치 판정 | 손가락이 10px 이상 움직이거나 350ms 넘게 누르면 탭이 아니다(아무 일도 없다). 두 번째 손가락은 무시. 마우스 클릭도 같다 |
| 2 | 바닥 좌표 | 탭 지점의 정사영 레이를 y=0 평면과 교차해 월드 (x, z) 를 구한다(보드의 `Raycaster.setFromCamera` + `ray.intersectPlane`) |
| 3 | 즉시 표시 | 누른 지점에 **목적지 링**이 100ms 안에 나타난다. 캐릭터는 아직 움직이지 않는다(위치는 서버 구간이 와야 정해진다) |
| 4 | 보정 | 서버가 지점을 보정하면 링이 보정된 지점으로 180ms 미끄러져 간다 |
| 5 | 출발 | 서버 구간을 받으면 내 캐릭터가 출발한다. 보통 300ms 안, 최대 500ms(통신 포함 기준값) |
| 6 | 걷는 중 | 링은 도착할 때까지 남는다. 중간에 새로 누르면 새 목적지로 즉시 갈아타고 이전 링은 120ms 에 사라진다 |
| 7 | 도착 | 캐릭터가 서고 링이 `dur-fast`(180ms)에 사라진다 |
| 8 | 응답 없음 | 1.5초 안에 구간을 못 받으면 링이 사라지고 `TopToast` "연결이 불안정해요. 다시 시도해 주세요"(기존 `NETWORK_TEXT`) 한 번 |

- 탭 간격이 150ms 보다 짧으면 뒤 탭은 무시한다(서버 속도 제한은 보이지 않게 둔다. 서버가 막은 탭에는 문구를 띄우지 않는다).
- **걷는 속도(시작값)**: 서버 상수 `MOVE_SPEED = 1.8` 월드 단위/초. 승인 보드 시연값은 1.245(`1.5 × SCALE 0.83`)이지만 직선 시연용이라 14×14 방을 걷기에 느리다(맵 한 끝에서 반대 끝 약 12 단위가 약 10초). 스파이크·팀 확인 뒤 조정한다("확정 필요" 5번). 모든 폰에서 같은 속도다.
- **두 폰에서 같아 보이는 기준**: 같은 캐릭터의 월드 좌표 차이가 같은 머신 E2E 에서 어느 시점에도 0.3 단위 이하, 실기기는 0.5 이하 또는 시계 오프셋 잔차를 함께 기록(리서치 Pitfall 5).
- 연결이 끊긴 동안(`canSend` false)에는 탭을 무시한다. 링도 띄우지 않고 대기열에 쌓지 않는다. 안내는 재접속 띠가 한다.
- 맵 전체가 입력이고, 헤더·행동 줄·아래 패널이 있는 곳은 그쪽(DOM)이 먼저 받는다.
- 손짓·햅틱·소리는 없다.

### 목적지 링 (`DestinationRing`, 3D)

- 바닥에 놓인 납작한 원(3D 이라 아이소메트릭에서 자연히 타원으로 보인다). 보드의 발밑 고리(`st.ring`: `TorusGeometry(반지름 0.42, 굵기 0.035)`, 바닥에 눕힘)를 바탕으로 **반지름 0.45, 굵기 0.04, 색 `gray-50`**, 그 바깥에 **윤곽 링(반지름 0.5, 굵기 0.05, `night-950` 불투명도 0.6)**을 한 겹 더해 어떤 바닥에서도 읽히게 한다. 둘 다 `MeshBasicMaterial`(조명 영향 없음).
- 맥박: 크기 1 → 1.15 → 1, `dur-pulse`(1100ms) 반복. `prefers-reduced-motion` 이면 맥박을 끄고 고정.
- 장면 안 메시라서 가구 뒤에서는 가려지고 캐릭터 위가 아니라 **바닥 위**에 있다.
- 처음 한 번만 뜨는 **손짓 링**(`WalkCue`): 아래 "안내".

### 카메라 (MAP-03)

- 정사영, 승인 값: `yaw = π/4`, 위치 오프셋 거리 17·높이 12.5, `lookAt(target.x, 0.6, target.z)`, 기본 목표 `(−0.4, −0.4)`(내가 아직 없을 때), 배율 `PX_PER_UNIT 58.2`(고정, `view = 캔버스 높이 ÷ 58.2`).
- **내 캐릭터가 스테이지 사각형 가운데에 오도록** 장면을 `setViewOffset` 으로 옮긴다: `offsetY = H/2 − (스테이지 위 끝 + 스테이지 높이/2)`(`H` = 캔버스 높이). 390×844 에서 패널이 승인 보드 높이일 때 이 식은 보드의 110 에 가깝다. 패널 높이는 DOM 에서 재서 쓰므로 7페이즈에 패널이 자라면 구도가 따라간다(캔버스는 다시 만들지 않는다).
- 내 캐릭터를 부드럽게 따라간다: 거리의 약 90% 를 350ms 에 줄이는 감쇠(시간 상수 약 152ms), 도착 후 멈춤. `prefers-reduced-motion` 이면 감쇠 없이 즉시 붙는다(카메라 이동은 상태 변화라 끄지 않는다).
- **카메라 목표 이동 한계(`pan`)**: 연구의 가정값 ±4.0(390 폭·`view 14.5` 기준 화면 반폭 약 3.35, 계산값)을 시작값으로 하고, 순수 함수 `clampTarget` 의 단위 테스트가 정한다 — 걸을 수 있는 **모든 격자점 × 위 6개 폰 크기**에서 ① 내 캐릭터와 이름표가 스테이지 사각형 안에 보인다 ② 스테이지 사각형 안에 빈 배경이 없다. 테스트가 이기면 한계를 줄인다.
- 한계에 걸리면 카메라는 멈추고 캐릭터가 가운데를 벗어나 움직인다. 가장자리에 서 있어도 캐릭터와 이름표는 스테이지 사각형 안에 보인다.
- **손으로 끌어서 둘러보기는 6페이즈에 없다**(탭과 끌기가 겹치지 않게). 맵 전체 보기·핀치 확대도 없다.
- 처음 들어오거나 새로 고치거나 재접속했을 때 카메라는 날아가지 않고 **내 캐릭터 위치에 바로 붙는다**.
- 크기 변화(주소창 접힘 등) 뒤에는 카메라 중심을 `dur-fast`(180ms)에 다시 맞춘다.

### 입장·퇴장 연출 (몰입 기본형, 결정 0006)

| 일 | 연출 |
|----|------|
| 새 사람이 들어옴(첫 스냅샷 이후) | 입장 지점 위에 3D 캐릭터가 **내려앉듯 등장**: 크기 0.6→1, 위 0.4 단위→0, `dur-med`(420ms), `ease-out`(투명도는 쓰지 않는다). 발밑 그림자는 같은 시간에 0.3 까지. 이름표는 같은 시간에 불투명도 0→1. `TopToast` "{닉네임} 님 입장" |

### 안내 (결정 0051-5: 안내는 한 번, 그리고 사라진다)

- `PhaseHeader` 안내 한 줄 "바닥을 눌러 걸어요"가 **맵이 열린 뒤 약 2.5초만** 보이고 접힌다(`showHint`). 로비를 열 때마다 보인다(2.5초뿐이라 방해가 아니다).
- **처음 방문한 기기에서만**: 맵이 열린 600ms 뒤 내 캐릭터 앞(화면 아래 방향 약 2 단위)의 걸을 수 있는 바닥에 **손짓 링**(`WalkCue`)이 목적지 링과 같은 모양으로 3번 맥박한 뒤 사라진다. 내가 처음 탭하면 즉시 사라지고, 한 번 보였으면 이 기기에서 다시 보이지 않는다(`localStorage` 키 `mf-hint-walk`). `prefers-reduced-motion` 이면 맥박 없이 2.5초 고정 표시 뒤 사라진다. 이 링은 글이 없고 `aria-hidden` 이다.

### 로비에서 맵으로 들어가고 나오기

- 게임이 시작되면(역할 배정 단계로 넘어갈 때) 맵을 `night-900` 으로 420ms 가려 v1.0 `Assigning` 화면으로 넘어가고, 가려진 뒤 WebGL 자원을 해제한다(`dispose()` + `forceContextLoss()` + 캔버스 제거). 걷던 캐릭터는 그 자리에서 멈춘다.
- 한 판이 끝나 대기실로 돌아오면 맵을 다시 만든다. 열고 닫기를 반복해도 메모리가 늘지 않아야 한다(스파이크 검사 항목: `info.memory.geometries/textures` 가 처음 값으로 돌아온다).
- `RoomScreen` 이 단계마다 리마운트되는 구조(`key={sceneKey(phase)}`)이므로 렌더러 수명은 부품 안에 가두지 않고 훅/모듈로 분리한다(8페이즈에서 맵이 단계에 걸쳐 살 수 있게, 리서치 Pitfall 10).

## 연결·복귀 상태 (MAP-05, CONN-04)

**원칙**: 위치의 진실은 서버다. 복귀하면 화면은 서버가 보낸 지금 위치로 **걷지 않고 바로** 맞춘다(끊기기 전의 낡은 위치에서 새 위치로 걸어가는 연출은 없다). 단, 서버 구간이 진행 중이면 그 구간의 지금 지점부터 이어서 걷는다.

| 상태 | 내 화면 | 다른 캐릭터 | 띠·문구 | 입력 |

| 정상 | 위 계약대로 | 서버 구간대로 걷는다 | 없음 | 탭 가능 |

| 복귀(첫 상태 도착) | 카메라와 모든 캐릭터가 서버 위치로 즉시 맞춘다. 등장 연출·토스트 없음 | 같다 | 띠가 "다시 연결됐어요"로 바뀌고 2초 뒤 사라진다(`RESTORED_MS`) | 탭 가능 |

### 검사 가능하게 둘 것 (E2E 규칙)

- 이름표 층 루트에 `data-world-stage`, 이름표마다 `data-seat`·`data-me`·`data-away`. 목적지 링 상태는 루트의 `data-ring="x,z"`(링이 바뀔 때만 갱신, 없으면 속성 제거).

- 기존 자동 검사 묶음 중 G(글자 14px 이상·누르기 44px·가로 넘침 없음·콘솔 오류 없음·다른 출처 요청 없음)와 H(헤더 글씨 대비 4.5:1)를 대기실 화면에도 적용한다. H 는 위쪽 가림막 위에서 잰다. 폰 크기 6종(위 표)에서 확인한다.
- 이름표 폭: 전각 8자 + " (나)" 닉네임에서 `scrollWidth === clientWidth`, `text-overflow` 가 `ellipsis` 가 아님, 8명이 한 점에 모인 스크린샷에서 맨 앞 이름표가 읽힘.

- 대기실 화면은 `PhaseHeader` 안내 한 줄과 행동 버튼 글자뿐이라 "화면당 안내 문장 하나"(`data-guide`)는 헤더 안내 하나만 센다.

## 쓰지 않을 것

- 맵 위 글자(이름표·안내를 캔버스에 그리기). 채팅 내용을 말풍선에 띄우는 것은 7페이즈 "…" 입력 표시까지만이고 채팅 본문은 아래 패널 기록에만 둔다.
- 캐릭터끼리 몸 충돌·밀치기, 이름표 자동 밀어내기, 캐릭터가 가구를 뚫고 걷는 것.
- 로비 캐릭터의 자동 동작·감정표현(10페이즈), 의상 교체 UI(10페이즈), 맵 선택 UI(11페이즈).
- 손으로 끌어 맵 둘러보기, 핀치 확대, 맵 전체 보기.
- 진홍·앰버·놋쇠·네온·보라 그라데이션을 UI 에 쓰는 것, 따뜻한 색의 UI, 금테, 의미 없는 유리 효과, 이모지 아이콘.
- 햅틱·진동·소리(앱 전환·12페이즈).
- 자체 시계·위치 스트림 가정: 위치는 서버 구간만 따른다(0044-17). 클라이언트가 먼저 움직여 보이는 예측 이동을 하지 않는다.
- 안내 문장을 여러 줄 늘어놓는 것, 방 코드를 대형 글자로 헤더에 두는 것(코드는 공유 시트 안).
- v1.0 `DayTable` 을 몰래 대체 로비로 쓰기. 응접실·광장 맵을 로비에 쓰기. `three` 를 CDN 으로 불러오기. 보드의 30fps 상한·자동 동작·직선 이동을 제품으로 가져오기.
- 캐릭터 상세 소개·성격 문구(`CHARX-01` 은 다음 마일스톤 후보).
