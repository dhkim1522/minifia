## 알려진 한계 (고치지 않는다)

메모리 규칙(진행에 지장 없는 작은 화면 가장자리 문제는 고치지 않음)과 07-UI-SPEC UI Considerations 20 에 따라 기록만 한다.

1. 방 높이 640 이하 폰(360×640 · 390×664 · 360×560)에서 키보드가 열리면 스테이지가 128(캐릭터 80 + 이름표 26 + 입력 중 22) 미만이다. 내 이름표 · 입력 중 칸이 잘릴 수 있다. 최악 360×560 은 12px 만 남는다(K=336 기준).
2. 테이블 화면은 키보드가 열려도 장면을 다시 배치하지 않아, 올라온 패널이 테이블 아래쪽 인물을 가릴 수 있다. 테이블 틀은 8페이즈에서 삭제된다.

## 검사 실패 때 내리는 순서 (07-UI-SPEC) — 적용 단계

앞 단계부터, 한 단계마다 다시 확인한다. 4단계로 가려면 07-UI-SPEC 을 개정한다.

| 단계 | 바꾸는 것 | 적용 여부 |
|------|-----------|-----------|
| 1 | `lift` 식 보정: `visualViewport` 대신 `window.innerHeight` 변화로 대체(WebView 가 레이아웃을 줄이는 경우) | 적용 안 함 (사람 확인 결과에 따라 07-22 이후 갭 닫기) |
| 2 | 키보드 열림 동안 헤더·토스트를 `vv.offsetTop` 에 맞춤 / 맞추지 않음 선택 | 적용 안 함 |
| 3 | 메타 `interactive-widget=resizes-content` 추가 + 캔버스 px 고정만으로 버팀(Android Chrome 한정) | 적용 안 함 |
| 4 | 마지막 수단: 입력줄만 키보드 바로 위에 뜨는 한 줄 입력 시트 | 적용 안 함 |
