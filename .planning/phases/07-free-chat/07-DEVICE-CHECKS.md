## 사용자가 아침에 할 일 (Task 3 — 자동 승인 불가)

Task 3 은 `checkpoint:human-verify` `gate="blocking-human"` 이다. 07-21 실행 때 사용자가 자는 중이라 에이전트는 답을 기다리지 않고 이 문서에 **"미확인 — 사용자 확인 대기 (아침 `/gsd-verify-work 7`)"** 로 적고 계획을 끝냈다. 아래 항목 어느 것도 통과로 세지 않는다. 표 C·D 의 `대기` 칸과 위 "머리 위 입력 중" · 표 B 조건 A 칸이 사용자 답으로 채워질 때까지 성공 기준 3 의 실기기 몫은 열려 있다.

준비: iPhone 16 Pro, 저전력 모드 끄기, 다른 앱 종료. **Safari 와 iOS용 Chrome 두 브라우저에서 각각** 1~3 을 한다.

1. 로비 (검사 1·2·3·5·6): https://minifia-v2.dhplay.workers.dev?test=1 에서 방 만들기 → 입력칸을 눌러 키보드를 연다.
   - (검사 1) 입력줄·보내기가 키보드에 가려지지 않는다.
   - (검사 2) 맵이 깜빡이거나 크기가 바뀌지 않는다.
   - (검사 3) 내 캐릭터가 남은 맵 영역에 보인다.
   - (검사 6) "안녕하세요" 를 보내도 키보드가 닫히지 않고 입력줄이 그대로 보인다.
   - (검사 5) 맵 빈 곳을 눌러 키보드를 닫을 때 화면이 튀지 않고 캐릭터가 걷지 않는다(D4).
2. 한글 IME (검사 4): "안녕하세요" 를 치다가 마지막 글자 조합 중 키보드의 보내기(Enter)를 누른다 → 기록에 한 줄만, 입력칸에 남는 글자가 없다. 같은 방식으로 화면의 보내기 버튼도 한 번.
3. 테이블 (검사 7): [테스트] 로 봇 3명 → 시작 → [테스트] 넘기기로 낮 토론까지 → 1·2 를 낮 토론 하단에서 다시 한다(테이블 아래 인물이 가리는 것은 알려진 한계).
4. 입력 중 "…": 두 폰 또는 폰 + PC. 한쪽이 글자를 치면 다른 쪽 이름표 위에 "…" 가 뜨고 비우면 사라진다.
5. 5분 채팅 부하: Mac 터미널에서 iPhone 이 만든 방의 코드로

   cd ~/personal/minifia
