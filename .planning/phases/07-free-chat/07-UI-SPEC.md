# Phase 7 — UI Design Contract (자유 채팅)

> 화면·상호작용 계약서. 요구사항 CHAT-01, CHAT-02, CHAT-03, CHAT-04, CHAT-05, CHAT-06 의 화면 몫.
> 범위는 **하단 채팅 패널(기록 + 입력줄), 머리 위 입력 중 "…", 채널별로 달라지는 기록·입력 모양, 막힌 메시지 알림, iOS/Android 키보드·한글 입력 배치, 로비(맵)와 v1.0 고정 테이블 화면에 이 패널을 붙이는 방법, v1.0 순차 주장·빠른 메시지·텍스트 이모티콘 화면의 제거**다. 지목·변론 맵 연출, 밤 어둠, 유언 창, 동작(캐릭터 몸짓), 결과 화면 탭은 8~11페이즈 몫이고 이 문서가 정하지 않는다(자리만 남긴다).
> **가장 중요한 규칙(결정 0051, CLAUDE.md)**: 글은 최소로, 보고 누르는 조작 중심. 채팅은 본질이 글이라 이 규칙의 예외처럼 보이지만 아니다. 채팅 **본문만** 글이고, 나머지(누가 말하는 중 = 머리 위 "…", 어느 채널 = 아이콘·이름 색, 막힘 = 한 줄, 보내기 = 아이콘 버튼, 안내 = 없음)는 모두 장면·아이콘·점으로 한다. 이 페이즈가 새로 만드는 읽을 글은 **막힘 알림 한 줄**과 **채널 시작 안내 한 줄**뿐이다.

열지 못한 참고 자료: 클로드 아티팩트 주소(디자인 시스템 `L4eeQTUD9rCa9Vmzv6fKpU`, 화면설계서 `H3gEwciexb83CxEXK76YXs`)는 GSD 에이전트가 열 수 없어 저장소 사본(`design/v2.0/`)으로 대신했다. 화면설계서 PNG 사본이 없어 보드 마크업·로직으로 읽었다. 사용자가 이 페이즈용으로 준 별도 참고 이미지는 없다.

디자인 방향 한 줄: 6페이즈 "같은 공간의 스산한 밤"을 그대로 잇는다. 채팅 패널은 남색 면 위의 조용한 기록이고, 따뜻한 색·진홍은 맵 빛과 마피아 채널에만 둔다.

참고 자료와 다르게 하는 곳(이유 포함)
1. 승인 `ChatPanel` 은 **키보드가 열리면 기록 칸 최소 높이를 96 → 72 로 줄이고 행동 줄을 숨긴다.** 부품 CSS 에 없는 규칙이다. 이유: 키보드(약 300~340)가 열린 폰 화면에서 맵 스테이지를 남기기 위해서다(아래 "패널과 키보드").
2. 승인 `ChatPanel` 기록 칸은 내용에 따라 96~152 로 자란다. 제품은 **방 높이로 한 번 정한 고정 높이**(96 또는 152)를 쓴다. 이유: 메시지가 올 때마다 패널이 자라면 카메라 구도가 흔들린다(6페이즈 "카메라" 규칙: 패널 높이는 재서 따라가므로 자주 바뀌면 안 됨).
3. 입력칸 안 왼쪽에 **채널 아이콘**(마피아 `roleMafia`, 유령 `ghost`)을 더한다(부품에 없음). 이유: 입력 placeholder 는 글자를 치는 순간 사라지므로 "지금 어느 채널로 말하는지"가 입력 내내 보여야 한다(결정 0051: 글보다 아이콘).
4. 시안의 `tabs`([전체][마피아][유령])는 쓰지 않는다. 결과 화면(11페이즈, 결정 0054) 몫이다.

스타일 규칙
- 색·간격·크기·모션 값은 `tokens.css` 변수로만 쓴다. 화면 CSS 에 hex 를 직접 쓰지 않는다. **이 페이즈 전용 새 토큰은 0개**다.

### 구조

패널은 6페이즈 "아래 패널"(`night-800` 97%, 위 모서리 `radius-lg`, 안쪽 `14 16 22 + 안전 영역`, z `z-overlay` 50)을 그대로 쓰고 안에 `ChatPanel` 이 들어간다.

| 순서 | 요소 | 높이 | 비고 |
|------|------|------|------|
| 1 | 기록 칸 `ChatPanel` log | **고정 `LOG_H`**: 방 높이 ≥ 780 이면 152, 아니면 96 (키보드 열림 72) | `night-900` 면, 반경 `radius-badge` 12, 안쪽 `8 12`, 줄 간격 4, 안에서 스크롤 |
| 2 | 입력줄 | 48 (`control-input`) | [입력칸 flex 1] [보내기 48×48]. 위 칸과 간격 8. 입력칸 왼쪽에 **이후 페이즈 버튼 자리**(감정표현 48 · 깃펜 48, 간격 8)를 막지 않는다 |
| 3 | 행동 줄 | 52 (`control-button`) | **로비에서만**: 방장 [시작] / 손님 "방장을 기다리는 중…"(6페이즈 그대로). 테이블 화면에는 없음. 위 칸과 간격 10 |

- `LOG_H` 는 화면을 처음 그릴 때와 방향이 바뀔 때만 `window.innerHeight` 로 정한다. **키보드가 열리거나 주소창이 접혀 높이가 바뀌어도 다시 정하지 않는다**(포커스 중 값 동결).
- 로비 패널 높이 = `14 + LOG_H + 8 + 48 + 10 + 52 + 22` = `LOG_H + 154`. 테이블 화면 패널 높이 = `14 + LOG_H + 8 + 48 + 22` = `LOG_H + 92`(v1.0 157 에서 늘어남). 안전 영역 제외 값이다.
- 테이블 화면은 장면이 남는 높이를 쓰고(`flex 1`) 패널만 고정 높이다. 장면이 299 미만이면 기존 압축 규칙(`docs/screen-map.md`: `f = (높이 − 26) / 276.8`, 하한 0.77)이 그대로 돈다.
- 6페이즈 UI-SPEC "이월": 360×560 짧은 폰의 로비 스테이지는 이제 **248**이다(6페이즈 410 → 채팅 패널로 감소). 지원 하한은 방 높이 560으로 유지한다.

  - 탈락자가 되었을 때와 밤: `ghost` + "유령 채팅 · 산 사람에게 안 보여요" (승인 `Ghost` 보드 문구)
  - 변론 시작: `point` + 기존 `defenseStatus` 문구("{닉네임}님의 변론" 계열, `VERDICT_TEXT`)를 기록 첫 줄로 한 번
- 본문은 서버가 보낸 문자열을 **그대로** 보여 준다(화면이 문장을 만들지 않는다 — v1.0 `messageText` 템플릿 방식이 없어진다). 앞뒤 공백·제어 문자 정리는 서버 몫이다.
- 내 줄도 서버가 방송한 것이 돌아와야 나타난다(예측 표시 없음, 서버 권위). 정상 지연 100ms 안쪽이라 어색하지 않다.

### 채널별 모양

| 보는 사람 | 기록에 보이는 것 | 입력줄 | placeholder | 채널 아이콘(입력칸 안 왼쪽) |
|-----------|-------------------|--------|-------------|------------------------------|
| 로비 · 낮의 산 사람 | 공개 줄(`all`) | 있음 | 없음(빈 칸) | 없음 |
| 밤의 산 마피아 | 마피아 줄만. 낮 기록은 숨겼다가 아침에 돌아온다 | 있음 | "마피아끼리만 보여요" | `roleMafia` `crimson-300` 20px |
| 밤의 산 시민 · 경찰 · 의사 | 패널 없음(기존 `NightPanel`) | 없음 | — | — |
| 탈락자 | 공개 줄 + 밤 마피아 줄(읽기) + 유령 줄이 시간 순 한 흐름 | 있음(낮 토론·변론·밤) | "유령끼리만 보여요" | `ghost` `gray-300` 20px |

- 입력칸 안 왼쪽 아이콘은 입력칸 안쪽 왼쪽 여백 12 위치, 입력칸 안쪽 왼쪽 패딩을 16 → 40 으로 넓혀 글자와 겹치지 않게 한다. 아이콘은 장식(`aria-hidden`)이고 같은 정보를 입력칸 `aria-label` 이 말한다("마피아 채팅 입력", "유령 채팅 입력").
- 마피아가 밤에 입력줄을 쓸 때 낮 기록을 숨기는 이유: 어두운 밤에 낮 줄이 섞이면 어느 채널로 말하는지 흐려진다. 아침이 되면 공개 기록으로 돌아간다(밤에 쓴 마피아 줄은 공개 기록에 남지 않는다).

### 패널과 키보드

6페이즈가 `?chat-mock=1` 로 준비한 배치를 제품에 옮기고, 아래를 **합격 기준**으로 삼는다.

배치 규칙
- 패널은 항상 **보이는 화면(visual viewport) 맨 아래**에 붙는다. 키보드가 열리면 `lift = max(0, innerHeight − (vv.height + vv.offsetTop))` 만큼 올린다(`visualViewport` 의 `resize`·`scroll` 에서, 프레임당 한 번만 갱신). `visualViewport` 가 없으면 `lift = 0`.
- **캔버스(맵)는 크기를 바꾸지 않는다.** 캔버스 높이는 처음 그릴 때 px 로 고정한다(`100dvh` 로 키보드를 따라가지 않는다). 카메라 구도(6페이즈 `offsetY` 식)만 `visualViewport` 의 남은 영역 `[62, 보이는 아래 − 패널 높이]` 가운데로 옮긴다.
- 키보드 열림 = 입력칸에 포커스가 있고 `lift > 80`. 이때: 행동 줄을 숨기고(D3), 기록 칸을 72 로 줄이고, 패널 아래 여백을 22 + 안전 영역 → 8 로 줄인다. 닫히면 원래대로 돌아오고 카메라는 `dur-fast`(180ms)에 다시 맞춘다.
- 헤더·`TopToast`·재접속 띠는 **보이는 화면 위쪽**에 머문다: iOS 가 키보드를 위해 화면을 위로 밀면(`vv.offsetTop > 0`) 헤더 계열도 `vv.offsetTop` 만큼 내려 보이는 영역 맨 위에 맞춘다. `window.scrollTo` 로 되돌리는 처리는 하지 않는다(깜빡임) — 포커스 때 `focus({ preventScroll: true })`.
- 입력칸 속성: `type="text"`, `enterkeyhint="send"`, `autocomplete="off"`, `autocapitalize="off"`, `autocorrect="off"`, `spellcheck="false"`, `maxlength="100"`, `inputmode="text"`, 글자 16px.
- 포커스 중 맵·장면의 빈 곳을 누르면 **키보드만 닫고(blur) 걷지 않는다**(D4). 헤더 버튼은 평소대로 동작한다.
- 전송 후에도 **포커스를 유지**한다(키보드가 닫히지 않아 이어서 말할 수 있다). 입력칸은 비우고 보내기는 쿨다운 동안 흐려진다.

한글 입력(IME)
- Enter 로 보내려면 **`<form onSubmit>` 한 길**만 쓴다. `keydown` 에서 Enter 를 직접 가로채지 않는다.
- 조합 중(`compositionstart` ~ `compositionend` 사이)에는 보내지 않는다. 조합 중 보내기를 누르면 `compositionend` 를 기다려(최대 100ms) 확정된 값을 읽어 보낸다. iOS WebKit 은 `compositionend` 가 Enter `keydown` 보다 먼저 와서 `isComposing` 이 이미 거짓일 수 있다 → 보낼 때 값은 항상 **조합이 끝난 뒤의 입력칸 값**을 읽는다.
- 보낸 뒤 입력칸을 비울 때 조합이 남아 마지막 글자가 되살아나는 일이 없어야 한다(합격 검사 4).
- 입력 길이 100자는 입력칸 `maxlength` 와 서버가 둘 다 지킨다. 붙여넣기는 100자에서 잘린다.

합격 검사 — 6페이즈에서 이월한 다섯 줄(모두 미확인이었다)을 그대로 이 페이즈의 합격 기준으로 둔다. 결과는 `07-SUMMARY`/검증 문서에 이 표로 남긴다.

## 로비(맵)에 붙이기

6페이즈 "화면 틀과 레이아웃"을 다음과 같이 고친다.

| 층 | 6페이즈 | 7페이즈 |
|----|---------|---------|
| 아래 패널 | 행동 줄 하나, 높이 88 | 기록 + 입력줄 + 행동 줄, 높이 `LOG_H + 154`(위 표). 키보드가 열리면 150 |
| 스테이지 사각형 | 62 ~ (방 높이 − 88) | 62 ~ (방 높이 − 패널) — 패널 높이를 DOM 에서 재서 쓰므로 식은 그대로(6페이즈 카메라 `offsetY`) |
| 입력 중 칸 | 비워 둔 자리 | `HeadStack` 위 칸 사용 |

- 로비의 걷기 입력(탭 → 목적지 링)은 그대로다. 패널 영역(기록 칸·입력줄·행동 줄)은 DOM 이 먼저 받아 맵 탭이 되지 않는다.
- **D4**: 입력칸에 포커스가 있는 동안 맵·헤더 빈 곳을 한 번 누르면 키보드만 닫힌다(걷지 않음). 키보드가 닫힌 뒤의 탭부터 평소처럼 걷는다.

- 6페이즈 성능 게이트는 다시 재지 않는다. 기록 칸 DOM 갱신은 줄 하나씩 추가하고(리스트 전체 재렌더 없음) 맵 프레임을 막지 않아야 한다 — 채팅이 오가는 상태에서 5분 평균 fps 가 6페이즈 기준(55) 아래로 내려가지 않는지를 **검증 단계 확인 항목**으로 둔다(합격선은 6페이즈 그대로, 낮추지 않음).

## Spacing Scale

Declared values (multiples of 4) — 6페이즈와 같은 토큰:

| Token | Value | Usage |
|-------|-------|-------|
| xs (`space-xs`) | 4px | 기록 칸 줄 간격, 입력 중 알약과 이름표 사이 |
| sm (`space-sm`) | 8px | 기록 칸 안쪽 위아래, 기록 칸과 입력줄 사이, 입력줄 안 요소 사이 |
| md (`space-md`) | 16px | 패널 좌우 안쪽, 입력칸 좌우 안쪽(채널 아이콘 있으면 왼쪽 40) |
| lg (`space-lg`) | 24px | (이 페이즈 신규 사용 없음) |
| xl (`space-xl`) | 32px | (이 페이즈 신규 사용 없음) |
| 2xl (`space-2xl`) | 48px | 입력칸·보내기 높이(`control-input`) |
| 3xl (`space-3xl`) | 64px | (이 페이즈 신규 사용 없음) |

Exceptions (모두 출처가 있는 값)
- 패널 안쪽 `14px 16px 22px`와 항목 사이 10px, 기록 칸 안쪽 가로 12px, 이름과 본문 사이 6px, 점 크기 8px — 승인 로비 보드·`bundle.css`(`.mv-chat__log`·`.mv-chat__dot`) 값 그대로(14·22·12·10·6은 4의 배수가 아니지만 보드가 정한 것).
- 키보드 열림 때 패널 아래 여백 8px(보이는 화면 맨 아래라 안전 영역이 필요 없다), 기록 칸 고정 높이 72·96·152(모두 4의 배수), 입력 중 알약 안쪽 `6px 10px`·점 6px·점 사이 3px(승인 `.mv-typing`), 새 메시지 점 8px(누르는 영역은 44×44 로 투명 확장).

- 이 표의 높이 값(250·306 등)은 위 쌓기 계산의 결과이고 간격이 아니다.
- 그 밖에는 없다.

## Copywriting Contract

해요체, 짧게, 마침표 없음, 진행 중은 `…`, 이모지·느낌표 없음. 사람은 "{닉네임} 님". **3초 규칙**: 이 페이즈가 새로 읽게 하는 글은 막힘 알림 한 줄과 채널 시작 안내 한 줄뿐이다.

|---------|------|

## 접근성·모션·입력

- 기록 칸 `role="log"` `aria-live="polite"`. 막힘 알림 `role="status"`. 입력 중 알약은 읽지 않는다. 채널 아이콘은 장식, 의미는 입력칸 이름이 말한다.
- 보내기·새 메시지 점은 `aria-label`. 보내기 비활성은 `aria-disabled="true"`(포커스는 받는다).
- 누르기 대상 44 이상: 입력칸·보내기 48, 새 메시지 점 영역 44×44.
- 키보드 사용자(PC): Tab 으로 입력칸 → 보내기, Enter 로 전송(form 제출), Esc 는 입력을 비우지 않고 blur. 포커스 링 `gray-100` 2px, 오프셋 2px.
- 모션: `prefers-reduced-motion` 이면 입력 중 점 튕김·패널 오름·카메라 보정 전환(6페이즈 규칙)·새 메시지 점 맥박을 끈다.
- 온라인 기준(결정 0018): 옆 사람이 화면을 엿보는 것은 설계 제약이 아니다. 캡처·복사 방지 없음.
- 채팅 본문 선택·복사는 허용한다(입력칸·기록 칸은 `user-select: text`; 맵 위는 6페이즈 규칙 그대로 선택 금지).

### 검사 가능하게 둘 것 (E2E 규칙)

- 한글 조합 검사는 Chromium CDP `Input.imeSetComposition` 으로 자동화하고, iOS 는 사람이 확인한다.

## 쓰지 않을 것

- 채팅 본문을 머리 위 말풍선·이름표 옆에 띄우기(머리 위는 "…" 만).
- 빠른 메시지 문장 칩, 직업 주장 패널, 텍스트 이모티콘 트레이, 자동 문장, 채팅 내역 모달(`^`).
- 귓속말, 근접 채팅, 음성 채팅, 이미지·링크 미리보기·마크다운, 멘션, 읽음 표시, 시각 표시, 메시지 수정·삭제, 신고·차단·음소거(MODX-01 은 다음 마일스톤).
- 채널 탭([전체][마피아][유령])과 밤별 구분선 — 결과 화면(11페이즈, 결정 0054).
- 감정표현 버튼·동작 목록(10페이즈), 유언 깃펜(9페이즈) — 입력줄 왼쪽 자리만 남긴다.
- 화면에서 채널을 고르거나 "전체로 보내기" 같은 선택지를 두는 것(채널은 서버가 정한다).
- 화면에서 메시지를 거르는 방식의 채널 분리(서버가 안 보낸다).
- 진홍 면·버튼, 놋쇠·앰버·네온·보라 그라데이션, 따뜻한 색의 UI, 의미 없는 유리 효과, 이모지 아이콘.
- 햅틱·진동·소리.
- 서버 응답 전에 내 줄을 미리 보여 주는 낙관적 표시.
- 캔버스 크기를 키보드에 맞춰 바꾸기, `100dvh` 로 키보드를 따라가기, `window.scrollTo` 로 억지 복구.
- 안내 문장을 늘어놓기(이 페이즈의 새 안내 글은 위 두 가지뿐).
