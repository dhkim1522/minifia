## 이월 메모 (뒤 계획용)

**새 이름과 위치**
- `shared/game/bots.ts`: `export function turnPointSteps(state, bot, now, randInt): BotStep[]`. `planFor` 의 nomination 분기는 `state.pickTurn !== undefined` 이면 `turnPointSteps`, 아니면 옛 코드(주석 "차례 없는 지목 — 09.1-05 가 지운다"). 옛 분기의 상수 `POINT_BASE_MS`·`POINT_SPAN_MS` 와 머리 주석의 옛 난수 계약 줄(nomination = 후보 수 → 6000)도 09.1-05 가 같이 지운다.
- `shared/game/testTools.ts`: `export function finishNomination(state, randInt): RoomState`, `skipPhase` 맨 앞의 차례 분기(`state.phase === "nomination" && state.pickTurn !== undefined`). 옛 `botsVoteNow` 의 nomination 분기는 차례 없는 상태용으로 남아 있다(09.1-05 가 지운다).

**주의할 점**
- `planBotSteps` 는 `phaseEndsAt` 이 있어야 하고 `at >= phaseEndsAt - 500` 인 단계를 버린다. 차례 계획은 `at = now` 라 호출 시 `now` 는 **차례가 시작된 시각**(차례 마감 − 8000)이어야 하고, DO 는 차례 전환(상태 변경) 직후 `syncBotPlan` 에 그 시각을 넘겨야 한다(09.1-04). `botPlanKey` 가 `${phase}:${phaseEndsAt}` 라 차례마다 마감이 달라 새 계획이 선다. 단 사람이 차례 안에 지목해 `phaseEndsAt` 이 `now + 900` 으로 당겨지면 키가 또 바뀌어 같은 차례에 `doneAt` 이 있는 상태로 재계획되는데, `turnPointSteps` 가 `doneAt` 있으면 빈 배열이라 중복 지목은 없다.
- 봇 지목 실행이 `castTurnPoint` 를 지나므로 DO 의 봇 `point` 실행 경로(지금 `castPoint` 호출)를 `pickTurn` 이 있을 때 `castTurnPoint(state, botId, target, now)` 로 바꿔야 한다(09.1-04). 봇이 지목하면 `phaseEndsAt` 이 앞당겨지므로 알람도 다시 건다.
- `finishNomination` 은 `castPoint` 로 지목을 넣고(차례·마감 검사 없음) 지금 차례 주인이 봇이어도 `pickTurn` 의 `doneAt` 을 따로 세우지 않는다 — 곧바로 `i: order.length` 로 바꾸므로 의미 없다. 이후 `tick` 이 nomination 마감 훅(`resolveNomination`)을 호출해 집계하고 `pickTurn` 을 지운다. 09.1-04 가 마감 훅을 `stepNomination` 으로 바꾸면 `i: order.length` 자리의 끝 알림 마감이 `stepNomination` 의 "끝 알림 뒤 → 집계" 분기로 간다(같은 결과, `stepNomination` 은 `turn.i >= order.length` 에서 바로 집계).
- 시험 헬퍼: `bots.test.ts`·`testTools.test.ts` 의 `gathering()`·`advance()` 가 `enterNomination` + `stepNomination` 으로 차례 상태를 만든다. 09.1-04 가 tick 에 엔진을 걸어도 그대로 쓸 수 있고, 헬퍼를 실제 tick 으로 바꿀 때는 모이기 마감 → 방장(사람) 기권 → 사이 끝 세 걸음이 봇 seat1 차례 직전이다.
- 알려진 불안정 시험: `test/worker/bots.test.ts` 의 밤 마피아 채팅 항목과 `test/worker/testTools.test.ts` ended 항목이 전체 실행에서 한 번 실패 후 재실행 통과.
