# Phase 09.1.1 Plan 05: 결선 배치·봇·넘기기 Summary

**결선 앞머리에 서버가 두 후보를 무대 앞 마주 보는 두 점으로 걷게 하고, 테스트 방 봇이 투표 창에서 한 표씩 던지며, 넘기기 한 번이 결선을 끝까지 돌리게 했다. 서버 규칙(09.1.1-04)은 바뀌지 않았다.**

## 한 일

- **Task 1 (트레이서, 배치)**: `layoutKey` 가 runoff 에서 `{일차}:runoff` 를 돌려주고, `layoutFor` 는 후보 둘을 `RUNOFF_SPOTS`(낮은 좌석 = [0] = 화면 왼쪽)로, 나머지 산 사람은 지목에서 걸은 둘레 자리 그대로(이동 없음)로 정한다. 후보의 둘레 자리는 기억 슬롯에 남아, 변론으로 가면 승자는 무대로 진 후보는 자기 자리로 돌아간다(기존 변론 규칙이 같은 일차 기억을 쓴다). 멱등·지목 기억이 없는 복원·8곳×2점 도착을 단위 시험으로, 방 DO 의 world move 프레임(전원에게, 후보 둘만, 끝점 = RUNOFF_SPOTS)과 변론 복귀를 워커 시험으로 고정. `worker/room.ts` 는 무변경(`syncLayout` 이 키 비교로 그대로 처리).
- **Task 2 (봇)**: 투표 창(step 1)에서만 후보가 아닌 산 봇이 좌석 오름차순으로 `randInt(2)` → `randInt(2500)`, `at = now + 500 + [0,2500)` 에 `{t:"point", target}` 한 스텝. 앞머리·결과·후보 봇·탈락 봇에는 스텝과 난수가 없다. 고정 pick host/other 는 후보 중 해당 쪽을 따르고(결정 난수 건너뜀, 지연 난수는 유지) 해당이 없으면 무작위로 돌아간다. 사람과 같은 `applyPoint` → `applyRunoffVote` 길을 지나고(워커 시험: 프레임 열에 `runoffVote`·`botPlan`·`isBot` 없음, `day.runoff.voted` 만 `[2,3]`, 방장 view 에 `me.ballot` 없음), 기존 단계 시드 고정 값은 하나도 바뀌지 않았다.
- **Task 3 (넘기기)**: `finishRunoff(state, randInt)` — step 0·1 이면 아직 안 던진 후보 아닌 산 봇이 좌석 순 `botRunoffTarget` 으로 던지고 `stepRunoff` 로 득표(tally)를 확정해 step 2 로 만든다. `skipPhase` 의 runoff 분기는 이어서 마감을 now 로 당겨 `tick` 이 집계하게 해 한 번에 defense/night 로 벗어난다. step 2 는 이미 확정된 득표 그대로 집계. 방장이 후보여도 막히지 않고 일반 방 BAD_MESSAGE·손님 NOT_HOST·`resetToLobby` 의 runoff 키 소거를 시험.
