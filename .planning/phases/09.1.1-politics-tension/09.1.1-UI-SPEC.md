# Phase 9.1.1 — UI Design Contract (정치·박진감 장치)

> 화면·상호작용 계약서. 대상은 결정 `docs/decisions/0066-v2-politics-tension-devices.md` 의 일곱 장치다. 범위는 **(A) 직업 주장 배지, (B) 귓속말, (C) 찬반 기록 공개 + 판결 순간 연출, (D) 동점 결선, (E) 마지막 3인 결전, (F) 순차 지목 마지막 지목자 조명**이다. 결과 화면의 귓속말 본문·주장 이력 공개(11페이즈), 효과음(12페이즈), 캐릭터 몸짓(10페이즈)은 정하지 않는다.
> **가장 중요한 규칙(결정 0051)**: 글은 최소로, 보고 누르는 조작 중심. 이 페이즈의 정보는 **장면(핀 조명·가운데 마주 선 두 사람·얼굴 두 묶음) → 아이콘·숫자(직업 아이콘 배지·표 수·초) → 글** 순서로 보여 준다. 새로 읽게 하는 글은 단계 이름, 알약 한 줄(`n / N`·이름·초), 시트 제목, 사용자가 쓴 한 줄(귓속말·마지막 한마디) 뿐이다.
> **가장 중요한 불변식(결정 0002·0021·0037·0066 누설 규칙, 아래 "누설 불변식" L17~L24)**: 직업 주장은 **공개 값**이고 실제 역할과 무관하다(서버는 주장의 참·거짓을 판정하지도 알려주지도 않는다). 귓속말 본문은 보낸 사람·받은 사람 소켓에만 간다. 찬반 기록·결선 후보·마지막 3인 단계는 모두 공개 정보다. 화면에서 숨기는 방식이 아니라 서버가 받는 사람별로 걸러 보낸다.

## 시안과 다르게 하는 곳 (기존 초안 대비, 이유 포함)

1. **색은 hex 가 아니라 토큰이다.** 초안은 `#1e2847`·`#e6e8ee`·`#3a4778`·`#8b92a6`·`#ff9aa6` 등 hex 를 직접 쓰고 `ds/minifiav2/tokens.css` 만 불러온다. 보드는 토큰 변수만 쓴다(아래 Color).
2. **글자 크기를 승인 4개(14·16·24·36)로 옮긴다.** 초안의 12·13·15·20·40px 은 디자인 시스템 크기에 없다. 초안 칩 15px → 16, 초안 `n/30` 13px → 14, 초안 결선 숫자 40px → 알약의 24px, 초안 "도윤 님 처형" 20px → 결과 알림 36px(9.1 틀).
3. **"말 바꿈"은 진홍 계열이 아니다.** 초안은 분홍 글자(`#ff9aa6`) 알약이다. 진홍은 시간 신호·마피아 본인 표시 전용이고, 주장은 거짓일 수 있어 어떤 직업(마피아 포함)의 주장도 진홍을 쓰지 않는다. "말 바꿈"은 `gray-100` 면 작은 아이콘 점 + 바뀐 순간에만 보이는 글자 알약(`gray-100` 테두리)이다(A-1).
4. **초안 이름 아래 글자 배지 → 이름표 모서리 아이콘 배지.** 초안은 얼굴 아래 12px 글자 배지다. 0051(아이콘·숫자 먼저)과 14px 하한 때문에 직업 아이콘 20px 원을 이름표 오른쪽 위 모서리에 걸고, 글자는 접근성 이름에만 둔다.
5. **결선 투표는 하단 큰 버튼이 아니라 두 사람을 직접 누른다.** 초안은 화면 아래 "서연/도윤" 버튼 두 개다. 결정 0051(대상 직접 누르기)과 09.1 지목·찬반 틀을 따라 가운데 마주 선 두 사람의 이름표가 버튼이다. 두 이름표 사이가 멀어 오탭 위험이 낮다.
6. **마지막 3인 빠른 문구는 3개가 아니라 4개 + [직접 쓰기]다.** 초안 칩 3개에는 글 입력이 없다. 결정 0066-5 "빠른 문구 칩 또는 짧은 한 줄"에 맞춰 직접 쓰기를 더한다. 말하는 사람 강조 "지금 8초" 글자는 알약이 대신한다(09.1 `PickTurnBlock` 재사용).
7. **귓속말 시트 윗줄 "오늘 1번 남음"은 글이 아니라 이름표 점이다.** 남은 횟수는 버튼의 점(있음/없음)으로 말하고, 시트에는 상대 얼굴 칩 + `n/30` 만 둔다.
8. **찬반 공개는 얼굴 큰 원 + 이름이 아니라 "이름표 알약" 묶음이다.** 초안은 44px 원 + 12px 이름이다. 8자 이름이 14px 하한 아래로 내려가지 않고 폭 360 에서 두 줄로 넘치지 않도록 얼굴 24px + 이름 14px 700 알약으로 만든다(C-2).
9. **동점 결선·마지막 3인의 중앙 숫자·강조 원은 쓰지 않는다.** 초안의 가운데 큰 숫자 5, 맥박 원은 장식이다. 시간은 알약·막대, 강조는 핀 조명과 발밑 고리가 맡는다.

# C. 찬반 기록 공개 + 판결 순간 연출

대상 단계: 찬반(`verdict`) 마감 → 처형(`execution`) 진입. "투표가 끝나 결과가 나오는 순간"을 **처형 단계 진입 시각 T**로 본다. 부결(처형 없음)이어도 같은 연출이다.

## C-1. 시간표 (T 기준, 모두 기본값)

| T + | 일 |
|-----|----|
| 0 | 단계 전환. 어둡게 막 `night-950` 45% 가 `dur-med` 에 켜진다(9.1 지목의 막보다 짙지 않게 — 핀 조명이 읽혀야 한다). **변론자에게 핀 조명**이 `dur-fast` 에 켜지고(F-1 과 같은 장치) 실내등이 `dur-med` 에 0.6배가 된다. **카메라 느린 확대 0.6초**: 줌 1 → 1.10, `ease-in-out`(600ms). 스테이지 높이 `ZOOM_MIN_STAGE_H`(360) 미만이면 줌은 하지 않고 핀 조명만(기존 과반 연출 규칙). 헤더 제목 '처형' |
| 0.6 | 줌 끝. **결과 알림 "찬성 n · 반대 m"**(36px, `placement="top"` = 위 72)이 뜬다(기존 600ms 페이드). 동시에 `BallotReveal`의 **찬성 묶음**이 나타난다(`dur-pop` 260ms, 아래 8에서 올라오며 페이드) |
| 1.0 | **반대 묶음**이 나타난다(찬성 묶음 뒤 0.4초) |
| 2.6 | 알림이 "{이름} 님 처형"(3.0초) 또는 "처형 없음"(1.4초)으로 바뀐다(기존 알림 시간표를 **0.6초 뒤로 민 것**). 처형이면 변론자가 안개 유령으로 떠오른다(8페이즈 규칙, 산 사람에게는 기본 코트) |
| 4.6 | `BallotReveal` 이 `dur-med` 에 사라지고 같은 시각에 **채팅 카드**("찬성 n · 반대 m" 두 줄 + 이름들)가 도착한다. 줌이 `ease-in-out` 600ms 로 1 로 돌아온다 |
| 4.0 (부결) / 5.0 (처형) | 핀 조명이 `dur-med` 에 꺼진다(부결은 "처형 없음" 알림이 끝난 때, 처형은 유령이 사라지는 시각). 실내등은 같은 시각에 원래대로 |
| 5.6 | 처형 단계 끝 → 밤(또는 마지막 3인·승패 판정 경로) |

- 서버 처형 단계 길이: `EXECUTION_MS` **5_000 → 5_600**(= 기존 5초 + 판결 앞머리 `VERDICT_LEAD_MS` 600). 화면 알림 시간(`ANNOUNCE_TALLY_MS` 등)은 그대로 두고 **시작만 0.6초 미룬다**(O-6).
- 얼굴 묶음이 보이는 시간 = 0.6 ~ 4.6초 = **4.0초**(최대 7명 이름을 읽기에 3초 이상 확보).
- 모든 폰에서 시간표가 같다(줌만 높이 조건). 재접속·새로 고침은 지금 시각이 0.6 ~ 4.6 안이면 묶음을 **애니메이션 없이** 바로 보여 주고 줌·핀 조명을 현재 값으로 시작한다. 4.6 이후면 만들지 않는다(카드는 복원된 채팅에 있다).

# D. 동점 결선

대상: 지목(`nomination`)이 끝났을 때 득표 최다가 **정확히 둘**로 동점인 경우. (최다 동점이 셋 이상이거나 0표이면 이 단계 없이 기존 "처형 없음" 경로.)

## D-1. 시간표 (결선 시작 R 기준, 기본값)

| R + | 일 |
|-----|----|
| 지목 끝 알림(2초) | 동점이면 위 한 줄이 "모두 골랐어요"가 아니라 "동점이에요"가 된다(14px, 400ms 페이드). 알약·막대는 기존대로 사라진다 |
| R + 0 | 단계 전환(`runoff`). 헤더 제목 '결선'. **동점인 두 사람이 `dur-slow`(800ms)로 가운데로 걸어 마주 선다**(가운데 ± 0.9 단위, 화면 가로로 나란히). 나머지 산 사람은 모인 원 자리에 그대로. 실내등 0.6배(`dur-med`), focus 점광이 두 사람의 가운데 위에 켜진다(F-1 의 같은 장치, 한 점) |
| R + 1.0 | **알약·막대 등장**(`dur-med`): `결선` · `{초}초`. 후보가 아닌 산 사람의 헤더 안내 "둘 중 한 명을 눌러요", 두 후보의 이름표가 **버튼**이 되어 깜빡인다. 후보 본인 화면: 안내 "결과를 기다려요", 이름표는 버튼이 아니다 |
| R + 1.0 ~ 6.0 | **5초 카운트다운**(`RUNOFF_VOTE_MS = 5000`). 알약 초·막대·헤더 링이 줄어든다 |

| 마감 직후 누름 | 서버 거절, `TopToast` "지금은 고를 수 없어요", 낙관 표시를 서버 값으로 되돌림 |

## D-3. 시간 색 (`timerTone`)

`timerTone(남은 ms, 5000)` 한 호출이 알약 숫자·테두리·막대·헤더 링의 색을 정한다(9.1 A-3 과 같은 규칙). **단계 길이 5000 은 문턱 `URGENT_MS` 5000 보다 크지 않아 `calm` 만 나온다**(5초 아침과 같은 규칙: "5초짜리 단계는 색 없음"). 그래서 결선 카운트다운은 `gray-100`/`gray-50` 한 가지이고 긴장은 장면(마주 선 두 사람·핀 조명)과 줄어드는 막대가 말한다. 진홍을 쓰려면 `timerTone` 문턱 규칙을 바꿔야 하므로 이 페이즈에서는 바꾸지 않는다(O-10).

## D-4. 폰 크기

알약·막대·스테이지 높이는 9.1 A-1 표와 같다(알약 아랫변 160, 스테이지 164 ~ 방 높이 − 패널; 360×560 은 압축형 124 · 스테이지 244). 결선은 두 후보가 가운데로 모이고 나머지는 모인 원에 있어 이름표 상자는 지목과 같거나 작다. 360×560 의 19 모자람은 지목과 같은 알려진 한계다. 후보 이름표 버튼 둘은 서로 140px 이상 떨어져 있어 겹치지 않는다(E2E 가 44×44 이상·교차 없음 확인).

# E. 마지막 3인 결전

대상: 낮이 시작될 때 산 사람이 정확히 **셋**인 날(**인원수로만 정해지는 공개 정보**). 낮 토론(`discussion`)을 건너뛰고 이 단계(`showdown`)가 열린다. 지목·변론·찬반은 건너뛴다.

## E-1. 시간표 (S 기준, 기본값)

| S + | 일 |
|-----|----|
| 낮 시작 발표(2초) 뒤 S+0 | 단계 전환. 헤더 제목 '마지막 셋'. 세 사람이 가운데 정삼각형으로 모인다(`dur-slow`). 위 한 줄 "마지막 셋이에요". 어둡게 막 0.4(500ms), 실내등 0.6배 |
| S + 2.0 | **한마디 1번째**: 알약 `1 / 3` · `{이름} 님 차례` · `{초}초`(9.1 `PickTurnBlock`), 말하는 사람 발밑 고리 + **머리 위 핀 조명**(F-1), 8초 |
| + 8 + 0.9 | 확정(또는 시간 초과) 0.9초 뒤 2번째, 다시 3번째 (`PICK_GAP_MS` 재사용) |
| 마지막 한마디 + 0.9 | **동시 지목**: 알약이 `지목` · `모두 동시에` · `{초}초`로 바뀌고 핀 조명은 꺼진다. 8초 |
| 지목 마감 | **동시 공개**(1.5초): 세 사람이 같은 순간 가리키는 동작, 대상 머리 위 `VoteBadge` 가 `dur-pop` 으로 뜬다 |
| 공개 + 1.5 | 과반(2표 이상)이면 득표자에게 핀 조명 + 결과 알림 "{이름} 님 처형"(3.0초) + 안개 유령 상승(8페이즈 규칙). 1-1-1 이면 "처형 없음"(1.4초). 이어서 승패 판정 또는 밤 |

- 한마디 순서는 **자리 번호 오름차순**(9.1 지목과 같다, 역할과 무관 — L21). 서버가 정한다.
- 시간 상수(`phases.ts`): `SHOWDOWN_GATHER_MS 2000`, `SHOWDOWN_TURN_MS 8000`, 사이 `PICK_GAP_MS 900`, `SHOWDOWN_POINT_MS 8000`, `SHOWDOWN_REVEAL_MS 1500`. 총 약 `2 + 3 × 8.9 + 8 + 1.5 + 결과 ≈ 42초`(기존 토론 90초 + 지목 + 변론 + 찬반을 대신한다).
- 시간 색은 `timerTone(남은, 8000)` 한 호출: 남은 5초 이하 진홍(9.1 규칙 그대로, 모든 사람의 차례에 똑같이). 동시 지목도 같다.

## E-2. 내 한마디 차례 (`speak`)

| 순간 | 내 화면 |
|------|---------|
| 시작 | 헤더 안내 "한마디를 골라요"(약 2.5초 뒤 접힘). 아래 채팅 패널 자리를 **한마디 시트**가 덮는다: 시트 높이 = 패널 높이(188 · 244), 윗변이 패널과 같다. 칩 5개 |
| 칩 | 빠른 문구 4개 + **[직접 쓰기]**(`quill` 아이콘 + "직접 쓰기"). 칩 높이 44, 안쪽 좌우 16, 칩 사이 8, 줄 바꿈. 문구 기본값(O-11): **"저는 아니에요" · "쟤가 수상해요" · "저를 믿어 주세요" · "끝까지 지켜봐요"**. 최대 3줄 = `44×3 + 8×2 = 148`, 시트 안쪽 위아래 12 → 172 ≤ 188 |
| 칩 누름 | 즉시 확정. 시트가 사라지고 채팅 패널이 돌아온다. 위 인용 카드와 채팅 줄이 생긴다 |
| 직접 쓰기 | 시트가 `LineSheet` 입력으로 바뀐다(상한 30자소, 상대 칩 없이 윗줄 "한마디" 제목 + `n/30` + 닫기). 보내면 확정. 닫으면 칩 시트로 돌아온다 |
| 시간 초과 | 말없이 넘어간다("건너뜀" 글 없음). 인용 카드 없음, 채팅 줄 없음 |
| 확정 뒤 | 같은 차례에 다시 못 한다(취소·바꾸기 없음) |
| 내 차례가 아닐 때 | 채팅 패널 그대로. 채팅은 계속 할 수 있다(지목 단계와 같은 규칙) |

**인용 카드**(모두에게): 알약 아래 간격 8, 가운데, 폭 `화면 폭 − 32`, 면 `night-800` 92%, 테두리 1.5px `gray-100`, 반경 `radius-lg`, 안쪽 `8 16`, 글 16px 700 `gray-50` 최대 두 줄(`keep-all`·`anywhere`), `dur-med` 페이드. 차례가 끝나고 0.9초 사이가 지나면 사라진다. 같은 글이 채팅 `player` 줄("{이름}" 이름 점 + 글)로도 남는다(다시 읽기). 알약 위치는 9.1 과 같다(위 100, 360×560 압축 72). 인용 카드는 압축형에서도 만든다(스테이지에 사람이 셋뿐이라 자리가 있다).

## E-3. 동시 지목 (`point`)

| 순간 | 내 화면 |
|------|---------|
| 시작 | 헤더 안내 "의심되는 사람을 눌러요"(접힘). 나를 뺀 두 사람의 이름표가 **버튼**(안쪽 11 / 바깥 -11, 이름 "{닉네임} 님 가리키기", 묶음 `role="group" aria-label="지목"`)이고 깜빡인다 |
| 누름 | `mine`(밝은 면 + 손가락), 내 캐릭터가 가리킨다. 마감까지 **다른 사람을 눌러 바꿀 수 있다**(O-12). 취소 없음 |
| 남의 선택 | **마감 전에는 보이지 않는다**. 고른 사람의 이름표에 `done` 체크만 붙는다. 득표 배지·손가락은 마감 공개 때 한꺼번에 |
| 안 누름 | 기권(공개 때 가리키지 않음) |
| 마감 직후 누름 | `TopToast` "지금은 고를 수 없어요" |
| 유령 | 같은 진행을 본다(이름표 누를 수 없음, `RoleChip`) |

과반 처형은 8페이즈 처형 연출(알림 36px + 유령 상승)을 그대로 쓰고, 찬반 얼굴 묶음은 없다(찬반을 하지 않았다). 직전 결정(0053 찬반 규칙)은 건드리지 않는다.

## E-4. 폰 크기

알약·막대는 9.1 표와 같다. 사람이 셋뿐이라 이름표 상자(약 190)가 모든 폰의 스테이지(최소 244)에 들어간다. 한마디 시트(패널 높이 188 · 244)는 패널을 정확히 덮어 레이아웃을 바꾸지 않는다. 직접 쓰기 입력에서 키보드가 열리면 `WillSheet` 규칙(패널을 가리고 시트만 키보드 위, 입력 2줄 압축)을 그대로 쓴다.

# F. 지목 핀 조명 (마지막 지목자 조명)

대상: 순차 지목(`nomination` 차례)·마지막 3인 한마디. (판결 순간 연출 C 도 같은 장치.)

## F-1. 장치 하나로 세 곳

`setPin({ seat | point | null, travelMs?, dimOthers })` 한 가지가 세 곳에서 쓰인다: 지목 차례(F-2), 마지막 3인 한마디(E-1), 판결 순간·결선(C-1, D-1). 렌더러가 **처음부터 갖고 있는 focus 점광**의 위치·세기와 **실내등 그룹의 세기**를 움직일 뿐이다 — 새 광원을 만들지 않는다(셰이더 재컴파일·성능 위험 없음, 09 Pitfall 7).

| 값 | 기본 |
|----|------|
| 핀 위치 | 대상 캐릭터 머리 위 약 2.6 단위(`blockout.js` 의 focus 점광 높이), 아래로 부드러운 원뿔 |
| 세기 | 켜질 때 `dur-fast`(180ms), 꺼질 때 `dur-med`(420ms). 켜진 세기는 기존 선두 연출 레벨 1(0.9) |
| 나머지 어둡게 | 실내등(`room`·`vote` 그룹) 세기 × 0.6, `dur-med` 에 전환. **캐릭터를 회색으로 칠하는 `setDim`(접속 끊김 표시)은 쓰지 않는다** — 연결 끊김과 혼동된다. 이름표(DOM)는 어두워지지 않는다 |
| 대상 이동 | 시작 지점에서 끝 지점으로 선형이 아닌 `ease-in-out` |
| 줌 | 핀 조명 자체에는 줌이 없다. 줌은 C-1 판결 순간에서만 |
| 모션 줄이기 | 이동·줌 없음: 핀이 대상 위치로 즉시 건너뛴다. 어둡게 전환도 즉시 |
| 성능 | 6페이즈 게이트(5분 평균 55fps)를 지킨다. 어둡게는 광원 세기 한 값이라 비용이 없다 |

## F-2. 지목 차례의 핀 조명

| 시각 | 일 |
|------|----|
| 차례 시작 | 차례인 사람 머리 위에 핀이 켜지고(`dur-fast`) 나머지는 한 단계 어두워진다. 발밑 흰 고리·이름표 앞으로(9.1)는 그대로 유지된다 — 고리는 "누구 차례", 핀은 "무대" |
| 지목 확정(사람·봇) | 핀이 **지목받은 사람 머리 위로 0.9초 동안 미끄러진다**(`PICK_GAP_MS` 900ms = 사이 시간과 같다. 서버 일정과 어긋나지 않는다). 가리킴 동작·득표 배지(+1)·위 한 줄은 확정과 동시(서버 값) |
| 도착 | 대상 이름표가 `dur-pop` 으로 아주 작게 튄다(`scale 1 → 1.06 → 1`, 이름표만, 배지와 무관) |
| 다음 차례 시작(= 사이 끝) | 핀이 다음 차례 사람 머리 위로 `dur-fast` 교차 페이드로 옮겨진다(미끄러지는 것이 아니라 켜고 끈다) |
| 기권(시간 초과) | 이동 없음. 핀이 `dur-fast` 에 꺼졌다가 다음 차례 사람 위에 켜진다 |
| 모이는 중·끝 알림 | 핀 없음. 마지막 차례의 이동 도착 뒤 핀은 `dur-med` 에 꺼진다. **선두·과반 사람을 비추지 않는다**(0064-2, 되살리지 않음) |

내 차례에도 같다(내 머리 위로 핀이 켜진다). 눌러야 할 이름표 깜빡임·44 영역은 그대로다. 핀은 DOM 이 아니라 3D 이므로 이름표 위치·누르기에 영향이 없다.

## 접근성 · 모션 · 입력

- 누르기 대상 44 이상: 칩 44, 떠 있는 버튼 48, 이름표 버튼 44(11/-11), 시트 닫기 44, 입력 48. 배지·찬반 알약·인용 카드·알약은 누르는 대상이 아니다(`pointer-events: none`).

### 검사 가능하게 둘 것 (E2E 규칙)

## 쓰지 않을 것

- 직업 주장의 참·거짓 표시, 주장과 실제 역할이 다르다고 알리는 어떤 단서(색·소리·판정), 거짓 주장 거절. 이전 주장 값을 어디에도 보이지 않는다.
- 주장 배지·찬반 알약·귓속말 줄의 진홍·놋쇠·초록. 찬성/반대에 의미 색.
- 이름표 상시 버튼(걷기 탭 충돌). 귓속말 본문을 보낸·받은 사람 소켓 밖으로 보내고 화면에서 거르는 방식.
- 마지막 3인·결선에서 마감 전 개인 선택 공개, 클라이언트가 정하는 순서·후보.
- 캐릭터를 회색으로 칠하는 `setDim`(접속 끊김 표시)으로 "나머지 어둡게" 표현. 새 광원 추가.
- 선두·과반 사람을 비추는 핀 조명(0064-2 유지). 지목 중 "유력" 도장·맥박 되살리기.
- 새 글꼴·새 글자 크기·hex 직접 사용. 이모지 아이콘, 의미 없는 유리 효과, 보라·파랑 그라데이션, 앰버. 소리·햅틱·진동. 화면 전체를 덮는 깜빡임을 1초에 3번 이상.
- 캔버스 크기를 키보드나 패널에 맞춰 바꾸기.
