# Phase 12 — UI Design Contract (소리와 마무리)

> 범위: **(A) 소리 방식과 코드 구조 (B) 켜기·끄기·잠금 해제(SOUND-03) (C) 단계별 소리 목록과 대본(SOUND-01·02) (D) 믹스·성능 (E) 소리 시험 페이지 (F) 마무리 목록(청소·문서·사람용 TO-DO·팀 테스트)**. 화면 변경은 소리 단추 하나와 "소리 켜기" 알약뿐이다. 효과음·진동 중 진동은 앱 전환 때(범위 밖).
> **가장 중요한 규칙(결정 0051)**: 소리는 보조다. **소리로만 알리는 정보는 없다**(SOUND-03). 모든 소리는 화면이 이미 보여 주는 사건에 붙고, 소리를 끈 사람이 잃는 것은 분위기뿐이다. 글은 늘리지 않는다(새 글: "소리 켜기" 한 곳).
> **가장 중요한 불변식(결정 0002·0021, PITFALLS Pitfall 2)**: **소리는 숨은 정보를 나르지 않는다.** 밤 동안 서버 프레임으로 내는 소리는 0개다. 밤 소리는 역할과 무관하게 모두 같은 대본(공개 단계 진입 + 각자 폰의 난수 큐)이다. 암살 효과음은 판정 뒤 암살당한 본인 화면에만 난다.
> **분위기**: 스산한 재즈 바. 소리도 낮은 채도 — 밝은 팡파르·높은 금속음 없음. 낮도 낮은 명도에 맞춰 부드럽게, 밤은 거의 침묵에 가깝게.

# A. 소리 방식과 코드 구조

## A-1. 방식: 모든 소리를 Web Audio 로 합성한다 (D-1)

- **외부 오디오 파일 0개, 외부 소리 라이브러리 0개.** 소리는 `src/audio/recipes.ts` 의 레시피 표(발진기·필터링한 잡음·엔벨로프)가 전부 정의한다. 라이선스·출처 위험이 없고(공개 저장소), 번들이 늘지 않으며, 레시피가 순수 데이터라 오프라인으로 시험된다.
- 배경음도 합성한다: 코드 진행 데이터 + 시드 고정 난수로 음을 고르는 **생성형 침대**(느린 패드 + 아주 약한 브러시 + 가끔 낮은 베이스·피아노 비슷한 음). 알려진 곡의 선율을 쓰지 않는다(저작권 흔적 0).
- 품질 한계(전자음 느낌)는 인정한다. 사용자가 E 의 시험 페이지에서 듣고 마음에 들지 않는 id 는 **id 단위로** CC0 샘플로 바꿀 수 있게 `SoundId → 레시피` 표를 단일 정의로 둔다(하이브리드 문, 이번 페이즈에 샘플 코드는 만들지 않는다).

## A-2. 모듈 (`src/audio/`)

| 파일 | 역할 | 규칙 |
|------|------|------|
| `recipes.ts` | `SoundId` 목록, 레시피 표, 배경음 표, 순수 계산(`renderPlan(id)` → 이벤트 평면 목록, 길이, 최대 레벨 추정) | **import 0개**(정적 검사). Web Audio 를 모른다 |
| `script.ts` | 순수 대본: `verdictScript(passed, last)`·`nightCues(rng)`·`resultScript(n, win)`·`awardScript(k, n)`·`willScript` — `[{ at, id, gain? }]` | 시각은 공개 단계 시각·상수의 함수. `Math.random` 은 인자로만 받는다 |
| `director.ts` | 순수: `(prev: AudioView \| null, cur: AudioView, local: LocalSignals) → Cue[]` (단계 전환 표 + 대본 시작). 첫 스냅샷·재접속(`epoch` 변경)은 **일회성 소리 없이 침대만** | 읽을 수 있는 `RoomView` 필드는 허용 목록(LS-6) |
| `engine.ts` | `AudioContext` 하나, 버스(master → compressor → destination; bgm·sfx·ui 게인), 소음 버퍼 하나(시드 고정), 보이스 풀, 덕킹, 침대 스케줄러(lookahead), 잠금·중단·숨김 처리 | 부수효과는 여기만. 가짜 `AudioContext` 로 시험한다 |
| `prefs.ts` | `localStorage` `minifia:sound` = `{ v: 1, on: boolean }`. 접근 예외·깨진 값은 기본값(켜짐) | 읽기·쓰기 모두 try |
| `useSound.ts` | 방 화면(`RoomScreen`)이 쥔다: view 차이 → director → engine, 단추 상태(`on`·`locked`) | 연결·스토어 모듈을 직접 부르지 않는다(LS-6) |
| `testHook.ts` | `window.__mfSound` (E2E 문맥 `?e2e=1`·개발 빌드만) | 아래 A-4 |

## A-3. 레시피 형식 (시험이 고정하는 계약)

```
Layer  = { src: sine|triangle|square|sawtooth|noise, at: ms, dur: ms, f?: [Hz, Hz](지수 램프),
           gain: 0..1, env: [a, d, s, r], filter?: { type, f: [Hz, Hz], q }, detune?: cents }
Recipe = { id, bus: bgm|sfx|ui, layers: Layer[≤4], prio: 0|1|2, max: 같은 id 동시 상한,
           gapMs: 같은 id 최소 간격, gainDb: -24..0, duck?: { db, holdMs } }
Bed    = { id, bpm, chords: MIDI[][], bass: MIDI[], pad 필터 f·LFO, brush?: 비율, notes?: { p, seed },
           oscillators ≤ 6 }
```

- 한 레시피 길이 ≤ 3000ms(대본 단위 소리 제외), 주파수 40~9000Hz, 레이어 ≤ 4, 침대 발진기 ≤ 6 + 소음 1, LFO ≤ 8Hz. 레벨 추정(레이어 이득 합 × 버스 이득)이 −6 dBFS 이하.
- 음 이름은 MIDI 번호로 쓰고 `440 * 2^((m-69)/12)` 로 바꾼다. 난수는 시드 고정 `mulberry32`만(침대 음 고르기·소음 버퍼). 렌더 계획은 **같은 입력이면 항상 같은 출력**.

## A-4. 테스트 훅 `window.__mfSound` (E2E 문맥에서만, 역할 정보 없음)

```
{ state: "locked" | "running" | "suspended" | "off", on: boolean, bed: BedId | null,
  voices: number, log: [{ id: SoundId, at: Date.now(), gain: number, played: boolean }] (최대 300), clear() }
```

- 엔진이 재생 **요청**을 받는 순간 로그에 남긴다(`played` 는 잠금·끔 때문에 실제로 안 났으면 false). 그래서 E2E 는 **실제 소리 출력에 기대지 않는다**(헤드리스에서도 같다). DOM 에는 `data-sound-button`·`data-sound-state="{on|off|locked}"` 만 둔다(역할 값 없음). 이름은 `test/unit/e2eContract.test.ts` 가 고정한다.

# B. 켜기·끄기·잠금 해제 (SOUND-03)

## B-1. 소리 단추 (`SoundButton`)

| 항목 | 값 |
|------|----|
| 위치 | 방 화면(로비·낮·밤·결과 모두) 오른쪽 위, **헤더 아래 끝(62) 아래 8 · 오른쪽 `space-md` 16**(헤더와 같은 안전 영역 기준). `RoomScreen` 이 한 번만 그린다. 층은 헤더와 같은 `z-toast`(이름표·월드 위, 시트·모달 아래) |
| 크기 | 누르기 44×44, 시각 지름 36(칩과 같은 규칙: 아이콘 24 + 안쪽 6) |
| 상태 | `on`: `sound` 아이콘 `gray-300` · `off`: `soundOff` 아이콘 `gray-300`, 불투명도 0.6 · `locked`: 알약(B-2) |
| 면 | `night-800` 80% + 1px `night-600` 테두리. 아이콘 단추이므로 접근성 이름: on "소리 끄기" · off/locked "소리 켜기", `aria-pressed` |
| 밤 | 같은 위치·같은 모양(밤에도 닿는다). 어둠 대비 4.5:1 유지 |
| 들어가기 전 화면 | 홈·링크 참가·닉네임 시트에는 단추가 없다(소리가 아직 없다) |
| 겹침 | 6페이즈 재접속 띠·`TopToast`(가운데)·[테스트] 와 겹치면 **소리 단추가 위**(z). 겹침 0 은 E2E 사각형 검사로 고정(O-1) |

- 누르면 즉시 토글하고 `localStorage` 에 저장한다. 끄면 **현재 소리를 120ms 에 페이드아웃**하고 침대·예약된 대본을 멈춘다. 켜면 `ui.toggle` 한 번 + 현재 단계의 침대로 1.2초 페이드인(지난 일회성 소리는 재생하지 않는다).
- 한 단추는 **전체 on/off 만** 한다(D-5). 볼륨 슬라이더·배경음/효과음 분리 없음(O-9).

## B-2. "소리 켜기" 알약 (`locked`)

- 조건: 저장값이 켜짐인데 오디오가 `running` 이 아닐 때 — **새로고침·재접속·탭 복귀 후 `resume()` 거절·iOS `interrupted`**. 처음 참가는 참가 버튼에서 깨우므로 보이지 않는다.
- 모양: 높이 44, 최소 폭 112, 아이콘 `soundOff` 24 + 글 "소리 켜기"(Label 14 / 700) + 안쪽 테두리 2px `gray-100`(Accent). **8초 뒤 아이콘 단추로 접힌다**(접힌 뒤에도 눌러서 켠다).
- **화면의 아무 곳이나 한 번 눌러도 깨운다**: `RoomScreen` 이 `pointerup`·`keydown` 첫 이벤트에서 `resume()` 을 시도한다(iOS 는 `touchend`·`click` 만 인정하므로 `pointerup` 로 받되 `touchend` 도 겹쳐 건다). 알약은 그 사실을 몰라도 되게 하는 안내다.
- 저장값이 꺼짐이면 알약은 없다(끈 사람에게 다시 권하지 않는다, O-12).

| 규칙 | 값 |
|------|----|

| 재연결·재접속 | 소리와 무관(침대 유지). 첫 스냅샷·`epoch` 변경 직후는 일회성 소리 없음(6페이즈 첫 스냅샷 규칙과 같다) |

## C-7. 동작 소리

- 훅: 동작 **프레임을 받아 몸 동작을 재생하는 그 자리**에서 소리도 부른다. 받지 못한 동작(예: 시민이 못 받는 마피아 밤 동작)은 소리도 없다(LS-4).
- 내 동작은 0 dB, 남의 동작은 −6 dB. 1초에 동작 소리 3개까지(그 이상은 조용히 버림), 동시 4개 이하(`EMOTE_RENDER_MAX` 와 같다). 모션 줄이기와 무관(O-5).

# E. 소리 시험 페이지 (`SoundLab`) — 소리의 "캔버스 시안"

- 누르기 대상 44 이상, 글은 id 와 한글 이름 한 줄. 위 화면은 사람 귀용이라 장식 없음.
- **자동 검사 `sound-render`**: 같은 페이지의 [전부 계산]이 `OfflineAudioContext` 로 56개를 렌더(소리 출력 없음, 헤드리스 Chromium 가능)해 피크·RMS·길이를 낸다. 합격: 피크 ≤ −3 dBFS · NaN 0 · RMS ≥ −60 dB · 길이가 레시피 선언과 ±50ms.
- 사용자가 아침에 할 일: `npm run dev -- --host` 후 폰으로 `/?sound-lab=1` 을 열고 ▶ 로 듣는다. 마음에 들지 않는 id 를 알려 주면 레시피 한 줄을 고친다.

## 접근성 · 모션 · 입력

- 소리 단추는 키보드(PC)로 Tab → Enter. 포커스 링은 승인 토큰.

**D-1. 소리를 어떻게 만들까?** (a) 전부 Web Audio 합성(레시피 표) · (b) CC0 샘플 번들(파일 + 약관 기록) · (c) 합성 기본 + 일부 CC0 샘플(하이브리드). **추천 (a)**. 이유: 소리 담당자도 라이선스 자산도 없고 저장소가 공개다. (c)는 (a)로 시작해 마음에 안 드는 id 만 나중에 바꾸는 길로 열어 둔다(`SoundId → 레시피` 단일 정의). 이번엔 샘플 코드를 만들지 않는다. 연구 문서(STACK.md)의 샘플 전제는 이 결정으로 바뀐다(래퍼 `src/audio/`·Howler 불사용은 유지).

## 이월 · 위험

- **11페이즈 의존**: 결과·시상 소리(C-6)는 11페이즈 최종 이름·시간표(`window.__mfResult`, `data-award-plate`)에 맞춘다. 계획 단계에서 11페이즈 SUMMARY 로 확인한다. 11페이즈가 시간표를 바꾸면 `resultScript`·`awardScript` 상수 두 곳만 고친다.
- **소리 취향 위험**: 합성 음색은 취향을 탈 수 있다. 시험 페이지로 일찍 들어 보고(⑧을 앞 웨이브에 둘 수 있다) 레시피 값만 고친다.
- **iOS 실제 동작**: 무음 스위치·`interrupted` 복구·`audioSession` 은 문서·커뮤니티 근거라(STACK.md MEDIUM) 실기기로만 확정된다. 안 되면 B-3 을 고친다. 12-TEAM-TEST 에 칸.
- **시민 편 30초 긴장(9페이즈 관찰 ⑤)**: 소리가 붙은 뒤 다시 관찰한다. 필요하면 큐 수·세기를 레시피 값으로 조정한다.
- **정리 목록이 낡았을 위험**: HANDOFF 의 정리 후보는 이미 지워진 것이 있을 수 있다. 삭제 표가 존재 확인을 먼저 한다.
- 진동·햅틱은 앱 전환 때. 감정 머리 위 표시 없음(0064-16).
