# Phase 16 — UI Design Contract (튜토리얼 · 단추 정리 · 심부름 증거)

> 새 화면은 둘이다: **연습 화면**(대기실 틀을 재사용, 서버에 보내지 않음)과 **연습 끝 기다림 화면**. 나머지는 기존 화면의 정리다: 아이콘 단추 아래 글 이름표를 모두 뺀다, 단추를 한 규칙으로 모은다, 심부름 화면을 시작 카드·컬러 장소·화살표·장소 위 [처리]로 바꾼다, 아침 흔적을 "같은 옷 표시 + 마지막 목격"으로 키운다.
> 결정 0051(글 최소·보고 누르기·3초 규칙)이 먼저다. 이 페이즈는 **글을 늘리는 것이 아니라 줄이는** 페이즈다(이름표 삭제). 새로 생기는 글은 단계 이름·한 줄·숫자뿐이다.
> 0077 은 **0073-나**(모든 아이콘 단추에 이름표)와 **0074 D-03**(마피아도 같은 목록)을 바꾼다. 15페이즈 UI-SPEC 가운데 이 문서와 다른 줄(장소 표지 36·`ErrandDock`·점선 링 외 화살표 칩·흔적 카드 단독·`독 아랫변 B+52`)은 **이 문서가 이긴다**. 안 건드린 줄은 14·15 그대로다.
> 기준 번호: ROADMAP Phase 16 성공 기준 **SC-1~5**, 결정 0077 의 **0077-1~6**. 요구사항 ID 는 로드맵에 아직 TBD 라 새로 만들지 않는다(계획 단계에서 부여).

시안과 **다르게 한 곳**(이유):
1. 시안의 글자 크기 15·17·18·22·28 은 캔버스 자리 표시용이다. 실제는 4개 크기(36·24·16·14)와 굵기 2개(400·700)만 쓴다(Typography 표).
2. 시안의 색(`#c9a46a #e8d3a8 #ffcf8a #1e2847 #2a3760` 등)은 토큰과 같은 값이라 토큰 이름으로 옮긴다(`brass-400 brass-200 light-lamp night-700 night-600`). 시안의 `#4a5578`(대기 점)은 토큰에 없어 `gray-500`, 에셋 타일 면 `#221d2e` 는 `night-800` 으로 옮긴다(V-27, 새 토큰 없음).
3. 시안의 코치 막은 `rgba(5,6,12,.74)` 다. 토큰 `--scrim`(.6)을 쓴다(새 토큰 없음, 구멍·램프 링으로 충분히 읽힘).
4. 시안 아침 보드는 "마지막 목격" 카드를 맨 아래(40)에 놓았다. 실제 아침 아래에는 채팅 패널이 있어(≈200) 겹치므로 **흔적 카드와 한 장으로 합쳐 같은 자리**에 둔다(V-28).
5. 시안 아침 보드의 흔적 카드는 "같은 옷을 입은 사람에게 빨간 테두리"라고 색 이름을 글로 썼다. 표시 색은 **조각마다 그 조각의 색**이고(시안 "같은 색 표시"), 글은 색 이름 없이 쓴다(V-29).
6. 시안 연습 화면(`Tut-Step`)의 오른쪽 열은 소리·맵·봇·옷장 넷이다. 실제 연습 화면은 방 설정인 맵·봇을 빼고 **소리·옷장** 둘만 둔다(V-11).
7. 시안 기다림 화면(`Tut-Wait`) 카드 아래의 안내 한 줄("모두 끝나거나 시간이 다 되면 …")은 뺀다. 시간 막대와 "n초"가 이미 말한다.
8. 시안의 4의 배수가 아닌 값을 가까운 4의 배수로 옮긴다: 알약·카드와 타일 사이 10 → 8, 스위치 알 22(안쪽 3) → 20(안쪽 4), 체크 배지 22 → 24, 시간 막대 6 → 8, 모서리 18 → 16, 알약 안 아이콘 18 → 16, 시작 카드 위 230 → 232.

## 아침 증거 계약 (SC-5, 0077-6)

- 언제: 피해자가 있는 아침, 피해자 알림(+유언·쪽지) 다음 `MORNING_TRACE_MS`(5초). 피해자가 없으면 카드·구간·띠 줄·이름표 표시가 **모두 없다**(TRACE-03 유지). 모든 사람(유령 포함)에게 같은 카드.
- **증거 카드 모양**(V-28): 폭 328, 높이 128, `overlay-ink-strong` 면, `radius-badge`, 테두리 1 `night-600`, 안쪽 12 16. 1행(44): 조각 그림 타일 44(면 `night-700`, 아트 36, 테두리 2 `var(--trace-mark)`) + 두 줄 [조각 이름 Body 16/700 `gray-50` / "같은 옷을 입은 사람에게 표시" Label 14/400 `gray-300`]. 구분선 1 `night-600`(행 사이 16 의 가운데, 위아래 8). 2행(44): V-30. 가운데 정렬 아님(왼쪽 정렬).
- 등장·퇴장: `opacity` 0 → 1 + `translateY` 8 → 0(`dur-med`), 사라짐 `opacity`(`dur-fast`). 모션 줄이기면 즉시. 도착 소리 `ui.card` 한 번(V-31).
- **이름표 표시**(V-29): 카드가 뜨는 순간부터 낮이 끝날 때까지. 같은 의상 입은 산 사람 이름표 = 테두리 2 `var(--trace-mark)` + `thread` 16(이름 앞). 마지막 목격자 이름표 = `eye` 16 `brass-200`(이름 앞). 둘 다면 두 아이콘 나란히. 이름표 폭이 늘면 15 의 겹침 규칙이 그대로 적용되고 8자 가장자리 잘림은 알려진 한계다. **캐릭터 몸에는 표시를 그리지 않는다**(3D 장면을 건드리지 않음 — 시안 아침 보드의 몸 테두리 번짐은 이름표 표시로 대신한다).
- 띠 문장 3개와 빛남 없음(아래 문구 표). 캔버스에 없는 설명 문장은 더하지 않고, "범인"·"증거"·"확정" 같은 글·색은 쓰지 않는다.
- **누설 경계**: `day.morning.trace`(조각 id, 공개)는 15 그대로 의상 id·좌석·역할을 싣지 않는다. 같은 옷 판정은 클라이언트가 공개된 의상과 조각→의상 표로 계산한다. 새로 필요한 공개 값은 **마지막 목격자 좌석(없을 수 있음) + 장소 id(선택)** 뿐이고 피해자 좌석은 이미 공개다(역할·확신·"수상함" 값 없음). 서버가 장소 id 를 줄지는 계획 단계 확인.

## 남은 위험 · 플래너 확인 목록

- **서버가 함께 바뀐다(UI 가 읽는 값만 적는다)**: 방 설정 `tutorial`(시작 메시지에 켬·끔), 연습 단계와 `TUTORIAL_MS`(90초)·방 view 의 공개 값 `tutorial {done, total, endsAt}`, 연습 끝 메시지 하나, 마피아의 가짜 장소(배정 1곳 + 응답 규칙), 마지막 목격자(+선택 장소 id). `PhaseId` 에 연습 단계를 더하면 15 처럼 `PHASE_SCENE`·`PHASES`·`hostChimeOf`·E2E 단계 목록이 컴파일 오류로 따라온다. 모두 `RULESET` 스위치가 아니라 방 설정·정상 단계로 둔다.
- **가짜 장소의 응답(V-25)**: 서버가 무변화로 답하면 마피아의 점이 2/3 에 멈춘다. 이 "탭해도 반응 없음"이 버그처럼 읽힐 수 있다. 추천 기본은 UI 에 아무 설명도 더하지 않는 것이다(마피아만 있는 줄 금지). 계획 단계에서 서버 규칙과 함께 확정하고, 사용자가 돌아와 바꿀 수 있다.
- **이름표 삭제의 부작용**: `TOOL_ROW_EXTRA` 삭제로 채팅 패널 높이 계산(`expectedPanelH`)·`useMapInsets`·E2E 기대값이 바뀐다. 14 의 `emcee-tools`·`emcee-band` 일부 검사를 뒤집는다. 전체 6종 회귀는 페이즈 끝에 한 번(사용자 메모).
- **조각 표시 색(V-29)은 위임 기본값**: 조각마다 다른 색이라 마피아 색으로 읽히지 않지만, 시안 아침 보드가 붉은 한 가지만 그렸다. 한 가지 색(예 `brass-200`)으로 통일하려면 `--trace-mark` 를 한 줄로 고정한다.
- **낮 끝까지 표시(V-29)**: 표시가 토론 내내 보이는 것은 시안이 직접 말하지 않은 확장이다. 아침에만 보이게 되돌리려면 표시 유지 조건 한 줄을 바꾼다.
- **컬러 에셋 옮기기**: 인라인 `<svg>` 25개를 `design/v3.0/assets/` 사본과 JSX 표로 옮기는 일은 기계적이지만 양이 많다. 옮긴 뒤 aria-label·id 일치와 장소 16 구분 검사를 자동 시험(`placeArt.test`)으로 고정한다. `V2Icon` 의 `place*` 16개는 삭제 전에 참조(`placeIconOf`·ErrandDock 외 사용처)를 `grep -rn "place[A-Z]\|placeIconOf" src` 로 확인한다.
- **연습 화면의 가짜 상대·가짜 밤 목록**은 연습 전용 상수여야 하고 `RoomView`·역할 계산을 읽지 않는다(누설 검사 확장 ①).
