## Warnings

### WR-01: 처형 연출의 몸 불투명도(1 → 0.26)가 실제 `WorldCharacter` 에는 적용되지 않는다

**File:** `src/world/character.ts:1255-1259`, `src/world/runtime.ts:1186-1190`, `src/world/presence.ts:222-238`
**Issue:** `character.setOpacity` 는 `if (disposed || !ghostOn) return;` 로 유령 상태에서만 동작한다. 그런데 처형 연출 중인 산 사람 화면의 좌석은 `visibleSeats` 에서 `ghost: dead && (ghostViewer || !fadingNow)` 이므로 연출 동안 `ghost === false` 다. 그래서 `runtime.ts` 가 매 프레임 `a.handle.setOpacity?.(bodyFade)` 로 `executionFade` 값(0.6 → 0.26)을 보내도 실제 캐릭터는 무시한다. 결과적으로 몸은 2.4초 내내 불투명하게 떠오르다가 `ghostRise` 타이머가 좌석을 놓는 순간 0.3초 페이드인 유령 그림으로 "툭" 바뀐다. 이름표만 흐려진다. 이번 단계가 새로 넣은 `EXEC_END_OPACITY`(C-4)·`tagFade` 식·"끝점에서 같은 자리에 유령 그림이 나타난다" 설계가 모두 이 no-op 위에 서 있다. 이전 코드도 `ghostMat` 이 없으면 똑같이 무시했지만, 이번에는 "끝점 0.26 에서 서 있다가 그림으로 교체"라는 연속성이 요구사항이 되어 눈에 띄는 결함이 된다. 단위 테스트가 가짜 handle 을 쓰면 통과해 버리는 종류다.
**Fix:** 비유령 상태에서도 몸 불투명도를 바꿀 수 있게 한다. 예를 들어 `setOpacity` 가 `ghostOn` 이 아닐 때는 전용 복제 재질(`fadeMat`, transparent·depthWrite false)을 쓰고 1 이면 공유 `bodyMaterial` 로 되돌린다. 또는 연출용 `setFade(alpha)` 를 따로 두고 `applyGhost` 의 대체 몸 경로와 재질 복제 로직을 공유한다. 이때 `dispose()` 에서 복제 재질을 해제하는 것을 잊지 않는다. 그리고 `test/unit/character.test.ts` 에 "ghost 아님 + setOpacity(0.3) → 몸 재질 불투명도 0.3" 케이스를 추가한다.

### WR-02: 재접속·새로고침 뒤에는 산 사람 화면의 탈락자 유령이 통째로 사라진다

**File:** `src/world/store.ts:123-130, 163-165`, `src/world/runtime.ts:112-120(segFor), 1050-1060`, `src/screens/RoomScreen.tsx:308`
**Issue:** 탈락자 유령은 서버 구간이 아니라 `WorldStore.lastSegs`(이 화면이 과거에 받은 구간)에 전적으로 의존한다. 새로고침·앱 재시작·신규 접속(폰 잠자기 후 복귀가 흔한 모바일 게임)에서는 스토어가 비어 있어 `segFor(seat)` 가 `undefined` 를 돌려주고 `createActor` 가 건너뛰어진다. 즉 같은 판 같은 시점인데 처음부터 있던 사람은 유령을 보고, 중간에 다시 들어온 사람은 탈락자가 없는 광장을 본다. 이름표 DOM 은 `scene.seats[seat].ghost === true` 로 남아 있어 `HeadStack is-ghost` 는 있는데 몸이 없는 상태가 된다. `store.ts` 주석("이전 연결의 위치는 섞지 않는다 — reset() 과 retainSeats() 에서만 지운다")도 실제와 다르다. `reset()` 은 판 번호가 바뀔 때만(RoomScreen:308) 불리고, 같은 판 안의 재접속(새 epoch snap)에서는 `lastSegs` 가 지워지지 않아 옛 연결의 위치가 남는다. 새로고침 시에만 비는 것이다. 그래서 재접속 방식에 따라 동작이 갈린다.
**Fix:** 서버가 탈락자 구간을 다시 보내지 않는 것이 전제라면(서버 변경 범위 밖), 구간이 없는 탈락 좌석은 결정적인 대체 자리에 세운다. 예를 들어 `ringSlots` 로 계산한 모임 자리 또는 `map.spawns[seat]` 를 `segFor` 의 마지막 대안으로 쓴다. 이렇게 하면 접속 이력에 상관없이 모든 클라이언트가 유령을 본다. 최소한 `store.ts` 주석을 실제 동작(재접속은 이어 쓰고 새로고침은 비운다)에 맞게 고치고, 이 한계를 결정 기록(0083-2)에 적는다.

### WR-03: 유언 [저장] 이 오프라인·전송 실패를 조용히 삼키고 창을 닫는다

**File:** `src/net/useWill.ts:172-190, 192-204`
**Issue:** 유언 저장이 `close(text)` 와 같은 길이 되면서 `submit` 의 반환값 중 `"offline"`(`canSend === false`)이 `onFail()` 없이 통과한다. `result === "failed"` 일 때만 알림이 간다. 시트가 열린 뒤 연결이 끊기면 사용자가 [저장]을 눌러도 아무 전송 없이 시트가 닫히고, 알림도 없고, 유언 단추의 `willSaved` 표시도 켜지지 않아 저장됐는지 알 수 없다(글은 `kept` 에 남지만 사용자는 모른다). 이전 `save` 는 시트를 열어 둔 채여서 실패가 눈에 보였다. 서버 확인을 기다리지 않는 설계(0083-6)로 바뀐 만큼 실패 알림 경로가 더 중요해졌다.
**Fix:** `close` 의 결과 분기에서 `"offline"` 도 실패로 알린다.
```ts
const result = submit(open, text);
if (result === "failed" || result === "offline") live.current.onFail();
```
또는 오프라인이면 시트를 닫지 않는다(`save` 에서 `submit` 결과가 `offline` 이면 `finish` 를 건너뜀).

### WR-04: 유령 그림 텍스처가 모듈 import 시점에 한 번만, 재시도 없이 불러진다

**File:** `src/world/character.ts:780-800`
**Issue:** `new TextureLoader().load(...)` 가 모듈 최상단에서 실행되고 실패 콜백은 빈 함수다. 모바일 망에서 이 한 번의 요청이 실패하면 세션 내내 `ghostArt === null` 이라, 모든 탈락자가 폴백 반투명 몸(0.6)으로 그려지고 `window.__mfGhosts.ready` 도 영원히 `false` 다. 폴백 자체는 의도된 안전장치이지만, 이번 변경의 핵심 시각 요구(탈락자 = 같은 유령 그림)가 일시적 네트워크 오류 하나로 영구히 꺼진다. 또한 import 부작용이라 `character.ts` 를 가져오는 모든 경로(시험 포함, happy-dom 은 `document` 가 있어 실제 요청을 시도한다)에서 네트워크 요청이 생긴다. 로드 시점도 월드 청크 실행 시점이라 첫 유령이 나올 때까지 도착한다는 보장이 없다.
**Fix:** 로드를 `ensureGhostArt()` 같은 함수로 빼서 `createCharacter`(또는 `setGhost(true)` 첫 호출) 시점에 지연 실행하고, 실패하면 일정 횟수(예: 2회, 지수 대기) 재시도하며, 진행 중 중복 호출을 막는다. 모듈 최상단의 즉시 실행은 제거한다.
