# Phase 18.1 — UI Design Contract (화면 손보기: 역할 확인 겹침 · 채팅 2줄 · 유령 · 시간대 아이콘 · 결과 기록 숨김)

> 새 화면은 없다. 기존 화면 다섯 곳을 고친다: **역할 카드(역할 확인·[내 역할] 시트·튜토리얼 직업 카드의 글) · 채팅 패널(대기실·게임·결과) · 유령 표시 · 게임 맵 헤더(시간대 아이콘 신설) · 결과 화면 탭**. 새 글자 크기·굵기·간격 값은 없다. 새 토큰은 없다. 시간대 아이콘은 컬러 날씨 SVG 에셋 4개다(`public/weather/`, 아래 D 절).
> 결정 0051(글 최소·보고 누르기·3초 규칙)이 먼저다. 이 페이즈는 글을 늘리지 않고 **줄인다** — 역할 카드의 글은 **한 덩어리**만 남기고(사용자 확정 문구, 2026-11-12 사용자 요청으로 첫 문장 제거 — 할 일 한 문장, 카드에서 1~2줄) 목표 줄은 없애며, 결과 화면의 탭 라벨도 사라진다. 사용자가 확정한 문구가 결정 0051 의 "한 줄 이하"보다 길다 — **사용자 요청이 우선이고, 문구는 이 한 덩어리만 둔다**(목표 줄·칩·설명 두 벌을 두지 않는 것으로 0051 의 취지를 지킨다). 새로 생기는 화면 글은 접근성 이름뿐이다.
> 기준 번호: ROADMAP Phase 18.1 요청 **R1~R5**(아래 A~E 절이 1:1). 같은 페이즈의 **G-18-1**(낮·밤 조명 대비 개선: 재질·하늘·방향광 색을 시간대별로 분리)과 시간대 표현이 겹치지만, 시간대 배지는 **자체 배경이 있는 컬러 에셋**을 쓰고 맵 하늘색에 연동하지 않으므로 G-18-1 과 **독립**이다(D 절).
> 확정된 사용자 답: 이 문서의 열린 질문은 모두 닫혔다(Q1 산 사람 화면 유령 채택 · Q2 시간대 4가지 · Q3 결과 탭 전부 숨김 · Q4 R1 재정의 · Q5 튜토리얼에서 배지 끔).
> 범위 밖: 햅틱·진동 등 앱 전용 기능, 작은 폰 가장자리 잘림처럼 진행에 지장 없는 문제(07-UI-SPEC UI Considerations 20 그대로), 서버가 보관하는 채팅·결과 기록의 저장 방식(결정 0027·0058 그대로), 캐릭터 새 디자인(세트 C 생김새·0063-2 유령 안개 그대로), 튜토리얼 화면의 레이아웃.
> 17·18 과의 관계: 17-UI-SPEC 의 포커스 테두리·사회자 띠·튜토리얼 계약과 18-UI-SPEC 의 토큰·톤은 **그대로 이긴다**. 이 문서가 바꾸는 것은 아래 A~E 가 적은 것뿐이다.

## A. 역할 카드 — 글은 한 덩어리만 — R1

> **R1 재정의(사용자 확인)**: 사용자가 본 "겹침"은 3D 이름표가 아니라 **역할 카드 안의 글 내용 중복**이다. 설명과 목표가 같은 말을 되풀이했다. 사용자가 **새 문구를 직접 확정**했다(아래 A-1). A-1 이 본안이다. 이전에 찾은 이름표 층 겹침(A-2)은 실제 결함이라 **보조 항목으로 남기고 우선순위를 낮춘다**.

### A-1 원인 (현재 코드)

역할 카드 앞면(`RoleCard` `CardFront`)과 [내 역할] 시트(`RoleCardSheet` `Front`)는 직업 이름 아래에 **글 두 덩어리**를 그린다: 설명 `ROLE_TEXT[role].desc` 와 구분선 아래 '목표' 칩 + 목표 문장 `ROLE_TEXT[role].goal`(`RoleGoal`, TOOL-03). 두 문장이 거의 같은 말이다.

| 직업 | 지금 설명(desc) | 지금 목표(goal) | 겹치는 말 |
|------|-----------------|-----------------|-----------|
| 시민 | 대화와 투표로 마피아를 찾아요 | 대화와 투표로 마피아를 모두 처형하면 승리합니다. | "대화와 투표로 마피아를" 그대로 반복 |
| 마피아 | 밤에 함께 한 명을 지목해요 | 밤마다 한 명을 없애 시민 편과 수가 같아지면 승리합니다. | 밤에 한 명을 고르는 행동 반복 |
| 경찰 | 밤마다 한 명을 조사해요 | 밤마다 한 명을 조사해 마피아를 찾아내세요. | "밤마다 한 명을 조사" 그대로 반복 |
| 의사 | 밤에 한 명을 살려요 | 밤마다 한 명을 지켜 마피아의 암살을 막으세요. | 밤에 한 명을 살리는 행동 반복 |

### A-1 계약

1. **카드에는 글 한 덩어리만**: 직업 이름(36px) 아래 **확정 문구**(`.mf-card__desc`, 16px/1.5)만 둔다. 목표 줄·'목표' 칩(`RoleGoal`, `.mf-goal`)·그 윗선은 카드 앞면과 [내 역할] 시트에서 **그리지 않는다.** 남기는 필드 = `desc`, `goal` 필드는 폐지(P181-0).
2. **줄 구성(사용자 확정, 개정 5)**: 글은 **할 일 한 문장**이다. 2026-11-12 사용자 요청으로 첫 문장 제거 — 정체 선언(직업 이름은 바로 위 36px 이름이 이미 말한다)과 줄바꿈 문자가 없다. 문장이 길어 접히면 `word-break: keep-all`(기존 규칙) 단어 단위로 접힌다. 전체 **1~2줄, 카드 상한 2줄**(문장 폭 173~219px, 카드 안쪽 폭 146~192px). [내 역할] 시트(14px/20, 텍스트 열 약 136px@360 ~ 178px@402, 시트 사진에서 잰 추정)와 튜토리얼 직업 카드(14px/1.35, 열 약 130px@360 추정)는 **상한 3줄**이다. 상한은 이전 값(3·4·4)에서 없앤 첫 줄 하나씩을 뺀 값이다 — 남은 문장은 글자·글꼴·열 폭이 그대로라 접히는 자리가 같다. 이전의 "공백 포함 10자 이하·한 줄" 요건은 **폐기**한다.
   - **예외(알려진 한계)**: **360×560 의 의사**는 문구 "시민 팀을 마피아에게서 지키세요."(폭 219px)가 카드 안쪽 폭 146px 에서 "시민 팀을" / "마피아에게서" / "지키세요." 세 줄로 접혀("시민 팀을 마피아에게서" 153px > 146) **3줄**이 된다. 이 짧은 폰은 07-UI-SPEC 이 이미 알려진 한계로 둔 크기라 문구도 카드도 더 줄이지 않는다. 다른 폰 5종은 네 직업 모두 2줄 이하다.
3. **문자열·접근성(개정 5)**: `ROLE_TEXT[role].desc` 는 줄바꿈 문자가 없는 한 문장이다(예: `"추리로 마피아를 찾아내세요."`). `.mf-card__desc`·`.mf-rolecard__desc`·`.tut-role__line` 세 곳의 `white-space: pre-line` 은 개정 3 때 건 것이 그대로 남아 있고, 줄바꿈 문자가 없어 보이는 차이는 없다(`word-break: keep-all` 유지). DOM 은 **한 요소·한 텍스트 노드**다. 말투는 사용자 확정 문구 그대로("~하세요" 체)이고 마피아 문구에는 "마피아 팀과 함께"·"들키지 않고"를 넣지 않는다(혼자인 마피아가 있다). 의사 문구는 의사 본인도 시민 팀이고 자기 자신도 지킬 수 있어 "시민을"이 아니라 "시민 팀을"이다.
4. **마피아 동료 줄**(`동료 · {이름}`·`혼자예요`)은 기존 그대로(구분선 + 한 줄, 마피아 본인에게만).
5. **TOOL-03 재해석**: "역할 확인 화면과 역할 카드에 내 목표가 한 줄로 보인다" — 확정 문구 한 덩어리(직업 확인 + 할 일)가 내 목표를 겸한다. `goal` 필드와 `[data-role-goal]` 표식은 폐지하고, 이를 읽던 E2E·단위 시험(`lib.GOALS`·`HOST_MARKERS`·`roleCard.test.tsx` 의 목표 시험·emcee 누설 시험)은 같은 검사를 **문구 한 덩어리(`data-role-line`, 값 없는 표식)** 로 옮긴다: 자기 직업의 문구만 DOM 에 있고 다른 직업의 문장은 없다.
6. **카드 모양과 높이**: 카드 크기 규칙은 그대로(폭 `min(64vw, 240px, 52dvh × 2/3)`, 높이 ≤ 52dvh). 문구가 여러 줄이 되어도 카드는 자라지 않고 **직업 그림이 먼저 줄어든다**(`flex: 0 1 auto`, 기존 규칙). **직업 그림 높이 하한 64**(어느 폰·직업에서도 접히지 않는다. 개정 4 실측의 최악은 360×560 마피아 3줄 + 동료 줄 75 였고, 개정 5 는 문구가 한 줄씩 줄어 그림이 그만큼 커진다).
7. **튜토리얼 직업 카드·[내 역할] 시트**: 같은 `ROLE_TEXT.desc` 를 읽으므로 코드 변경 없이 문구가 따라온다. 개정 5 로 줄 수가 한 줄씩 줄었다(시트 2줄 이하, 튜토리얼 카드 열 130px@360 기준 시민·마피아·경찰 2줄·의사 3줄). 시트는 본체 최소 높이(그림 액자 160 + 안쪽 32 = 192)가 텍스트 열보다 커서 높이가 변하지 않고, 튜토리얼 카드는 줄 하나(14px×1.35 ≈ 19px)만큼 낮아진다.

4. **모양**: **원형 44×44**(`border-radius: var(--radius-pill)`, 안쪽 잘림), 테두리 1px `night-600`. 안은 **컬러 날씨 일러스트 에셋**이다(아래 에셋 계약) — 단색 선 아이콘이 아니다. 글자 없음. 접근성: 바깥 상자 `role="img"` + `aria-label`(위 표, 한 단어 — 결정 0073-2), 안의 `<img>` 는 `alt=""`·`aria-hidden`. 누를 수 없음(`pointer-events: none`, 포커스 안 받음).
   - **에셋 자체 배경을 쓰고 맵 하늘색과 연동하지 않는다.** 배지 색은 조명표(`PLAZA_LIGHT_TUNE`·`LIGHT_TUNE`)를 읽지 않는다. G-18-1 이 하늘색·재질·방향광을 바꿔도 배지는 그대로이며, 두 작업은 서로 독립이다. (배지의 밝기 순서는 에셋이 정한다: 낮 > 아침 > 저녁 > 밤으로 읽히게 그린다.)
   - **에셋 계약(앱용, 사용자가 Design 캔버스 Weather 보드에서 내보낸 원본을 그대로 쓴다 — 코드로 다시 그리지 않는다)**:

| 시간대 | 파일 | 그림 방향 |
|--------|------|-----------|
| 아침 | `public/weather/weather-morning.svg` | 낮은 해 + 옅은 구름(연한 보랏빛 회색 하늘) |
| 낮 | `public/weather/weather-day.svg` | 흐린 낮: 해 + 구름 |
| 저녁 | `public/weather/weather-dusk.svg` | 노을: 해가 낮게 걸린 따뜻한 하늘 |
| 밤 | `public/weather/weather-night.svg` | 초승달 + 별 + 어두운 남색 하늘 |

   - 규격: 정사각 `viewBox`(예 `0 0 88 88`, 44×44 로 쓰면 2× 선명), **배경이 꽉 찬 사각형**(원 잘림은 CSS), 파일당 ≤ 8KB, 외부 참조(`href`·폰트·이미지)·스크립트·애니메이션(SMIL·CSS) 없음. **채도 낮은 컬러**(낮도 마피아 분위기: 배경·구름 HSL 채도 ≤ 0.30, 해·달 포인트 ≤ 0.50, 맑은 하늘색·쨍한 노랑·진홍 금지). 4장은 같은 그림 문법(윤곽·질감)으로 맞춘다.
   - **큰 원본**은 `design/v3.0/weather/` 에 사본으로 둔다(디자인 시스템 저장 규칙). 에셋 4개가 계획 시작 때 저장소에 없으면 그 일이 **첫 막힘**이다(조정자에게 알린다 — 임의로 그리지 않는다).
   - 불러오기: 4장을 모두 `<img width="44" height="44">` 로 겹쳐 두고 현재 시간대만 불투명도 1(나머지 0)로 한다. 그래서 첫 전환에서 로딩 깜빡임이 없고 자리가 흔들리지 않는다.
5. **움직임**: 시간대가 바뀔 때만 — 이전 에셋이 `--dur-med`(420ms) 동안 투명해지고 새 에셋이 같은 시간에 나타나는 크로스페이드 하나(`opacity` 만, 크기 변화 없음). **반복 애니메이션 없음**(구름 흘러가기·별 깜빡임 금지: 상시 움직임이 단계 안내와 경쟁하고 성능을 쓴다). 모션 줄이기: 전환 없이 즉시.
6. **누설 없음**: 입력은 `view.phase` 하나(공개). 역할·좌석을 읽지 않는다. `data-tod="morning|day|dusk|night"` 한 속성만 남긴다(E2E 훅, 값은 공개 단계에서 나옴).
7. **G-18-1 과 독립**: 배지는 조명표·하늘색을 읽지 않으므로 G-18-1(재질·하늘·방향광 색 분리)과 어떤 순서로 해도 충돌하지 않는다. 장면(조명)과 배지의 단계 대응은 `lightingOf(phase)` 한 함수로 맞춘다 — 그림이 단계와 어긋나지 않게 하는 연결은 이것뿐이다.
