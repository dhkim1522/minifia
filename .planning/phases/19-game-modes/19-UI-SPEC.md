# Phase 19 — UI Design Contract (방장 전용 줄 · 판 종류 시트 · 참가자 판 종류 칩 · 기본 마피아 판의 화면)

> 새 화면은 없다. 기존 화면 네 곳을 고친다: **대기실(방장 줄 신설·방장 튜토리얼 줄 이동) · 판 종류 시트(신설) · 참가자 대기실의 판 종류 칩(신설) · 결과 화면(방장 줄·칩)**, 그리고 **기본 마피아 판에서 사라지는 것**(기록 단추·심부름 표시·흔적 표시)이다.
> 결정 0051(글 최소·보고 누르기·3초 규칙)이 먼저다. 이 페이즈가 새로 보이는 글은 판 이름 두 개와 한 줄 설명 두 개, 시트 제목 하나뿐이고 나머지는 아이콘이다. 방장 단추에는 보이는 글이 없다(접근성 이름만).
> 기준: ROADMAP Phase 19 성공 기준 **1·3·6**(성공 기준 1 은 19-CONTEXT D-05 에 맞춰 "[시작] 때 서버로 간다"가 아니라 "고르면 방 상태에 저장되어 모두에게 방송된다"로 읽는다). 17·18·18.1 의 UI-SPEC(포커스 테두리·사회자 띠·시간대·유령·결과 탭)은 **그대로 이긴다**. 이 문서가 바꾸는 것은 아래 A~F 가 적은 것뿐이다.
> 범위 밖: 정치 장치("정통 판") 켜기, 판 종류별 튜토리얼, 실내 방·집(20), 등불·집 찾기(21), 햅틱·진동(앱 전환 때), 작은 폰 가장자리 잘림처럼 진행에 지장 없는 문제(07-UI-SPEC UI Considerations 20 그대로).
> 사람을 부르는 말은 **'참가자'** 다('손님' 금지 — 이 문서에서 새로 만드는 글과 접근성 이름 모두).

**쓰지 않는 참고 자료**: 시안 B(`RailLabel`)·C(`Drawer`). 이유: B 는 글이 늘고(0051), C 는 한 번 더 눌러야 한다.

시안과 다르게 한 곳(아래 '기본값 기록' 표가 이유를 적는다): 단추 지름 48 → **52**(P19-1), 시트 글자 크기 18·17 → **24·16**(P19-7), 맵 단추 아이콘 핀 → **현재 맵 아이콘 유지**(P19-4), 칩 세로 자리·카드 안 간격 같은 4의 배수 맞춤(P19-11·P19-7). 그 밖의 치수·색·아이콘은 시안 그대로다. 방향은 한 줄이다: **방장 전용은 금빛 테두리 단추로 왼쪽에 모으고, 참가자 공용은 오른쪽에 그대로 두며, 글은 늘리지 않는다.**

## Spacing Scale

6~18.1 과 같은 토큰. **새 값 없음**(아래 예외는 모두 기존 값의 재사용).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 칩 안 간격 |
| sm | 8px | 칩 안 아이콘↔글 간격, 시트 칸 안 간격, 칩 세로 보정 |

Exceptions(모두 4의 배수, 1px·1.5px·2px 선은 간격이 아님):

- 52 — 방장 줄 단추 지름(`--control-button`, 오른쪽 열과 같음, P19-1).
- 12 — 줄 안 칸 사이(오른쪽 열 `SIDE_GAP` 과 같음), 두 번째 열 간격, 시트 두 칸 사이, 칩 좌우 안쪽, 시트 칸 안쪽 좌우.

- 32 — 참가자 칩 높이. 누르는 것이 아니라 `--tap-min` 44 요건 밖이다(읽기 전용).
- 40 — 시트 칸 아이콘 한 변. 칸 안쪽 위아래 16.
- 48 — 테스트 방에서 줄이 평소보다 내려가는 양. [테스트]는 띠 아래 + 8 에서 시작하고 높이 44 라 아랫변은 띠 아래 + 52, 거기에 간격 8 을 더하면 줄 위 시작은 띠 아래 + 60 이다. 평소(띠 아래 + 12)보다 **+48**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `night-950`·`night-900`·`night-800` | 화면 바탕, 시트 면 `night-900`(기존 시트), 시트 칸 바탕 `night-800`, 칩 바탕 `night-900` |
| Secondary (30%) | `night-700`·`night-600`, `gray-300`·`gray-100`·`gray-50` | 방장 줄 단추 바탕 `night-700`, 시트 칸 테두리 `night-600`, 고른 칸 바탕 `night-700`·테두리 2px `gray-100`, 칩 테두리 1px `night-600`, 칸 설명 `gray-300` |

Accent reserved for: ① **방장 줄 단추의 테두리(1.5px)와 아이콘**(방장 전용을 나타내는 유일한 색, P19-0) ② **방장 줄 왕관 표식** ③ **[튜토리얼 먼저]가 켜졌을 때의 금빛 채움**(아이콘은 `night-900`) ④ **방장 줄 단추의 포커스 테두리·시트가 열렸을 때의 안쪽 2px 링**(`box-shadow: inset 0 0 0 2px var(--light-lamp)`) ⑤ 기존: 17 의 포커스 테두리·`.is-call` 램프 깜빡임(사회자가 부르는 대상, 그대로).

방장 줄 단추는 **깜빡이지도 번지지도 않는다** — `.is-call` 은 줄 단추에 걸리지 않는다(`callTargetsOf` 의 대상은 [시작]뿐, 이 페이즈에서 바뀌지 않음). 정지한 금빛 테두리(방장 전용)와 깜빡이는 금빛 테두리(지금 누를 것)를 구별하는 것은 **움직임**이다. 이 한 줄이 둘의 약속이다. 참가자 공용 단추(오른쪽 열)는 기존 그대로 `night-600` 테두리·`gray-100` 아이콘. 진홍·놋쇠는 쓰지 않는다. 채도는 시안 그대로 낮게 유지한다(밝은 노랑을 따로 만들지 않는다).

## A. 방장 줄 — 대기실 왼쪽 세로 줄 — 성공 기준 6

대기실에서 **방장에게만** 그린다(참가자에게는 마크업이 없다 — 숨김이 아니라 미렌더). 오른쪽 열(`SideColumn`)과 좌우로 나뉜다.

1. **자리**: 왼쪽 16(`--space-md`), 위 = `calc(var(--mf-host-bottom, 62px) + 12px)` — 오른쪽 열(`.mv-side`)과 **같은 식**이라 두 줄의 첫 칸 윗변이 같다. `position: absolute`·`z-index: var(--z-overlay)`(오른쪽 열과 같은 층). 컨테이너는 눌림을 통과시키고 단추만 받는다(`pointer-events`). 가상 뷰포트 이동(`--mf-vv-top`)에 따라 내려오는 규칙과 시트가 열려 있을 때 숨는 규칙(`.mf-room:has([data-sheet-layer])`)은 `.mv-side` 와 같은 줄에 묶는다.
2. **순서(위 → 아래)**: ① [판 종류] ② [맵](허용 맵이 둘 이상일 때, `PLAYABLE_MAPS.length > 1`) ③ [봇](`view.me.testBots !== undefined`, 결정 0075) ④ [튜토리얼 먼저](판 종류가 확장판일 때만, D-10). 기본 마피아를 고르면 ④ 만 사라지고 ①~③ 의 자리는 움직이지 않는다(맨 아래라서).
3. **단추**: 지름 52 원(`--control-button`), 칸 사이 12, 테두리 **1.5px `--light-lamp`**, 바탕 `--night-700`, 아이콘 24 `--light-lamp`. 모양은 `FloatAction`(`.mv-float`)을 따르되 색만 방장 전용이다.
4. **상태**:
   - 기본: 위 값.
   - 시트가 열려 있음(눌림): `aria-pressed="true"` + 안쪽 2px 금빛 링(Color ④). [판 종류]·[봇]·[맵](꾸미기 시트 [맵] 탭이 열려 있을 때).
   - 켜짐(토글 [튜토리얼 먼저]): `role="switch"` `aria-checked="true"`, 바탕 `--light-lamp`·아이콘 `--night-900`·테두리 `--light-lamp`. 꺼짐은 기본 모양과 같다(`aria-checked="false"`).
   - 사용 불가(`!canSend`, 또는 [시작] 잠금 2초 동안의 튜토리얼 토글): `aria-disabled="true"`·불투명도 0.45·눌러도 아무 일 없음(기존 `FloatAction` 규칙).
   - 포커스: `outline: 2px solid var(--light-lamp)`·`outline-offset: 2px`.
   - 누름: `:active` 에서 `transform: scale(0.94)` 하나뿐. mousedown 의 기본 동작을 막아 채팅 입력칸의 포커스(키보드)를 뺏지 않는다.
5. **왕관 표식**(P19-2): 폭 52·높이 20 칸에 아이콘 `crown` 20, 색 `--light-lamp`, `role="img"`·`aria-label="방장 전용"`. 첫 칸 위에 놓고 아래 간격 12. 눌리지 않는다. 그려지지 않을 때는 줄 컨테이너가 `role="group"`·`aria-label="방장 전용"` 을 가진다(왕관이 있을 때도 컨테이너 이름은 같다).
6. **[판 종류] 단추**: 아이콘 `deck`(P19-14), 접근성 이름 "판 종류: 확장판" / "판 종류: 기본 마피아"(지금 값). 누르면 `ModeSheet`(B 절)를 연다. 입력칸이 포커스를 갖고 있었으면 먼저 blur 한다(`DressSheet` 열 때와 같다).
7. **[맵] 단추**: 기존 `MapChip`(아이콘 = 지금 맵, 접근성 이름 `MAP_CHIP_NAME`). 누르면 `openDress("map")`. 보이는 조건·동작은 그대로(P19-4).
8. **[봇] 단추**: 기존 [봇] 시트(`BotSheet`)를 연다. 아이콘 `bot`, 접근성 이름 "봇". 눌림 상태는 시트가 열려 있는 동안.
9. **[튜토리얼 먼저] 토글**: 아이콘 `book`, 접근성 이름 "튜토리얼 먼저", 값은 화면 로컬 상태(서버에 방송하지 않음, 17-07 그대로)이며 [시작] 순간 `start` 메시지로 간다. 초기값은 첫 판 켜짐·다시 하기(2판째)·테스트 방 꺼짐(기존 규칙 그대로). **판 종류가 기본 마피아면 줄에서 사라지고 [시작]은 `tutorial: false` 를 보낸다**(D-10, 사라져 있어도 값은 유지돼 확장판으로 돌아오면 이전 값). 누르면 TopToast 한 줄(P19-8).
10. **기록 칸 위 튜토리얼 한 줄(`.tut-toggle` 행)은 그리지 않는다**(P19-12). 패널은 위에서부터 기록 칸 + 입력줄 + 행동 줄뿐이다.
11. **[시작] 단추**: 자리·모양·크기·빛남 불변(D-17). 방장 줄에 넣지 않는다.
12. **오른쪽 열**: 방장도 [소리](독의 첫 칸) · [옷장] 둘이다. 참가자와 같다. 방장 전용 단추가 하나도 남지 않는다.

## B. 판 종류 시트 — 두 칸 선택

`Sheet`(아래에서 올라오는 네이티브 `<dialog>` 시트) 안. 기존 `BotSheet` 와 같은 틀이다: `<Sheet label="판 종류" showClose onClose className="mf-mode-sheet">`, 제목 `<h2 className="mf-t-heading mf-sheet__title">판 종류</h2>`.

1. **격자**: 두 칸, `grid-template-columns: repeat(2, minmax(0, 1fr))`, 칸 사이 12. 칸은 `button`(`aria-pressed`), 안쪽 위아래 16·좌우 12, 모서리 `--radius-md`(14), 테두리 1px `--night-600`, 바탕 `--night-800`, 안에 위에서부터 세로 가운데 맞춤: 아이콘 40(`modeBasic`·`modeExtended`, `currentColor` = `--gray-100`) → 이름 16/700 → 한 줄 설명 14/400 `--gray-300`(최대 2줄), 간격 8. 두 칸 높이는 같게 늘어난다.
2. **고른 칸**: 테두리 2px `--gray-100`, 바탕 `--night-700`, 오른쪽 위(8, 8)에 지름 24 원(바탕 `--gray-100`)과 그 안의 `check` 아이콘 18(색 `--night-900`, 선 2.4). 시안 그대로 — 금빛이 아니다(P19-15). 같은 칸 안에서 이름·설명 색은 그대로(`--gray-50` 이름만 허용).
3. **칸**: ① "기본 마피아" — 한 줄 설명 "토론하고 투표해요" ② "확장판" — "증거를 찾아 추리해요". 순서와 두 칸 나란히는 고정, 기본 선택은 확장판(D-01).
4. **동작**: 칸을 누르면 `canSend` 일 때만 `send({ t: "modePick", mode })`(D-05) 를 보내고 시트는 열어 둔다. 고른 표시(`aria-pressed`·테두리·V 배지)는 서버가 방송한 `view.mode` 에서만 나온다(낙관 갱신 없음, P19-6). 이미 고른 칸을 누르면 아무것도 보내지 않는다. 방장이 아니거나 판이 진행 중이라 서버가 거절하면 오류 문구 없이 최신 state 한 프레임이 와서 표시가 되돌아온다. 시트는 대기실·결과 단계에서만 열린다(게임 중에는 단추가 없다).
5. **닫기**: 기존 `Sheet` 의 [닫기] 44×44·끌어 내리기·배경·Esc. 시트가 닫히면 초점은 [판 종류] 단추로 돌아간다(`DressSheet` 의 복원 규칙).
6. **연결 끊김**(`!canSend`): 두 칸이 `aria-disabled="true"`·불투명도 0.45, 눌러도 아무 일 없고, [닫기]는 동작한다(재접속 띠가 덮는다).
7. **참가자에게는 열리지 않는다**(방장 줄이 없고 칩은 누를 수 없다, D-07).

## C. 참가자 대기실의 판 종류 칩 — 읽기 전용

1. **자리**: 왼쪽 16, 위 = 방장 줄 위 시작 높이 + 8(P19-11) — 곧 `calc(var(--mf-host-bottom, 62px) + 20px)`. 높이 32, 알약(`--radius-pill`), 테두리 1px `--night-600`, 바탕 `--night-900`, 글자 14/400 `--gray-100`, 안쪽 좌우 12, 아이콘 `deck` 16 + 글 사이 8. 폭은 글에 맞춘다(약 80~116). 오른쪽 열과 같은 층(`--z-overlay`)·같은 숨김 규칙.
2. **내용**: 지금 `view.mode` 의 이름 — "확장판" 또는 "기본 마피아". 접근성 이름 "판 종류: 확장판" / "판 종류: 기본 마피아"(`role="status"` 아님 — 읽기 전용 정적 텍스트, `aria-live` 없음. 바뀜은 TopToast 가 알린다, P19-9).
3. **누를 수 없다**: `button` 이 아니고 포커스를 받지 않으며 눌림을 통과시킨다. 방장 줄이 없는 참가자의 왼쪽 위에 이 칩 하나뿐이다.
4. **방장에게는 그리지 않는다**(방장 줄의 [판 종류]가 같은 정보를 준다). 방장이 바뀌어 참가자가 방장이 되면 칩 대신 줄이 나타난다(서버 view 의 `isHost` 로만 판정).
5. 결과 화면의 참가자도 같은 칩(P19-10).

## D. 결과 화면 — 방장 줄 같은 규칙 — 성공 기준 6

결과 화면의 오른쪽 열은 연출이 끝난 뒤(5600ms)에 나오고(결정 0083-7), 방장 줄과 칩도 **같은 때** 나온다(`finished && !expanded && !dressOpen`, 키보드가 열려 있으면 그리지 않는다, P19-16).

1. **방장**: 왼쪽 줄 ① [판 종류] ② [맵](허용 맵이 둘 이상일 때). [봇]·[튜토리얼 먼저]는 없다(대기실 전용). 단추 모양·치수·색·간격·위 시작 식은 A 절과 같다. 오른쪽 열은 [소리] · [옷장].
2. **참가자**: 왼쪽 위 읽기 전용 칩(C 절).
3. **다시 하기**: 판 종류를 바꾸지 않고 [다시 하기]를 시작하면 지금 값으로 시작한다(D-06). 바꾸면 다음 판부터 그 판 종류다. 준비 상태는 유지한다(P19-13). [다시 하기] 알약·방장 [시작]의 자리·모양은 바꾸지 않는다.
4. 결과 화면 `[맵]` 단추는 오른쪽 열을 떠나 왼쪽 줄 두 번째 칸이 된다(대기실과 같은 `MapChip` 줄 변형).

## E. 기본 마피아 판에서 사라지는 것 — 성공 기준 3

기본 마피아(`view.mode === "basic"`)에서는 **서버가 관련 키를 싣지 않는다**(D-08, 값이 비어 있는 것이 아니라 키가 없다). 화면은 "키가 없으면 그리지 않는다"는 기존 경로로 비워지고, 아래 표는 그 결과로 **DOM 에 아예 없어야 하는 것**이다(숨김이 아니라 미렌더, 확장판 판에서는 지금 그대로 나온다).

### E-1. 사라지는 화면 요소

| 요소 | 확장판에서 | 기본 마피아에서 | 판정 근거(키·조건) |
|------|-----------|----------------|--------------------|
| [기록] 머리 단추(목격 기록, 아이콘 `timeline`) | 토론 단계에서 `me.record` 가 있으면 보임 | **없음**(머리는 제목 + [내 역할] + 시간대 낱말뿐) | `view.me.record` 키 없음(`witnessRows === null`) |
| 목격 기록 카드(`RecordCard`) | [기록]을 누르면 열림 | **없음** | 위와 같음 |
| 심부름 단계·"오늘 갈 곳" 시작 카드·장소 타일·화살표·[처리]·진행 점 | 낮 시작 뒤 심부름 단계 | **없음** — 낮 발표 뒤 바로 토론(D-08) | `phase === "errand"` 에 들어가지 않음 |

| 토론 중 증거 카드(두 줄: 같은 옷·마지막 목격) | 흔적이 있는 날 | **없음** | `day.evidence` 키 없음 |

### E-2. 사라지지 않는 것(확인)

역할 확인 카드·낮 토론·지목·변론·찬반·처형 연출·밤 얼굴 고르기·아침 발표(누가 죽었는지)·유언·결과 화면·채팅·[내 역할]·시간대 낱말(18.1·0083-1)은 두 판 모두 같다. 기본 마피아의 아침은 "누가 없어졌는지" 큰 글만 있고 흔적 구간·증거 카드가 없는 것뿐이다. 하단 패널은 심부름 단계가 없어 `noPanel`(아래 패널 없는 단계)이 생기지 않으므로 스테이지 사각형이 낮 내내 같은 아래 끝을 쓴다.

### E-3. 자막 띠 문구(사회자 줄) — 변경 없음(P19-17)

기본 마피아에서 닿는 문구는 모두 심부름·증거를 말하지 않는다. 시험으로 고정한다:

| 키 | 문구 | 기본 마피아 |
|----|------|-------------|
| `dayAnnounce.wait` | 모두 모여 주세요 | 도달(변경 없음) |
| `discussion.act` | 의심 가는 사람을 이야기해 주세요 | 도달(변경 없음) |
| `errand.act`·`errand.done`·`errand.ghost`("빛나는 곳을 찾아 처리해 주세요" 등) | 심부름 문구 | **도달하지 않음** |
| `witness`("기록 단추로 본 것을 확인해 주세요") | 목격 기록 안내 | **도달하지 않음**(`me.record` 없음) |
| `discussion.evidence`("같은 옷과 엇갈린 목격을 살펴보세요") | 증거 안내 | **도달하지 않음**(`day.evidence.trace` 없음) |

기본 마피아 판에서 어느 단계에서도 위 세 군("도달하지 않음")의 문구가 `[data-host-line]` 에 나오지 않는 것을 E2E 한 판에서 확인한다(E 절 검증 표의 BM3). `hostLineOf` 의 새 분기는 만들지 않는다.

### E-4. 튜토리얼(D-10)

방장 줄의 [튜토리얼 먼저]는 기본 마피아에서 사라진다(A-9). 서버도 `basic` + `tutorial: true` 를 튜토리얼 없이 처리한다. **첫 화면의 혼자 하기 튜토리얼은 그대로**다(확장판을 가르친다).

### E-5. 봇·유령·누설

봇은 방의 판 규칙을 따라 기본 마피아에서 심부름 행동을 하지 않는다(D-11, 화면 변화 없음). 유령 화면(탈락자)에서도 기본 마피아에는 심부름·증거 요소가 없다. 판 종류 값은 역할과 무관한 공개 값이라 모든 참가자에게 같다(D-12). 새 DOM 표식은 enum 값(`basic|extended`)과 단추 이름뿐이고 좌석·역할 값이 없다.

## F. 폰 6종 — 방장 줄이 스테이지·패널과 겹치지 않는 규칙

방장 줄은 스테이지 위에 **떠 있는 오버레이**다(오른쪽 열과 같은 방식, 스테이지 사각형의 위·아래 끝을 바꾸지 않는다). 겹침 규칙은 오른쪽 열과 같은 식으로, 줄의 높이는 `sideMaxH`(= 방 높이 − 아래 패널 − 8 − (띠 아랫변 + 12))를 쓴다.

### F-1. 겹치지 않아야 하는 것(전부 교차 0)

| 대상 | 규칙 |
|------|------|
| 아래 패널 | 줄의 아랫변 ≤ 패널 윗변 − 8. 줄이 길면 F-2 로 줄인다 |
| 머리 단추·자막 띠·소리 독 | 줄의 윗변 ≥ 띠 아랫변 + 12(`--mf-host-bottom + 12`). 소리 독은 오른쪽이라 가로로 겹치지 않는다 |
| 위 알림(TopToast, 가운데) | 가로로 겹치지 않는다(줄 16~68, 알림 가운데). 폭 360 에서 알림이 왼쪽으로 길어져도 줄 바로 위(띠 아래 12)로는 오지 않는다 |
| `[테스트]` | 테스트 방이면 줄(과 칩)은 `[테스트]` 아랫변 + 8 에서 시작한다(P19-5: 평소 + 48). 줄의 최대 높이도 48 만큼 줄여 계산한다 |
| 오른쪽 열(소리·옷장) | 줄의 오른쪽 끝과 오른쪽 열의 왼쪽 끝 사이 ≥ 16(폭 360 한 열 기준 줄 68 ↔ 열 292, 두 열 접힘 기준 132 ↔ 228) |
| 재접속 띠·꾸미기 시트·확인 시트 | 뜨는 동안 줄 위로 올라오지 않는다 — 방 루트의 시트 층(`data-sheet-layer`)이 열리면 줄도 숨는다(오른쪽 열과 같은 CSS 줄) |
| 키보드 열림 | **줄·칩을 그리지 않는다**(`kbOpen`, P19-16). 패널이 키보드 위로 올라오고 행동 줄이 숨는 기존 규칙 그대로 |

스테이지 위의 캐릭터·이름표와 줄이 겹치는 것은 오른쪽 열과 같은 정책이다(스테이지는 화면 전체 캔버스이고 줄은 그 위의 오버레이). 이름표 끝이 줄에 가려지는 것은 진행에 지장이 없으면 고치지 않는다(알려진 한계 정책 그대로, 참고 줄로만 남긴다).

### F-2. 줄 높이와 접기 규칙

n = 줄 안 단추 수(방장 대기실: 확장판 4 / 기본 마피아 3, 테스트 방·맵 하나뿐인 빌드면 그만큼 줄, 결과: 2). 줄 높이 = 52 n + 12 (n − 1), 표식을 더하면 + 32(= 20 + 12).

1. `n·52 + (n−1)·12 + 32 ≤ 줄 최대 높이` → **한 열 + 왕관 표식**.
2. 아니면 `n·52 + (n−1)·12 ≤ 줄 최대 높이` → **한 열, 표식 없음**.
3. 아니면 `splitSideColumn(n, 줄 최대 높이)` 로 나눈 **두 열**(한 열 최소 2칸, 표식 없음). 두 번째 열은 첫 열의 **오른쪽 12** 옆.

줄 최대 높이는 기존 `sideMaxH`(테스트 방은 −48)를 그대로 읽는다 — 새 측정은 만들지 않는다. 아래는 **계산한 기대값**이다. 값의 출처: 방장 패널 222(P19-12), 띠 아랫변 B = 한 줄 123 / 두 줄 144(`docs/screen-map.md` 16페이즈 절, 대기실 문장 폭 360 기준 최악 144 사용), 줄 최대 높이 ≈ 방 높이 − 222 − 8 − (B + 12). 폭이 넓은 폰은 띠가 한 줄이라 B 가 작아 같거나 더 넉넉하다. **계획 단계가 폰 6종 실측으로 확정한다**(UI Considerations 의 backstop).

| 폰 | 줄 최대 높이(B 144 / 123) | n = 4 확장판 | n = 3 기본 마피아 |
|----|---------------------------|---------------|--------------------|
| 360×560 | 174 / 195 | 두 열([2,2] / [3,1]), 표식 없음 | B 144: 두 열([2,1]), B 123: 한 열, 표식 없음 |
| 360×640 | 254 / 275 | 한 열, 표식 없음(표식까지 276) | 한 열 + 표식(212) |
| 390×664 | 278 / 299 | 한 열 + 표식(276, 2px 여유 — 띠가 더 높으면 표식이 빠지는 것이 정상) | 한 열 + 표식 |
| 390×844 | 458 / 479 | 한 열 + 표식 | 한 열 + 표식 |
| 402×874 | 488 / 509 | 한 열 + 표식 | 한 열 + 표식 |
| 430×932 | 546 / 567 | 한 열 + 표식 | 한 열 + 표식 |

폰 6종 모두에서 줄은 아래 패널(222)과 교차 0이고, 360×560 은 줄이 두 열로 접혀도 오른쪽 열(소리·옷장은 한 열, 폭 52 + 16 → x 292~344)과 가로로 160 떨어진다. 오른쪽 열이 방장도 둘뿐이 되어 지금 360×560 방장 대기실의 오른쪽 열 접힘(알려진 한계)은 **없어진다.** 방장 패널이 54 줄어 스테이지 사각형은 다시 참가자 값이 된다(예: 390×844 에서 506 → 560, 360×560 에서 222 → 276).

결과 화면(n = 2)은 줄 148(표식 포함) 이라 폰 6종 모두 한 열 + 표식이 기대값이다(결과 화면의 `sideMaxH` 를 기존대로 읽음).

### F-3. 화면 영역 표 갱신(계획 단계가 `docs/screen-map.md` 에 반영)

- "오른쪽 열" 행: 방장 = 소리 · 옷장, 참가자와 같다(`data-side-button` 값은 sound·dress 둘). `sideColumnChecks`(SC)의 "방장 넷" 기대를 "방장 둘"로 바꾼다.
- 새 행 "왼쪽 방장 줄 / 참가자 칩": 왼쪽 16·위 = `--mf-host-bottom + 12`(칩은 +20)·지름 52·간격 12·테스트 방 +48·접기 규칙(F-2).
- "방장 아래 패널" 절: 튜토리얼 줄 +54 삭제, 방장 패널 = 참가자 패널(222 / 키보드 열림 146).
- 알려진 한계 "360×560 방장 대기실 열이 둘로 접힌다"는 오른쪽 열에서 **왼쪽 줄**로 옮겨 적는다(줄이 접힌다, 진행에 지장 없음).
