# Phase 22 — UI Design Contract (판 하나로 · 낮 투표 개편 · 유언 통일 · 유령 수정)

> 이 페이즈는 **새 화면을 만들지 않는다.** 지우는 화면의 목록(그리지 않아야 할 것)과, 낮 흐름이 **토론 → 찬반 → 차례 지목 → 유언 → 처형 → 밤** 으로 바뀌면서 기존 부품이 놓이는 자리·문구·시간을 정한다. 시안은 24(포스트잇·튜토리얼)·23(키워드 카드) 몫이다.
> 결정 0051(글 최소·보고 누르기)이 먼저다: 정보는 **장면 · 아이콘 · 숫자**로, 글은 단계 이름과 한 줄 이하(3초 규칙), 행동은 **대상(이름표·찬반 두 단추)을 직접 누르는 것**이다. 이 페이즈가 새로 만드는 단추는 **[남기기]** 한 낱말뿐이고 그것도 기존 [저장] 자리의 글만 바꾼 것이다.
> 6~21 의 UI-SPEC(영역 배치·빛남 규칙·이름표·카메라·단계 조명)은 **그대로 이긴다.** 이 문서가 바꾸는 것은 아래가 적은 것뿐이고 이유는 '기본값 기록'에 적었다. 숫자의 원천은 코드(`useMapInsets`·`chatUi.ts`·`phases.ts`·`tokens.css`)이고 이 문서의 숫자는 360×560~430×932 에서 대조한 값이다.
> 사람을 부르는 말은 **'참가자'**(새 글·접근성 이름·시험 이름에 '손님' 금지). 낮도 마피아 분위기(낮은 명도·채도), 깔끔 담백, 말투는 해요체(기존 문구 표와 같음).
> 범위 밖: 키워드 카드·답 공개·D1 기록(23), 의심 포스트잇·새 튜토리얼(24), 서버 규칙·와이어(D-01~D-21 이 맡는다 — 이 문서는 화면에 닿는 결과만 적는다), 햅틱, 진행에 지장 없는 작은 화면 가장자리 문제(07-UI-SPEC UI Considerations 20 그대로 — 고치지 않는다).

## 출처와 참고 자료 (design-refs)

`gsd-addons:design-refs` 스킬을 불러와 따랐다. 이 페이즈에는 사용자가 준 참고 이미지·에셋 경로가 없다(`22-CONTEXT.md`·`docs/decisions/0089-…md` 에 "참고 자료" 항목 없음). 그래서 새 장식 스타일을 만들지 않고 이미 승인된 부품과 토큰만 쓴다. 방향 한 줄: **기존 낮 화면(찬반 두 단추·차례 알약·인용 카드·유언 시트·처형 핀)을 순서만 바꿔 다시 놓고, 빼는 것으로 더 담백하게 만든다.** `design/references/` 의 캐릭터·배경 참고(`notes.md`)는 이 페이즈 화면과 무관해 열지 않았다. **열지 못한 참고 자료: 없음**(필요한 경로는 모두 읽음).

### E. 유언 — 나머지 사람 화면 (D-16)

처형자 스포트라이트를 본다. 채팅 입력은 비활성(P22-9)이고 기록 칸은 읽기만 된다. 띠에 `defense.wait`(산 사람) / `defense.ghost`(유령). 10초 막대·헤더 링은 기존 단계 시간 표시 그대로. 걸을 수 없다(기존 막힘).

### F. 처형 (D-15·D-14, P22-11~14)

| 시각(처형 단계 시작 기준) | 화면 |
|----------------------------|------|
| 0~3.0초 | 유언 카드(`QuoteCard`, P22-11) — 글 또는 "말없이 떠났어요". 핀·콘 유지, 판결 줌 시작. 띠는 빈 줄 |

## 영역 배치 — 폰 폭 360~430 (유언 화면과 키보드)

원칙: **새 요소는 14·21 이 정한 안전선 밖에만 놓는다.** 위 안전선 = 띠 아랫변 `B`(한 줄 123 / 두 줄 144, 360×560 기준), 독 줄 아랫변 `D = B + 52`(175 / 196). 값은 코드(`useMapInsets`·CSS 변수)가 원천이다. 스테이지 높이 = 방 높이 − `B` − 아래 패널(또는 시트) 높이(키보드 열림은 − 키보드 올림 `K`, iPhone 기준 336).

**쓰지 않는 문구**: "투표"(지목 단계 제목은 "지목"), "최후 변론"·"변론"·"해명", "범인"·"마피아가 …", 누가 누구를 골랐는지 요약하는 문장("A 님이 … 에게 투표"), 찬반 기록·표 공개 문구, "시상"·상 이름, "확장판"·"판 종류"·"튜토리얼 먼저", 설명 문단, 이모지.

접근성 이름: 찬성 단추 "찬성"(`aria-pressed`), 숫자 줄 `role="status"` "찬성 n표, 반대 m표", 지목 이름표 "{닉네임} 님 가리키기"(기존), 시트 `role="dialog"` "유언", [남기기] "유언 남기기", 유언 카드 `role="status"`, 처형자 남은 초 `aria-hidden`(막대·헤더가 읽음).

## 접근성 · 모션 · 입력

- 누르기 영역 44 이상(이름표 44, 찬반 84, [남기기] 높이 48, 시트 [닫기] 높이 44, [유언] 44). 포커스 링 `gray-100` 2px. Tab 순서: 헤더 [내 역할] → 소리 → (스테이지의 이름표) → 아래 패널 단추. 시트가 열리면 시트 안(글칸 → [닫기] → [남기기])이 먼저이고 시트 밖은 `aria-hidden` 이 아니라 시트가 위에 덮는다.
- 진행·상태는 색만으로 알리지 않는다: 고른 찬반 = 면 채움 + `aria-pressed`, [남기기] 후 = "남김" 글 + 비활성, 내 차례 = 알약 글 + 빛남.
- `prefers-reduced-motion`: 빛남은 정지한 테두리 + 중간 번짐, 인용 카드 등장·사라짐·핀 slide·줌은 즉시, 찬반 숫자는 원래 애니메이션 없음.
- 깜빡임은 기존 1Hz 미만 규칙. 한 화면에서 동시에 빛나는 대상은 같은 종류뿐이다.
- 버튼 `mousedown` 기본 동작을 막아 입력칸 포커스·키보드를 유지(기존 `WillSheet`·`VerdictPicker` 규칙).
- 폭 360 가장자리 8자 닉네임 이름표 잘림·360×560 찬반 투표자 스테이지 부족은 알려진 한계로 둔다(손보지 않는다).
