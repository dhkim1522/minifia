# Phase 23 — UI Design Contract (첫날 키워드 문제 · 모두의 답 · 정답 공개 · 일찍 넘어가기)

> 이 페이즈의 새 화면은 셋이다. **① 키워드 화면**(`keyword` 단계, 가운데 카드 + 아래 입력줄), **② 모두의 답**(토론 시작 때 자동으로 열리는 기록 카드 = 역할 카드 시트의 새 "첫날 답" 탭), **③ 정답 공개**(`answerReveal` 단계 3초의 큰 글). 나머지는 기존 부품·토큰을 그대로 쓴다. 일찍 넘어가기(0089-26)는 **새 단추·새 글자가 없고** 타이머 막대가 마감 단축을 어떻게 보이는지만 정한다.
> 결정 0051(글 최소·보고 누르기)이 먼저다: 정보는 **장면·카드·숫자**로 먼저 보이고, 읽을 글은 단계 이름과 한 줄 이하(3초 규칙)다. 이 페이즈가 새로 만드는 **글 단추는 없다**(입력줄의 [보내기]는 기존 채팅과 같은 아이콘 단추).
> 6~22 의 UI-SPEC(영역 배치·빛남·이름표·카메라·단계 조명)은 **그대로 이긴다.** 숫자의 원천은 코드(`useMapInsets`·`useHostMetrics`·`phases.ts`·`tokens.css`)이고 이 문서의 숫자는 360×560~430×932 에서 대조한 값이다(띠 아랫변 `B` = 한 줄 123, 독 아랫변 `D = B + 52` = 175, 22-UI-SPEC 과 같은 기준).
> 사람을 부르는 말은 **'참가자'**(새 글·접근성 이름·시험 이름에 '손님' 금지). 낮도 마피아 분위기(낮은 명도·채도), 깔끔 담백, 문구는 해요체(22 문구 표와 같음). 사용자가 정한 카드 글(`장르 : 영화`, `???`, `* 직접적인 키워드는 언급하면 안 됩니다.`)은 그대로 쓴다.
> 범위 밖: 키워드 목록·판정·서버 규칙·와이어(D-05~D-13 이 맡는다 — 이 문서는 화면에 닿는 결과만 적는다), D1 기록(화면 없음), 의심 포스트잇·새 튜토리얼(24), 햅틱, 진행에 지장 없는 작은 화면 가장자리 문제(07-UI-SPEC UI Considerations 20 그대로 — 고치지 않는다).

## 출처와 참고 자료 (design-refs)

### B. 키워드 화면 (P23-1~15)

층(아래 → 위): 3D 무대(`aria-hidden`, 이름표 `visibility: hidden`) → 어두운 막(`--scrim`, 기존 `.mf-reveal__dim`) → 머리(제목 "키워드" + [내 역할], 기존 `.mf-reveal__header`) → 띠(기존 `HostBand`) → 스테이지(카드) → 입력줄.

| 영역 | 위치 · 모양 | 규칙 |
|------|-------------|------|
| 카드 영역 | 스테이지(`flex: 1`, 윗변 = `--mf-host-dock + 8`, 아랫변 = 입력줄 윗변), 카드는 그 안 **세로 가운데**(키보드 닫힘) | 카드 높이: 각주 1줄 138 / 2줄 158, 키워드 2줄이면 +43 → 최악 **201**. 영역 높이 = 방 높이 − 281(아래 표)이라 모든 폰에서 들어간다 |

## 사회자 문구 표 (`hostLine.ts` 의 표를 이어 씀 — 해요체, 마침표 없음, 공백 포함 19자 이하)

읽는 값은 기존 허용 목록 + 공개 값 `day.keyword`(장르·정답 유무)와 **내 제출 여부**(내 view 의 `me` 값)뿐이다. **역할(`me.role`)을 읽는 곳은 지금처럼 밤 역할별 줄뿐이다** — 새 줄은 모두 역할과 무관하다(마피아가 키워드를 못 보는 것은 카드 글 한 곳이고 띠 문구는 같다).

| 단계 | 키 | 문구 | 비고 |
|------|----|------|------|
| `keyword` | `keyword.act` | 떠오르는 말을 적어요 | 아직 안 냈다(11자) |
| `keyword` | `keyword.wait` | 곧 모두의 답이 나와요 | 냈다(11자) |
| `answerReveal` | `answerReveal` | (빈 줄) | 큰 글이 말함 — `blank` 모드 |
| `ended` | `ended.answer` | `정답 · {키워드}` | 정답 값이 있을 때만(동적, ≤ 19자). 시간 행 없음 → `show` 모드. 값이 없으면 지금처럼 숨김 |
| 그 밖 | 기존 | 기존 | `HostKey` 에 가입해야 하는 표를 모두 갱신(D-04 — `HOST_HIDDEN_PHASES`·`TIMELESS_PHASES` 등은 컴파일러가 못 잡는다) |

- `hostChimeOf`: 단계 바뀜마다 `ui.host` 한 번(기존). `roleReveal → keyword`·`keyword → dayAnnounce`·`execution → answerReveal → night` 모두 같은 규칙, 새 소리 신호 없음.
- 빛남 표(`callTargetsOf`): `keyword.act` — **입력칸**(`{kind:"tool", tool:"chat"}` 재사용, 읽기 3초가 지난 뒤부터 — 화면이 3초 잠금을 알고 있으므로 이 함수가 아니라 화면이 시각을 정한다), `keyword.wait` — 없음, `answerReveal` — 없음.
- `PHASE_ANNOUNCE`·`PHASE_SCENE`·`BED_OF`·`TEST_PHASE_LABEL`·`ENTER_SOUND`·`FIXED_PHASES`·`TICK_PHASES`(미가입 확인)·`lightingOf`(`answerReveal` → `vote`, `keyword` → 기본 `talk`)는 D-04 의 grep 목록으로 계획이 전부 확인한다.

## 영역 배치 — 폰 폭 360~430 (키워드 화면·키보드)

원칙: **새 요소는 14·21 이 정한 안전선 밖에만 놓는다.** 위 안전선 = 띠 아랫변 `B` = 123(한 줄), 독 아랫변 `D = B + 52` = 175. 값의 원천은 코드(`--mf-host-bottom`·`--mf-host-dock`)이고 이 표는 대조값이다.

### 키워드 화면 영역 높이(띠 한 줄 `B` = 123, `D` = 175)

| 폰 크기 | 카드 영역(닫힘) = 방 높이 − 98(입력줄) − (`D` + 8) | 카드(큰) 138~201 | 컴팩트 카드 윗변(열림, `K` 336) = 방 높이 − 336 − 84 − 4 − 72 | 머리 아랫변 62 와 |
|---------|--------------------------------|------------------|----------------------------|------------------|
| 360×560 | 279 | 들어감 | **64** | 겹침 없음(2 여유) |
| 360×640 | 359 | 들어감 | 144 | 겹침 없음 |
| 390×664 | 383 | 들어감 | 168 | 겹침 없음 |
| 390×844 | 563 | 들어감 | 348 | 겹침 없음 |
| 402×874 | 593 | 들어감 | 378 | 겹침 없음 |
| 430×932 | 651 | 들어감 | 436 | 겹침 없음 |

- **키보드 열림 + 높이 ≤ 664 폰**: 컴팩트 카드(`z`는 띠·독 위, `z-overlay` 이상)가 띠 아랫변(123)·소리 단추 줄(175)을 일부 덮는다 — 360×560 은 띠 전체(윗변 ≈ 70)와 소리 단추를, 360×640 은 소리 단추 줄 31px 를, 390×664 는 7px 를 덮는다. 시간은 입력줄 위 메타 줄의 "n초"(P23-7)가 한 번 더 보이므로 가려져도 읽을 수 있고, 띠 문장은 입력줄·카드가 말하는 것과 같아 잃는 정보가 없다. 소리 단추는 10초 동안 못 눌러도 진행에 지장 없다(알려진 한계). 높이 ≥ 844 폰은 덮지 않는다.
- 키보드가 자동으로 안 올라와도(iOS 는 사용자 누르기 없이 포커스가 키보드를 못 연다) 화면은 닫힘 상태로 읽힌다. 입력칸을 누르면 열림 상태로 바뀐다. 읽기 3초가 끝나 빛남이 켜졌을 때 입력칸을 직접 누르게 하는 신호다.
- 입력줄 폭 = 화면 − 32(좌우 16). 입력칸은 가로 `폭 − 8 − 48`(360 에서 272) — 20자(16px 한글 ≈ 320)는 칸 안에서 가로로 밀리며 스크롤된다(보이는 건 끝부분). "n/20"이 전체 길이를 말한다.
- 카드·입력줄은 폭 430 에서 부모를 따라 늘어난다(가운데 정렬, 최대 폭 제한 없음 — 22 와 같음).
- 모두의 답 시트는 기존 시트 위치(화면 아래, 최대 `min(420, 80dvh)`)다. 키보드가 열려 있는 채로 자동 열림이 일어나지 않는다(토론 시작에는 키보드가 닫혀 있다 — 키워드 입력줄이 언마운트되며 포커스가 사라짐).

## 접근성 · 모션 · 입력

- 누르기 영역 44 이상([보내기] 48, 시트 [닫기] 44, 탭 높이 44). 포커스 링 `gray-100` 2px. Tab 순서: 머리 [내 역할] → 소리 → 입력칸 → [보내기]. 키워드 카드는 포커스를 받지 않는다. 읽기 3초 동안 입력칸이 `disabled` 라 포커스가 건너뛴다.
- 진행·상태는 색만으로 알리지 않는다: 읽기 잠금 = 흐림 + 빛남 없음 / 쓰기 = 빛남 + 띠 문장, 제출 = `check` 아이콘 + "냈어요" + 읽기 전용, 거절 = 글 알림(색만이 아님), 번호 = 숫자(색 아님).
- `prefers-reduced-motion`: 입력칸 빛남은 정지한 테두리 + 중간 번짐(기존), 카드 등장·정답 공개 등장·시트 이동·막대 전환 즉시.
- 깜빡임은 기존 1Hz 미만 규칙. 한 화면에서 동시에 빛나는 대상은 입력칸 하나뿐이다.
- 버튼 `mousedown` 기본 동작을 막아 입력칸 포커스·키보드를 유지(기존 채팅·`WillSheet` 규칙). Enter = 제출(한글 조합 중이면 `compositionend` 를 기다린다 — `ChatPanel` 의 규칙·`IME_WAIT_MS`·`DUP_SUBMIT_MS` 를 재사용).
- 글자 입력에서 HTML·링크 변환·마크다운 없음. 서버가 같은 정리 함수로 한 번 더 자른다.

## 남은 위험 · 플래너 확인 목록

- **새 PhaseId 가입(D-04)**: `keyword`·`answerReveal` 을 `Record<PhaseId,…>`(컴파일러가 잡음)와 `Set`/배열(잡지 못함)에 모두 가입한다. 이 문서가 요구하는 가입: `PHASE_ANNOUNCE`·`TEST_PHASE_LABEL`·`BED_OF`·`PHASE_SCENE`·`ENTER_SOUND`·`FIXED_PHASES`(answerReveal)·`lightingOf`(answerReveal → `vote`)·`sceneKeyOf`(keyword → `preGame`, answerReveal → `gameMap`)·`hostKeyOf`·`HOST_LINES`·`TIMELESS_PHASES`(미가입 확인)·`TICK_PHASES`(미가입 확인)·`RoomScreen` 의 단계 분기.
- **내 초안·확정 여부를 본인 view 로 돌려받는 서버 계약(P23-13)**: 재접속에서 입력칸과 제출 상태가 복원되어야 한다. 서버 전용 키·누설 허용 경로 표(`SERVER_ONLY_KEYS`·`ALLOWED_WIRE_PATHS`)에 가입하고 마피아·시민의 모양이 같음을 시험한다(값만 다르다).
- **결과 화면 정답 줄(P23-22)**: `HOST_HIDDEN_PHASES` 의 `ended` 를 조건부로 바꾸므로 `hostBandModeOf` 시험·결과 화면 기하(`--mf-host-bottom` 불변, 방장 줄·칩 자리)를 다시 잰다. 정답 값을 `day.keyword.answer` 와 결과 중 어디서 읽는지(서버가 싣는 한 곳)는 한 선택기 `keywordAnswerOf(view)` 로 묶는다.
- **역할 카드 시트가 시민에게도 탭 줄을 갖는 변경(P23-16)**: `showBack`(역할 확인 단계에서 앞면을 못 본 사람)에는 탭을 만들지 않는다(기존 규칙). `journalRole` 분기·탭 키보드 이동(←/→/Home/End)·`recordsSeen` 점 규칙이 3칸에서도 맞는지 확인한다.
- **자동 열림의 `fresh` 판정(P23-17)**: 재접속·새로고침에서 열리지 않아야 하고 한 판 안에서 두 번 열리지 않아야 한다(상태는 `RoomScreen` 한 곳, 판이 다시 시작하면 초기화).
- **마감 단축 감지(P23-23)**: 이전 `phaseEndsAt` 를 단계 키(`phase`+`day.n`)와 함께 기억해 "작아짐"만 `data-early` 로 삼는다. 단계 전환·재접속 첫 프레임에서는 켜지 않는다. `useCountdown`·`HostTime` 외 다른 타이머(헤더 링·`HostBand`)도 같은 규칙을 쓰는지 grep 으로 확인한다.
- **조기 진행 서버 계약(D-11)과 화면 타이머**: `phaseDurationMs` 가 불변이라는 가정으로 막대가 `ratio = remaining ÷ duration` 로 계산된다 — 서버가 duration 을 바꾸면 막대가 튄다. 시험으로 고정한다.
- **키워드 12자소 상한(P23-27)**: `keywords` 시험에 넣는다. 한 글자 키워드 부재와 함께.
- **이름·표식 시험**: `test/unit/e2eContract.test.ts` 에 새 표식·상수 목록을 가입하고 `scripts/e2e/lib.mjs` 의 단계 목록(`GRAPH`/`PHASE_NEXT`/`EXPECTED_SCENE`)도 D-04 대로 갱신한다.
- 새 결정 기록(0091)에 화면 계약(키워드 카드·입력줄·거절 문구·모두의 답 시트·정답 공개·조기 진행 타이머)을 적고 `docs/screen-map.md` 의 해당 절을 고친다(D-21).
