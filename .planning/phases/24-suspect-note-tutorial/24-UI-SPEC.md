# Phase 24 — UI Design Contract (의심 포스트잇 · 기록 카드 일반화 · 혼자 하기 튜토리얼)

> 이 페이즈의 새 화면은 넷이다. **① [의심] 단추와 의심 모드**(토론 입력줄 오른쪽 끝 아이콘 단추 하나 + 가까운 사람 이름표만 눌리는 모드), **② 포스트잇 3D 에셋**(캐릭터 몸에 붙은 "의심" 종이, 쌓기·붙음·떨어짐), **③ 기록 카드**(23 의 "첫날 답" 탭을 일차별 구역으로 일반화해 의심 줄을 더함), **④ 혼자 하기 튜토리얼**(첫 화면 [혼자 하기] → 실제 화면 위 가짜 view 열 장면 + 진행 점·한 줄 알약·포커스 링 틀). 나머지는 기존 부품·토큰을 그대로 쓴다.
> 결정 0051(글 최소·보고 누르기)이 먼저다. 의심은 **글 단추 없이 아이콘·이름표·종이 모양**으로 말하고, 튜토리얼은 **설명 문단 없이 연출 + 한 줄 알약**으로 가르친다. 이 페이즈가 새로 만드는 **글 단추는 [혼자 하기]·[홈으로] 둘뿐**이다.
> 6~23 의 UI-SPEC(영역 배치·빛남·이름표·카메라·단계 조명·사회자 띠·키워드 화면)은 **그대로 이긴다.** 숫자의 원천은 코드(`useMapInsets`·`useHostMetrics`·`phases.ts`·`tokens.css`·`camera.ts`)이고 이 문서의 숫자는 360×560~430×932 에서 대조한 값이다(띠 아랫변 `B` = 한 줄 123, 독 아랫변 `D = B + 52` = 175, 아래 패널 높이 토론 222·채팅 160 — 22·23 과 같은 기준).
> 사람을 부르는 말은 **'참가자'**(새 글·접근성 이름·시험 이름에 '손님' 금지). 낮도 마피아 분위기(낮은 명도·채도), 깔끔 담백, 문구는 해요체(22·23 문구 표와 같음). 사용자는 튜토리얼을 **익사이팅하게**(목적·재미·직업·흐름을 연출로, 단추 연습 아님) 원했고 포스트잇은 **디테일이 좋은 에셋**으로 원했다 — 이 문서의 두 큰 절이 그것이다.
> 범위 밖: 서버 규칙·와이어·D1 (D-01~D-09, D-19~D-21 이 맡는다 — 이 문서는 화면에 닿는 결과만 적는다), 봇의 포스트잇(D-05), 포스트잇 떼기·반응 동작, 시상, **방장 [튜토리얼 먼저]·함께 진행 튜토리얼(D-15 로 만들지 않는다)**, 햅틱, 진행에 지장 없는 작은 화면 가장자리 문제(07-UI-SPEC UI Considerations 20 그대로 — 고치지 않는다), 새 소리 레시피.

## 출처와 참고 자료 (design-refs)

`gsd-addons:design-refs` 스킬을 불러와 따랐다. 사용자가 준 별도 참고 이미지는 없고, **채택된 시안**(`design/v3.0/suspect-note/README.md`·`index.html`, 세 묶음 모두 A, 결정 0089-11·0089-15 와 24 CONTEXT D-14 로 채택)을 기준으로 삼았다. 새 장식 스타일을 만들지 않고 승인된 부품·토큰만 쓴다. 방향 한 줄: **귓속말의 "이름표를 눌러 고르는 모드"를 그대로 빌려 [의심] 한 단추로 끝내고, 종이는 캐릭터 몸에 실제로 붙는 작은 3D 한 장, 기록은 이미 있는 시트에 구역만 더하며, 튜토리얼은 실제 게임 화면에 알약 하나와 깜빡이는 테두리만 얹는다.** 열지 못한 참고 자료: 없음(캔버스 URL 은 에이전트가 열 수 없어 저장소 사본으로 대체).

시안과 **다르게 한 곳**(이유):
1. 시안 [의심] 은 글이 든 알약("📝 의심")이다. 실제는 **48 원 아이콘 단추**(글 없음, 접근성 이름만 "의심 붙이기") — 입력줄의 다른 단추(동작·보내기·유언)가 모두 48 원 아이콘이고, 글 단추는 폭 360 에서 입력칸을 160 아래로 줄인다(P24-2).
2. 시안 포스트잇 색은 임의의 분홍·하늘·노랑이다. 실제는 **붙인 사람의 좌석 토큰 색을 종이색과 섞은 옅은 틴트**(P24-10, 새 hex 없음).
3. 시안 진행 점은 화면 위(밴드 아래)에 있다. 실제는 **알약 바로 위 아래쪽 묶음**(P24-20) — 위쪽은 14·21·22 가 정한 안전선이라 새 요소를 두지 않는다.
4. 시안 링의 바깥 어둡게는 `rgba(10,14,28,.55)` 다. 실제는 토큰 `--scrim`(.6)을 쓴다(0081 허용, 새 값 없음).

- **걷기와의 관계**: 땅 탭은 계속 걷게 한다. 모드는 땅 탭으로 끝나지 않는다. 이름표와 땅이 겹친 곳의 탭은 이름표가 이긴다(기존 `WorldPick`·`stopPropagation`).
- **탭 피드백**: 이름표를 누르는 순간 이름표 깜빡임 정지·모드 끝·단추 눌림 해제(같은 프레임). 종이는 서버 확인 뒤(~100~200ms) 나타난다. 확인이 오기 전 같은 단추를 다시 눌러도 `useSendGuard` 가 막는다.
- **거절**: 서버 오류 프레임(`BAD_MESSAGE`)이 최근 3초 안 `suspect` 전송과 이어지면 위 알림 "가까이 가야 붙여요"(2.5초) + `ui.deny`. 그 밖 오류 코드·채팅 속도 제한은 알림을 만들지 않는다(귓속말의 `sendGuard` 기억 규칙).
- **키보드가 열려 있을 때**(P24-4): 단추를 누르면 입력칸이 포커스를 잃고 키보드가 닫혀 패널·스테이지가 원래 높이로 돌아온 뒤 이름표가 보인다. 입력 중이던 글은 지우지 않는다.
- **다른 층과의 관계**: 열린 시트(`will`·`claim`·`line`·`speak`)가 있으면 [의심] 은 눌리지 않는다(`layerKind !== null` 이면 비활성과 같은 무반응). 모드가 켜져 있는 동안 키워드·유언 시트의 자동 열림은 일어나지 않는다. **호출 빛남(`callTargetsOf`)은 모드 중 꺼진다**(`!whisper.mode` 와 같은 조건에 `!suspect.mode` 를 더함).

## 접근성 · 모션 · 입력

- 누르기 영역 44 이상([의심] 48, [그만두기] 44, 이름표 44, [홈으로] 48, [다시 보기] 44). 포커스 링(키보드) `gray-100` 2px. Tab 순서(낮 토론): 헤더 [내 역할] → 소리 → (모드 중 근처 이름표) → 입력줄 [동작] → 입력칸 → [보내기] → **[의심]** → [토론 끝내기]. 튜토리얼: [그만두기] → 소리 → 링 대상(하기 장면에서만).
- **색만으로 알리지 않는다**: 모드 = 단추 눌림 + 머리 안내 글 + 이름표 깜빡임(색 아님), 붙였음 = 점 + 이름 "옮기기", 종이 수 = 칩 숫자, 기록 줄 = 닉네임 글, 진행 = 점 길이 아닌 `aria-valuenow`.
- `prefers-reduced-motion`: 종이 붙음·떨어짐·쌓임 모션 없음(즉시), 링 깜빡임 정지(정지 테두리 + 중간 번짐), 알약 교차 페이드·카드 뒤집힘·시트 이동·답 줄 순차 등장 모두 즉시, 이름표 깜빡임은 `gray-100` 2px 고정.
- 깜빡임은 1Hz 이하. 한 화면에서 깜빡이는 대상은 **링 하나(튜토리얼)** 또는 **모드 이름표 무리 하나(실게임)**.
- 입력: [의심]·이름표는 `onMouseDown preventDefault` 규칙을 따르되 **[의심] 만 키보드를 닫는다**(P24-4). Esc = 모드 끄기(PC).
- 종이는 장식이 아니라 상태이므로 스크린리더에는 칩·기록 카드로 전달한다(3D 는 `aria-hidden`).
