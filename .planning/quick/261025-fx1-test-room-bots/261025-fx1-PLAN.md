## 봇 행동 규격 (`shared/game/bots.ts` — 단위 테스트가 이 표를 지킨다)

- `BOT_NAMES` = 봇가나·봇다라·봇마바·봇사아·봇자차·봇카타·봇파하(`scripts/bots.mjs` 의 NAMES 와 같은 목록). `isBot(p)` = `p.isBot === true`, `botCount(state)`.
- `botPlanKey(state)`: 단계가 claim·discussion·night 일 때만 단계 이름과 phaseEndsAt 을 이은 문자열, 그 밖은 null.
- `planBotSteps(state, now, randInt)` → `BotStep[]`(`{ at, botId, act }`, act 는 claim·say·emoji·pick 네 모양 — 사람 ClientMessage 의 같은 칸 이름). 사람이 한 명도 연결되어 있지 않으면 빈 배열. 살아 있는 봇만, seat 오름차순으로, 봇마다 아래 순서로 randInt 를 부른다(호출 순서가 계약 — 시드 테스트로 고정):
  - claim: `botClaimChoice(state, bot, randInt)` 가 돌려준 `{ claim, delayMs }` 를 `at = now + delayMs` 에. botClaimChoice: `randInt(100) < 15` 이면 none, 아니면 `rolesInPlay(인원)` 에서 `randInt(길이)` 번째, 그다음 `delayMs = 500 + randInt(3000)`. 지금은 살아 있는 봇이면 항상 값을 돌려주고, 돌려줄 값이 없으면 null(결정 0023 차례 주장에서 "그 봇 차례가 아님" 에 쓴다).
  - discussion: 첫 행동 `at1 = now + 2000 + randInt(10000)`, 종류 `randInt(2)` — 0 이면 이모티콘 `EMOJI_IDS[randInt(8)]`, 1 이면 say `innocent`. 둘째 행동 `at2 = at1 + 8000 + randInt(30000)`, 종류는 같은 방식.
  - night: 역할이 마피아·경찰·의사면 `botNightTarget(state, bot, randInt)` 가 돌려준 대상으로 pick 을 `now + 1000 + randInt(5000)` 에. 마피아 봇은 이어서 `randInt(10) < 6` 이면 `now + 8000 + randInt(6000)` 에 `randInt(2)` — 0 이면 say `nightAgree`, 1 이면 이모티콘 `EMOJI_IDS[randInt(8)]`.
  - `botNightTarget`: 후보를 seat 오름차순으로 — 마피아는 살아 있고 역할이 마피아가 아닌 사람(자신·동료 제외), 경찰은 살아 있는 다른 사람, 의사는 살아 있는 모두(자신 포함), 그 밖 역할은 undefined. 후보가 없으면 randInt 를 부르지 않고 undefined. **randInt(0) 호출은 어디에도 없다**(cryptoRandInt(0) 은 RangeError).
  - 단계 마감 500ms 전(`BOT_END_MARGIN_MS`)보다 늦은 행동은 버린다. 결과는 at 오름차순(같으면 원래 순서 — 안정 정렬).
- `syncBotPlan(state, now, randInt)`: 봇이 없으면 botPlan 키를 빼고(없으면 입력 그대로 — randInt 를 부르지 않는다), 키가 null 이면 botPlan 을 뺀 상태, 저장된 키와 지금 키가 같으면 입력 그대로, 다르면 `{ key, steps: planBotSteps(…) }` 를 둔 새 상태.
- `takeDueBotSteps(state, now)` → `{ state, due }`: botPlan 키가 지금 키와 다르면 `due` 빈 배열·입력 그대로. 같으면 `at ≤ now` 인 행동을 순서대로 꺼내고 나머지만 남긴 새 상태(꺼낼 것이 없으면 입력 그대로).
- `botWakeAt(state)`: 키가 맞는 계획의 첫 행동 시각, 없으면 null.
