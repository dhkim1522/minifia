# Feature Research

**Domain:** 온라인 소셜 추리(마피아) 게임에 "같은 공간"(맵 이동·자유 채팅·동작 캐릭터)을 얹는 v2.0 마일스톤
**Researched:** 2026-10-30
**Confidence:** MEDIUM (유령 채팅 규칙처럼 웹으로 확인한 부분은 HIGH~MEDIUM. 구스구스덕 이모트, 마피아42 세부 규칙, 모바일 카메라 관행은 사전 지식과 설계 추론이어서 LOW~MEDIUM. 해당 항목마다 표시했다)

## 범위와 읽는 법

이 문서는 결정 0044 가 정한 v2.0 대상 기능만 다룬다. 방 만들기·재접속·서버 타이머·역할·밤 행동·아침 발표·탈락자 관전·결과 화면은 v1.0 에 이미 있으므로 "의존"으로만 적는다. 비교 대상은 Among Us, 구스구스덕(GGD), Town of Salem(ToS), 마피아42, Gather.town 류 공간 앱, Fall Guys/Stumble Guys 의 이모트다.

이 프로젝트가 비교 대상과 갖는 가장 큰 차이는 두 가지다. 첫째, 음성이 없고 4~8명 5~10분이라 모든 소통이 문자와 몸짓에 실린다. 둘째, 서버가 받는 사람별로 걸러 보내는 원칙(ADR-0002)이 위치·채팅·유령·밤 정보까지 넓어진다. 그래서 "있으면 좋은 기능"보다 "새 정보 통로가 정체를 새게 하지 않는가"가 기능 판단의 1순위 기준이 된다.

신뢰도 표기: [확인]은 이번 조사에서 웹으로 확인한 사실, [지식]은 사전 지식이라 팀이 직접 확인해야 하는 사실, [추론]은 이 프로젝트 조건에서 내린 설계 판단이다.

| Feature | Value Proposition | Complexity | Notes |

## 핵심 쟁점별 상세 (비교 게임의 방식과 이 프로젝트의 권장)

### 1. 타이핑 인디케이터 의미

- 의미: "이 채널에서 누군가 입력창에 내용이 있고 최근 몇 초 안에 바뀌었다". 내용·길이는 보내지 않는다.
- 발송: 입력이 비어 있다가 처음 바뀔 때, 이후 약 2초에 한 번만 클라이언트가 "입력 중" 신호를 보낸다. 서버는 신호를 받으면 5초 만료로 상태를 켠다. 전송, 입력 비움, 포커스 이탈, 만료 중 하나면 끈다. 연결이 끊긴 사람의 표시가 영원히 남지 않도록 서버 만료가 반드시 있어야 한다.
- 채널: 반드시 채팅 본문과 같은 수신자 필터를 거친다. 밤에 마피아가 "…" 를 띄우는 것은 마피아에게만, 유령은 유령에게만 보인다. 시민이 유언을 쓸 때는 "…" 를 켜지 않는다. 켜면 "누가 시민인가"가 새고, 유언 쓰기 자체가 시민 역할 신호가 된다.
- 지우고 안 보낸 경우에도 그냥 사라지게 둔다. 이것이 오히려 눈치 게임을 만든다.
- 신뢰도: 일반 채팅 UX 관행이며 이 프로젝트용 수치는 [추론].

### 2. 채팅 도배·길이

- Among Us·GGD 의 공개 텍스트 채팅은 짧은 글 위주다. 이 프로젝트는 폰 세로 한 줄 입력이므로 80자 안팎이 말풍선·로그 모두에 맞다 [추론].
- 속도 제한을 서버에서 건다(클라이언트 제한은 우회 가능). 제한에 걸리면 조용히 버리지 말고 입력창에 짧은 표시를 준다. 말이 사라지면 토론이 어긋난다.
- v1 의 "2초에 한 번"은 템플릿용이었다. 자유 채팅에는 너무 느리다. 90초 토론에서 사람마다 몇 번은 말해야 한다.
- 채팅 로그는 서버가 보관한다(결과 화면 공개, 재접속 복구에 모두 필요). 방당 채널별 최근 수백 건이면 충분하다.

### 3. 동작(이모트) 설계

- Fall Guys/Stumble Guys 류: 장착한 4~8개를 휠이나 버튼으로 누른다. 이동하면 취소되는 방식이 흔하다 [지식]. 이 게임도 같은 방식이 맞다.
- 재사용 대기: 동작 길이 + 약 1초. 한 번에 하나만. 연타는 서버가 무시한다. "킹받는" 효과는 연타가 아니라 타이밍(변론 중 한 박자 박수)에서 나온다.
- 이동 금지 구간(지목·변론·찬반)에도 동작은 허용(결정 0044 7항). 변론자의 말을 덮지 않게 같은 대기 규칙을 쓴다.
- 채널: 마피아의 밤 동작은 마피아에게만, 유령의 동작은 유령에게만 보인다. 이것도 채팅과 같은 필터 경로.
- 목록 크기: 시작은 8~10개. 동작×의상 파츠의 조합마다 아트가 맞아야 하므로 제작비가 곱셈으로 늘어난다. 의상 파츠는 머리·몸·손 소품 슬롯으로 제한하고, 동작은 뼈대 애니메이션으로 만들어 파츠가 뼈대에 붙는 방식이어야 한다. Lottie 처럼 파츠를 교체하기 어려운 방식은 맞지 않을 수 있다 → 스택 조사에서 확인할 것.
- 신뢰도: 구스구스덕의 구체 이모트 목록은 웹에서 확인하지 못했다(LOW). 위 내용은 설계 판단.

### 4. 이동·충돌·카메라 (작은 화면)

- 탭 이동은 "화면 어디나 탭하면 걸어간다" 때문에 UI 근처 탭이 의도치 않은 이동이 될 수 있다는 점이 플레이테스트에서 지적된 바 있다 [확인: 모바일 게임 플레이테스트 글, 일화 수준]. 대책: 하단 UI 영역과 HUD 위 탭은 이동 입력에서 제외하고, 이동 목적지에 짧은 표식(발자국·원)을 보인다.
- 길찾기: 맵을 개방형으로 두고 장애물은 적게 한다. 장애물이 있다면 격자 기반 경로가 필요하다(서버와 클라이언트가 같은 결과를 내야 함). 복잡도 절약을 위해 "직선 이동 + 벽 미끄러짐"으로 시작하는 쪽이 싸다 [추론].
- 카메라: 평소엔 내 캐릭터 추적(약간의 지연), 집결 구간엔 전원이 들어오게 자동 맞춤, 변론엔 변론자 확대. 화면 밖 대상 방향 표시는 밤에 마피아가 대상을 찾을 때만 있으면 충분하다.
- iOS 키보드: 채팅 입력 중 가상 키보드가 올라오면 보이는 영역이 폭 360px, 높이 200px대까지 줄 수 있다. 이때도 내 캐릭터·타이머·말풍선이 보이도록 `visualViewport` 기준 레이아웃이 필요하다. 이것을 늦게 챙기면 채팅 UI 를 다시 짜게 된다.
- 위치 방송: 목적지 + 서버 시뮬레이션이면 8명도 초당 몇 건이면 된다. 밤에 마피아 위치는 마피아에게만, 유령 위치는 유령에게만.

### 5. 밤 설계 쟁점 (이 마일스톤에서 가장 위험한 정보 유출 구간)

비교 게임에는 없는 "물리적 암살 + 시민 화면 어둠"이라서 직접 참조할 선례가 약하다. 아래는 규칙 결정이 필요한 쟁점이고, 페이즈 토론 때 확정해야 한다.

- **밤 시작 위치.** 낮이 끝난 자리가 가운데 집결이면 마피아는 한 걸음에 암살한다. 밤 시작 때 전원을 맵 곳곳의 정해진 자리로 흩어 놓아야 이동·암살이 의미를 가진다 [추론]. 흩어지는 위치는 서버가 정한다.
- **마피아가 둘일 때.** 한 밤에 한 명만 죽는다(v1 규칙 계승). 두 마피아가 서로 다른 대상에게 달려가면 누가 확정하나. 권장: 먼저 성공한 암살이 그 밤의 대상을 확정하고 다른 마피아의 시도는 막는다(밤 타이머는 끝까지 기다린다는 v1 규칙 유지). 또는 마피아 채팅으로 합의한 대상 하나에 "지목" 표시를 두고 그 대상에게만 암살 가능. 어느 쪽이 재미있는지는 플레이테스트가 필요하다.
- **아무도 못 죽인 밤.** 30초 안에 접근 못 하면 "아무 일도 없었습니다". v1 의 "행동 없음" 처리와 일치.
- **아침 위치.** 밤이 끝난 뒤 마피아가 시체 옆에 서 있으면 낮에 보이는 위치로 정체가 샌다. 아침이 되면 산 사람 전원을 같은 낮 시작 대형으로 옮기고 분필 윤곽만 사망 지점에 남긴다 [추론, 중요].
- **쪽지 작성 시간.** 암살 직후 쪽지를 쓸 시간이 필요한데 밤 30초에 이동도 들어간다. 암살자에게만 10초 안팎의 쪽지 창을 열고, 비워도 되게 한다.
- **경찰·의사가 쓰는 유언.** 결정 문구는 "시민은 유언 쓰기"다. 그런데 경찰·의사가 유언이 없고 시민만 유언이 있다면, 아침에 "유언 없음"이 곧 "이 사람은 경찰·의사였다"는 단서가 된다. 권장: 유언은 역할과 무관하게 모두가 낮·밤 어느 때나 편집할 수 있는 저장 초안으로 두고, 죽을 때 그 초안이 공개된다(ToS 방식 [확인: ToS 는 유언을 언제든 써 두는 방식]). 경찰의 유언이 "B 는 마피아"일 수 있다는 정통 마피아의 핵심 수도 살린다.
- **의사 보호 알림.** "누군가 살아났습니다"만 발표하고 보호받은 본인에게는 밤에 아무것도 알리지 않는다. 알리면 노려졌다는 정보가 샌다.
- **어둠 연출 소리.** 위 안티 피처 참조. 모든 시민에게 같은 시간표로 재생.

### 6. 쪽지(데스노트) 남용 방지

ToS 의 Death Note 는 킬러가 직접 쓰고 공개 때 함께 나온다 [확인]. 남용 형태: 다른 사람 행세, 시스템 메시지 위장, 장문 도배, 욕설. 이 프로젝트는 친구끼리라 필터를 두지 않는다(범위 밖). 최소 대책만:

- 40자 안팎, 한 번 쓰면 수정 불가
- 일반 텍스트만 렌더(이스케이프), 시스템 카드와 구분되는 전용 스타일로 "마피아가 남긴 쪽지" 라벨
- 익명: 마피아가 둘일 때도 누가 썼는지 표시하지 않음. 거짓말·위장은 허용(재미의 일부)
- 쓰지 않아도 됨

### 7. 아침 연출 시간

사망자 공개, 유언(최대 80~120자), 쪽지(40자), "살아났습니다"를 8초에 모두 읽히기는 어렵다. 한국어 한 줄 40자 읽기에 2~3초가 든다 [추론]. 권장: 아침 길이를 12~15초로 시작하거나 유언·쪽지 길이에 맞춰 서버가 정하고, 공개된 유언·쪽지는 낮 채팅 로그에 시스템 카드로 남겨 다시 읽게 한다. 서버 타이머가 기준이므로 클라이언트 임의 스킵은 없다.

### 8. 시상식 칭호

통계는 서버가 판 중 센다. 아래는 통계가 쉬운 순으로 골랐다. 원칙: 사람마다 한 칭호, 동률은 서버가 결정론적으로 정해 모든 폰이 같게, 해당자가 없을 때 쓸 예비 칭호를 둔다, 놀림이 아니라 웃음이 되도록 문구를 정한다. 투표형 칭호(베스트 유언 등)는 이후 후보.

| 능구렁이 | 마피아인데 지목을 거의 안 받음 | |
| 유령 수다왕 | 유령 채팅 건수 | 탈락자 몫 |
| 유언 장인 | 유언 글자 수 | 수치 기준이 낮으면 재미가 없음 |

시상식에서 모든 사람이 하나 이상 받도록 예비 칭호를 둔다. 탈락자가 먼저 나가면 관전 중에도 받을 수 있게 하면 이탈이 줄어든다 [추론].

### 9. 재대결 흐름

Among Us 는 결과 후 로비로 돌아가 같은 방에서 다시 시작하고 나간 사람은 빠진다 [지식]. 권장 흐름: 결과 화면의 "한 판 더" → 방이 로비로 돌아가고 남아 있는 사람이 자동으로 같은 방에 있음 → 방장이 시작. 안 누른 사람은 결과 화면에 남아 있거나(일정 시간 후) 정리. 의상은 유지, 역할·위치·채팅 로그·통계는 초기화. 로비에서 새 사람이 들어올 수 있어야 한다(v1 ROOM 재사용).

방장 이양: 방장이 끊긴 지 유예(예: 20~30초, v1 재접속 유예에 맞춤)를 넘기면 가장 오래 남은 연결자에게 넘긴다. 이전 방장이 돌아와도 방장을 되찾지 않는다 [추론]. 게임 중에는 방장이 필요 없다.

## Feature Dependencies

```
[v1: 방 + 재접속 토큰 (ROOM/CONN)]
    └──requires──> [맵 상태: 캐릭터 위치/스폰/로비]
                       ├──requires──> [서버 이동 시뮬레이션 + 위치 방송]
                       │                  └──requires──> [수신자별 가시성 함수 (위치/동작/타이핑/채팅 공통)]
                       └──requires──> [카메라 + 맵 에셋]

[v1: 서버 단계/타이머 (GAME)]
    └──requires──> [단계별 이동 가능 여부 / 집결 대형]
                       └──requires──> [실시간 지목] ──> [최후 변론] ──> [찬반] ──> [처형]

[수신자별 가시성 함수]
    ├──requires──> [자유 채팅 채널 (낮 전체/마피아/유령)]
    │                  ├──enhances──> [타이핑 인디케이터]
    │                  ├──requires──> [채널별 로그 보관] ──> [끝난 뒤 채팅 공개]
    │                  └──requires──> [유령 산책 + 유령 채팅]
    ├──requires──> [밤: 마피아 이동 + 암살] ──> [아침: 분필·쪽지·유언·구조 발표]
    └──requires──> [동작 가시성(마피아/유령 채널)]

[동작 캐릭터 몸체(뼈대)]
    ├──requires──> [의상 파츠 슬롯] ──> [로비 의상 갈아입기] ──> [같은 멤버로 다시 하기(의상 유지)]
    └──requires──> [동작 목록 + 재사용 대기]

[서버 통계 카운터 (채팅/동작/이동/지목 변경/역할)] ──requires──> [시상식]
[v1: 결과 화면 + 전체 역할 공개 (END)] ──enhances──> [시상식, 채팅 공개]
[v1: 탈락자 관전 (0021)] ──enhances──> [유령 산책]
[v1: 재접속] ──requires──> [위치/채팅 로그 복구] ──enhances──> [방장 이양]
[사운드] ──enhances──> [밤 연출, 처형, 동작]  (독립적, 마지막에 붙여도 됨)
```

### Dependency Notes

- **수신자별 가시성 함수가 모든 것의 기반이다.** 위치·동작·타이핑·채팅·유령·밤 정보를 하나의 `누가 무엇을 볼 수 있나(viewer, phase, entity)` 판정으로 통일하지 않으면 채널마다 필터가 따로 생겨 하나가 샌다. v1 의 "받는 사람별 상태" 빌더(ADR-0002)를 확장하는 방식이 맞다. 이 함수와 이동 시뮬레이션이 맵 페이즈의 첫 작업이어야 한다.
- **동작 캐릭터 몸체는 에셋 선행 의존.** 의상 파츠는 뼈대에 붙는 슬롯이 먼저 정해져야 하고, 동작 개수는 에셋 제작비가 정한다. 디자인 승인(캔버스) 후 화면 페이즈를 시작한다는 프로젝트 규칙과 연결된다.
- **지목은 집결(이동 제어)에 의존.** 집결 없이 지목만 먼저 만들면 카메라 밖 캐릭터를 가리키는 문제가 생긴다.
- **밤 암살은 이동 + 유언 + 쪽지 + 아침 연출을 한 묶음으로 설계해야 한다.** 아침 위치 초기화, 유언 공개 규칙, 쪽지 작성 창 등이 서로 얽혀 있다.
- **시상식은 통계 카운터가 판 처음부터 세어져야 한다.** 늦게 붙이면 이전 페이즈 코드를 다시 건드린다. 카운터 훅은 채팅·동작·이동·지목 구현 때 같이 심는다.
- **채팅 공개는 로그 보관에 의존.** 채팅 구현 때 채널 태그 + 서버 로그를 처음부터 둔다.
- **재대결은 재접속 토큰 모델에 의존.** 방 상태를 로비로 되돌릴 때 토큰·자리 매핑이 유지돼야 한다.
- **방장 이양은 재접속 유예에 의존.** 끊김과 이탈을 구분하는 시간 기준이 이미 있어야 한다.
- **v1 폐기 대상과 충돌:** 순차 직업 공개·빠른 메시지·이모티콘·찬반 전 처형 여부/후보 선택 투표는 v2 에서 제거(0044 "대체하는 것"). 제거하는 코드가 많아 v1 테스트(3094건)에서 깨지는 항목을 먼저 정리해야 한다.
- **스택 조사와 충돌 가능:** 파츠 교체형 뼈대 애니메이션(Rive/Spine 계열)과 Canvas/DOM 렌더 선택이 이동·카메라·말풍선 구현 방식을 바꾼다.

## MVP Definition

이 마일스톤은 범위가 이미 한 마일스톤으로 확정(0044 15항)이어서 "무엇을 뺄까"보다 "어떤 순서로 배포 가능한 조각을 만들까"가 중요하다. 아래는 순서 권장이다.

### Launch With (v2.0 필수, 앞 페이즈일수록 앞으로)

- [ ] 수신자별 가시성 함수 + 서버 이동 시뮬레이션 + 맵 렌더·카메라 + 로비 이동 — 나머지 모두의 기반
- [ ] 자유 채팅(채널·속도 제한·로그) + 타이핑 인디케이터 + 말풍선 — 토론의 본체
- [ ] 동작 캐릭터 몸체 + 동작 목록 + 로비 의상 — 팀 피드백 3·4번 직접 해결
- [ ] 낮 토론(이동·일찍 끝내기) → 집결 → 지목 → 변론 → 찬반 → 처형 — 정통 순서 복원
- [ ] 밤(마피아 이동·암살, 시민 어둠, 경찰·의사 얼굴 목록, 유언) → 아침(분필·쪽지·유언·구조 발표) — v2.0 의 핵심 연출
- [ ] 유령 산책 + 유령 채팅
- [ ] 결과: 채팅 공개 + 시상식 + 같은 멤버로 다시 하기
- [ ] 방장 이양·이탈자 정리, WR-01~04 정리
- [ ] 사운드(배경음, 밤·처형, 동작)

### Add After Validation (v2.x)

- [ ] 투표형 칭호(베스트 유언·베스트 쪽지) — 팀 테스트에서 시상식 반응이 좋을 때
- [ ] 유령끼리 보이는 전용 동작 — 탈락자 대기가 지루하다는 피드백이 나올 때
- [ ] 동작·의상 추가 — 반응이 좋은 동작의 변형
- [ ] 방장의 시간 조절·역할 구성 조정(ROLEX) — 시작값 조정이 필요할 때

### Future Consideration (v3+ 또는 출시 마일스톤)

- [ ] 신고·차단·필터 — 공개 서비스 전환 시
- [ ] 햅틱·진동 — 앱 전환(Capacitor) 때(사용자 메모: 웹에서 새로 만들지 않음)
- [ ] 의상 해금·수집 — 계정이 생긴 뒤
- [ ] 영매·기자 등 새 역할 — v2.0 팀 테스트 후(결정 0044)
