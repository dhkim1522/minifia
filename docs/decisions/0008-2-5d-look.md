# 0008 실시간 3D 는 쓰지 않고, 2D 화면에 입체감을 더한 2.5D 로 만든다

- 상태: 채택
- 날짜: 2026-10-21

## 배경

- 초안은 "단순한 2D 캐릭터" 였다. 사용자는 정적 2D 보다 구색과 완성도가 있는 화면과 캐릭터를 원한다.
- 테이블과 캐릭터를 실시간 3D 장면(three.js 등)으로 그리면 자리 누르기, 밤 지목, 투표 같은 모든 단계 화면이 3D 장면 위에서 만들어져야 한다. 나중에 바꾸기 어렵고, 링크로 바로 들어오는 게임에 로딩과 성능 부담이 크다.
- 사용자가 원하는 것은 맵 이동이나 고품질 3D 가 아니라, 간단한 게임이면서 2D 보다 입체감 있는 2.5D 형태다.

## 결정

- 실시간 3D 장면은 쓰지 않는다. 화면 구조는 일반 웹 화면(2D)이다.
- 보이는 모습은 2.5D 로 만든다.
  - 테이블은 비스듬히 내려다본 원근 구도의 타원 테이블이다. 내 자리(맨 아래)가 가장 가깝고 크게 보인다.
  - 그림자, 조명 레이어(밤 어두워짐, 스포트라이트), 앞뒤 겹침, 배경 패럴랙스로 입체감을 낸다.
  - 캐릭터는 입체감 있는 그림을 프레임 PNG 로 넘겨 움직인다. 일러스트로 그릴지 3D 로 렌더링한 그림을 쓸지, 쓸 도구는 5페이즈 논의에서 정한다.
- 1~4페이즈는 같은 원근 테이블 구도에 임시 정장 실루엣을 쓰고, 5페이즈에서 캐릭터 그림과 연출을 완성한다.

## 결과

- 1페이즈 계획 전에 하려던 실시간 3D 스파이크는 하지 않는다.
- 테이블·자리·인물은 게임 상태를 받아 그리기만 하는 화면 부품으로 두어, 5페이즈에서 그림만 바꿔 끼운다.
- PROJECT.md 의 "무거운 3D·고급 그래픽" 범위 밖 항목은 그대로 둔다.
- CHAR-01 의 "단순한 2D 캐릭터" 는 5페이즈에서 "프레임 PNG 로 움직이는 입체감 있는 캐릭터" 로 다듬는다. 애니메이션 라이브러리 후보(Rive 또는 Lottie)는 프레임 PNG 방식과 함께 5페이즈에서 비교한다.

## 보완 (2026-10-29, 결정 0038)

- 5페이즈에서 캐릭터 움직임은 하지 않기로 함(결정 0038, D-01). 프레임 PNG·Rive·Lottie 도입 결정은 닫는다. 플레이테스트(6페이즈)에서 밋밋하다는 반응이 나오면 v1.1 후보로 올린다.
- 위 본문의 "프레임 PNG 로 넘겨 움직인다"와 결과 절의 CHAR-01 다듬기 문장은 기록 보존을 위해 지우지 않는다. 5페이즈의 실제 결과는 정지 그림 8종 유지다.
