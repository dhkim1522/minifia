# 0010 구현 전에 MVP 전체 화면을 디자인하고, 사람용 산출물은 클로드 아티팩트로 만든다

- 상태: 채택
- 날짜: 2026-10-22

## 배경

- 1페이즈는 화면 설계 없이 계획까지 갔다. GSD 의 UI 자동 감지가 한국어 문구를 놓쳐 `/gsd-ui-phase` 를 건너뛰었고, 웨이브 3(화면 구현) 직전에 멈춰 UI-SPEC 을 따로 만들었다.
- UI-SPEC 은 AI 가 구현할 때 따르는 글 지침서다. 사람이 보는 화면 설계서(컬러, 컴포넌트가 입혀진 화면)는 따로 없다.
- 사용자는 이 프로젝트를 실무 제품개발 순서(기획 → 설계 → 디자인 → 구현 → 피드백 → 확장)로 진행하고, 끝나면 과정과 산출물을 포트폴리오로 정리하려 한다. 그 흐름은 gsd-addons 로 다른 프로젝트에도 쓴다(gsd-addons `docs/lifecycle.md`).

## 결정

- **디자인 먼저**: 남은 구현 전에 디자인 시스템과 MVP 전체 화면(1~4페이즈: 입장, 대기실, 역할 확인, 낮 토론, 투표, 최후 변론, 밤 행동, 아침 결과, 처형, 승패)을 설계하고 승인받는다. 2~4페이즈 화면은 `docs/product.md` 기획을 근거로 그리고, 각 페이즈 논의는 이 설계를 출발점으로 삼는다. 세부 상태는 각 페이즈 `/gsd-ui-phase` 에서 다듬고, 달라진 점은 설계에 다시 반영한다.
- **산출물 두 종류**:
  - 사람용(디자인 시스템, 화면 설계서, 최종 포트폴리오)은 클로드 아티팩트로 만든다. 디자인 시스템은 Design System 유형, 화면 설계서는 Design 캔버스 유형이다.
  - AI 용 작업 지침은 저장소에 둔다(`.planning/`, `docs/`, `design/`).
- **저장소 사본**: GSD 에이전트는 아티팩트를 읽지 못한다. 디자인을 승인할 때마다 `design/` 아래에 토큰(`tokens.json`)과 화면 PNG 사본을 둔다. 앱의 `src/styles/tokens.css` 는 `tokens.json` 에서 만든다(토큰 원본은 하나).
- **내보내기**: 진행 중에는 아티팩트를 내보내지 않는다. 구간이 끝날 때 아티팩트 버전에 이름표만 붙이고, 포트폴리오 단계(선택)에서 한 번에 내보낸다.
- **만들지 않는 것**: 구간 마무리 발표 자료, 별도 문제 해결 기록, PR·코드 리뷰 이력. `main` 직접 커밋을 유지한다.
- 캐릭터는 클로드 데스크톱에서 만든 세트 C(2~3등신 카툰, 72×96 투명 PNG)로 확정했다(2026-10-22). 원본은 `design/characters/`(인물 8, 유령 8+2, 직업 4, 확장 16), 규격과 쓰임은 그 폴더 README. 테이블에는 외형 인물만, 직업 그림은 본인 카드·마피아 동료·경찰 결과·게임 끝 결과에만 쓴다.
- 배경은 단색 바탕 대신 달빛 마을 광장 장면을 쓴다. 클로드 데스크톱에서 만든 그림 에셋(A_cute 그림체, 장면 4종 × 구도 2종)으로 확정했다(2026-10-22). 원본은 `design/backgrounds/`, 앱은 `public/backgrounds/*.svg`. 장면은 단계를 알려 준다(대기 `lobby`, 밤 `night`, 낮 `day`, 투표·처형 `verdict`). 남색·회청색 계열 토큰 안에서만 그렸고 진홍은 없다.

## 결과

- 1페이즈 웨이브 3 이후 구현은 디자인 승인 뒤로 미룬다. 승인되면 `01-UI-SPEC.md` 를 설계 사본에 맞춰 고치고, 웨이브 3 이후를 `/gsd-plan-phase 1` 로 다시 계획한다(완료된 01-01~01-03 은 그대로).
- `01-UI-SPEC.md` 의 토큰·규칙(색 60/30/10, 진홍 예약 다섯 곳, 글자 4단계, 간격 스케일)은 디자인 시스템의 출발점으로 쓴다.
- `CLAUDE.md` 문서 지도에 디자인 아티팩트 링크와 `design/` 사본 위치를 적는다.
