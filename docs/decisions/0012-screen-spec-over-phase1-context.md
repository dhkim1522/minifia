# 0012 1페이즈 화면은 승인된 화면설계서를 따르고, 어긋나는 1페이즈 논의 결정을 바꾼다

- 상태: 채택
- 날짜: 2026-10-23

## 배경

- 화면설계서 v0.2(https://claude.ai/artifact/QtbQYhk7ezy4fV7H98bZJz, 버전 15 "v0.2 승인본", 사본 `design/screens/`)를 사용자가 승인했다(결정 0011).
- 1페이즈 논의(`.planning/phases/01-walking-skeleton/01-CONTEXT.md` D-01~D-25)는 설계서보다 먼저 정해졌다. 설계서 일부가 그 결정과 어긋난다.
- 어긋나는 곳 가운데 게임 규칙에 걸린 네 가지는 사용자에게 물어 정했다(2026-10-23). 나머지 화면 구성·문구·그림 차이는 승인된 설계서를 따른다.

## 결정

- **화면의 기준**: 1페이즈 화면(S-01~S-06, C-01~C-03)의 구성·문구·장면·그림은 화면설계서 v0.2 를 따른다. 01-CONTEXT 의 화면 관련 결정과 다르면 설계서가 이긴다. 정리본은 `01-UI-SPEC.md`.
- **사용자가 정한 네 가지**
  - 시작 조건(D-16 변경): **연결된 사람이 4명 이상**일 때 [게임 시작]이 켜진다. 끊긴 사람은 자리를 지키지만 시작 인원에 넣지 않는다. 역할은 시작할 때 앉아 있는 모든 사람(끊긴 사람 포함)에게 배정하고, 끊긴 사람은 돌아오면 자기 역할로 이어서 한다. 대기실 인원 표시도 연결된 인원이다. 정원(8명)은 끊긴 사람을 포함한 자리 수로 센다.
  - 역할 카드(D-13 보완): 누르면 뒤집히고, 5초 안에 누르지 않으면 저절로 뒤집힌다. 앞면에서 다시 누르면 뒷면으로 가려진다.
  - [내 역할](D-19 변경): 누르고 있는 동안만 보이는 방식 대신, 누르면 **내 역할 시트(C-01)**가 올라오고 [닫기]나 아래로 끌기로 내린다.
  - 토스트(D-10 변경): 대기실에서 "○○님이 들어왔어요"(2초)와 "○○님이 새 방장이 되었어요" 토스트를 쓴다. 자리 등장 애니메이션은 그대로 둔다.
- **설계서를 따라 바뀌는 것(사용자 질문 없이)**
  - 방장 표시는 왕관(D-11) 대신 "방장" 배지.
  - 링크 참가(D-05)는 "미니피아에 초대받았어요 / 방 {코드}" 와 먼저 앉은 사람들, [참가하기], [다른 방 코드로 참가]. 서버 미리보기에 앉은 사람의 자리·닉네임을 더한다(역할 없음).
  - 첫 화면의 코드 참가 거절(D-07)은 오류 화면이 아니라 코드 칸 아래 오류 문장으로 보여 준다. 링크 참가의 거절은 입력 대신 사유와 [처음으로].
  - 인물은 임시 실루엣(D-21, D-25) 대신 세트 C 그림, 배경은 A_cute 그림(결정 0010·0011 에서 이미 정함).
- **설계서가 1페이즈 계획에 미룬 것**
  - 방장이 [나가기]를 누르면 **연결된 사람 가운데** 먼저 들어온 사람이 방장이 된다(아무도 연결돼 있지 않으면 전체에서 먼저 들어온 사람). 시작 조건이 연결된 사람 기준이 되었으므로, 끊긴 사람이 방장이 되어 아무도 시작할 수 없는 방을 막는다(D-17 보완, 계획 검토에서 나옴).
  - 방장이 끊긴 채 안 돌아올 때의 자동 이양은 D-17 대로 v2(CONNX-01). 1페이즈는 "방장 연결을 기다리는 중이에요" 안내만 한다.
  - 재연결이 30초 넘게 실패하면 "연결할 수 없어요" 와 [다시 시도]·[처음으로]를 보여 준다(30초는 가정, 플레이테스트로 조정).

## 결과

- `01-UI-SPEC.md` 를 설계서 기준으로 고쳤다. 01-CONTEXT 에는 이 결정으로 바뀐 D 번호를 적었다.
- 아직 실행하지 않은 1페이즈 계획(01-04~01-10)은 이 기준으로 다시 계획한다.
- 디자인 시스템 아티팩트도 맞춘다: 방장 배지, 내 역할 시트, 공유 시트, 토스트, 재접속 띠(높이 52, 내용을 밀어냄).
