# 0018 온라인 기준으로 만들되 오프라인에서도 할 수 있는 형태로 두고, 엿보기·캡처는 매너에 맡긴다

- 상태: 채택
- 날짜: 2026-10-24

## 배경

- 결정 0005 가 비대면(각자 폰, 앱 안 소통)을 기준으로 정했다. 그런데 일부 정책(밤 화면 구성을 모든 역할이 같게, 투표 동시 공개의 근거)이 오프라인에서 옆 사람이 폰을 보는 상황을 막으려는 전제로 쓰여 있었다.
- 3페이즈(밤과 아침) 논의에서 이 전제가 화면 설계를 불필요하게 묶는 것이 드러났다.

## 결정

- 제품은 **온라인 기준**으로 설계한다. 동시에 **같은 공간에 모여서 해도 문제없이 돌아가는 형태**를 목표로 한다("무조건 비대면"이 아니다).
- **옆에서 화면을 훔쳐보기, 화면 캡처 공유, 앱 밖 대화** 같은 것은 정책으로 막지 않고 **플레이어 매너**에 맡긴다. 그것까지 고려해 화면·규칙을 짜는 것은 과하다.
- 역할 때문에 어쩔 수 없이 드러나는 요소가 생기면, 나중에 **개별 설정**(소리 끄기, 화면 가리기 등)으로 확장한다.
- 단, **서버가 다른 사람의 역할을 클라이언트로 보내지 않는 것**(결정 0002)은 보안 규칙이라 그대로다.

## 결과

- NIGHT-04·ROADMAP Phase 3 성공 기준 1·`docs/product.md` 밤 화면 줄을 고쳤다: 밤 화면은 역할에 맞게 구성한다(마피아 동료 표시·동료의 선택, 경찰·의사 대상 선택, 시민 안내 문구).
- `docs/product.md` 투표 공개 방식에서 오프라인 비유 문구를 뺐다. 동시 공개의 이유는 눈치 투표 방지이며 그대로다.
- 앞으로의 논의에서 "주변에서 보일 위험"은 설계 제약으로 쓰지 않는다.
