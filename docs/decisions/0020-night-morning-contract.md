# 0020 밤·아침은 서버 단계 night·morning 이고, 밤 행동은 pick 메시지 하나로 받아 아침에 한 번 판정하며, 비공개 값은 받을 사람에게만 보낸다

- 상태: 채택
- 날짜: 2026-10-25

## 배경

- 3페이즈(밤과 아침)는 마피아·경찰·의사의 행동을 서로 모르게 받아 아침에 한 번에 발표한다. 이 페이즈의 위험은 새 기술이 아니라 비공개 정보 경계다.
- 결정 0016(낮 루프 구조: 단계 표·진입 훅 표), 0018(온라인 우선, 훔쳐보기는 매너), 0019(마피아 밤 채팅·아침 문구), 0021(탈락자 관전)이 이 계약의 입력이다. 이 문서는 03-01~03-08 이 만든 와이어 계약과 판정 규칙을 배포 직전(03-12) 모습으로 한 곳에 적는다.
- 누출 검사 `test/worker/leak.test.ts` 가 6명 한 판(두 밤·두 아침, 행동·마피아 채팅·탈락·관전 포함)의 모든 실제 프레임으로 이 계약을 지킨다.

## 결정

1. **단계**: `night` 30초, `morning` 5초. 흐름은 `discussion → night → morning → dayAnnounce` 다(4페이즈 전 임시 — 4페이즈가 discussion 과 night 사이에 투표·처형을 끼운다). 일차는 `dayAnnounce` 진입에서만 오른다. 모두가 일찍 골라도 밤은 30초가 다 지나야 끝난다(행동은 마감을 바꾸지 않는다). (2026-11-03 결정 0061-13 으로 v2.0 에서 개정했다: 아침 길이는 공개되는 내용에 따라 5~15초)
2. **밤 행동 메시지는 `{ t: "pick", target }` 하나**다. 행동 종류(살해 지목·조사·보호)는 보내지 않고 서버 저장 역할이 정한다. 같은 값 재선택은 저장도 전송도 없다. 마감까지 바꿀 수 있고, 마감 뒤에는 `WRONG_PHASE` 다. 아무 행동도 마감 시각을 바꾸지 않는다.
3. **판정 규칙표** (아침 진입 때 한 번 돈다):

   | 상황 | 결과 |
   | --- | --- |
   | 마피아 아무도 안 고름 | 지목 없음 → 탈락 없음 (아침 `{}`) |
   | 마피아 일부만 고름 | 고른 사람의 표만 센다 (**A2**) |
   | 최다 대상 하나 | 그 대상 |
   | 최다 동률 | 동률 seat 오름차순 목록에서 서버 난수로 하나 |
   | 저장된 지목이 탈락자·마피아 | 집계에서 뺀다 (방어적 재검증) |
   | 의사 보호 = 최종 지목 | 탈락 없음. 아침은 `{}` 로 지목 없음과 구별되지 않는다 (의사 구출 비공개) |
   | 의사 자기 보호 | 허용 |
   | 경찰·의사 안 고름 | 그 행동 없음 |
   | 경찰 조사 | `{ n: 일차, target, isMafia }` 를 그 경찰 기록 끝에 더한다. 자기 조사 = false |
   | 그 밤에 지목되는 경찰·의사 | 조사·보호는 그대로 적용한다 — 같은 밤의 행동은 동시에 해결한다 (**A1**) |
   | 탈락 처리 | 대상 `alive: false`. 아침 발표에 직업은 싣지 않는다 |
   | 아침 문구 | 탈락자가 있을 때만 번호 1..7 중 하나(결정 0036-9 로 8 → 7). 직전 번호를 뺀 후보에서 고른다 — 문구 연속 반복 없음 |

   난수는 `tick` 의 세 번째 인자(`cryptoRandInt`)이고, 필요할 때만(동률·문구) 정해진 순서로 부른다. 난수 없이 탈락이 생기는 밤을 마감하면 예외를 던진다(조용히 틀리지 않는다). **A1·A2 는 사용자가 나중에 바꿀 수 있는 기본값**이다. 바뀌면 규칙표와 `test/unit/night.test.ts` 만 고친다. (2026-11-03 결정 0061-6·12·17 로 v2.0 에서 개정했다: 산 마피아 전원 일치만 확정·난수 없음, 구출은 saved 로 공개, 문구 번호 삭제)
4. **view 필드** (`shared/protocol.ts`):
   - `players[].alive` — 항상 싣는다(공개 정보). `players[]` 키는 `alive`·`connected`·`isHost`·`nickname`·`seat` 다섯이다.
   - `me.pick` — 밤·생존 본인이 고른 seat. 본인에게만.
   - `me.allyPicks` — 밤·생존 마피아에게만. 동료가 고른 대상 seat 오름차순·중복 없음. 누가 골랐는지는 싣지 않는다.
   - `me.records` — 경찰 본인에게만. 역할을 싣는 모든 단계에서, 탈락한 뒤에도 보인다. `{ n, target, isMafia }` 만 있고 직업 이름은 없다.
   - `day.morning` — 아침 단계에서 모든 소켓이 같은 JSON(`{ eliminated?, phrase? }`). 키 없는 객체는 지난밤 무사다. (2026-11-03 결정 0061-12·17: `{ eliminated?, saved? }`)
   - `day.claims` — 낮 토론에 이어 밤·아침에도 싣는다(공개된 주장).
   - `spectate { seats[{ seat, job }], picks { mafia, police, doctor } }` — 탈락한 **본인 view 에만**, 탈락한 아침 state 부터(결정 0021). `picks` 는 밤에만 있고 지난 밤 정보는 없다. 키 이름은 `role` 이 아니라 `job`·`isMafia` 다 — 누출 검사가 `role`·`allies` 키를 `view.me` 밖에서 금지하기 때문이다.
5. **받는 사람 규칙**:
   - `pick` 뒤 state 는 행위자(마피아면 살아 있는 마피아 전원)와 탈락자에게만 간다. 그 밖의 소켓은 프레임을 받지 않는다. 거부(`WRONG_PHASE`·`BAD_MESSAGE`)는 보낸 소켓에만 `error` 와 최신 state 다.
   - 밤 `chat`·`emoji` 는 살아 있는 마피아와 탈락자 소켓에만 간다. 낮 방송은 지금처럼 모든 소켓이다.
   - 아침 state 는 모두에게 각자의 view 로 간다. `spectate` 는 탈락자의 view 에만 들어간다.
6. **밤 템플릿 ID**: `nightTarget`("○○ 지목해요", 대상 칸), `nightAgree`("동의해요"), `nightOther`("다른 사람을 지목해요"). 템플릿 표의 `when` 칸(`day`·`night`)이 쓸 수 있는 때를 정한다.
7. **거부 코드는 규칙 하나**다(결정 0016 의 순서: 단계 → 보낸 사람 → 템플릿·값. `claim`·`say`·`emoji`·`pick` 모두):
   - 틀린 단계면 누구든(살아 있든 탈락했든) `WRONG_PHASE`. 맞는 단계는 `say`·`emoji` 가 discussion·night, `claim` 이 claim, `pick` 이 night 다.
   - 맞는 단계에서 보낸 사람이 탈락자면 `BAD_MESSAGE`.
   - 밤에 살아 있는 비마피아의 `say`·`emoji` 는 `WRONG_PHASE`.
   - 예: 아침의 탈락자 say → `WRONG_PHASE`, 낮 토론의 탈락자 say → `BAD_MESSAGE`, 밤의 탈락자 emoji·pick → `BAD_MESSAGE`, 직업 공개 중 탈락자 claim → `BAD_MESSAGE`.
   - **밤 마피아 채팅 줄 번호는 밤 전용 `nextNightSeq`**(밤마다 1부터)이고, 낮 `nextMessageSeq` 는 밤에 바뀌지 않는다. 살아 있는 사람이 낮 `chat` 프레임의 seq 간격으로 밤 메시지 수를 셀 수 없다. 밤 줄은 저장하지 않는다(결정 0017-7). (2026-11-01 결정 0058 로 폐기했다: 밤 줄도 보관하고, 번호는 채널별로 센다)
8. **공개 생존 여부**: `alive` 는 공개 정보다. 살아 있는 사람에게 탈락자의 직업은 보이지 않는다(결정 0021-4). 아침에는 이름과 문구만 나온다.
9. **새 수사 기록 점은 폰 메모리**다. `minifia:records:{방코드}` 에 본 개수만 저장하고 기록 내용은 저장하지 않는다(03-11). 기기를 바꾸면 점이 다시 켜지는 정도의 손해다.
10. **4페이즈 전에는 승패가 없어 판이 끝나지 않는 것이 의도다.** 시민이 모두 탈락해도 판은 계속 돈다.

## 결과

- **되돌리기 비용**
  - `PhaseId` 의 새 값 `night`·`morning` 은 배포 뒤 **되돌릴 수 없다**(one-way, 결정 0016-1). 열린 방의 클라이언트가 이 값을 이미 받는다.
  - `pick` 메시지, 밤 템플릿 ID, view 필드, `spectate` 이름은 **비싸다**(costly) — 서버와 화면을 한 배포에서 함께 고쳐야 하고, 열린 방은 최대 3시간 옛 번들을 쓴다.
  - A1·A2 는 규칙표와 테스트만 고치면 되는 기본값이다.
- 누출 테스트가 이 계약을 지킨다: `test/worker/leak.test.ts`(한 판 전체 프레임 — 살아 있는 소켓에 `spectate`·남의 직업·밤 행동·마피아 채팅 없음, 탈락자는 탈락한 아침부터, `records`·`pick`·`allyPicks` 는 받을 사람만, 낮 seq 연속·밤 seq 는 밤마다 1부터), `test/unit/view.test.ts`(아홉 단계 뷰), `test/worker/night.test.ts`(소켓 단위 받는 사람).
- 결정 0021 의 관전 필드·받는 사람 규칙은 위 4·5 항으로 와이어 계약에 들어왔다.
- 결정 0016 "결과"의 탈락자 거부 문장은 이 결정으로 확정됐다. ROADMAP 3페이즈 성공 기준 4, REQUIREMENTS 의 `REQ-spectator` 행, 기획서의 탈락자 줄은 결정 0021 과 같은 문장으로 맞췄다.
