# 0022 테스트 방에서만 방장이 단계를 넘기고, 대기실로 되돌리고, 자기 직업을 고른다

- 상태: 채택
- 날짜: 2026-10-25

## 배경

- 한 판의 모든 단계를 확인하려면 4명이 모여야 하고 약 3분이 든다. 토론 90초·밤 30초를 매번 기다려야 해서, 화면·판정을 고칠 때마다 한 판을 다 돌리기 어렵다. 사용자가 "단계를 바로 넘기고, 같은 인원으로 처음부터 다시, 내 직업을 골라서" 확인하고 싶다고 요청했다.
- 결정 0017-5 는 방장 연장·넘기기를 일반 방에서 없앴고, 결정 0020 은 행동이 마감을 바꾸지 않는다고 정했다. 이 요청은 그 결정을 되돌리는 것이 아니라 개발·확인용 별도 방이 필요하다는 뜻이다.

## 결정

1. **테스트 방은 방을 만들 때만 정해진다.** 주소에 `?test=1` 을 붙여 연 앱에서 [방 만들기] 를 누르면 `POST /api/rooms` 본문에 `testMode: true` 가 실려, 서버 방 상태에 `testMode` 가 저장된다. 불리언이 아니면 400 `BAD_REQUEST`. 참가 본문의 `testMode` 는 무시된다(스키마가 모르는 키를 버린다). 만든 뒤에는 어떤 메시지로도 바꿀 수 없다.
2. **서버가 확인하는 것** — 신원은 소켓 첨부의 `playerId` 뿐이고(메시지에 seat·방장 여부 칸이 없다), 검사 순서는 `testMode` → 방장 → 단계 → (testRole 만) 직업이다. 일반 방은 `BAD_MESSAGE` 오류 프레임만 보낸다(상태 저장·방송·state 없음) — 이 기능이 없는 방에서는 알 수 없는 메시지와 같게 보여 테스트 기능이 있다는 사실도 드러내지 않는다. 테스트 방의 손님은 `NOT_HOST`, 맞지 않는 단계는 `WRONG_PHASE`, 구성에 없는 직업은 `BAD_MESSAGE` 이고, 이 셋은 오류 뒤 보낸 소켓에만 최신 state 를 보낸다(기존 `sendRejection` 규칙). 새 오류 코드는 만들지 않았다.
3. **메시지 이름과 모양**(strictObject — 덧붙은 키는 `BAD_MESSAGE`):
   - `{ t: "testSkip" }` — 현재 단계를 다음 단계로.
   - `{ t: "testReset" }` — 같은 방 대기실로.
   - `{ t: "testRole", role: "mafia" | "police" | "doctor" | "citizen" | null }` — 다음 판의 방장 직업(null = 무작위).
4. **testSkip** 은 현재 단계 마감을 `now` 로 당긴 상태에 `tick(now, randInt)` 를 부른다. 진입 훅을 따로 부르지 않으므로 정상 마감과 같은 경로(결정 0016 의 ON_ENTER 표)를 타서 밤 판정·아침 문구·일차 증가가 그대로 일어난다. 새 마감은 "당긴 마감 + 다음 단계 길이" 라 정확히 한 단계만 넘어간다. 모든 소켓이 각자 view 를 받고 알람이 새 마감으로 옮겨진다. 대기실(마감 없음)은 `WRONG_PHASE`.
5. **testReset** 은 허용 목록 리터럴로 방·플레이어를 다시 만든다(상태를 펼쳐 복사하지 않는다). 남기는 것: 방 코드·생성·만료 시각, `everConnected`, 방장, 가입 순번, 방 수명 동안 줄지 않는 `nextMessageSeq`, 앉은 사람의 `id`·`token`·`seat`·`nickname`·`nicknameKey`·`joinSeq`·`connected`·`connId`, `testMode`, `testRole`. 지우는 것: 역할·주장·밤 선택·수사 기록·탈락·일차·아침 결과·마지막 문구·밤 채팅 번호·메시지 쿨다운. 소켓은 닫지 않고, 알람은 방 만료로 옮겨진다. 대기실에서는 `WRONG_PHASE`.
6. **testRole** 은 대기실에서만, 지금 앉은 인원 구성에 있는 직업만 받는다(4명이면 의사 없음. 1~3명 대기실은 4명 구성으로 본다). 방 상태 `testRole` 에 저장하고 `testReset` 뒤에도 남겨 새 판마다 다시 쓴다. 시작할 때 인원이 바뀌었을 수 있으므로 실제 앉은 인원 구성에서 다시 확인하고, 없으면 무작위로 둔다. 배정은 보통 섞기를 먼저 하고, 그 직업을 받은 사람 가운데 seat 가 가장 낮은 사람과 방장의 직업을 맞바꾼다 — 직업 수가 구성표 그대로이고, 난수를 더 쓰지 않아 일반 방의 난수 호출 순서도 그대로다. 방장이 이미 그 직업이면 바꾸지 않는다. 성공하면 방장 소켓에만 state 를 보낸다(대기실의 다른 사람 view 는 바뀌지 않는다). 같은 값이면 저장·전송하지 않는다.
7. **view 공개 범위**: `me.testMode: true` 는 테스트 방 방장 본인 view 에만, `me.testRole` 은 그 방장의 대기실 view 에만 실린다. 손님 view·일반 방·미리보기(`GET /api/rooms/{code}`)에는 키 자체가 없다. 방장이 대기실에서 나가 방장이 바뀌면 새 방장 view 에 실린다(view 는 볼 때마다 만든다).
8. **화면**(시안 `design/screens/night-v1/T1-testbtn.dc.html`·`T2-testsheet.dc.html`·`f8.css` 의 `.tt`·`.tt-sheet__*`): 테스트 방 방장에게만 점선 [테스트] 버튼이 보인다. 대기실·낮 장면(직업 공개~아침)은 장면 상자 왼쪽 위, 역할 확인·낮 시작 발표는 위쪽 바 오른쪽 칸에서 [내 역할] 왼쪽이다. 배정(3초)에는 버튼이 없다(서버는 이 단계의 testSkip 도 받는다). 시트는 '테스트 도구' 제목·안내 한 줄·(대기실만) '내 직업' 칩·[다음 단계로 넘기기]·[대기실로 되돌리기] 이다. 넘기기 뒤 시트는 열린 채 '지금: 단계' 가 바뀌고, 되돌리기는 시트를 닫는다. 화면은 요청만 보낸다 — 단계 진행·직업 판정은 서버가 한다(결정 0002). 시안 파일은 저장소 사본(`design/screens/night-v1/`)에 있는 것을 따랐고, 새 시안은 만들지 않았다.

## 결과

- **결정 0017-5(방장 연장·넘기기 제거)와 0020(행동은 마감을 바꾸지 않는다)은 일반 방에서 그대로이며 되돌리지 않는다.** 이 도구는 테스트 방 전용 예외이고, 일반 방에는 버튼도 서버 처리도 없다.
- 와이어 계약(`testMode` 본문, `testSkip`·`testReset`·`testRole` 메시지, `me.testMode`·`me.testRole`)은 배포 뒤 한 방향이라 이름을 바꾸지 않는다.
- 테스트 방은 인증 없이 누구나 만들 수 있다. 피해는 그 방 하나뿐이고 다른 방·일반 규칙에 영향이 없다. 테스트 방을 아는 사람만 쓰는 개발자 도구라 **손님에게 테스트 방 표시를 하지 않는다(수용한 위험)**.
- 확인 스크립트: `node scripts/uat-test-room.mjs --prod` — 단계 넘기기·대기실 복귀·내 직업 지정(마피아 → 시작 → 방장 `me.role` 마피아)과 손님·일반 방·시작 뒤 거부를 배포본에서 증명한다(`UAT TEST-ROOM OK`, 종료 코드 0).
- 테스트 방 사용: `https://minifia.dhplay.workers.dev/?test=1` 에서 [방 만들기], 봇은 `node scripts/bots.mjs <코드> --prod --count 3`. 봇은 대기실로 되돌린 뒤 새 판 1일차에도 직업 공개·밤 행동을 하도록 고쳤다(일차 키 `day.n`, 대기실·배정에서 기록 초기화).
