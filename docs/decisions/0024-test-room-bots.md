# 0024 테스트 방 방장은 서버 봇으로 폰 한 대만으로 4~8명 판을 채운다

- 상태: 채택
- 날짜: 2026-10-25

## 배경

- 한 판의 모든 단계를 보려면 4명이 필요하다. 결정 0022 로 단계 넘기기·대기실 복귀·직업 지정은 되었지만, 사람은 여전히 모아야 했고 외부 `scripts/bots.mjs` 로 채우려면 PC 에서 `node` 를 계속 돌려야 했다. 사용자가 "폰 한 대로 4~8명 판을 테스트하고 싶다" 고 요청했다.
- `scripts/bots.mjs` 는 폰만으로는 못 쓰고, 배포·소켓 끊김에 다시 붙어야 하며, 방장이 대기실로 되돌리면 봇이 새 판을 따라가게 하는 보정도 따로 필요했다. 봇이 방 안에 있으면 이런 문제가 모두 없다.
- 결정 0023(차례 주장)이 채택되었고 아직 구현 전이다. 봇이 직업 공개를 어떻게 하는지가 그때 바뀌므로, 바뀌는 곳을 한 곳으로 모아 둔다.

## 결정

1. **테스트 방·방장·대기실에서만 `testBots` 를 받는다.** 메시지는 `{ t: "testBots", count }` (strictObject, `count` 는 정수 0..7 = `MAX_TEST_BOTS`). 검사 순서와 오류 코드는 결정 0022 와 같다 — 일반 방은 `BAD_MESSAGE` 오류 프레임만(state·저장·방송 없음), 테스트 방 손님은 `NOT_HOST`, 대기실이 아니면 `WRONG_PHASE`, 개수가 틀리면 `BAD_MESSAGE`. 새 오류 코드는 없다.
2. **`count` 는 원하는 봇 수(절대값)다.** 서버가 사람 + 봇 ≤ 8 로 잘라 정확히 그만큼 둔다 — 더할 때는 가장 낮은 빈 자리에, 뺄 때는 가장 높은 자리의 봇부터이고 사람은 건드리지 않는다. 절대값이라 연타해도 같은 요청이다. 사람이 봇 이름을 쓰고 있어 남은 이름이 모자라면 그 수까지만 둔다. 잘린 결과가 지금과 같으면 저장·전송하지 않는다.
3. **봇은 방 상태 안의 가짜 플레이어다.** `Player.isBot: true`, 토큰은 빈 문자열(어떤 `hello` 로도 봇 자리에 붙을 수 없고 `findPlayerByToken` 이 건너뛴다), 소켓 없음(`connId` null), `connected` 항상 true(깨어날 때 연결 재계산도 봇은 그대로 둔다). 닉네임은 5자 이하 고정 목록(봇가나다라·봇마바사아·봇자차카타·봇파하갸냐·봇더러머버·봇서어저처·봇커터퍼허, 모두 5글자 — 결정 0030)에서 사람과 겹치지 않게. 봇은 방장 이어받기 후보가 아니고, 사람이 모두 나가면 봇이 남아 있어도 방이 지워진다. 대기실로 되돌려도(`testReset`) 봇은 남는다. 시작 규칙(연결된 4명 이상)은 그대로이고 봇은 연결된 사람으로 센다.
4. **공개 범위** — `isBot`·`botPlan`·봇 id·토큰은 어떤 view·미리보기·이벤트에도 없다. `PublicPlayer` 는 지금의 다섯 키(`seat`·`nickname`·`connected`·`isHost`·`alive`) 그대로라 손님에게 봇은 평범한 연결된 플레이어로 보인다(닉네임의 '봇' 이 표시). 예외는 방장 본인 대기실 view 의 `me.testBots`(봇 수, 0 포함)뿐이다. 손님·일반 방·게임 중 view 에는 키 자체가 없다.
5. **행동은 서버 안의 순수 규칙 + 방 DO 알람이다.** 계획은 `shared/game/bots.ts` 가 단계(claim·discussion·night)에 들어갈 때 한 번 세우고(`RoomState.botPlan`, 키 = `단계:마감`), DO 알람 하나가 단계 마감·방 만료·다음 봇 행동 중 가장 이른 시각에 깨어난다. 메모리 타이머는 쓰지 않아 배포·하이버네이션에 살아남는다. 단계가 바뀌면 키가 달라져 남은 행동은 저절로 버려진다. tick·단계 표·판정 파일은 고치지 않는다 — 계획은 `reschedule` 에서 맞춘다.
6. **봇에게는 특권이 없다.** 실행은 사람 소켓 처리기와 같은 본체(`applyClaim`·`applySay`·`applyEmoji`·`applyPick`)를 봇 id 로 부르고 `selectClaim`·`say`(서버 1.8초 한도)·`emote`·`pickTarget` 검증과 같은 방송 범위(밤 채팅은 살아 있는 마피아·탈락자, pick 은 행위자 쪽·탈락자)를 그대로 거친다. 거부(`RATE_LIMITED` 포함)는 알릴 소켓이 없어 버린다.
7. **행동 표**(난수 호출 순서가 계약이고 단위 테스트가 고정한다. 단계 마감 500ms 전보다 늦은 행동은 버린다):
   - 직업 공개 — 살아 있는 봇마다 `botClaimChoice`: `randInt(100) < 15` 이면 말 안 함, 아니면 이번 판 직업 중 무작위, 진입 0.5~3.5초 뒤.
   - 낮 토론 — 봇당 최대 2번: 첫 행동은 2~12초, 둘째는 그 뒤 8~38초. 종류는 이모티콘(8종 중 무작위) 또는 "저 아니에요".
   - 밤 — 마피아는 살아 있는 비마피아, 경찰은 살아 있는 다른 사람, 의사는 자신 포함 살아 있는 사람 중 무작위로 1~6초 뒤 `pick`. 마피아 봇은 60% 확률로 8~14초에 밤 채팅(동의해요 또는 이모티콘).
   - 탈락한 봇과, 사람이 한 명도 연결되어 있지 않은 방(버려진 테스트 방)은 행동하지 않는다.
8. **화면** — 대기실 [테스트] 시트의 '내 직업' 칸 아래에 '봇' 줄 `[−] N명 [+]` 와 `[5명 채우기]`(5명이면 네 직업이 모두 나온다). 숫자는 서버 view 의 `me.testBots` 이고 낙관적 값은 없다. 기존 Button 과 토큰만 쓰고(색 리터럴 없음) 탭 대상은 44px 이다. 테스트 도구는 개발자용이라 새 시안은 만들지 않았다.

## 결과

- **결정 0023(차례 주장)을 구현할 때 봇 주장은 `shared/game/bots.ts` 의 `botClaimChoice` 한 함수만 바꾼다.** 그 봇 차례가 아니면 `null` 을 돌려주게 하고, 차례마다 계획이 새로 서도록 `botPlanKey` 에 차례 번호를 더한다. 나머지(계획·실행·알람·누출 경계)는 그대로다.
- `scripts/bots.mjs` 는 일반 방 수동 확인용으로 남긴다. 테스트 방은 서버 봇을 쓴다.
- 와이어 계약(`testBots` 메시지, `me.testBots`)은 배포 뒤 한 방향이라 이름을 바꾸지 않는다. `Player.isBot`·`RoomState.botPlan` 은 DO 저장소에 남는 서버 전용 필드다.
- 확인 스크립트: `node scripts/uat-test-bots.mjs --prod` — 봇 추가·제거(8명 한도, 높은 자리부터), 방장 + 봇 4 로 시작, 봇의 주장·토론 메시지·밤 pick 과 아침 결과, 누출 없음(`isBot`·`botPlan`·`token`·`testBots` 경로), 일반 방·손님·시작 뒤 거부를 배포본에서 증명한다(`UAT TEST-BOTS OK`, 종료 코드 0).
- 테스트 방은 인증 없이 누구나 만들 수 있다. 봇은 그 방 안에서만 움직이고 8석 한도·연결당 속도 제한은 그대로다. 수용한 위험은 결정 0022 와 같다.
