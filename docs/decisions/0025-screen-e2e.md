# 0025 화면 E2E 는 시스템 Chrome 과 playwright-core 로, 브라우저가 방장이 되어 실제 좌표를 검사한다

- 상태: 채택
- 날짜: 2026-10-25

## 배경

- 서버 규칙은 `scripts/uat-*.mjs` 봇 시나리오로 자동 확인되지만, 화면(배치·겹침·잘림·반응)은 사람이 폰으로만 봤다. 사용자가 "직접 할 수 있는 건 모두 자동 테스트로" 를 요청했다.
- 테스트 방(결정 0022)과 서버 봇(결정 0024)이 있어 폰 한 대 분량의 조작으로 원하는 단계·직업·인원을 만들 수 있다. 이 위에 헤드리스 브라우저를 얹으면 배포본의 실제 화면 좌표를 검사할 수 있다.
- 테스트 도구라 시안은 만들지 않았다. 화면 결함을 찾으면 기록만 하고 앱 코드는 이 작업에서 고치지 않는다.

## 결정

1. **도구**: `playwright-core` 를 devDependencies 에 정확한 버전(1.64.1, `^` 없음)으로 넣고 브라우저는 내려받지 않는다(`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`). 이미 설치된 시스템 Chrome 을 환경 변수 `CHROME_PATH` 로 띄운다. 값이 없으면 OS 기본 경로(macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, Windows `Program Files`·`Program Files (x86)`·`LocalAppData` 아래 `Google\Chrome\Application\chrome.exe`, Linux `/usr/bin/google-chrome` 등)를 본다. `CHROME_PATH` 가 있는데 파일이 없으면 기본 경로로 넘어가지 않고 그 경로를 말하며 종료 코드 2 로 끝난다. 앱 번들·배포에 들어가지 않는다(`scripts/e2e/` 전용, 빌드 결과에 playwright 문자열 0). 실행은 `npm run e2e`(= `node scripts/e2e/run.mjs`).
2. **브라우저가 방장이다**: 스크립트는 HTTP 로 테스트 방만 만들고(`POST /api/rooms`, `testMode: true`) 소켓을 열지 않는다. 페이지를 열기 전에 앱 주소의 localStorage `minifia:session` 에 `{ code, token }` 을 심어 브라우저 페이지가 방장으로 접속한다. 스크립트와 페이지가 둘 다 방장 소켓을 쥐면 앱이 앞 소켓을 4001 로 대체하기 때문이다. 방장 동작(봇 수·내 직업·[게임 시작]·단계 넘기기)은 실제 [테스트] 시트 버튼을 눌러 한다 — 테스트 도구 화면도 함께 검사된다.
3. **단계·직업은 페이지가 받은 state 프레임으로만 안다**: `framereceived` 만 구독해 `phase`·`me.role`·`me.allies`·`me.records`·`me.pick`·`players` 등을 추적한다. 보낸 프레임(hello 에 토큰이 있다)은 구독하지 않고 받은 프레임 원문도 찍지 않는다.
4. **검사 ID 와 기준**(결과 표의 항목 칸): S(준비) · G(공통: 가로 스크롤·화면 밖·탭 대상 44px·콘솔 오류·실패 요청·외부 요청) · L(대기실 [테스트]·봇 줄) · T(테스트 시트) · D(낮 장면) · C(채팅 내역·연장 버튼 없음) · N(밤) · M(아침) · R(수사 기록). 수치: 위쪽 제목 높이 ≤ 줄 높이의 1.6배, 얼굴 = 캐릭터 상자 위 45%, 겹침 허용 0.5px, 탭 대상 44px, 하단 패널 157px. 출처는 `design/screens/day-v3/SPEC.md`·`night-v1/SPEC.md`. 결과 한 줄은 `시나리오 | 크기 | 항목 | 결과 | 내용`, 종료 코드는 모두 통과 0 · 실패 1 · 중단 2.
5. **결함은 기록만 한다**: 알려진 결함 D1(경찰 방장 직업 공개의 위쪽 제목 줄바꿈)과 D4([테스트] 버튼이 캐릭터 상자와 겹침)는 평범한 단언이라 실패로 나온다. 허용 목록(`DECORATIVE_ALLOW`·`TAP_ALLOW`)에는 `.mf-tt`·`.mf-phasebar`·`.mf-dt__tag`·`.mf-dt__seat` 를 넣지 않고(단위 테스트가 막는다) 기준 수치를 낮추거나 특정 흐름·크기에서 검사를 건너뛰지 않는다. 고치는 일은 화면 변경이라 시안을 먼저 승인받는 별도 작업으로 하고, 고친 뒤 `npm run e2e` 로 회귀를 확인한다.
6. **보안**: 대상 주소는 `scripts/prod-url.txt` 가 기본이고 localhost·127.0.0.1·[::1] 의 http 만 받으며, 그 밖의 https 는 `--url` 로 명시했을 때만, 사용자 정보가 든 주소와 다른 scheme 은 거부한다(네트워크·브라우저보다 먼저 확인하고 실패하면 종료 코드 2). 브라우저는 대상 주소와 앱 글꼴 두 호스트(`fonts.googleapis.com`·`fonts.gstatic.com`) 밖의 요청을 막고 G6 로 보고한다. 모든 출력은 그 실행에서 받은 토큰을 가리는 한 함수로만 나가고, 추적·영상·HAR 기록을 켜지 않는다. 배포본에는 테스트 방만 만들고 동시에 최대 3개, 흐름이 끝나면 대기실 복귀·나가기로 방을 지운다.
