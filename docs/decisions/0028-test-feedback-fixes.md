# 0028 실기기 테스트 피드백 반영: 밤 끝 알림 제거, 차례 링 앞뒤 층, 밤 시작 문구, 테이블·캐릭터 기하 P2 고정

- 상태: 채택
- 날짜: 2026-10-25

## 배경

- 2026-10-25 실기기 테스트에서 네 가지 피드백이 나왔다: 밤 끝 알림이 거슬린다, 차례 링이 캐릭터 발을 감싸 보이지 않는다, 밤으로 넘어가는 순간이 밋밋하다, 대기실에서 낮으로 넘어갈 때 테이블과 캐릭터 위치가 바뀐다.
- 네 번째에 대해 사용자가 시안 P2(`design/screens/table-v1/`, 승인 사본)를 승인하고 테이블·캐릭터 기하를 모든 상황(대기실·역할 배정·낮·밤·아침)에서 고정하라고 요청했다. 이전 판 계획에서 범위 밖이던 「낮 테이블·캐릭터 위치(대기실과 낮의 기하 통일)와 역할 배정 화면이 늘어나는 문제」를 이 결정이 포함한다.
- 서버 규칙·시간·와이어·좌석 번호(`lowestFreeSeat`)·낮 차례 순서는 이 결정에서 바뀌지 않는다. 모두 화면 쪽 변경이다.
- 실행은 quick 261025-qvx 이다.

## 결정

1. **밤 끝 알림을 없앤다.** 결정 0026-6 의 알림 조항(눌러서 활동 기록 탭을 여는 알림)을 대체한다. `RoleCardToast`·`rolecard-toast.css`·DayScene 연결·활동 기록 열기 연결·`JOURNAL_TEXT.notice` 를 지운다. [역할 카드] 앰버 점·활동 기록 탭 안읽음 점·`NEW` 알약·폰 메모리의 읽은 개수는 그대로다. UI-SPEC 의 R6 알림 화면과 S13(좁은 폭 알림 여백 예외)은 폐기하고, E2E R6 은 「밤 끝 알림이 화면에 없음」을 보는 검사로 바뀐다.
2. **(결정 0030-1 이 대체: 발밑 원 전부가 후광으로 바뀌었다.) 차례 링을 자리 쌓임 맥락 안에서 두 호로 나눈다.** `.mf-dt__spot` 은 쌓임 맥락이 없는 묶음이고 안에 뒤쪽 호(`--back`, z-index -1, 윗쪽 반)와 앞쪽 호(`--front`, 그림 다음 마크업 순서, 아랫쪽 반)가 있다. 링의 크기(폭 140%·높이 24%)·두께 3px·색 gray-50·빛 18px 은 그대로이고 차례 자리마다 묶음은 정확히 하나다. 이름표 1~11·캐릭터 12~22·어둡게 층 30·방금 탈락한 유령 31·이모티콘 60+ 의 바깥 z 규칙은 불변이고 E2E D3a 가 그대로 통과한다. 새 E2E 검사 K4 가 두 호의 z-index·position·clip-path·DOM 순서를 본다.
3. **테이블·캐릭터 기하를 시안 P2 로 고정한다.**
   - 390폭(장면 폭 366)에서 테이블 면 216×108(위 150, 가로 가운데), 좌석 원 cy 210·rx 146·ry 100, 캐릭터 72×96·k0 0.8. cy 적응 규칙(`cy = max(177, min(210, 장면 높이 − 122))`)은 그대로다.
   - 다른 폭은 규칙으로: `rx = clamp(floor(장면 폭/2 + 장면 여백 − 49), 124, 150)`, `면 폭 = 2·(rx − 38)`. 장면 여백은 폰 폭 < 390 이면 4, 아니면 12.

     | 폰 폭×높이 | 장면 폭×높이 | 여백 | rx | 면 폭 | 면 left |
     |-----------|-------------|------|----|-------|---------|
     | 360×640 | 352×363.8 | 4 | 131 | 186 | 83 |
     | 375×667 | 367×390.8 | 4 | 138 | 200 | 83.5 |
     | 390×664 | 366×387.8 | 12 | 146 | 216 | 75 |
     | 430×932 | 406×655.8 | 12 | 150 | 224 | 91 |

   - 시안 SPEC 의 규칙 「rx = 장면 폭/2 − 36.4」 와 「면 폭 = 2·(rx − 38.4)」 를 쓰지 않는 이유: 앞 식은 360폰에서 rx 139.6 이 되어 99px 이름표(5글자)가 4·8명판 양옆 자리에서 폰 밖으로 최대 9.6px, 5명판 아래 양옆에서 2.8px, 7명판에서 6.1px 나가고 [테스트] 가 7명판 자리 3 과 깊이 9.8 로 겹친다. 뒤 식은 승인값 216 이 아닌 215.2 를 낸다. 390폭에서 승인값을 그대로 재현하는 규칙으로 바꿨다.
   - 4~8명 모두에서 캐릭터 상자는 장면 안에 있고(최소 여백 4.6, 390폭) 양옆 캐릭터는 발 줄에서 테이블 면과 4px 이상(계산 최소 6.2) 떨어진다. 이름표 보이는 비율 바닥(D3b)·D2·D4·D9 는 그대로 통과한다. 옛 기하의 8명판(60.7~63.2 %)과 같거나 낫다.
   - **칼날 경계**: 이름표 여유 49(`RX_TAG_HALF`)에서 양옆 자리(4·8명판, 정확히 180°)의 99px 이름표는 장면 상자 밖으로 최대 13px 나간다(390폭에서 장면 기준 −13). 폰 안이라 보이지만 폰 가장자리 여유가 390폭·360폭에서 −0.5px 이다(E2E D2·G2 는 폰 폭 전체로 `left ≥ −0.5` 허용). 5글자 이름표가 실기기 글꼴에서 99px 을 넘으면 폰 가장자리에 걸린다. 대안은 이름표 여유 49 → 50(상수 하나, 390폭 rx 145·면 214·양옆 간격 6.7). 이 결정은 승인값 146/216 을 따르고 한계를 문서와 실기기 목록에 남긴다. E2E 봇 이름은 3글자(70px)라 E2E 로는 이 경계가 시험되지 않는다(결정 0030-7 이 봇·방장 이름을 5글자로 바꿔 이후 E2E 가 늘 시험하며 통과했다).
4. **장면 상자는 모든 단계에서 같고, 대기실·배정도 `DayTable` 을 쓴다.**
   - 위 = 헤더 119.2, 아래 = 뷰포트 − 하단 패널 157(패널이 비어도 157 + 안전 영역), 좌우 여백 12(폰 폭 < 390 이면 4). 대기실의 머리·시트와 배정의 머리·빈 패널이 같은 값을 쓴다. `stageBox.test.tsx` 가 낮·대기실·배정 CSS 에서 이 숫자가 같음을 교차 확인하고 E2E T1 이 같은 폰에서 단계마다 장면 상자·테이블 면·내 캐릭터 사각형이 ±0.5px 같음을 본다.
   - 대기실에서 n 명은 좌석 번호 순서의 등간격 타원에 앉는다(내가 맨 아래 가운데, 2명 마주 봄, 3명 삼각, E2E L6). 사람이 들어오고 나가면 나머지가 짧은 CSS 전이(`var(--dur-med)`)로 새 자리로 미끄러진다. 축소 모션에서는 전이가 없다. 방장 왕관·끊김 흐림·끊긴 사람 내보내기 누르기·입장/퇴장 전이·내 링은 그대로다.
   - 서버 좌석 번호와 낮 차례 순서는 바뀌지 않는다. 옛 대기실 `Table`·`shared/seatLayout.ts`·퍼센트 기하·이전 계획의 비트반전 표시 슬롯 안은 폐기한다.
   - 역할 배정은 같은 테이블 위 어두운 막과 안내이고 역할·동료를 읽지 않는다(마크업이 역할 없이 동일, 결정 D-12 유지). 시안 P5 의 [역할 카드] 버튼·진행 막대는 그리지 않는다.
5. **밤 시작 문구는 클라이언트 오버레이다.** (결정 0030-5 가 낮 시작 문구와 한 부품 `SceneIntro` 로 합쳤다. 규칙은 그대로.) 같은 접속(epoch)에서 비밤 단계 → 밤으로 넘어가는 순간에만 모든 사람 화면(탈락자 포함)에 `N일차` / `밤이 되었습니다` 가 한 번 떠서 사라진다. 길이는 낮 시작 발표와 같은 `DAY_ANNOUNCE_MS`(2초), 번짐 800ms·ease-out, 축소 모션은 전역 규칙이 처리한다. 처음 마운트·재접속·밤 안의 다시 그리기에서는 뜨지 않고 터치를 막지 않으며(`pointer-events: none`) 역할에 따라 문구가 달라지지 않는다. 서버 단계·시간·와이어는 바뀌지 않는다. 막 색(`--night-950` 85%)·중앙 불투명도는 디자인 재량이다. E2E N6(밤 시작 직후 한 번 보임)·N7(3.5초 안에 사라짐).

## 결과

- **되돌리기 비용**: 모두 화면 쪽 변경이라 **쉽다**(reversible). 기하 숫자는 `src/game/dayTable.ts` 한 곳(상수 `SEAT_RX_MIN`·`SEAT_RX_MAX`·`RX_TAG_HALF`·`FELT_SIDE`·`SCENE_PAD_*` 와 `seatRx`·`feltWidthOf`)이고, 이름표 여유 49 → 50 은 상수 하나다. 알림을 되살리려면 결정 0026-6 의 문구를 다시 쓰고 부품을 새로 만들어야 하지만 서버는 건드리지 않는다.
- 기준 수치(OVERLAP_EPS 0.5, ONE_LINE_FACTOR 1.6, FACE_RATIO 0.45, TAP_MIN 44, PANEL_H 157)와 허용 목록(`TEXT_SIZE_ALLOW` 는 `.mf-journal__new`·`.mf-tt*` 뿐)은 그대로이고, 완화는 이미 승인된 M1·D3a/D3b·D4 뿐이다(결정 0030-8 이 2026-10-26 에 5명판 D3b 바닥 98.0% 완화 D3b-5 를 더했다). 새 검사: K4(링 앞뒤 층)·N6/N7(밤 시작 문구)·T1(단계가 바뀌어도 장면 상자·테이블·내 캐릭터 그대로)·T2(양옆 캐릭터가 테이블 면 바깥)·L6(대기실 둘이면 마주 봄·셋이면 삼각).
- 03.1-UI-SPEC 의 알림(R6·S13·S10·F4)·옛 기하 숫자·가독성 표를 이 결정에 맞게 고쳤고(승인 시안 사본 `design/screens/table-v1/` 은 고치지 않았다), HANDOFF 에 실기기 확인 목록을 남겼다.
- **아티팩트 동기화 목록**(디자인 세션 몫, GSD 에이전트는 아티팩트를 열 수 없다):
  - 화면설계서: R6 알림 화면 삭제, 차례 링 앞뒤 층, 밤 시작 문구, 대기실·배정·낮 공통 테이블 기하와 장면 상자.
  - 디자인 시스템: 테이블 면·좌석 원 숫자(폭별 규칙 포함).
- 열린 위험: 5글자 이름표 칼날 경계(−0.5px, 위 3번)는 실기기 글꼴로만 확인된다. 걸리면 이름표 여유를 50 으로 올린다.
