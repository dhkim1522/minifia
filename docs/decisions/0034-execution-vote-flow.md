# 0034. 처형 투표 흐름: 여부 → 후보 선택 → 변론 → 처형

- 날짜: 2026-10-26
- 상태: 확정(4페이즈 논의), 시안·구현 전
- 이전: 기존 기획(후보 선택 20초 → 변론 20초 → 찬반 10초 → 처형 5초), 0016(단계 표), 0021(관전)

## 결정

1. 처형은 "할지 말지"를 먼저 정한다. 여부 투표(10초, 찬성/반대) 과반이면 후보 선택(15초), 최후 변론(10초), 처형(5초)으로 간다. 변론 뒤 찬반은 없앴다. (2026-11-02 결정 0060 으로 v2.0 에서 개정했다: 토론 끝내기 → 지목 → 변론 → 찬반 → 처형. 여부 투표와 후보 선택은 없어지고, 변론 뒤 찬반이 돌아온다)
2. 과반·최다는 **던진 표** 기준이다. 기권 버튼은 없고, 시간 초과·연결 지연으로 못 보낸 표는 무효표로 세지 않는다. 동률이거나 던진 표가 없으면 처형하지 않는다. 후보 선택에서 자기 자신은 고를 수 없다.
3. 처형된 사람의 직업은 판이 끝날 때까지 비공개다.
4. 마감 뒤 투표 공개는 화살표와 표수 배지를 한 명씩, 무작위 순서로(서버가 정함) 보인다. 투표 기록은 유저 기록 카드에 날짜별로 쌓인다.
5. 변론·처형은 후보가 테이블 가운데로 이동해 스포트라이트, 나머지는 흐림·어두움(시간대별 최대 어두움). 투표 단계는 해질녘 배경(`verdictDusk`)으로 전환한다. (2026-11-02 결정 0060 으로 v2.0 에서 개정했다: 변론자는 무대 위에 서고 나머지는 모이는 자리 원 위에 선다 — 0060-7)
6. 승패는 처형 직후와 아침 직후 즉시 판정한다. 결과 화면은 승패·모든 역할·판 요약이다. 요약은 판 종료 때만 서버가 전체에 보낸다.
7. 이 결정은 요구사항 VOTE-01~04, ROADMAP 4페이즈 성공 기준, `docs/product.md` 진행 표를 바꾼다. 와이어 계약(단계 ID, 투표 메시지, 공개 결과, 종료 결과)은 계획에서 정해 이어서 적는다.
8. 알림: `docs/product.md` 에 있던 "투표 공개 방식 (결정 0011)" 표기는 번호가 틀렸다(0011 은 데스크톱·코드 분담). 이 결정이 투표 공개 방식을 대신한다.
9. 투표 공개는 각 투표 뒤 별도 4초 구간이다(처형 구간 최대 약 48초). 배경 어두움은 시간대별로 나누지 않고 퍼센트 한 값(시작 45%, 흐림 3px)을 쓴다. (→ 결정 0039: 공개 구간은 고정 4초가 아니라 한 표 2초, 서버가 표 수로 400 + n×2000 + 600(0표 2초), 처형 구간 최대 60초)
10. 처형 문구 4개("조용히 눈을 감았습니다"는 아침 묶음에만 둔다)와 변론 템플릿 6개를 확정했다(`04-CONTEXT.md` D-11·D-13). 아침 묶음의 "이슬이 되어 사라졌습니다"는 처형 쪽으로 옮긴다.
11. 여부 투표는 익명이다: 찬성·반대 집계 수가 실시간으로 보이고 마감 전까지 번복할 수 있으며, 누가 무엇을 골랐는지는 서버가 보내지 않는다. 화살표 공개는 후보 선택 투표에만 쓰고, 공개 구간 4초도 후보 선택 뒤에만 둔다(5·9항 수정). (2026-11-02 결정 0060 으로 v2.0 에서 폐기했다: 여부 투표 자체가 없어지고, 찬반은 변론자를 뺀 산 사람 기준 — 0060-4)
12. 여부 투표 시작 때 메인 화면에 적색 계열 '처형 투표' 카드가 위에서 떨어져 중앙에 멈췄다가 사라진다(코드로 제작, 약 1.6초, 탭 통과). (→ 결정 0039: 처형 투표 카드는 3초, 여부 투표는 13초. 처형 무효 카드는 1.6초 그대로) (2026-11-02 결정 0060 으로 v2.0 에서 폐기했다: 처형 투표 카드 단계가 없다 — 0060-1)
13. 색 의미: 낮의 공개 투표 = 노란색(앰버), 죽음·마피아(밤 암살, 처형 집행) = 진홍. 화살표 모양은 직선(A) 확정. 득표가 사실상 확정되면 그 후보의 캐릭터와 표수 칩이 두근 효과를 낸다(`04-CONTEXT.md` D-31·D-32·D-33).
14. 와이어 계약·규칙표는 결정 0036 에 적었다.
