# 0036 처형·승패는 서버 단계 여섯 개로 돌고, 여부 투표는 집계 수만, 후보 선택은 마감 뒤 서버가 정한 순서로 공개하며, 판 결과는 종료 단계에서만 보낸다

- 상태: 채택
- 확인: 2026-10-30 사용자가 실기기 확인과 기본값을 모두 승인했다(전체 승인, 항목별 기록 없음).
- 날짜: 2026-10-26

## 배경

- 결정 0034 가 처형 흐름을 "여부 → 후보 선택 → 변론 → 처형" 으로 바꾸고, 와이어 계약(단계 ID, 투표 메시지, 공개 결과, 종료 결과)을 계획에 맡겼다(0034-7). 이 문서가 4페이즈 서버·공유 로직 웨이브(04-01~04-08)가 만든 와이어 계약과 규칙을 한 곳에 적는다. 이름은 `shared/protocol.ts`(04-01 이 정함)를 그대로 옮겼고, 화면 계획(시안 승인 → `/gsd-ui-phase 4` 뒤)과 누출 테스트가 이 문서를 기준으로 삼는다.
- 입력: 결정 0016(단계 표·훅 표), 0020(밤·아침 계약, 비공개 값은 받을 사람에게만), 0021(탈락자 관전), 0027(차례 단계의 와이어 선례), 0022·0024(테스트 방·봇), 0018(사회적 채널은 매너).
- 누출 검사 `test/unit/view.test.ts`(4~8명 × 시드 전수, 익명 차분 포함)와 `test/worker/leak.test.ts`(처형 경로를 더한 한 판의 모든 실제 프레임)가 이 계약을 지킨다.
- 화면 연출(D-14~D-16·D-19~D-24·D-29~D-35·D-38 — 해질녘 배경, 스포트라이트, "처형 투표" 카드, 화살표, 두근 효과, 회색 "처형 무효" 카드, 관전 표시)은 서버에 영향이 없다. 서버 시간표에 연출 시간을 넣지 않는다. (→ 결정 0039: 공개 슬롯 시간표(앞·한 표·뒤)만 서버 단계 길이에 들어가고, 화살표가 자라는 시간·사라짐 같은 연출 값은 여전히 화면에만 있다)

## 결정

1. **단계와 시간**: `discussion` 90 → `execVote` 10 → [통과] `candidateVote` 15 → `candidateVoteReveal` 4 → [후보 있음] `defense` 10 → `execution` 5 → `ended` 또는 `night`(초). 여부 투표 뒤에는 공개 구간이 없다(`execVoteReveal` 단계를 두지 않는다). 처형 구간은 최대 44초(10 + 15 + 4 + 10 + 5). (→ 결정 0039: 토론 40초, 여부 투표 13초, 공개 400 + n×2000 + 600(0표 2초), 처형 구간 최대 60초) 시간은 `shared/game/phases.ts` 한 곳(`EXEC_VOTE_MS`·`CANDIDATE_VOTE_MS`·`candidateRevealMs`·`DEFENSE_MS`·`EXECUTION_MS`)이다. 투표는 조기 종료하지 않고 0표여도 정해진 시간을 거친다(D-28). 어떤 투표 행동도 `phaseEndsAt` 을 바꾸지 않는다 — 마감을 당기면 투표 타이밍이 샌다(claim 의 `selectClaim` 과 다르다). (2026-11-02 결정 0060-1 로 v2.0 에서 개정했다: 단계는 discussion → nomination → defense → verdict → execution → night → morning)
2. **분기 규칙**: 단계 표의 `next` 는 "기본 다음 단계" 데이터일 뿐이고, 분기는 `tick` 의 마감 훅(`ON_DEADLINE`)이 `next` 를 돌려 정한다 — `execVote`(미통과 → `night`), `candidateVoteReveal`(후보 없음 → `night`), `execution`·`morning`(승패 → `ended`). 훅이 `next` 를 주지 않으면 표의 기본 `next` 로 간다. 마감은 항상 "이전 마감 + 다음 단계 길이" 로 이어진다(알람이 늦어도 모든 폰이 같은 마감). 진입 훅은 진입 시각 `at` 을 세 번째 인자로 받는다.
3. **여부 투표**: 메시지 `{ t: "execVote", agree: boolean }`. 규칙표: (2026-11-02 결정 0060-4 로 v2.0 에서 폐기했다: 여부 투표 메시지·집계는 찬반 `verdict` 로 바뀌고 분모는 변론자를 뺀 산 사람 수)

   | 상황 | 결과 |
   |---|---|
   | 던진 표 0 | 통과 아님 → 밤 |
   | 찬성 × 2 > 던진 표 (분모는 **던진 표**, 생존자 수가 아니다) | 통과 → 후보 선택 |
   | 동률, 반대 다수 | 통과 아님 → 밤 |
   | 던진 표 1(찬성) | 통과 (알려진 한계 참고) |
   | 마감 전 번복 | 마지막 값이 유효, 집계 수는 즉시 바뀐다 |
   | 같은 값 재전송 | 상태 불변, 저장·전송 없음 |
   | 마감 뒤 도착 | `WRONG_PHASE` (보낸 소켓에만 error + 최신 state) |
   | 탈락자·방에 없는 사람 | `BAD_MESSAGE` |
   | 던진 뒤 연결이 끊김 | 던진 표는 유효 (못 보낸 표만 무효, CONN-02) |

   받는 사람: 값이 바뀌면 방의 모든 소켓이 각자 view 를 받는다(집계 수는 공개 정보, D-02). 개인 표 `Player.execVote` 는 서버 전용이고 마감 훅이 집계 직후 키째 지운다 — 익명을 "보내지 않는다" 만이 아니라 "서버에도 남지 않는다" 로 지킨다. 실시간 집계와 마감 집계는 같은 함수(`execTallyOf`)다.
4. **후보 선택**: 메시지 `{ t: "candidateVote", target: number }`. 검사 순서는 단계(`WRONG_PHASE`) → 행위자(방에 있고 생존, 아니면 `BAD_MESSAGE`) → 대상(정수·앉은 생존자, 자기 자신·탈락자·없는 자리는 `BAD_MESSAGE`) → 같은 값이면 입력 그대로. 최다 득표 한 명이 후보이고, 동률·0표는 후보 없음이다(난수로 고르지 않는다, D-03). 번복은 마지막 값이 유효하다. 받는 사람: 투표자 본인 소켓에만 state(`me.voteTarget`)를 보낸다 — 방송하지 않고 관전자에게도 보내지 않는다(남의 선택은 보이지 않는다, D-19). (→ 결정 0040: target 은 number | null 이고 null 은 취소다. 고른 표가 있으면 지우고 투표자에게만 state, 없으면 무전송) (2026-11-02 결정 0060-3 으로 v2.0 에서 개정했다: 메시지는 `point`, 지목은 공개 정보이며 취소 없이 바꾸기만 한다)
5. **공개 구간**: `candidateVoteReveal` 진입 때 서버가 던진 표를 seat 오름차순으로 모은 뒤 Fisher–Yates 로 섞어 `day.voteLog[그날].cand.votes` 에 그 순서로 싣는다 — 배열 순서가 모든 폰의 공개 순서다(D-20). 난수 호출 계약: 던진 표 수 n ≥ 2 이면 `i = n-1 … 1` 에 `randInt(i+1)`, n ≤ 1 이면 부르지 않고, `randInt(0)` 은 부르지 않는다. 화면이 4초 안에 연출을 맞춘다(D-21). (→ 결정 0039: 화면 시간표 끝 + 600ms = 서버 마감) 확정 판정(두근 효과, D-31)은 화면이 `votes` 로 계산한다 — 서버 추가 필드가 없다. 무효표는 줄이 없다. (2026-11-02 결정 0060-3 으로 v2.0 에서 폐기했다: 후보 공개 구간은 없고 지목은 처음부터 공개다)
6. **메시지 허용표**: 쿨다운은 빠른 메시지와 이모티콘 합산 1.8초 그대로.

   | 단계 | `say` | `emoji` |
   |---|---|---|
   | discussion · execVote · candidateVote | 생존자, 낮 템플릿 (D-12) | 생존자 |
   | defense | **후보만**, 변론 템플릿 여섯 개 (후보가 아닌 생존자의 say 는 `WRONG_PHASE`, 후보가 낮 템플릿을 보내면 `BAD_MESSAGE`) | 생존자 누구나 (D-13) |
   | candidateVoteReveal · execution · ended | 아무도 못 보냄 (`WRONG_PHASE`) | 아무도 못 보냄 (`WRONG_PHASE`, A3) |

   변론 템플릿 ID 와 화면 문장: `defNotMe`(① 저 아니에요) · `defCitizen`(② 저는 시민이에요) · `defSuspect`(③ [○○] 의심해 주세요, 대상) · `defTrust`(④ [○○] 믿어 주세요, 대상) · `defRole`(⑤ 제가 [직업]입니다, 직업) · `defPlead`(⑥ 한 번만 믿어 주세요). 서버는 ID 와 고른 값만 받는다(COMM-04). 기존 `innocent` 와 문구가 같아도 ID 를 따로 둔다(때가 한 값이라 판정이 단순).
7. **처형**: `execution` 진입 때 후보를 탈락(alive false)시키고 문구 번호를 `1..EXECUTION_PHRASE_COUNT`(4) 중 직전 처형 문구를 뺀 오름차순 후보에서 `randInt` 한 번으로 정한다(아침 문구와 따로 센다). `day.execution { seat, phrase }` 는 처형 단계에만 실린다. 직업은 싣지 않는다(D-09) — 처형된 본인은 탈락자 관전(결정 0021)으로 모두의 직업을 받는다. 문장은 화면 표가 만든다(D-11): ① 더는 함께할 수 없게 되었습니다 ② 형장의 이슬이 되었습니다 ③ 잔혹하게 처형되었습니다 ④ 처형대에 올랐습니다 — 이름 뒤에 항상 "님이". "조용히 눈을 감았습니다" 는 아침 묶음에만 있다. (2026-11-02 결정 0060-5 로 v2.0 에서 개정했다: 처형 발표에는 좌석만 싣고 문구 번호는 없앤다)
8. **처형 무효(D-34)**: 처형이 성립하지 않아 밤으로 온 그 밤 단계의 view 에만 `day.noExecution { reason }` 을 모두에게 같게 싣는다. 이유 코드:

   | reason | 뜻 |
   |---|---|
   | `notMajority` | 여부 투표에서 찬성이 과반이 아님 — 반대 다수·동률 |
   | `noVotes` | 여부 투표나 후보 선택에서 던진 표가 0 |
   | `tie` | 후보 선택 최다 득표 동률 |

   서버 상태 필드를 따로 두지 않는다. 그날 공개 투표 기록(`voteLog`)에서 파생하므로 아침으로 넘어가면 저절로 사라진다(수명). 처형이 이뤄진 날의 밤, 다른 모든 단계, `ended` 에는 키가 없고, 키는 정확히 `reason` 하나(개인 정보 없음)다. 회색 "처형 무효" 카드(약 1.6초)는 밤 시작 화면 위 클라이언트 연출이며 단계 시간을 늘리지 않는다. 여부 투표 동률을 `notMajority` 로 묶은 것은 바뀔 수 있는 기본값이다.
9. **아침 문구**: 처형 쪽으로 옮긴 한 문장("이슬이 되어 사라졌습니다")을 빼고 일곱 개(`MORNING_PHRASE_COUNT` 8 → 7)다. 번호가 한 칸씩 당겨지며, 열린 방의 옛 번들은 범위 밖 번호를 첫 문구로 보여 준다(최대 3시간, 무해).
10. **승패**: `execution`·`morning` 마감에서만 판정한다 — 아침 5초를 보여 준 뒤 종료한다(D-10). 살아 있는 마피아 0 → 시민 팀, 살아 있는 마피아 ≥ 나머지 생존자 → 마피아 팀(END-01). 분모는 연결 여부와 무관한 생존자(D-05, CONN-02). 역할이 배정되지 않은 상태는 판정하지 않는다. 와이어 승리 값은 `GameWinner` = `citizenWin` | `mafiaWin` 이다(`mafia`·`citizen` 은 누출 검사의 역할 단어 목록이라 쓰지 않는다).
11. **종료(`ended`)**: 마감이 없는 종단 단계(`durationMs` null — 마감이 과거로 남아 알람이 재발화하지 않게). 진입 때 `winner` 를 기록하고 방 만료를 진입 시각 + 30분(기존 만료가 더 이르면 그대로)으로 앞당긴다(D-28) — 새 타이머 없이 기존 만료 알람이 정리한다. `result { winner, seats[{seat, job}] 전원, summary }` 는 `ended` 단계 view 에만 모두에게 같게 실린다(D-17). `summary` 는 날짜별 한 줄 `{ n, exec?{yes, no, passed, candidate?}, night?{target?, died} }` 이고, 지목했는데 `died` 가 false 면 의사가 지킨 밤이다(D-27). 밤 기록(`nightLog`)은 판 중에는 어떤 view 에도 없다(결정 0020-3: 게임 중에는 의사 구출이 지목 없음과 구별되지 않아야 한다). 방이 만료되면 소켓은 `room_closed` 로 닫힌다 — 결과 화면의 [처음으로]·닫힘 처리는 화면 계획이 정한다.
12. **view 필드와 받는 사람**:

    | 필드 | 단계 | 받는 사람 |
    |---|---|---|
    | `day.execTally {yes, no}` | execVote | 모든 viewer, 같은 값 (관전자 포함, A13) |
    | `me.voteAgree` | execVote | 생존한 본인만 |
    | `me.voteTarget` | candidateVote | 생존한 본인만 (취소하면 키 없음, 결정 0040) |
    | `day.voteLog[] {n, exec{yes,no,passed}, cand?{votes[{seat,target}], candidate?}}` | 낮 단계마다(`ended` 포함) | 모두. `cand` 는 공개 구간부터 |
    | `day.candidate` | candidateVoteReveal · defense · execution (후보가 있을 때) | 모두 |
    | `day.execution {seat, phrase}` | execution | 모두 |
    | `day.noExecution {reason}` | 처형 무효로 온 night | 모두 |
    | `result {winner, seats, summary}` | ended | 모두 |

    **의도적으로 없는 키**: 여부 투표 개인 줄(`voteLog[].exec.votes` 없음 — 타입에도 없다), "몇 명 투표함" 류 진행 요약, `players[]` 의 투표 표시(키는 다섯 개로 고정), 진행 중 후보 선택의 남의 값, 처형자의 직업(`ended` 전), 진행 중 밤 기록. **서버 전용 키**: `Player.execVote`·`Player.candidateVote`·`RoomState.verdict`·`nightLog`·`lastExecPhrase` 는 어떤 프레임에도 없다(누출 검사의 키 이름 금지 목록에 넣는다). `winner`·`execution` 은 같은 이름의 view 키(`result.winner`·`day.execution`)가 있어 키 이름 금지 목록에는 넣지 않고 경로·단계로 검사한다.
13. **테스트 방·봇(결정 0022·0024)**: 서버 봇은 여부·후보 선택에 사람과 같은 처리기로 투표하고, 후보인 봇만 변론한다(대상·직업이 필요 없는 템플릿). `testSkip` 은 투표 단계에서 아직 안 던진 봇을 지금 던지게 한 뒤 분기를 따라 넘긴다(사람의 표는 건드리지 않는다). 대기실 복귀(`testReset`)는 허용 목록 리터럴로 방을 다시 만들어 새 필드를 모두 지운다. 종료 뒤 대기실로 복귀하면 앞당긴 만료가 다음 시작 때 다시 3시간이 된다.
14. **`day.voteLog` 의 optional 표기**: 타입은 optional 이지만 서버는 낮 단계마다(`ended` 포함, 빈 배열 포함) 항상 싣는다. 타입을 필수로 하면 화면 테스트의 `DayView` 리터럴이 서버 웨이브에서 한꺼번에 바뀌므로 화면 계획이 필요하면 필수로 올린다. `ended` 도 `day` 를 싣는다(공개 정보뿐). (2026-11-02 결정 0060-11 로 v2.0 에서 개정했다: 모양은 유지하고 exec = 찬반 결과, cand.votes = 지목 마감의 최종 지목, cand.candidate = 변론자)
15. **배포**: 서버 웨이브만 따로 배포하지 않는다(D-26). 새 단계를 모르는 클라이언트는 `연결 중…` 에서 멈추므로 새 단계를 그리는 화면 계획과 한 단위로 배포한다.

## 알려진 한계

- **소규모 방의 산술 추론**: 집계 수를 실시간으로 공개하므로 4명 중 3명이 던져 찬성이 3 이면 모두가 누가 찬성했는지 안다. 본인 표를 아는 사람이 "나 빼고 N명 중 찬성 k" 를 뺄셈으로 계산하는 것도 같다. 집계 공개(D-02)의 필연이며 서버가 막을 수 없다.
- **1표 통과·1표 처형**: 분모가 던진 표라서(D-02~D-04), 다른 생존자가 모두 연결이 끊기거나 늦으면 단 한 명의 찬성으로 여부가 통과하고 단 한 명의 선택으로 후보가 정해진다. 버그가 아니라 잠긴 결정의 귀결이며 테스트로 고정한다.
- **번복이 드러내는 것**: 합계가 증가했는지 이동했는지로 최초 투표와 번복이 구별된다. 누구인지는 모른다.
- **사회적 채널**: 같은 순간의 이모티콘·빠른 메시지는 서버 밖이다. 결정 0018(매너)과 같은 범주다.
- **방송 증폭**: 번복 연타는 연결당 20msg/s 한도와 같은 값 무전송으로 제한된다(최악 약 20 × 인원 프레임/s). 수용한다(A8).
