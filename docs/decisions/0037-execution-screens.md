# 0037 처형 구간 화면은 해질녘 배경 한 장·앰버/회색 카드·후광 최대 3개로 그리고, 테스트 방은 봇 투표를 고를 수 있다

- 상태: 채택
- 확인: 2026-10-30 사용자가 실기기 확인과 기본값을 모두 승인했다(전체 승인, 항목별 기록 없음).
- 날짜: 2026-10-28

## 배경

- 결정 0034 가 처형 구간의 흐름과 화면 연출(D-14~D-16·D-19~D-24·D-29~D-38)을, 결정 0036 이 서버 와이어 계약을 잠갔다. 이 문서는 화면 웨이브(04-13~04-33)가 그 위에서 **실제로 만든 것**과 UI-SPEC(`04-UI-SPEC.md`)과 코드가 어긋난 곳을 코드 기준으로 한 곳에 적는다. 결정 0036(와이어)은 건드리지 않는다.
- 입력: 승인 시안 사본 `design/screens/execution-v1/`, UI-SPEC 14(확인 대기 P-1~P-18), 결정 0030(후광·장면 전환), 0022·0024(테스트 방·봇).
- 서버 쪽 변경은 04-15 의 `testBotVote` 메시지 하나뿐이다. `shared/` 의 나머지는 서버 웨이브 그대로다.

## 결정

1. **장면 매핑(P-1·P-2)**: 투표 다섯 단계(`execVote`·`candidateVote`·`candidateVoteReveal`·`defense`·`execution`)의 배경은 조명이 없는 그림 `dusk` 한 장이고, `ended` 는 `night`(= 대기실과 같은 파일)다. `verdictDusk` 는 장면 목록에 등록만 남고 어떤 단계도 가리키지 않는다 — 그림에 위에서 떨어지는 조명이 구워져 있어 빛은 원뿔 층 하나여야 한다는 D-29 와 맞지 않는다. 그림 파일과 `ASSET_VERSION`(`i3`)은 바뀌지 않았다. 매핑은 `src/game/scenes.ts` 의 `PHASE_SCENE` 한 곳이고 E2E 의 `EXPECTED_SCENE` 이 같은 표다.
2. **색 의미와 토큰(P-12)**: 앰버(`amber-400` `#f2b84b`) = 낮의 공개 투표(카드·화살표·표수 칩·후광·처형 카드 띠), 진홍 = 마피아의 밤 암살과 팀 표시(동료 후광·마름모, 마피아 승 결과 번짐), 회색 = 처형 무효. 투표·처형 장면에 새로 진홍을 쓰지 않는다. 토큰 `amber-700`(`#7a5314`)·`amber-900`(`#3a2508`)은 처형 투표 카드 바탕 그라데이션 면, `cone-light`(`#fff4d6`)는 원뿔 스포트라이트 면(위 55% → 아래 20%)이며 모두 글자색으로 쓰지 않는다. `amber-400`·`crimson-500` 의 usage 문구를 이 색 의미로 고쳤다. 값의 원천은 `design/tokens.json`(앱 `tokens.css` 는 `npm run tokens`).
3. **연출 수치는 `src/game/verdict.ts` 한 곳(D-38)**: 어둡게 `VERDICT_DIM_PERCENT = 45`, 흐림 `VERDICT_BLUR_PX = 3`, 후보 배율 `VERDICT_CANDIDATE_SCALE = 1.7`, 이동 `VERDICT_MOVE_MS = 600`, 원뿔 `CONE_W/CONE_H`·`VERDICT_CONE_DELAY_MS`·`VERDICT_CONE_FADE_MS`, 인트로·무효 카드 `EXEC_INTRO_MS`·`NO_EXEC_CARD_MS`(1600)·`INTRO_CARD_W/H`, 밤 문구 지연 `NO_EXEC_INTRO_DELAY_MS`(1600), 공개 `REVEAL_LEAD_MS`·`REVEAL_SLOT_MAX_MS`·`REVEAL_BUDGET_MS`·`REVEAL_DRAW_MS`·`REVEAL_FADE_MS`, 확정 두근 `CLINCH_BEAT_MS`(700), 칩 크기 `CHIP_H`·`CHIP_H_LEAD`·`CHIP_W`·`CHIP_W_LEAD`, 처형 전환 `GHOST_FADE_MS`(400), 결과 `RESULT_FLIP_AT_MS`·`RESULT_SUMMARY_AT_MS` 등. 문구도 같은 파일의 `VERDICT_TEXT` 한 곳이다. 서버 시간표에는 연출 시간을 넣지 않는다(0036). 순수 함수(`revealPlan`·`revealStateAt`·`clinchedTarget`·`clinchBeat`·`candidateCenter`·`chipAnchor`·`chipPlacement`·`capHalos`·`summaryLines`)도 같은 파일이라 단위 시험이 숫자를 고정한다. (→ 결정 0039: 공개 슬롯 상한·예산 상수(`REVEAL_SLOT_MAX_MS`·`REVEAL_BUDGET_MS`)가 없어지고 `REVEAL_SLOT_MS`(2000)·`REVEAL_TAIL_MS`(600)가 서버 공개 길이와 같은 출처(`shared/game/phases.ts`)를 import 한다. `EXEC_INTRO_MS` 3000, `REVEAL_DRAW_MS` 1200)
4. **후광 우선순위·상한**: 한 화면 후광은 최대 3개(`HALO_MAX_SIMULTANEOUS`)이고 우선순위는 흰(내 선택·변론 후보) > 앰버(공개의 방금 닿은 대상·유일한 최다) > 진홍(동료 표시)이다. 한 자리에는 가장 높은 하나만 남기고(`capHalos`), 3개를 넘으면 낮은 우선순위(진홍 → 앰버)부터, 같은 순위에서는 번호가 큰 자리부터 꺼진다(흰은 항상 남고 마름모도 남는다). 진홍 후광은 마피아 viewer 와 탈락 관전자에게만 보이고, 방장이 시민이면 투표·처형 화면에 진홍이 하나도 없다(D-33).
5. **후보 패널 236 단일 예외**: 변론에서 후보 본인의 하단 패널은 템플릿 칩 6개 때문에 높이 236 이다(승인 시안 `DC-defense-me`). 기준 수치 `PANEL_H 157` 은 낮추지 않고 E2E `APPROVED_RELAXATIONS` 에 `P-PANEL-236` 한 줄을 더했다(T1·D7 의 `dayStates` 에서 `defense`·`execution`·`ended` 는 빼고 전용 검사 P5·P6·P8 이 본다). 후보 가운데 y 는 `min(cy+80, sceneH−38)` — 계획 값 34 는 이름표 상자의 실제 높이(26)를 넣자 360×640 에서 오차가 드러나 38 로 고쳤다(04-22).
6. **기록 카드 투표 줄(P-16)**: 여부 투표는 날짜별 집계만 보여 준다(개인 줄 없음, 0036). 후보 선택은 이 사람 본인의 줄만 둔다. 후보 선택 기록이 있는 일차에서 이 사람의 줄이 없으면 행 자체를 만들지 않는다(탈락자와 무효표를 구별할 수 없다).
7. **처형 하단 문구(P-10)**: 처형 5초의 하단 안내는 `곧 다음으로 넘어가요`. 이 시점 클라이언트는 승패를 모르므로 밤을 단정하지 않는다. 처형된 본인·탈락 viewer 도 같은 두 줄(`ReadOnlyRow` 없음)을 본다. 처형 카드는 앰버 띠 + 문구 `…님이 (4개 꼬리 중 하나)`, 후보 그림은 400ms 에 사람 → 유령으로 크로스페이드하고 직업은 어떤 살아 있는 viewer 에게도 안 보인다(D-09).
8. **테스트 방 봇 투표 선택(P-13)**: 메시지 `{ t: "testBotVote", exec: "random"|"yes"|"no", pick: "random"|"host"|"other" }`. 대기실에서만 바꿀 수 있고(검사 순서는 결정 0022 와 같다: 테스트 방이 아니면 `BAD_MESSAGE`, 방장이 아니면 `NOT_HOST`, 대기실이 아니면 `WRONG_PHASE`, 값이 범위 밖이면 `BAD_MESSAGE`), 방장의 대기실 view 에서만 `me.testBotVote` 로 보이며, 무작위가 아닌 값이 있을 때만 키가 있다. `testReset` 뒤에도 남는다(`testRole` 과 같다). `pick: other` 는 방장도 자기도 아닌 살아 있는 사람 중 가장 낮은 seat, 조건이 안 맞으면 무작위로 돌아간다. 고정 값이면 결정 난수(`randInt(100)`·`randInt(후보 수)`)를 부르지 않고 지연 난수는 그대로 부른다. 화면은 테스트 시트의 두 칩 그룹(`봇 처형 투표: 무작위·모두 찬성·모두 반대`, `봇 후보 선택: 무작위·방장·방장 아닌 사람`)이다. 결정 0022·0024 의 확장이며 일반 방에는 영향이 없다.
9. **모션 줄이기**: 연출 시간표(JS)는 훅이 하나로 돌리고 CSS 는 `animation-delay` 와 전역 축소 규칙(`base.css`)으로 분기한다. 축소 모션에서는 낙하·바운스·셰브런 이동·두근 크기 변화·후보 이동 전이가 없고 페이드와 밝기 깜빡임만 남는다. 결과 화면은 시간표를 돌리지 않고 곧바로 최종 상태다(UI-SPEC 11.2 의 160ms 페이드 대신, `RESULT_REDUCED_FADE_MS` 로 필요하면 별도 규칙).
10. **한 단위 배포(D-26)**: 이 화면 웨이브는 서버 웨이브와 한 번에만 배포한다(마지막 계획 04-35, 사용자 go-ahead 뒤). 그 전의 배포본은 새 단계에서 `연결 중…` 에 멈춘다.

### 코드와 UI-SPEC 이 어긋난 곳(코드가 맞다)

- 공개 칩 톤: 유일한 선두 → 큰 칩 + 앰버 후광, 방금 닿은 대상(선두 아님) → 팝, 그 밖 → 보통. 그래서 첫 표가 닿는 순간 1표짜리도 선두가 되고 동률이면 선두 표시가 사라진다(사용자 확인: 그대로 둔다).
- 공개 확정 두근: 확정 700ms 안에 같은 후보에 표가 더 닿으면 칩 두근이 다시 돈다(사용자 확인: 그대로 둔다). 느린 박동은 주기 1.2초·진폭 작게(캐릭터 1.04, 칩 1.1) — 시안은 2.2초.
- 공개 칩 위치: 기본 자리(머리 위 가운데)가 다른 이름표와 겹치면 캐릭터 폭 안에서 옆으로, 안 되면 위로 비킨다(`chipPlacement`, 04-32 에서 E2E P10 이 잡은 결함).
- 집계 줄: 모두 던진 뒤 문구를 `모두 투표했어요` → `모두 냈어요` 로 줄였다(360 폭에서 한 줄이 넘쳐 말줄임표). 줄바꿈하면 마지막 사람이 던지는 순간 버튼이 20px 밀리기 때문이다.
- 인트로 카드 제목 44 → 36px(P-18, 사용자 확정). 글자 크기는 4종 유지.
- 변론 후보 본인의 대상·직업 고르기는 기존 `QuickMessageSheet`(칩 하나)를 재사용하고 보낸 직후 안내 줄이 2초 `보냈어요 · {문장}` 이다(P-8). 새 선택 UI 없음.
- 투표 두 단계(`execVote`·`candidateVote`)에 말하기·이모티콘 아이콘을 넣지 않는다(P-7, 사용자 결정으로 D-12 개정). 서버는 계속 허용하지만 화면만 뺐다.
- 처형 무효 밤: 회색 카드가 먼저 1.6초, 밤 시작 문구는 그 뒤(카드 뒤 1.6초부터)에 뜬다. 도착 열쇠는 일차(n)라 마감 시각이 바뀌어도 카드가 되살아나지 않는다(P-3).
- 결과 화면: 판이 끝나면 열려 있던 테스트 시트도 닫는다(모달이 [처음으로] 를 가렸다).
- E2E P9 의 `후광 0` 은 관전자에게 틀린 기준이었다: 탈락 관전자는 모든 직업을 받아 마피아 자리에 진홍 동료 후광이 투표 장면에도 남는다(D-33). 흰·앰버 후광만 0 으로 본다.

## 알려진 한계

- **iOS `backdrop-filter`**: 변론의 흐림 3px 이 배경 그림까지 먹는지는 실기기에서만 확인된다. 안 먹으면 UI-SPEC 12.3 의 대체안(어둡게 층만, 더 진한 알파)으로 간다. 눈으로 보는 가독성(어둡게 45%·흐림 3px)도 실기기 몫이다(D-38).
- **8명판 후광**: 앰버·흰·진홍이 합쳐 3개를 넘는 경우 일부가 꺼진다(우선순위 규칙). 8명판 공개 4초에 화살표가 동시에 여럿 보이는 프레임의 체감은 실기기.
- **내 자리와 후보의 가운데 자리**: 내 자리가 아래 가운데면 변론 후보의 가운데 자리와 겹쳐 내 캐릭터·이름표가 가려진다.
- **360 폭의 인트로 셰브런**: 장면이 낮으면 셰브런 높이가 하한 96 이라 카드 영역과 겹쳐 작게(약 50px 폭) 보인다.
- **E2E 로 못 본 것**: 모션 줄이기의 결과 화면·공개, 관전자(후보 아닌 탈락자)의 변론·공개, 진홍 번짐의 시각 품질, 실기기·iOS, 배포본 E2E. 04-35 와 사용자 실기기 확인이 맡는다.
- **살아 있는 방장 E2E 의 무작위**: 첫 밤 암살로 방장이 탈락하는 확률은 설계대로이며(4명판 방장 시민 1/3, 5명판 약 1/5, 시드 2만 판 모의로 확인) 서버 버그가 아니다. 흐름은 새 방에서 최대 4번 다시 돈다.

- **되돌리기 비용**
