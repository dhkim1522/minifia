# 0040 후보 선택은 고른 뒤 장면의 빈 곳을 눌러 취소할 수 있고(와이어 target null), 마감 때 고른 사람이 없으면 무효표다

- 상태: 채택
- 날짜: 2026-10-29

## 배경

- 배포본 실플레이(2026-10-29) 뒤 사용자가 정했다. 후보 선택은 한 번 고르면 `선택 안 함` 으로 돌아갈 길이 없었고, 아무도 안 고르면 무효표가 된다는 규칙(04-CONTEXT D-04)이 화면에 안내되지 않았다.
- 사용자 결정 네 가지: ① 고른 뒤 장면의 사람이 아닌 빈 곳을 탭하면 선택이 풀린다. ② 새 "투표 안 함" 버튼은 만들지 않는다(기권 버튼 없음, D-04 그대로). ③ 안내 줄에 안 고르면 어떻게 되는지·취소 방법을 적는다. ④ 오작동을 막는다(헤더·하단 패널·버튼·[테스트]·사람은 빈 곳이 아니다). 처형 여부 투표(찬성/반대)는 이번 범위가 아니다.
- 서버(와이어)와 화면을 함께 다시 배포하는 것도 승인했다(서버만 먼저 배포하지 않는다, 결정 0036-15).
- 입력: 결정 0006(참여 플레이어의 몰입), 0034·0036(처형 흐름과 와이어), 0037(처형 구간 화면), 0039(공개 길이가 표 수로 정해짐).

## 결정

1. **와이어**: `{ t: "candidateVote", target: number | null }`. `null` = 선택 취소. 스키마(`shared/schemas.ts`)는 strictObject 에 target 이 0..7 정수 또는 null 이다. 빠진 target·문자열·불리언·범위 밖·소수·덧붙은 키는 `BAD_MESSAGE`. `nullable` 은 이 한 곳뿐이다(`pick`·`say` 의 target 은 null 을 거부한다).
2. **규칙표** (`shared/game/vote.ts` `castCandidateVote`, 검사 순서 단계 → 행위자 → 취소 → 대상):

   | 상황 | 결과 |
   |---|---|
   | 후보 선택 단계가 아님 | `WRONG_PHASE` (보낸 소켓에 error + 최신 state) |
   | 방에 없는 사람·탈락자 | `BAD_MESSAGE` |
   | 고른 표가 있는 사람의 `null` | 그 사람의 `candidateVote` 키를 지운다. 투표자에게만 state |
   | 고른 표가 없는 사람의 `null` | 상태 그대로, 저장·전송 없음 (같은 값 재전송과 같은 규칙) |
   | 마감 전까지 | 고르기·취소·다시 고르기를 몇 번이든 할 수 있다 (마감은 그대로, D-28) |
   | 마감 때 고른 사람이 없음 | 무효표: 세지 않고 분모가 아니다. 공개 표(`cand.votes`)에 그 사람 줄이 없다. 아무도 없으면 후보 없음 → 0표 공개 2초 뒤 처형 없이 밤(`noExecution` reason `noVotes`) |
   | 공개 단계 길이 | 실제로 던진 표 수로 정해진다 (결정 0039: `400 + n×2000 + 600`, 0표 2000) — 취소가 키를 지우기만 하므로 저절로 맞는다 |
   | 자기 자신 고르기 | 그대로 `BAD_MESSAGE` |

3. **받는 사람과 누출**: 취소를 받아들이면 투표자 본인 한 명에게만 state(`me.voteTarget` 키가 없는 view)를 보낸다(A7 그대로). 다른 viewer(생존·관전)는 고르기 전·고른 뒤·취소 뒤 view 가 같고 그 사이 프레임을 받지 않는다. 저장된 상태는 취소 뒤 고르기 전과 같다(키가 남지 않는다). 검사: `test/unit/vote.test.ts`(뷰 차분), `test/worker/vote.test.ts`(소켓 프레임), `test/worker/leak.test.ts`(한 판의 모든 프레임), 배포본 `scripts/uat-vote.mjs`.
4. **화면** (판정 한 곳 `src/game/blankTap.ts`): 빈 곳 = 장면 상자(`.mf-dayscene__scene`) 안에서, 대상이 `[data-seat]`·버튼류·`.mf-tt-anchor`([테스트]) 안이 아니고, 어떤 `[data-seat]` 사람 상자를 `BLANK_TAP_SLOP_PX`(8px) 넓힌 범위 밖인 탭. 이름표는 `pointer-events: none` 이라 이름표를 탭하면 대상이 그 아래 요소가 되므로 좌표 판정이 필요하다. 헤더·하단 패널·시트는 장면 상자 밖이라 대상이 아니다. 후보 선택 단계의 살아 있는 viewer 에게만 켠다. 고른 표가 없거나 보낼 수 없을 때(`canSend` 거짓)는 아무 일도 없다. 다른 사람을 탭하면 다시 고르기(기존), 같은 자리 재탭은 그대로 무시(아래 바뀔 수 있는 기본값). 취소는 낙관적으로 곧바로 알약 `선택 안 함`·흰 후광 0 이 된다.
5. **문구**: 하단 패널 안내 줄(제목 아래 14px 회색 한 줄)만 바뀐다. 네 역할이 같은 글자를 본다. 관전자 문구와 `[data-guide]`(제목 하나)는 그대로다.

   | 상태 | 안내 줄 | 폭 (360폭 패널 안 328px, 한글 14px 대략) |
   |---|---|---|
   | 고르기 전 | `아무도 고르지 않으면 무효표가 돼요` | 한글 15자 + 띄어쓰기 4 ≈ 226px |
   | 고른 뒤 | `빈 곳을 누르면 선택이 취소돼요` | 한글 13자 + 띄어쓰기 4 ≈ 198px |
   | 관전자 | 기존 관전 안내 그대로 | — |

   고른 뒤 문장에 "다른 사람을 누르면 바뀌어요" 까지 넣으면 약 326px 로 360폭 한 줄 한계에 붙는다. 다시 고르기는 후광이 따라 움직여 보이므로 취소만 적는다.

   **빠진 옛 안내 문장**(04-UI-SPEC §7.2 candidateVote 안내 행 그대로): `자기 자신은 고를 수 없어요 · 마감까지 바꿀 수 있어요`. 빼는 이유: 자기 자리는 버튼이 아니라 눌리지 않고(서버도 거부) 한 줄 칸에는 무효표·취소 안내가 먼저다.
6. **새 "투표 안 함"·기권 버튼은 없다.** 아무도 고르지 않는 것이 곧 무효표다(D-04).

## 알려진 한계

- 키보드·화면 읽기 사용자는 빈 곳 탭으로 취소할 수 없다 (장면의 빈 곳은 포커스·읽기 대상이 아니다). 다른 사람으로 다시 고르기는 된다.
- PC 마우스 클릭 경로는 E2E 가 건드리지 않는다 (E2E 는 터치 탭만 쓴다). 실기기 확인 ⑮ 에서 PC 마우스 클릭도 본다.
- 사람 상자 근처 8px 안은 취소되지 않는다 (손가락 오차 보호의 대가).
- 낙관적 선택이 서버에 닿기 전에 취소하면 잠깐 고른 값이 다시 보였다가 취소 상태가 된다 (서버가 보낸 순서대로 처리하고 새 view 가 서버 값을 이긴다).
