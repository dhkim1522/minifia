# 0051 v2.0 화면은 글을 최소로, 보고 누르는 조작 중심으로 만든다

- 상태: 채택 (기획·설계·디자인 전 단계의 지침)
- 날짜: 2026-10-31
- (보완: 0073-2 — 기능 이름 한 단어·숫자 시간)

## 배경

- 화면설계서 묶음 A 검토에서 사용자가 지적: 글이 많아질수록 눈이 피로하다. 텍스트를 최소화하고 사용자 상호작용과 경험 중심의 UI/UX 로 만들고 싶다. 가장 중요한 지침이다.
- v2.0 은 3D 공간에서 캐릭터가 움직이고 조명이 바뀌는 게임이라, 많은 정보를 장면 자체로 보여 줄 수 있다.

## 결정

1. **보여 주고, 읽히지 않는다.** 정보는 장면(조명·자리·캐릭터 동작·표정) → 아이콘·숫자·점 → 글 순서로 고른다. 글은 마지막 수단이다.
2. **3초 규칙.** 한 화면에서 읽어야 하는 글은 단계 이름과 한 줄 이하다. 처음 보는 사람도 3초 안에 무엇을 할지 알아야 한다.
3. **직접 조작.** 행동은 대상(캐릭터·이름표·맵 그림)을 직접 누르게 한다. 버튼은 아이콘 + 한두 단어, 가능하면 아이콘만(접근성 이름은 단다).
4. **진행과 개수는 모양으로.** 남은 시간은 링·막대, 모인 수는 점(●●●○○), 표 수는 배지 숫자. "3/5" 같은 글은 보조로만. (개정: 0062-2, 2026-11-03 — 모인 수·진행은 점이 아니라 "현재 / 최대" 숫자)
5. **안내는 한 번, 그리고 사라진다.** 단계 안내 문장은 단계가 시작될 때 잠깐 보여 주고 줄어든다. 처음 하는 사람에게만 손짓 표시(누를 곳이 깜빡임)를 보여 준다.
6. **고르기는 그림으로.** 맵·의상·역할처럼 고르거나 확인하는 것은 그림 카드(맵 그림, 캐릭터 미리보기, 직업 카드)로 보여 주고 이름은 짧게.
7. **시스템 메시지는 기록용이다.** 채팅의 시스템 메시지는 짧은 형식("민준 → 도윤")으로 남기고, 순간 정보는 장면과 화면 위 알림이 맡는다.
8. 이모지는 쓰지 않고 직접 그린 SVG 아이콘을 쓴다(v1.0 규칙 유지).

## 적용

- 기획(요구사항·UI-SPEC)과 화면설계서, 디자인 시스템의 모든 부품은 이 결정을 먼저 따른다. 화면을 검토할 때 "이 글을 그림·조작으로 바꿀 수 있나"를 먼저 묻는다.
- 디자인 시스템 README 에 같은 내용을 "글은 최소로, 조작은 직접" 으로 둔다.
