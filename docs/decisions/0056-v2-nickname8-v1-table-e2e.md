# 0056 v2.0 8자 이름과 v1.0 고정 테이블 화면의 E2E 이름표 검사는 승인 완화 범위로 다룬다

- 상태: 채택
- 날짜: 2026-11-01

## 배경

- 결정 0052-3 은 테스트 봇 이름을 모두 8자로 채우라고 했다. 가장 넓은 이름표를 E2E·실기기가 늘 시험하게 하려는 뜻이다.
- 6페이즈는 로비만 맵으로 바꾸고, 시작 이후 낮·밤·투표·결과는 v1.0 고정 테이블 화면 그대로 돌아야 한다(ROADMAP 6페이즈 성공 기준 3). 이 테이블은 8~9페이즈에 지운다.
- 고정 테이블 이름표는 5자 기준(결정 0017-4)으로 자리 간격을 잡았다. 8자 이름표는 약 130px(결정 0052-2)이라 5·8명판에서 이웃과 겹칠 가능성이 높아 E2E D9 "이름표끼리 안 겹침"과 D3b "이름표 보이는 비율"이 깨질 수 있다.
- E2E 기준 수치와 승인 완화 목록은 사용자 승인 없이 낮추지 않는다는 규칙이 있다(RETROSPECTIVE "Patterns Established").
- 06-06 계획 Task 2 에서 사용자에게 세 안(a 완화 범위 표시 / b 곧 지울 테이블 이름표를 두 줄로 / c 봇 이름 5자 유지)을 묻고 a 를 골랐다.

## 결정

사용자가 **a** 를 골랐다(2026-11-01).

1. 테스트 봇 이름은 8자로 적용한다(`봇가나다라마바사` 등 7개, 모두 정확히 8 그래핌, 비교 키 서로 다름). `shared/game/bots.ts`·`scripts/bots.mjs`·`scripts/uat-test-bots.mjs` 세 목록은 같은 값·같은 순서이고 `test/unit/bots.test.ts` 가 이를 고정한다.
2. v1.0 고정 테이블 화면에 한해 E2E D9·D3b 를 "6자 이상 이름이 앉은 판" 범위로 승인 완화 목록(`APPROVED_RELAXATIONS`)에 올린다. 기준 수치는 바꾸지 않고 적용 범위만 표시한다. 6자 이상 이름이 없는 판과 새 맵 화면의 검사는 그대로다.
3. v1.0 테이블 화면(`DayTable`·`daytable.css`)은 고치지 않는다.

## 06-17 이 할 일

- `scripts/e2e/lib.mjs` 의 `APPROVED_RELAXATIONS` 에 D9·D3b 를 "v1.0 고정 테이블 화면 + 6자 이상 이름" 범위로 추가하고, 단위 테스트(`lib.test.mjs`)가 목록과 범위를 고정하게 한다.
- 실제 실패 목록(어느 검사가 몇 인원·몇 크기에서 깨지는지)은 06-17 이 E2E 로 잰다. 잰 실패가 이 결정이 고른 범위(D9·D3b)를 넘으면 다시 사용자에게 묻는다.
- 새 맵 이름표는 8자 최악 폭으로 계속 시험한다. 완화하지 않는다.

## 결과

- 8~9페이즈에 고정 테이블을 지울 때 이 완화 항목도 함께 지운다.
- 8~9페이즈 전까지 v1.0 테이블 화면의 이름표 겹침(실게임 8자 이름)은 E2E 가 잡지 못한다. 이 위험은 사용자가 받아들였다.
- REQUIREMENTS MAP-07 의 "테스트 봇 이름은 8자" 문구는 그대로 두고 유지한다.

## 개정 (2026-11-01): 완화 범위를 G2·D2·P10 으로 넓힌다

06-17 이 로컬 E2E 로 v1.0 게임 흐름의 실제 실패 목록을 쟀다. D9·D3b 는 한 번도 실패하지 않았고(완화 미사용), 실제로 깨진 것은 이 결정의 범위 밖 검사였다. 사용자가 **같은 범위를 넓히는 안(선택 1)** 을 골랐다(2026-11-01). 두 줄 이름표(b)와 게임 흐름 봇 이름 5자(c)는 고르지 않았다.

### 잰 숫자 (로컬, 360x640·390x664·430x932·360x560)

- **G2 "화면 밖"·D2 "이름표가 장면 밖"**: 4~8명판 모두에서 양옆 자리의 8자 봇 이름표(약 133px)가 화면 가로 밖으로 나간다. 360·390 폭 왼쪽 10.8~17.7px, 오른쪽 약 15px. 430 폭은 5명판 통과, 8명판(mafia8)은 1.7px. 이름 5자인 방장 이름표는 멀쩡하다.
- **P10(vote5 공개)**: 칩(자리 1)이 이름표(자리 2)와 겹친다. 4개 크기 모두 94/94 표본.

### 넓힌 범위

- `APPROVED_RELAXATIONS` 에 `G2-8ch`·`D2-8ch`·`P10-8ch`(approved: 결정 0056)를 더한다. 기준 수치(화면 가로 0.5px, 장면 안, 칩-이름표 겹침 0.5px)는 바뀌지 않는다.
- 적용 범위는 D9·D3b 와 같다: **v1.0 고정 테이블 화면 + 방에 6 그래핌 이상 이름**. 각 판정은 이름표(`.mf-dt__tag` 와 그 안쪽 요소)·칩에 대해서만 완화한다.
  - G2: 6 그래핌 이상 이름의 이름표 요소만. 그 밖의 요소가 화면 밖이면 그대로 실패.
  - D2: 그 이름표의 "장면 밖"만. 하단 패널과 겹침은 그대로 실패.
  - P10: 칩이 그 이름표와 겹친 것만. 칩·카드가 헤더·패널과 겹치거나 카드가 장면 폭 밖이면 그대로 실패.
- 5자끼리, 이름을 모르는 이름표, 새 맵 화면의 검사(NT1·NT3·NT4)는 완화하지 않는다. 단위 테스트(`lib.test.mjs`)가 범위 안은 완화·범위 밖은 실패를 양쪽에서 고정한다.

### 감수하는 점

8~9페이즈에 고정 테이블을 지우기 전까지, v2 시험에서 6자 이상 이름의 양옆 이름표는 폰 화면 가장자리에서 눈에 띄게 잘린다(최대 약 18px). 이 위험은 E2E 가 잡지 못하며 사용자가 받아들였다.

### 지우는 조건

고정 테이블(`DayTable`·`daytable.css`)을 지울 때 `G2-8ch`·`D2-8ch`·`P10-8ch` 를 `D9-8ch`·`D3b-8ch` 와 함께 `APPROVED_RELAXATIONS` 에서 지운다.
