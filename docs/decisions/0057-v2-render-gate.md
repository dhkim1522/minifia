# 0057 v2.0 렌더 성능 게이트 판정: 통과, 사다리 0단계로 확정한다

- 상태: 채택
- 날짜: 2026-11-01

## 배경

- 결정 0046 은 6페이즈 끝에 "three.js 맵 + 캐릭터 8명" 성능 게이트를 두고, 모자라면 맵을 미리 구운 이미지로 바꾸는 탈출구를 정했다(ROADMAP 6페이즈 성공 기준 4).
- 결정 0055 는 확인 기기를 사용자 폰(iPhone 16 Pro)과 크롬 CPU 4배 스로틀로 정했다. 이 폰의 숫자만으로는 합격을 선언하지 않고 스로틀 결과와 함께 본다. 저가 Android·구형 iPhone·카카오톡 인앱은 9페이즈 팀 테스트로 넘긴다.
- 06-19 가 배포본(`350b7fb`, Worker 버전 `86304aab-7b07-458d-bbe1-79627d5c3452`)에서 두 조건을 쟀고, 판정은 사용자가 골랐다. 측정 원문과 표는 [06-PERF-RESULTS](../../.planning/phases/06-world-skeleton/06-PERF-RESULTS.md).

## 결정

사용자가 **a — 통과** 를 골랐다(2026-11-01). 판정 선택지는 a 통과 / b 사다리를 더 줄여 재측정 / c 미리 구운 이미지로 전환이었다.

1. 렌더 예산은 지금 그대로 **사다리 0단계** 로 확정한다(`DEFAULT_BUDGET_STEP = 0`). 느린 기기에서는 자동 강등(1~3단계)이 지킨다. 코드와 배포본은 바꾸지 않는다.
2. 합격 기준(평균 55fps 이상, 끊김(50ms 초과) 5회 이하, draw call 120 이하, 점광원 3 이하)은 낮추지 않았다.

- 반응(Fast 4G + CPU 4배, 3회 중앙값): 입장 → 조작 가능 760ms(기준 3,000ms), 탭 → 링 2.1ms(기준 100ms), 탭 → 내 캐릭터 출발 66ms(기준 500ms).

조건 A — iPhone 16 Pro, iOS 27.0.1, **iOS용 Chrome(CriOS 156, WebKit 엔진)** 이며 Safari 가 아니다:

- vote 5분 평균 **59.98fps**, 끊김 1회(최장 52ms), rAF 60Hz, 저전력 모드 아님.
- 첫 1분과 끝 1분이 같다(59.99 → 59.99, 열 저하 신호 없음), 5분 뒤 열감 "차갑다".
- calls 최대 69, 점광원 3, 5분 동안 탭 재로딩·경고 보고 없음.

## 결과

- 3D 맵과 3D 캐릭터를 유지한다. 미리 구운 이미지 렌더러 전환은 하지 않는다. 10페이즈 아트 투자도 3D 기준으로 계속한다.
- 저가 Android·구형 iPhone·카카오톡 인앱 브라우저는 9페이즈 팀 테스트에서 확인한다(결정 0055). 그때 미달이면 사다리 기본 단계 상수를 조정하거나 이 판정을 다시 연다.
- 하단 채팅 확인표는 7페이즈 UI-SPEC 의 입력이다.
- 이 판정은 iPhone 16 Pro 한 대와 데스크톱 스로틀에 근거한다. 고사양 폰이므로 저사양 기기에 대한 보증이 아니다.
- 배포를 가로지르는 맵 로비 위치 이어짐(deployhold)은 판정 대상이 아니며 미확인으로 남는다. DO 하이버네이션 때문에 배포가 소켓을 끊지 않았다. 다음 v2 배포 때 `npm run e2e -- --only deployhold` 로 확인한다.
