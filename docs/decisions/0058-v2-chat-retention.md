# 0058 v2.0 채팅은 서버가 판이 끝날 때까지 보관하고, 재접속하면 채널별 최근 30줄을 되돌려 준다

- 상태: 채택
- 날짜: 2026-11-01

## 배경

- 7페이즈 UI-SPEC 결정 D2(사용자 확정, 2026-11-01): 재접속하거나 새로 고침하면 내가 볼 수 있는 최근 줄이 서버에서 되돌아온다. 대안인 "빈 기록으로 시작"은 기각했다.
- 결정 0017-7 은 "채팅 내역은 서버에 저장하지 않는다"고 정했다. 줄을 되돌려 주려면 서버가 보관해야 하므로 이 결정과 충돌한다.
- 11페이즈 END-03(마피아·유령 채팅을 판이 끝날 때 공개)도 서버가 판 끝까지 줄을 보관해야 한다. 보관은 어차피 필요하다.
- 결정 0021-2 는 탈락자에게 "탈락 시점부터" 정보를 보내고 이미 끝난 밤의 지난 정보는 보내지 않는다. 복원이 이 규칙보다 넓으면 안 된다.
- 설계 근거는 리서치 Pattern 2(연번·마스크), Open Questions 1·2·5, Security Domain V7·V8.

## 결정

1. **보관 대상은 로비·낮 공개 줄(`all`), 밤 마피아 줄(`mafia`), 탈락자 줄(`ghost`) 모두이고, 방 Durable Object storage 의 줄 단위 키 `chat:` + 6자리 쓰기 순번(예 `chat:000001`)에 저장한다.** room 키에 넣지 않는다. room 키는 입장·시작마다 통째로 다시 쓰이므로 world 키를 분리한 것과 같은 이유로 줄도 따로 둔다.
2. **줄마다 보낼 때 서버 audience 함수가 정한 받는 사람 좌석 비트(좌석 0~7 → 8비트 마스크)를 같이 저장하고, 재접속 복원은 이 마스크에서 내 좌석 비트가 켜진 줄만 준다.** 그래서 복원은 라이브 전송과 같은 규칙이다. 결정 0021-2 "탈락 시점부터"를 그대로 지킨다. 새로 탈락한 사람은 탈락 이전의 마피아 줄을 복원으로도 받지 않는다(사용자 결정 2).
3. **복원 범위는 채널별 최근 30줄(`all`·`mafia`·`ghost`, 최대 90줄)이며 hello 직후 한 프레임(`chatLog`)으로 보낸다.** 줄이 없어도 빈 프레임을 보낸다. 값은 상수 하나 `CHAT_REPLAY_PER_CHANNEL = 30` 에서 조정한다(사용자 결정 1).
4. **보관 상한은 채널별 all 100줄 · mafia 300줄 · ghost 300줄이고, 넘치면 오래된 줄부터 20줄씩 묶어 지운다.** 11페이즈 공개가 판 전체의 마피아·유령 줄을 쓰므로 둘을 `all` 보다 넉넉히 둔다. 공개 때 모자라면 상수 한 곳을 고치는 새 결정을 쓴다.
5. **줄 번호(`seq`)는 채널마다 따로 센다.** 전역 번호면 시민이 받는 공개 줄 번호의 틈으로 비공개 채널 줄 수를 셀 수 있다. 결정 0020 이 밤 번호를 낮과 따로 센 이유와 같다.
6. **마스크·쓰기 순번·일차는 저장에만 있고, 클라이언트로 나가는 프레임에는 없다.**
7. **보관 줄은 방이 지워질 때(마지막 사람 퇴장, 방 수명 3시간 만료) storage 전체 삭제와 함께 사라지고, 테스트 방 [대기실로 되돌리기] 때 `chat:` 키를 모두 지운다.** 게임 시작 때는 지우지 않는다. 로비 줄이 게임 중에도 이어진다(UI-SPEC "방 한 번 들어오면").
8. **서버 로그에 채팅 본문·닉네임을 남기지 않는다.** 거절은 코드 한 줄로만 알린다.
9. **11페이즈 결과 화면(END-03)은 이 보관 줄로 마피아·유령 채팅을 공개한다.** 판이 도는 동안에는 마스크 밖으로 어떤 경로로도 보내지 않는다.
10. **결정 0017-7 을 개정한다.** 0016-7(메시지 보관), 0019-1(밤 채팅 "서버에 저장하지 않고"), 0020(밤 줄은 저장하지 않는다), 0023-5(채팅은 그날 낮 줄만 폰 메모리)를 같은 이유로 폐기한다. 각 결정에는 원문을 남기고 개정 표시를 덧붙였다.

참고(결정 아님): 낮 토론 길이 `DISCUSSION_MS` 는 7페이즈에서 40초 그대로 두고, 90초는 8페이즈 DAY-07 이 바꾼다(사용자 결정 3, 2026-11-01).

## 결과

- 구현은 07-02(`shared/game/chatLog.ts` 순수 규칙)와 07-14(DO 저장·복원·누설 검사)가 한다. 두 계획은 이 기록의 숫자와 규칙을 그대로 옮긴다.
- 무료 플랜 쓰기 한도와 저장 크기는 줄 단위 쓰기와 채널별 상한으로 묶인다.
- 누설 검사는 복원 줄도 라이브와 같은 audience 를 지나는지 본다. 살아 있는 사람은 복원으로도 마피아·유령 줄을 받지 않는다.
- 탈락자에게 지난 마피아 줄까지 보여 주려면(관전 재미) 마스크 정책을 바꾸는 새 결정이 필요하다. 이 기록은 그것을 하지 않는다.
