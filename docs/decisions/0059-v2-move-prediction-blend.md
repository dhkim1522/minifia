# 0059 v2.0 내 캐릭터는 탭하자마자 걷고, 서버 구간이 오면 부드럽게 맞춘다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

- 7페이즈 UAT(07-UAT.md 9번, 사용자 실기기 iPhone 16 Pro): "약간 자연스럽지 않고 살짝 멈췄다 움직이는 느낌", "움직일 때 핑이 튀는 것처럼 끊긴다".
- 진단(`.planning/debug/lobby-move-hitch.md`): 모든 캐릭터를 서버 구간으로만 그리고 구간이 바뀔 때 섞지 않는다. 탭 뒤 한 번 왕복하는 동안 서 있다가, 응답이 오면 `MOVE_V × RTT/2` 앞으로 튄다. 걷는 중 방향을 틀면 최대 `MOVE_V × RTT` 만큼 튄다.
- 측정: 한국에서 `minifia-v2.dhplay.workers.dev` 는 Cloudflare LAX 로 연결되어 왕복이 약 155ms(p50)다. 서버 처리 시간은 0~1ms다. 경로는 코드로 고칠 수 없다.
- 6페이즈 UI-SPEC(81·348-360·606·644행)이 "예측 이동 금지, 출발 300~500ms 정지 허용"을 잠갔다. 결정 0044-17 은 "목적지만 보내고 서버가 경로를 정한다, 위치 스트림·서버 틱 없음"만 정했고 예측을 금지하지 않았다.
- 원래 리서치(`.planning/research/ARCHITECTURE.md` 159-160행)는 "내 탭 즉시 예측 이동"과 "남의 새 구간 100~150ms 섞기"를 권했다.

## 결정

1. **탭하면 내 캐릭터가 바로 걷기 시작한다.** 클라이언트는 서버와 같은 공용 길찾기(`shared/game` 의 경로·맵·`MOVE_V`)로 예측 구간을 만들어 그린다. 목적지만 보내는 프로토콜(0044-17)은 그대로다.
2. **위치의 진실은 계속 서버 구간이다(결정 0002).** 내 서버 구간이 오면 예측을 버리고 서버 구간으로 맞춘다. 서버가 요청을 버린 경우(막힌 목적지, `TOO_SOON` 등, 응답 없음 1.5초)에는 예측을 멈추고 서버가 아는 위치로 돌아간다.
3. **구간이 바뀌는 순간 화면 위치 차이는 100~150ms 에 걸쳐 0으로 줄인다.** 내 캐릭터의 예측→서버 교정과 다른 사람의 새 구간 모두 같다. 걷기·서기 자세와 방향도 짧게 섞는다. (0085 로 바뀜 — 내 캐릭터의 예측→서버 교체는 업링크만큼의 앞섬을 위치 차이로 당기지 않고 시각 앞섬으로 넘긴다. 당기면 화면에서 뒤로 걸었다.)
4. **다른 사람의 캐릭터는 예측하지 않는다.** 남의 위치는 서버가 보낸 구간과 섞기만 쓴다.
5. 6페이즈 UI-SPEC 의 "예측 이동 금지"와 "출발 300~500ms 정지 허용"을 이 결정으로 개정한다. 그 문서에 원문을 남기고 개정 표시를 덧붙인다.

## 결과

- 탭 뒤 멈춤과 응답 때 튐이 화면에서 사라진다. 판정·속도 제한·이동 가능 영역 검사는 서버가 계속 한다.
- 예측과 서버 구간이 크게 어긋나는 경우(서버가 거절, 다른 길을 고름)에는 짧게 미끄러져 돌아가는 모습이 보일 수 있다.
- LAX 경로로 인한 왕복 시간은 그대로다. 유료 요금제·Argo·사용자 도메인이 도움이 되는지는 확인하지 않았다. 출시 마일스톤에서 다시 본다.
