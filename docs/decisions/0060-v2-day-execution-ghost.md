# 0060 v2.0 낮 처형은 토론 끝내기 → 지목 → 변론 → 찬반 → 처형 단계로 돌고, 유령의 위치는 유령에게만 간다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

- ROADMAP 8페이즈 "낮 처형과 유령": 낮 토론이 맵 위에서 열리고 지목 → 변론 → 찬반 → 처형이 정통 순서로 돌며, 처형된 사람은 유령이 되어 끝까지 지켜본다.
- 입력 결정: 0044-3·13·14(같은 공간·이동·가시 범위), 0049(지목 표시), 0053(찬반·처형 규칙: 수만 공개, 처형 때 역할 비공개, 변론자는 투표하지 않음), 0021(탈락자 관전).
- 8페이즈 UI-SPEC(`08-UI-SPEC.md`) 승인 때 사용자가 추천안으로 확정한 A1~A4(2026-11-02): A1 밤·아침 임시 틀, A2 [역할 카드] 시간 링 왼쪽 버튼, A3 지목은 과반이어도 마감까지, A4 유령 이동은 모든 단계에서 자유.
- plan-phase 컨펌 게이트에서 사용자가 확정한 두 건(2026-11-02): ① 변론자는 무대 위에 선다(단일 예외 `STAGE_SPOT`), ② 찬반은 마감까지 고정이고 조기 종료가 없다.
- 이 문서는 뒤 계획들이 코드 주석과 시험에서 "결정 0060-N" 으로 가리킬 규칙 번호를 먼저 고정한다. 실기기 확인은 모든 개발이 끝난 뒤 한꺼번에 한다(사용자 결정 2026-11-02).

## 결정

1. **서버 단계**: `discussion`(90초) → `nomination`(지목 15초) → `defense`(최후 변론 20초) → `verdict`(찬반 10초) → `execution`(처형 5초) → `night`(30초) → `morning`(5초). v1.0 의 처형 여부 투표·후보 선택·후보 공개 세 단계는 없어진다. 값은 `shared/game/phases.ts` 한 곳에 둔다. 아침 5초는 그대로 두고 9페이즈가 정한다.
2. **토론 끝내기**: 메시지 `{t:"endDiscussion", on}`. 산 사람만 보낼 수 있고 다시 눌러 취소한다. 산 사람의 과반(⌊산 사람 ÷ 2⌋ + 1)이면 서버가 마감을 지금으로 당겨 지목으로 넘긴다. 누가 눌렀는지는 서버 전용이고 개수만 공개한다.
3. **지목**: 메시지 `{t:"point", target}`. 산 사람이 자기를 뺀 산 사람 한 명을 가리키고 마감 전까지 바꾼다(취소 없음). 같은 사람의 변경은 250ms 간격이고, 그 안의 요청은 본인 화면만 서버 값으로 되돌린다. 누가 누구를 가리키는지는 공개 정보라 모두의 view 에 실린다. 과반이어도 마감까지 이어진다(UI-SPEC A3). 마감에 최다 득표가 정확히 한 명이면 그 사람이 변론자가 되고, 동률이거나 0표면 처형 없이 밤으로 간다.
4. **찬반**: 메시지 `{t:"verdict", agree}`. 변론자와 유령은 투표하지 않는다. 분모는 던진 표가 아니라 변론자를 뺀 산 사람 수 E 이고, 찬성 × 2 > E 면 처형이다(결정 0053-3 "8명이면 7명 중 4표"). 못 던진 사람은 기권이다. 전원이 던져도 마감(10초)까지 기다린다(사용자 확정 2026-11-02). 투표를 마친 좌석은 공개하고 값은 본인에게만 보낸다. 처음 던질 때만 전원에게 방송하고, 값을 바꿀 때는 본인에게만 보낸다. 집계 직후 개인 값은 키째 지운다. 결과는 찬성·반대 수만 처형 단계에서 공개한다(결정 0053-1, 구현 세부는 0053 을 따른다).
5. **처형**: 찬반이 통과하면 변론자가 탈락해 유령이 된다. 역할은 알리지 않는다(결정 0053-2). 처형 발표에는 좌석만 싣고 v1.0 처형 문구 번호(문구 추첨)는 없앤다. 처형 5초의 결과 알림 시간표는 다음과 같다.
   - 0~2.0초: "찬성 n · 반대 m"
   - 통과: 2.0~5.0초 "{닉네임} 님 처형"(유령이 1.4초 동안 떠오르고 2.4초까지 사라진다)
   - 부결: 2.0~3.4초 "처형 없음"
   - 지목 동률·0표: 밤이 시작하고 1.4초 동안 "처형 없음"
6. **이동(MAP-04)**: 서버 순수 함수 `canMove` 가 정한다. 로비·낮 시작·토론은 산 사람이 자유롭게 움직이고, 지목·변론·찬반·처형·밤·아침은 산 사람이 정지한다(밤 마피아 이동은 9페이즈). 유령은 모든 지도 단계에서 자유롭다(UI-SPEC A4). 막힌 요청은 오류 없이 버린다. 채팅은 막지 않는다.
7. **모이기**: 지목이 시작되면 서버가 산 사람 N명(2~8)을 무대 둘레 반지름 2.65 원 위 슬롯으로 걷게 한다. 시작은 90°에서 반시계이고, 8명이면 서로 2.03 떨어진다. 변론·찬반 동안 변론자는 무대 위 `STAGE_SPOT`(블록아웃 `ctx.center`, 좌표 0,0, 높이 0.29)에 선다. 이것이 이동 마스크의 단일 예외이고 `lineWalkable`·`snapToWalkable`·저장 복원이 같은 판정을 쓴다(사용자 확정 2026-11-02). 부결이면 변론자는 자기 슬롯으로 돌아온다. 배치는 "지금 단계가 요구하는 배치"를 맞추는 멱등 동기화라 알람 따라잡기·퇴거에도 안전하다. 밤은 선 자리 그대로 두고, 9페이즈가 정한다.
8. **유령(GHOST-01·02)**: 산 사람의 이동 프레임은 방 전원에게, 유령의 이동 프레임은 유령에게만 간다. 접속 스냅샷도 보는 사람별로 보낸다(산 사람은 산 사람 위치만). 유령은 모든 사람의 역할과 밤 선택을 본다(결정 0021 의 spectate 경로 그대로). 처형 연출은 화면이 처형 이벤트 하나로 그리는 일회성이고, 서버가 산 사람에게 유령 위치를 보내는 것이 아니다.
9. **밤·아침 임시 틀(UI-SPEC A1)**: 고정 테이블을 지우므로 밤·아침도 맵 위에서 v1.0 규칙 그대로 돈다(이름표를 눌러 대상을 고르고, v1.0 하단 문구를 쓴다). 9페이즈가 이 틀을 대체한다.
10. **[역할 카드]** 는 시간 링 왼쪽의 44×44 아이콘 버튼이다(UI-SPEC A2).
11. **공개 투표 기록(`voteLog`)**: 모양은 유지하고 뜻만 바꾼다. `exec` = 찬반 결과(열리지 않았으면 0/0/false), `cand.votes` = 지목 마감의 최종 지목, `cand.candidate` = 변론자. 줄은 지목 마감 훅이 항상 만든다.
12. **옛 저장 방**: 처형 여부 투표·후보 선택·후보 공개 단계로 저장된 방은 깨어날 때 토론(새 90초 마감, 일차 유지)으로 옮기고 옛 개인 투표 키를 지운다. 옛 번들이 보내는 옛 투표 메시지는 스키마에서 거부된다.
13. **테스트 방 봇**: 토론 30~60초에 토론 끝내기, 지목 2~8초에 한 명, 찬반 1~6초에 찬성 70%. 방장 도구 '봇 투표' 두 값은 찬반(`exec`)과 지목 대상(`pick`)으로 뜻을 바꾼다.
14. **결정 0056 완화 삭제**: v1.0 고정 테이블에 대한 E2E 승인 완화(D9·D3b·G2·D2·P10)는 테이블과 함께 이 페이즈에서 지운다.

## 결과

- 서버가 막고 보내지 않는 방식이라 누설 검사가 서버 한 곳에서 증명된다. 결정 0053-1 대로 찬반에서 누가 무엇을 골랐는지 공개하는 길은 어디에도 남기지 않는다.
- 밤·아침 임시 틀은 9페이즈에서 버려진다. 임시 틀은 같은 맵에 밤 조명·이름표 선택·v1.0 문구만 둔다.
- 단계 이름(`nomination`·`verdict`)은 저장된 방의 단계 문자열을 바꾼다. 되돌리려면 정규화가 한 번 더 필요하다(방 수명 3시간, 일방향은 아니다).
- 옛 결정 0034·0036·0037·0039·0040·0049·0056 의 해당 항목에 이 결정으로 개정·폐기했다는 표시를 붙인다. 원문은 지우지 않는다(v1.0 배포본 `v1` 브랜치에서는 여전히 유효하다).
