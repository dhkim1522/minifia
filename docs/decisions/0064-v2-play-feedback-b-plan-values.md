# 0064 v2.0 묶음 B 계획 값: 끊긴 차례는 8초를 기다리고, 지목 중에는 배지 숫자만, 시간 값은 phases.ts·willLetter.ts 한 곳, 손글씨 글꼴은 저장소에 둔다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

- 결정 0063 "이 결정이 정하지 않는 것"(UI-SPEC 미결 M-3~M-13)을 09.1 계획(`09.1-01-PLAN.md` 미결 항목 결정 표)이 정했다. M-1(자리 순서)·M-2(과반이어도 끝까지)·M-7(인장 "M")은 0063-4 로 이미 확정됐다.
- 실행 중 각 계획 SUMMARY(09.1-01~11)와 빠른 작업 09.1-q1 이 바꾼 값이 있으면 바뀐 값을 적었다. 시간 값은 모두 기본값이고 플레이테스트 뒤 조정한다(한 판 평균 10~15분은 참고 목표).

## 결정

0064-1. **연결 끊긴 사람의 차례도 8초를 다 기다린다(M-3).** 그 안에 다시 붙으면 고를 수 있고, 지나면 기권이며 차례는 다시 오지 않는다.
- 엔진(tick)은 `connected` 를 읽지 않는다. 폰 화면 잠금·앱 전환 같은 짧은 끊김에 억울한 기권이 없고, 모든 소켓에 같은 시간표가 간다(L14). 비용은 최악 8초.

0064-2. **지목 중 득표 표시는 배지 숫자만이다(M-4).** 선두 맥박·"유력" 도장·실내등 절반·카메라 8%·`hot` 채팅 줄·위 알림(TopToast)은 지목 단계에 없다.
- 변론 단계의 배지 + "유력" 도장(8페이즈)은 그대로. 선두가 바뀔 때의 손사래는 캐릭터 반응이라 둔다.
- 과반이어도 끝까지 가므로(0063-4) 과반 표시는 결과를 미리 말할 뿐이다. 도장 칸을 빼야 360×640 스테이지에 이름표 상자가 들어간다.

0064-3. **지목 시간은 모이기 3초 · 차례 8초 · 사이 0.9초 · 끝 알림 2초다(M-5).** `shared/game/phases.ts` 한 곳(`NOMINATION_GATHER_MS`·`PICK_TURN_MS`·`PICK_GAP_MS`·`NOMINATION_END_MS`).
- 최악(산 8명 전원 기권) 76.2초, 봇만이면 약 12초. 차례 시간 색은 `timerTone` 하나를 모든 사람의 차례에 쓴다(5초 이하 진홍, 그 위 흰색 `gray-100`, 기권 확정 순간은 0초 흰색). 남의 차례 진홍이 잦으면 "내 차례만" 조건 한 줄로 되돌린다.

0064-4. **내 차례에 "한 걸음 나오기"는 하지 않는다(M-6).** 발밑 차례 고리 + 이름표 앞으로 + 깜빡임만. 10페이즈 "지목 중 제자리 동작"이 같은 몫을 한다.

0064-5. **편지 접힘은 420ms(`dur-med`), 채팅 쪽으로 아래 120px · 0.5배 · 투명이다(M-8).** 5초 기준은 등장(T0). 값은 `src/game/willLetter.ts` 한 곳(`LETTER_FOLD_AT_MS`·`LETTER_FOLD_MS`·`LETTER_END_AT_MS` 등).
- 카드 도착 시각이 글 길이와 무관해 아침 길이가 공개 내용만의 함수로 남는다(L6). 접힘 모양은 실기기·육안 묶음에서 사용자가 골라 바꿀 수 있다.

0064-6. **아침 길이 공식은 9페이즈 그대로다(M-9).** 유언 +2초 → 유언 있는 아침 9초, 쪽지까지 11초. 가장 늦은 경찰 화면도 8.02초로 9초보다 먼저 끝난다. 불변식 시험이 있다(09.1-10).

0064-7. **손글씨 글꼴(Nanum Pen Script)은 저장소에 두고 같은 출처로만 부른다(M-10).**
- Google Fonts 가 배포하는 woff2 조각 93개(unicode-range, 합계 1,311,112 바이트, 2026-11-04 측정)를 고치지 않고 `public/fonts/nanum-pen-script/` 에 둔다. `OFL.txt` 동봉, 출처는 `sources.json`.
- 편지가 필요할 때 그 글자 조각만 `document.fonts.load` 로 받고 최대 1초(`LETTER_FONT_WAIT_MS`) 기다린다. 외부 주소 요청은 없다. 파일을 고치지 않아 OFL 수정본 조항을 건드리지 않는다.

0064-8. **처형된 사람의 유언은 편지로 바꾸지 않는다(M-11).** 9페이즈 채팅 카드(처형 연출 2.4초 보류) 그대로. 0063-3 범위는 암살 유언이고, 처형 단계 5초에 5.42초 편지가 들어가지 않는다.

0064-9. **판 종료 뒤 탈락자 표시(산 사람 시점)는 이 페이즈에서 바꾸지 않는다(M-12).** 의상 대응 함수는 좌석 → 직업 목록을 받게 만들어 11페이즈 결과 연출이 `result.seats` 로 다시 쓴다(이월).

0064-10. **지목 오탭 완화는 없다(M-13).** 시안대로 즉시 확정, 취소·바꾸기 없음. 누르기 44 · 고른 이름표 즉시 `mine` 표시(서버 확인 전 배지 +1)로 완화한다. UAT 에서 잦으면 다시 정한다.

0064-11. **지목 검사 순서는 단계 → 행위자 → 차례 → 대상이다.** 단계(WRONG_PHASE) → 행위자 산 사람(BAD_MESSAGE) → 차례(WRONG_PHASE) → 대상(BAD_MESSAGE).
- 차례 순서는 진입 때 산 사람 좌석 오름차순을 `pickTurn.order`(서버 전용)에 저장한다. 공개 차례는 `day.turn`(모두에게 같은 값, 역할 무관).
- 확정 뒤 같은 사람의 재전송은 WRONG_PHASE 다. 8페이즈의 250ms 지목 간격 규칙은 지웠다. 유령의 지목은 차례와 무관하게 BAD_MESSAGE.
- 테스트 도구의 넘기기는 남은 차례를 봇 표로 채워 지목을 한 번에 끝낸다(`finishNomination`).

0064-12. **차례 정보가 없는 옛 지목 방은 깨어날 때 지목을 다시 시작한다.** `enterNomination` + 모이기 3초. 그날 지목 표는 지워진다(배포 직전 진행 중인 방만 해당).

0064-13. **차례 고리는 기존 발밑 고리 메시에 `gray-100` 을 쓴다(새 메시 없음).** 이름표 상자 우선순위는 선두와 같은 가중을 한 번만 준다.

0064-14. **유령과 편지의 구현 값.**
- 유령 안개: 직업 의상에 불투명도 0.26(`GHOST_MIST`) + 밝은 발광. 직업 의상은 유령에게만 오는 `spectate` 로 화면이 입힌다(서버 새 필드 없음). 유령 이름표는 불투명이고 직업은 `RoleChip` 이 알린다(8페이즈 0.6 을 바꿈).
- 편지 머리글 색 `--letter-label` 은 시안 `#6a7388`(4.14:1) 대신 `#5f687b`(종이 위 4.88:1) — 14px 4.5:1 문턱.
- 글이 인장 자리(84×84)에 닿으면 글 덩어리를 머리글 아래로 올리고 인장 옆 줄의 오른쪽을 비워 다시 나눈다(인장 피하기 띠 배치).
- 암살 유언은 카드(`k: "will"`)로 오고, 화면이 편지로 보인 뒤 접힐 때 카드를 채팅에 낸다(카드 보류, 새 메시지 종류 없음).

0064-15. **유언은 50자(문자 단위, grapheme)까지다(사용자 결정 2026-11-05, 빠른 작업 09.1-q1).** `shared/game/will.ts` 의 `WILL_MAX_GRAPHEMES = 50`. 쪽지는 100자 그대로. 0061-10 의 유언 100자를 바꾼다.
- 편지가 50자를 넘지 않아 폭 360 에서도 편지 안에 들어간다(E2E `WILL50`, 360폭 LT5 통과).

0064-16. **10페이즈 감정표현은 몸 동작만이다(사용자 결정 2026-11-05).** 머리 위 표시(말풍선·아이콘·이모지)는 전혀 두지 않는다.

- 편지 접힘 모양의 최종 선택(M-8, 육안 확인 때 사용자가 고른다).
