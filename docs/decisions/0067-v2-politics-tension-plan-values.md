# 0067 v2.0 정치·박진감 장치 계획 값: 새 메시지는 badge·whisper 뿐, 결선·마지막 3인은 기존 point·chat 을 단계별로 쓴다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

- 결정 0066 "열린 것"과 09.1.1 UI-SPEC 미결 항목 O-1~O-22 를 계획(09.1.1-01~17)이 정했다. 사용자 위임(2026-11-05 취침 전)에 따라 추천안·기본값으로 정했고, 바꾸고 싶은 값은 플레이 뒤에 다시 요청한다.
- 실행 중 각 계획 SUMMARY(09.1.1-01~16)가 바꾼 값이 있으면 바뀐 값을 적었다(O-19 결선 후보 위치). 시간·세기·배율·위치 값은 모두 기본값이고 실기기·팀 테스트 뒤 조정한다(한 판 평균 10~15분은 참고 목표라 연출을 줄이는 근거가 아니다).

## 결정

0067-1. **와이어는 최소로: 새 메시지는 `badge`·`whisper` 둘뿐이다.**
- 결선 투표와 마지막 3인 지목은 기존 `point` 를 단계(`runoff`·`showdown`)별로 분기한다. 마지막 한마디는 기존 `chat` 을 차례 주인에 한해 한마디로 확정한다(30자소, 길이 거절은 속도 제한을 쓰지 않는다).
- 이름은 `badge`·`badgeSwapped`·`badgeLog` 로 한다. 옛 순차 주장 `claim*` 이름은 정규화·누설 가드가 이미 박혀 있어 충돌한다. 화면 표식만 `data-claim` 이다.
- 거절 코드는 단계 어긋남만 `WRONG_PHASE`, 나머지는 모두 `BAD_MESSAGE` 다(행위자·대상·횟수·본문을 구분하지 않는다).

0067-2. **"말 바꿈"은 직전 값 기준이다(O-1).** 직업을 건 뒤 다른 값으로 바꾸면(직업→다른 직업, 직업→말 안 함) 말 바꿈이고 판이 끝날 때까지 남는다.
- 처음 거는 것(말 안 함→직업)과 같은 값으로 다시 거는 것은 바꿈이 아니다. 낮 안에서 바꿔도 바꿈이다(결정 0066-1 이 낮 안 변경을 허용한다).
- 결정 0015 의 "다음 낮에 다른 직업을 고르면"을 개정한다(구현: `badge.ts` 의 `setBadge`).
- 알약 "말 바꿈"은 서버 규칙과 같게 직전 값이 직업이었고 새 값이 다르면 매번 뜬다. 모션 줄이기에서는 즉시 나타나 2.4초 뒤 사라진다(O-22, 점은 영구라 정보 손실 없음).

0067-3. **서버 전용 보관: `Player.badgeLog`(일차·값)와 `RoomState.whispers`(O-20).** 모든 확정 변경과 귓속말 본문을 서버에만 쌓고, 화면은 이 페이즈에 만들지 않는다(11페이즈 입력). 채팅 보관 상한과는 별개이고 방 삭제와 함께 지운다(결정 0058-7).

0067-4. **귓속말 규칙.**
- 낮 토론(`discussion`)에서만 보낸다(O-3). 낮마다 1번, 상수 `WHISPER_PER_DAY`(O-4).
- 연결이 끊긴 사람에게도 보낼 수 있고 돌아오면 복원으로 받는다(O-5). 이름표가 이미 끊김을 보인다.
- 유령은 보내지도 받지도 못하고, 낮 `all` 의 "A → B 귓속말" 사실 줄만 본다. 본문은 없다(O-21).
- 본문 줄과 사실 줄은 `all` 채널 seq 를 한 번만 소비해 같은 seq 를 쓴다(틈 없음). 받는 사람은 audience(all) 한 번을 당사자와 나머지로 가른다.

0067-5. **찬반 기록 공개.**
- 처형 단계 길이는 5,000 → **5,600 ms** 다(O-6, `VERDICT_LEAD_MS` 600 한 상수). 판결 줌 0.6초를 알림보다 앞에 두기 위해서다.
- `verdict.ballots` 는 처형 단계 view 에서만 나간다. 시간 초과로 투표하지 않은 사람·변론자·탈락자는 어느 묶음에도 넣지 않는다(O-7).
- 채팅 카드 `ballots` 는 보관 상한의 계수·삭제에서 빠지고, 복원 때 채널 30줄 한도와 별도로 마스크에 든 최근 3장을 더한다(O-8, `CHAT_REPLAY_BALLOTS`).
- 카드는 찬반이 부결돼도 낸다. 지목 0표·동률로 처형 단계가 없는 경로는 내지 않는다. 결정 0053-1 "수만 공개"를 개정한다.
- 공개 `voteLog` 줄은 `last` 를 옮기지 않는다. L24 허용 경로 목록을 지키려고 새 공개 경로를 처형 단계의 `day.verdict.last` 하나로 줄였다.

0067-6. **동점 결선.**
- 시간 `RUNOFF_INTRO/VOTE/END` = 1,000 / 5,000 / 1,500 ms. 기권 표는 세지 않고, 마감 전까지 바꿀 수 있다. 탈락한 사람의 남은 표는 세지 않는다.
- 개인 선택은 마감 전 비공개(`done` 체크만), 마감 뒤에는 득표 수만 공개한다(O-9). 5초 단계는 `timerTone` 문턱을 못 넘어 색 변화가 없다(O-10, calm).
- 후보 걷기 위치(O-19)는 계획의 가운데 ±90 이 아니라 무대 앞 두 점 `RUNOFF_SPOTS` = (10,200)·(200,10) 이다. 무대 원기둥이 이동 마스크에서 막혀 있어 안쪽 점에 설 수 없고, 처음 값 (30,180)/(180,30) 은 화면에서 약 123px 라 UI-SPEC D-4 의 140px 에 못 미쳐 넓혔다. 두 점의 중점 (105,105) 은 그대로라 핀 위치는 변하지 않는다.
- 넘기기(유령 방장 도구)는 결선을 한 번에 벗어난다: 남은 산 봇 표를 채우고 득표를 확정한 뒤 집계한다.

0067-7. **마지막 3인 결전.**
- 진입은 낮 시작 발표(`dayAnnounce`) 마감 훅 한 곳이고 산 사람 정확히 3명일 때만이다. 역할·연결을 읽지 않는다(O-16·O-17).
- 시간 `SHOWDOWN_GATHER/TURN/POINT/REVEAL` = 2,000 / 8,000 / 8,000 / 1,500 ms. 세 자리는 기존 `ringSlots(3)` 을 쓴다. 봇 한마디는 차례 시작 시각에 `chat` 한 줄이다.
- 빠른 문구 네 개(O-11): "저는 아니에요" · "쟤가 수상해요" · "저를 믿어 주세요" · "끝까지 지켜봐요". 직업 주장 문구는 배지가 맡아 넣지 않는다.
- 동시 지목은 마감 전까지 바꿀 수 있고 조기 종료가 없다(O-12). 남의 선택은 `done` 체크만, 득표 배지는 공개 1.5초에서만이다(O-18).
- 과반(2표 이상)이면 최후 변론·찬반 없이 처형하고 처형은 `verdict.last` 로 알린다. 1-1-1 이면 처형 없음이다.
- **실행이 정한 화면 규칙(09.1.1-16).** 동시 지목·공개 단계에서는 떠 있는 배지 버튼을 접는다(모이기·한마디 단계에서는 보인다). 390×664 같은 낮은 폰에서 삼각형 아래 오른쪽 이름표의 지목 버튼이 이 버튼에 통째로 가려졌기 때문이다(O-2 가 예고한 위험). 서버는 showdown 전체에서 주장을 받는다.
- **1-1-1 처형 없음 알림.** 마지막 3인에서 온 밤도 지목·결선에서 온 밤과 같게 "처형 없음" 1.4초 알림 뒤 "밤이 되었습니다"를 띄운다(UI-SPEC E-1).

0067-8. **핀 조명(O-14·O-15).**
- `setPin` 은 기존 focus 점광과 실내등 그룹만 움직인다(새 광원 없음). 켜진 세기 0.9, 실내등 ×0.6, 원뿔 불투명도는 기존 그대로. 조정은 `pinPlan.ts` 의 `PIN_STRENGTH`·`PIN_DIM` 두 줄이다.
- `dim` 은 실내 발광에 그대로 곱하는 값이다(런타임이 k 에서 미리 계산).
- 다른 좌석으로 건너뛸 때는 켜짐을 0 으로 내렸다가 180 ms 에 다시 켠다(한 점광이라 교차 페이드를 못 하고 "켜고 끈다", UI-SPEC F-2).
- 판결 줌은 1.10(O-15)이고 높이 360 미만에서는 줌이 없다. 처형 단계 핀은 view 만으로 정해지는 고정 창이고 위치·세로 오프셋·줌이 같은 시간·같은 ease 로 움직인다.
- 지목 차례 핀은 선두·과반을 비추지 않는다(결정 0063 이 뺀 연출을 되살리지 않는다). 결선 핀은 두 후보 자리의 중점인 월드 좌표 한 점이다.

0067-9. **화면(O-2·O-13·O-22).**
- 떠 있는 버튼 묶음은 오른쪽 16, 지름 48, 두 칸(48+8+48)을 항상 같은 자리에 잡는다(배지가 위 칸, 귓속말이 아래 칸). 빈 칸은 `pointer-events: none` 이라 땅 탭 걷기를 가리지 않는다.
- 새 아이콘 `whisper`·`swap`·`quiet` 은 직접 그린 모양으로 시작한다(O-13, 실기기 묶음에서 고른다). 모션 줄이기 알약은 0067-2 와 같다.
- **귓속말 모드는 화면에 보이는 이름표만 고를 수 있다.** 화면 밖·가려진 이름표는 누를 수 없으니, 대상이 가려지는 폰 크기는 실기기 묶음에서 본다.

## 이 결정이 정하지 않는 것

- 실기기·팀 테스트 뒤 시간·세기·배율·위치 값 조정(`phases.ts`·`pinPlan.ts`·`gather.ts` 한 곳씩), 귓속말 횟수·직업 주장 규칙 조정.
- 11페이즈: 결과 화면의 귓속말 본문·주장 이력 공개, 찬반 카드 보관 재검토.
- 12페이즈: 핀 조명·판결·결선·한마디 효과음. 10페이즈: 마지막 3인·결선 중 제자리 몸짓.

## 관찰·정리 후보 (결정이 아님)

- 말 바꿈의 "직전 값" 해석(`badge.ts`)이 O-1 의 "발표된 값" 해석과 다를 수 있다. 같은 낮 안에서 했다 취소하는 경우 사용자가 기대하는 표시와 맞는지 플레이에서 본다.
- 결선 후보 위치 상수 `RUNOFF_SPOTS`(gather.ts)는 육안으로 고칠 수 있다. 차가 (d, −d) 꼴이어야 나란하다.
- 핀 교차 페이드는 180 ms 의 "켜고 끈다" 도약이다. 점광이 하나라 부드러운 교차는 광원을 더해야 한다.
- 유령 방(ghost) 흐름 GH13 이 360×560 에서 가끔 실패한다(간헐 실패, 원인 미확인).
- `scripts/uat-vote.mjs`·`scripts/uat-night.mjs` 는 옛 15초 규칙을 쓴다. 12페이즈에서 정리한다.
- `leaderShift`·`DayState.leader`·`sure` 는 지목 단계에서 더 쓰이지 않는다. 12페이즈 청소 후보다.
