# 0069 v2.0 결과 공개·다시 하기·방 연속성·맵 선택 계획 값: 끝난 뒤에만 공개하고, 준비한 사람들로 같은 방 다음 판을 연다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

- 11페이즈 UI-SPEC(`.planning/phases/11-result-rematch/11-UI-SPEC.md`)의 결정 D-1~D-26 과 미결 O-1~O-17 을 사용자 위임(2026-11-05 취침 전)에 따라 추천안·기본값으로 정했고, 계획(11-01~11-14)이 구현했다. 바꾸고 싶은 값은 플레이 뒤에 다시 요청한다.
- 실행 중 각 계획 SUMMARY 가 UI-SPEC 문구에서 벗어난 곳은 0069-2~0069-10 에 이유와 함께 적었다. 시간·세기·횟수·점수 값은 모두 기본값이고 실기기·팀 테스트 뒤 조정한다.
- 결정 0054(결과 화면 약속), 0066-3(판 중 찬반 공개), 0067(정치 장치 값), 0068(동작·의상)을 이어받는다.

## 결정

0069-1. **와이어: 새 메시지는 `ready`·`rematch`·`mapPick` 셋, 새 프레임은 `resultLog` 하나다(L40).**
- `ready{on, round}`(손님만), `rematch{round}`(방장만), `mapPick{map}`(방장만, 값은 bar·plaza·random).
- 새 프레임 `resultLog{part, i, end, lines}`. 새 view 키는 `round`·`mapChoice`·`map`(시작 뒤에만)·`players[].ready`·`players[].sat`·`resting`(쉬는 사람 본인에게만)·`result.awards`. 모두 신분과 무관한 값이다(L44).
- 거절(간격 안·단계 밖·권한 없음·낡은 판 번호)은 오류 프레임 없이 보낸 소켓에 최신 `state` 한 프레임만 돌려준다. 같은 값 `ready` 와 쉬는 사람의 요청은 0프레임이다. 응답이 사유를 가르면 오라클이 되기 때문이다.
- `view.round`·`view.mapChoice` 는 항상 싣고 `view.map` 은 시작 전에는 키가 없다. 클라이언트 쪽 `round?`·`mapChoice?`·`map?` 는 optional 로 읽는다(옛 서버 응답과 시험 리터럴이 그대로 통한다).

0069-2. **판 번호: 단계 키는 `'{판}:{일차}:{단계}'`, 첫 판도 `1:` 접두를 붙인다(D-5, D-26).**
- `phaseKey({phase, day?, round?})` 한 곳에서 만든다. 이전 판 키와 옛 형식 키는 폐기한다(받으면 버린다).
- `rematch` 가 `round` 를 올리고 `stats`·`badgeLog`·`whispers`·채팅 보관·동작 순번을 새로 시작한다. 낡은 판의 `ready`·`rematch` 는 판 번호가 달라 거절된다(동시 클릭·늦은 메시지가 꼬이지 않는다).

0069-3. **칭호: 열 개 + 대체 둘, 정렬까지 서버가 끝낸다(D-4~D-7, O-1~O-3).**
- 칭호는 `actor detective angel whiff target firstVictim talker swapper whisperer mood survivor spectator` 열두 이름(열 개 점수 칭호 + 대체 둘)이다. 점수·최소값(`AWARD_MIN` 한 곳)·동점 순서(점수 → 생존/늦은 탈락 → 낮은 좌석)·패 순서(진 팀 → 이긴 팀, 대체 → 작은 → 중간 → 큰, 낮은 좌석)를 서버가 끝내고 화면은 재정렬하지 않는다.
- 한 칭호는 한 사람, 한 사람은 한 장이다. 후보가 없으면 그 칭호는 목록에 없다(패 수 = 참가자 수, 열 개가 다 있다고 가정하지 않는다).
- 읽기 허용 목록에는 `.view.result.awards[].seat|award|k|at` 만 둔다. 줄 키 이름에 `id` 를 쓰지 않는다(누설 검사 금지 키라서). 그래서 화면 계약서가 말한 `id` 대신 **칭호 키 이름은 `award`** 다.
- 통계 `Player.stats = {say, emote}` 는 서버 전용이다. 판 중 열 단계의 전체 채팅과 받아들인 동작만 센다(결과 단계 채팅은 세지 않는다, O-16). 채팅 줄마다 `room` 키를 다시 저장하는 비용은 마지막 계획의 5분 nightload 로 재어 문제 없음을 확인했다(T-11-03, 수치는 11-14-SUMMARY).
- 최소값 표(`AWARD_MIN`)는 기본값이고 플레이 뒤 조정한다(O-1).

0069-4. **숨은 기록 공개: 끝난 순간 한 번, 40줄 청크(D-2, D-9~D-11, O-14).**
- `resultLog` 부분 순서는 mafia → ghost → whisper → claim → ballots. 부분마다 줄이 없어도 `{i:0, end:true, lines:[]}` 한 프레임을 보내 화면이 끝났음을 안다. 청크는 40줄 이하다. `ended` 진입 때 한 번 보내고, 재접속 hello 가 저장소에서 복원한 채팅으로 같은 열을 다시 보낸다. 신분별 차이는 없다.
- **결과 단계 채팅은 `CHAT_PHASES`·`channelOf` 로 열지 않았다.** UI-SPEC 은 `CHAT_PHASES` 에 `ended` 를 더하자고 했으나, 그러면 모든 채널 계산이 `ended` 를 알게 된다. 그래서 `channelOf` 는 `ended` 에서 null 을 유지하고, `applyChat`·`audience` 분기와 `view.me.chat === "all"` 로 전체 채널 하나만 연다. 동작과 입력 중 표시는 `ended` 에서 서버가 버리고, 클라이언트는 보내지 않는다.
- 사전 예고는 0069-9.

0069-5. **결과 연출: 시간표와 건너뛰기(D-1, D-24, D-25, O-13, O-15).**
- 시간표 상수: 모임 1200 / 뒤집기 간격 400 / 승리 조명 4600 / 알림 끝 5200 / 시상식 시작 5600(ms), 칭호 한 장당 2500ms(걷기 900, 패 900 뒤 표시). (0083-7 로 시상식 삭제 — 시상식 시작 5600 은 최종 상태 시각 `finalAtMs`, 칭호 값은 소리 대본에만 남음)
- 시상식 걷기는 서버 월드가 아니라 클라이언트가 만든 **로컬 snap** 으로 보인다(같은 방 사람마다 걷는 위치가 달라도 상관없는 연출). 서버 snap 은 마운트·epoch 변경 때만 먹이고 그 사이는 로컬이 이긴다. (0083-7 로 시상식 삭제)
- 무대 탭은 현재 연출 단계를 건너뛴다. [넘기기] 는 칭호 한 장씩. 확장 탭이 열리면 시계가 멈추고 접히면 이어서 간다. 박수는 이긴 팀 가장 가까운 4명, 유령 포함(`CLAP_MAX = 4`). (0083-7 로 [넘기기]·칭호 시상 삭제 — 무대 탭 건너뛰기는 그대로)
- 시상식이 끝나면 직업 의상에서 고른 의상으로 갈아입는다("의상 유지"가 눈에 보인다). (0083-7 로 시상식 삭제 — 끝의 갈아입기도 함께 없어짐)
- **떠 있는 버튼 열 읽는 법**: 두 칸 열에서 위 칸은 시상식 동안만 [넘기기](끝나면 빠짐), 아래 칸은 [꾸미기]다. 시상식 중에는 아래 칸의 꾸미기를 숨긴다. 끝난 뒤 꾸미기만 남으면 단독 칸(`single`)이다. (0083-7 로 시상식 삭제 — [넘기기] 칸 없음)
- **칭호 문구 계약**: 패 이름·아이콘·이유 문구는 `awardText` 한 파일, 이유 문구는 `k` 를 숫자로 끼워 만든다(글 최소, 결정 0051).

0069-6. **다시 하기: 준비·쉬는 사람·꾸미기(D-12, D-13, D-15, D-16, D-19, O-7, O-12, O-17).**
- 손님은 [준비], 방장은 자동 준비 후 [시작]. 봇은 자동 준비(O-17). 준비한 연결된 사람이 4명 이상일 때 [다시 하기]가 켜지고, 준비 안 한 연결된 사람이 있으면 확인 시트가 한 번 뜬다(얼굴만, 이름 없음, 접근성 이름에 닉네임, O-7). 끊기면 준비가 풀린다.
- 준비 안 한 사람은 `bench` 에 분리된다(게임 코드가 보지 않는 데이터 구조). 판이 끝나면 `sat` 로 결과에 합류한다. 쉬는 사람 view 는 `resting` 키와 **자기 한 줄만 든 `players`**(`me:{seat, isHost:false}`, 마감 없음)이고, 월드·채팅은 없다. 표식 이름도 `resting` 이다.
- 다시 하기는 허용 목록 리터럴(`id token seat nickname nicknameKey joinSeq connected connId isBot look`)로 방을 다시 만든다. 펼쳐 복사하지 않는다(L39). 테스트 방의 `testRole`·`testBotVote` 는 남는다. 의상(`look`)은 남는다.
- 결과 단계에서도 꾸미기가 된다(`dress` 문 = 대기실 + 결과 단계, 참가자·sat 모두, 쉬는 사람은 무시). 게임 중에는 거절이다.
- 방 수명: `rematch` 가 만료를 `now + 3시간` 으로 늘리고 방 생성 후 12시간이 상한이다. 결과 진입 때의 30분 단축은 그대로고, "30분 뒤 닫힘" 예고 문구는 지웠다(O-12).
- 알약(준비·시작) 활성은 시상식 알림이 끝나는 `4600ms` 이후, 입력줄 옆(전체 탭) 또는 확장 탭 위 `pill` 자리에 놓는다. (0083-7 로 시상식 삭제 — 연출이 끝나는 5600ms 부터)

0069-7. **방 연속성: 방장 이양과 정리(D-14, D-17, D-18, O-6).**
- 방장이 끊긴 지 45초(테스트 방 3초)가 지나면 연결된 사람 중 가장 이른 `joinSeq` (봇 제외)에게 넘기고 옛 방장은 일반이 된다. 옛 방장이 돌아와도 되돌려주지 않는다. 알림은 대기실·결과 단계만이다(게임 중 알림은 집중을 깬다).
- 끊긴 지 3분(테스트 방 6초)이면 대기실·쉬는 사람을 지운다. 게임 중에는 지우지 않고, 결과 단계는 `rematch` 때 한 번에 정리한다(연출 중 명단이 바뀌지 않게). `rematch` 는 `left` 와 끊긴 지 60초(`REMATCH_STALE_MS`) 넘은 사람을 제거한다.
- 결과 단계에서 나가면 `left:true` 로 표시만 하고 4003 `left` 로 소켓을 닫는다. 방장이 나가면 즉시 이양한다. 서버 전용 필드(`disconnectedAt`·`left`·`bench`·`stats`)는 view 에 실리지 않는다.
- 이양·정리 시계는 워커 `advance` 끝(tick 뒤)과 hello 에서만 돌고 알람은 `nextWakeAt` 한 곳에 합쳐진다.

0069-8. **맵 선택: 표와 잠금(D-20~D-22, O-8, O-9, O-11).**
- 맵은 `MapDef` 표(`MAPS`, 마스크·입장 지점·장애물·장면·조명)로 등록한다. 광장은 `PLAZA_MAP`(마스크 래스터화), 장면 `buildPlazaScene`. 6~10페이즈 연출은 새 연출 코드 없이 광장에서도 같은 규칙으로 돈다. 광장의 결과 단계 조명은 night + 이긴 팀 스포트라이트(O-9)다.
- **`PLAYABLE_MAPS = ["bar", "plaza"]` 로 열었다(11-13).** E2E map-select 통과 뒤에 열었고, 불안하면 그 한 줄을 `["bar"]` 로 되돌리면 칩·탭이 자동으로 사라지고 `random` 도 바만 뽑는다(되돌림 절차). 마지막 계획에서 광장 5분 nightload 를 재어(4배 스로틀·390×844) 평균 59.93fps·끊김 1회로 합격선 안이라 **열린 채로 둔다**(재즈 바 59.92fps·끊김 1회, 8명 의상×박수 4 시나리오 광장 59.99fps·끊김 0·점광원 3). 수치 전체는 11-14-SUMMARY·`11-DEVICE-CHECKS.md` 표 A.
- 랜덤은 시작(`beginGame`) 때 서버가 주입 가능한 난수로 정한다. 시작 전 view 에는 `map` 이 없다(L42). 방장이 대기실과 결과 단계에서 고르고, 같은 값은 0프레임이다.
- 워커 통합 시험은 `test/worker/setup.ts` 가 허용 맵을 바 하나로 잠그고, 광장이 필요한 시험만 `openPlaza()` 로 연다. 단위 시험에서 난수 호출 수나 `map` 값을 보는 시험은 `onlyBar()` 로 잠근다.
- **지도 칩 36/44(보이는 크기 36, 누르는 영역 44).** 방장 로비 360×560 **테스트 방**에서만 칩이 [테스트] 버튼 옆으로 비켜 서며 가장 긴 닉네임 이름표와 약 16px 겹친다(MS6). 이 겹침은 E2E 검사를 둘로 나눠(방장 칩 / [테스트] 버튼) 테스트 방에서만 남기고, 제품 화면은 건드리지 않았다.
- **광장 조명 값은 기본값**이고 실기기 묶음에서 조정한다(`PLAZA_LIGHT_TUNE`). **맵 카드 그림과 새 아이콘 6개는 첫 초안**이다(O-8).

0069-9. **사전 안내(D-23, O-10).**
- "끝나면 밤 대화와 귓속말이 공개돼요" 한 줄을 역할 확인 단계(4초)와 귓속말 보내기 시트에 보인다. 모두에게 같은 문구라 역할 정보가 아니다.
- 구분선은 일차 번호만 쓴다(마피아 `{n}밤`, 유령·귓속말 `{n}일차`).
- 기록 탭 하루 상세에서 찬반 배지는 숫자만 보이고 이름은 얼굴 묶음으로 본다. 마지막 3인 최후 결전의 날은 뷰에 `last` 가 없어, 후보가 있고 찬반이 0/0 인 날을 "처형됨" 으로 읽는다.

0069-10. **UI 값(기본값, 실기기 뒤 조정).**
- 준비 알약 96×48, 지도 칩 보이는 36 / 누르기 44, 맵 카드 96×112, 시상 패 96, 타임라인 카드 72×112(간격 8), 확장 탭 높이 min(0.7 × 방 높이, 520).
- 타임라인 카드는 일차 카드 띠(낮·밤 두 칸) + 하루 상세. 거짓 주장은 진홍 점선, 진홍은 그 점선과 마피아 칩·탭 아이콘에만 쓴다.
- 결과 화면의 칭호 문구는 작은 화면에서 읽히는지 실기기에서 본다.

### 개정과 오래된 결정과의 관계

0069-11. **결정 0053-1 개정.** "결과 화면에서도 찬반 내역은 공개하지 않는다" 를 **공개로 바꾼다.** 판 중에는 결정 0066-3 대로 찬반이 끝나는 순간 공개하고, 끝난 뒤 결과 화면의 기록 탭 하루 상세에서 일차별 찬반 내역(`ballots` 부분)을 다시 보인다. 0053 의 다른 항목은 그대로다.

0069-12. **UI-SPEC 문구에서 벗어난 곳 정리.** 위 본문에 이유를 적은 것의 목록이다. 결과 단계 채팅은 `CHAT_PHASES`·`channelOf` 가 아니라 `applyChat`·`audience`·`view.me.chat` (0069-4), 칭호 줄 키는 `award`(0069-3), 쉬는 사람 표식은 `resting` 이고 view 에 자기 한 줄 (0069-6), 떠 있는 버튼 열 읽기(0069-5), 방장 이양 E2E 는 11-12 에 있음, 결과 화면 부하는 기존 성능 장면으로 잼(별도 결과 장면 없음), 채팅 줄마다 `room` 키 재저장 (0069-3), view 타입 `round?`·`mapChoice?`·`map?` 은 optional (0069-1), 마지막 3인 처형일 판독 (0069-9).

## 이 결정이 정하지 않는 것

- **소리**: 승리 팡파르·박수·칭호·방장 이양 알림 소리는 없다. 12페이즈에서 정한다.
- **시상식 다시 보기**(O-4): 만들지 않았다. 재접속한 사람은 하루 상세만 본다.
- **결과 단계 새 합류**(O-5): 거절(`GAME_STARTED`). 다음 판은 기존 멤버만 한다.
- **예비·보조 칭호**(O-2, O-3): 만들지 않았다. 한 사람이 여러 조건을 채워도 칭호는 하나다.
- **보조 칭호 아이콘**: 칭호 열두 개의 아이콘 모양은 첫 초안이고, 대체·보조 칭호용 별도 아이콘은 만들지 않았다.
- **칭호 임계값(`AWARD_MIN`)**: 플레이 뒤에 조정한다(O-1).
- 조명·분위기·아이콘 모양·템포의 육안 조정은 실기기 묶음(`11-DEVICE-CHECKS.md`)에서 한다.
- 광장 조명 값·맵 카드 그림·새 아이콘 6개는 첫 초안이다.
