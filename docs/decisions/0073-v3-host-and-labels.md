## 결정

0073-1. **사회자는 헤더 아래 자막 띠 한 줄이다. 글과 알림음만 쓰고 음성은 없다(D-01·D-02·D-03).**
- 모든 방 화면의 헤더 바로 아래, 맵 위에 얹힌다(스테이지를 줄이지 않는다). 종 아이콘 + 합쇼체 한 문장("밤이 되었습니다. …", 1~2줄) + 시간 막대 + "{n}초". 띠는 눌리지 않고 탭은 맵으로 통과한다.
- 문장은 순수 함수 `src/game/hostLine.ts` 의 `hostLineOf(view)` 가 만든다. 키는 단계 × 상태(`act`·`wait`·`ghost`) × 역할(밤만)이고 키마다 한 줄이다. 할 일이 있는 사람에게는 "무슨 일 + 내 할 일", 없는 사람에게는 지금 무슨 시간인지만, 유령에게는 관전 줄이다(HOST-03).
- 기존 안내 줄(헤더 hint·역할 확인 안내)과 36px "낮이 되었습니다/밤이 되었습니다" 알림은 띠가 같은 말을 하므로 그리지 않는다. 값이 있는 알림(찬반 집계·처형·처형 없음·아침 결과·피해자·조사 결과)은 그대로다.
- 음성 낭독은 넣지 않는다(D-01). 소리는 합성만 쓴다(결정 0070 유지).

0073-2. **결정 0051 을 폐기하지 않고 보완한다 — "글은 최소로, 기능 이름은 한 단어로 붙인다, 남은 시간은 막대와 숫자로 함께"(D-04).**
- 0051 의 "글을 최소로·보고 누르는 조작" 방향은 그대로다. 읽을 글은 단계 이름 + 띠 한 줄이다. 달라진 두 가지: (가) 눌리는 모든 아이콘 단추에 아이콘 아래 한 단어 이름표를 항상 붙인다(`data-tool-label`). 아이콘만으로는 처음 보는 사람이 도구를 알지 못했다. (나) 남은 시간은 링이 아니라 띠 아래 막대 + "{n}초" 하나로 통일한다(TOOL-02). 0051 의 "진행은 모양으로"는 막대로 이어지고 숫자가 보조에서 병기로 올라왔다.
- 이름표 규칙: 3자 이하(예외 "내 역할"), 누르기 44×44 이상, 라벨 14/400 `gray-300`(빛나면 700 `brass-200`). 접근성 이름은 보이는 낱말을 포함한다(0073-8 e). 이미 글자가 있는 단추([시작]·[준비]·[찬성]·[반대]·[테스트]·이름표)는 그대로다.
- 목록(14): 나가기·공유·맵·옷장·넘기기·내 역할·소리·동작·보내기·유언·새 글·닫기·꾸미기 시트 탭(맵/의상)·결과 탭(전체·마피아·유령·기록). 면제는 E-1(방장 내보내기 ×, 확인 시트가 이름을 말함)·E-2(테스트 방 봇 ±, 개발 도구)·E-3(채널 아이콘, 누르는 것이 아님) 셋뿐이고 이 밖의 아이콘 단추는 결함이다(`test/client` 전수 시험).
- 이름 바꿈: 새 메시지 점 → "새 글", 꾸미기 → "옷장", 역할 카드·아이콘만 두 모양 → "내 역할" 하나로 통일.

0073-3. **빛남은 "지금 이걸 누르세요" 하나만 뜻한다(D-02·D-08, HOST-03·04).**
- 대상에 `data-call` + `is-call`: `light-lamp` 테두리 + 정지 빛, 처음 반복 5회(약 5.5초)는 맥박, 이후 정지. 모션 줄이기는 맥박 없이 정지 빛만. 한 화면에 한 종류(같은 그룹)만 빛난다.
- 대상은 `callTargetsOf(view)` 가 view 로 만든다(대기실 방장 [시작], 역할 확인 카드 면, 토론 입력칸, 투표 산 사람 이름표, 변론자 [유언], 찬반 [찬성]·[반대], 밤 산 경찰·의사의 이름표). 마피아 밤은 빛나지 않는다(동료·대상이 빛으로 드러나지 않게). 소리는 내지 않는다.
- 내가 그 도구를 쓰면 즉시 꺼지고 되살아나지 않는다. "썼음" 상태는 클라이언트 로컬이고 키는 `phase:day.n:candidate` 라 단계·일차·변론자가 바뀌면 풀린다. 재접속처럼 이미 고른 상태(`day.points` 내 줄·`me.pick`·`me.verdictVote`)는 처음부터 켜지 않는다. 열린 시트·키보드·귓속말 모드에서도 켜지 않는다.
- 색 약속: `light-lamp` 는 빛남만, `brass-200/400` 은 공개 투표(맵 위)와 사회자 띠(띠 안)로 겹치지 않게, `crimson-400` 은 마지막 5초, `gray-100` 눌림 면은 내가 이미 고른 것. 13페이즈의 투표 깜빡임(3초)은 빛남이 대체하고 삭제했다(U-7).
- 경찰·의사 밤 빛은 얼굴 칸(`FaceList callSeats`)에 켠다(밤 맵 이름표에는 `call` 이 없다. 마피아 이름표 선택은 그대로).

0073-4. **알림음 `ui.host` 는 띠의 단계 키가 바뀐 프레임에 한 번 울린다(D-01, HOST-02).**
- 새 닫힌 신호 `{ kind: "host" }`(인자 없음). 레시피는 `src/audio/recipes.ts` 의 합성 맑은 종 두 음 상승(880 → 1318 Hz, 약 350ms), `ui` 버스. 소리 끄기·잠김은 기존 엔진이 따른다. `docs/audio.md` 에 행을 더했고 시험 페이지에서 들을 수 있다(소리 57개).
- 같은 단계 안 문장 변화(투표 중 선두·카드 연 뒤)·재접속·처음 마운트의 첫 프레임·빛남 변화에는 울리지 않는다.
- **밤 진입의 알림음은 밤 무음(LS-7)의 예외다.** LS-7 은 사용자 행동·역할이 소리로 드러나지 않게 하는 규칙이다. `ui.host` 는 인자 없는 공개 단계 전환이라 모든 역할(마피아·경찰·의사·시민·유령·모션 줄이기)이 같은 프레임에 같은 소리를 듣는다. `tap`·`card`·`vote`·`deny`·`result` 의 밤 무음은 시험이 그대로 지킨다. 시험은 "`ui.host` 를 뺀 `ui.*` 는 0, `ui.host` 는 여섯 로그 모두 한 번"으로 바뀌어 같은 소리를 듣는다는 증거가 더 강해졌다.
- **낮 시작 → 토론은 울리지 않는다**(낮 시작에서 이미 울렸고 2초 단계라 뭉개진다). 판정은 `hostChimeOf` 가 하고 방 화면은 그 식만 부른다.

0073-5. **역할 확인 화면·[내 역할] 시트 앞면에 목표 한 줄(D-05, TOOL-03).**

0073-8. **계획 단계에서 정한 것.**
- (a) **꺼진 장치로 이루어진 화면(순차 지목·결선·마지막 3인·귓속말 모드)은 13페이즈 계약 그대로 헤더 안내 줄·차례 링을 쓴다(`LegacyMapHeader`).** 기본판 서버는 그 view 를 보내지 않아 화면에 나타나지 않는다(결정 0072 선례). 장치를 다시 켜면 옛 머리가 돌아온다.
- (b) **밤 진입 알림음은 LS-7 의 예외, 낮 시작 → 토론은 무음**(0073-4). 모두 같은 소리라 정보가 새지 않는다.
- (c) **쉬는 사람 화면(`view.resting`)에는 띠가 없다**(U-9 예외, T-11-40). 쉬는 사람은 이번 판 view 가 없고 자기 한 줄만 받으므로 띠가 말할 것이 없다. 띠가 없는 화면(쉬는 사람·연결 실패·다른 창 안내)에는 소리 단추만 있는 `HostDock` 을 옛 자리에 둔다(`[data-host-band]` 는 없다).
- (d) **남은 초는 올림이다**(U-4). CONTEXT 재량 문구("정수 초 내림")와 달리 기존 링·E2E·`timerTone` 과 같은 값을 쓴다.
- (e) **접근성 이름은 보이는 낱말을 포함한다**(WCAG 2.5.3 Label in Name). 이미 낱말을 품은 이름("동작 고르기"·"유언 쓰기"·"닫기"·"전체 대화"·"판 기록")은 그대로 두고, 낱말이 없던 "새 메시지"만 "새 글"로, 꾸미기는 "옷장"으로, 역할 카드는 "내 역할"로 바꿨다. 소리 잠김 알약("소리 켜기")만 "보이는 글자가 낱말로 시작"으로 판정한다.
- (f) **`PhaseBar`·`Timer` 부품은 사용처 0이지만 지우지 않는다.** 꺼진 장치 화면(a)이 옛 머리를 쓰고, 다시 켤 때 돌아올 부품이다.
- (g) **빛남의 "썼음" 상태는 클라이언트 로컬**이고(0073-3) 맥박은 반복 5회다.
- (h) **새 기록 점은 gray-100 8px 로 통일**(옛 글자판의 앰버 12px 폐기, v2.0 은 앰버를 쓰지 않는다는 규칙에 맞춤). 헤더 윗여백은 18 → `--space-sm` 8: [내 역할] 단추가 약 57 로 커져 띠가 내려가는 것을 줄이기 위함이다.
- (i) **경찰·의사 빛남은 얼굴 칸에 켠다**(0073-3). 소리 단추 독은 띠 안에 있어 `[data-host-band]` 가 독을 포함하고, 스테이지 안전선은 띠 면(`[data-host-band] .mv-host__band`)만 잰다.
- (j) **라이브 영역은 문장 칸이다.** 띠 전체가 `role="status"` `aria-live="polite"`, 시간은 `role="timer"`(초마다 읽지 않음).

## 실행 중 달라진 곳 (14-01~14-08 SUMMARY 편차)

- **14-01**: 띠가 없는 화면(쉬는 사람·연결 실패)의 소리 단추가 사라지는 결함을 막으려 `HostDock` 을 추가했다(Rule 2). `[data-host-band]` 표식을 띠 루트(독 포함)에 두기로 계획 두 곳의 어긋남을 풀었다. 떠 있는 재접속 띠는 같은 자리라 `z-index` 를 `--z-overlay + 2` 로 올렸다. 새 `role="timer"`·`role="status"` 로 깨진 시험 다섯 파일을 판정 완화 없이 새 계약으로 고쳤다.
- **14-02**: 헤더 안내 줄·시계를 지우고 띠로 옮겼다. 꺼진 장치 화면은 옛 헤더를 유지한다(0073-8 a). nightMap·gameMap 의 헤더 링 단언도 새 계약으로 고쳤다.
- **14-03**: 밤 진입 알림음 예외(0073-4). nightMap "밤 소리" 시험은 `ui.host` 만 한 번 허용하는 단언으로 바꿨다. 소리 개수 56 → 57. `director` switch 에 `host` case 를 두지 않았다(좁힘이 완전성을 보장, TS2678). E2E 밤 동일성은 `ui.host` 를 뺀 나머지 id 로 본다(다른 문턱·개수는 그대로).
- **14-04**: `.is-call` 라벨 규칙 선택자를 부품 규칙 시험(진홍·놋쇠 없음)과 충돌하지 않게 썼고 예외 목록에 `.mv-tag.is-call` 을 더했다. 이미 찬반을 고른 사람(재접속)에게 [찬성]·[반대]가 켜지던 결함을 `me.verdictVote === undefined` 조건으로 고쳤다. 맵 화면 빛남 시험의 RED 커밋은 따로 남기지 못했다.
- **14-05**: 역할 확인 머리를 게임 화면 헤더와 같은 절대 배치로 바꿨다(띠가 같은 방식으로 붙게). `RoleCardButton` 은 `data-tool-label` 을 싣기 위해 raw `<button>` 이다.
- **14-06**: `ToolButton`(신규 작은 부품)을 더했다. 시트 닫기 알약이 약 84 폭이라 제목 오른쪽 여백을 넓혔다. 결과 탭 안쪽 여백 10 → 8.
- **14-07**: `DRESS_TEXT.open` 한 곳만 바꿔 옷장 이름이 단추·접근성·시트에 함께 바뀐다. 떠 있는 단추 지름 48 은 단추가 아니라 면이 맡는다. 귓속말·배지 `FloatAction` 은 기본판에서 나오지 않아 전수 시험에 단추가 없다(다시 나오는 판에서는 `word` prop 으로 짧은 낱말을 줘야 한다).
- **14-08**: 새 E2E 흐름 `emcee-band`·`emcee-tools`·`emcee-leak`·`emcee-sound` + 읽기 도우미. 역할 확인 머리의 [테스트] 단추가 가려져 눌리지 않던 것(`pointer-events`)을 고쳤다. **마지막 5초 숫자 색은 `crimson-300`(대비 5.5:1)이고 막대는 `crimson-400` 그대로다 — `crimson-400` 숫자가 어두운 면 위에서 4.2:1 이라 묶음 H(4.5:1)에 못 미쳤다. UI-SPEC 의 "숫자도 같은 색" 문구와 다르다.** 뷰 키 허용 목록 사본에 `me.will`·`me.note`·`day.chalk` 를 더했다(9페이즈 상태 의존 키, `emcee-leak` 이 처음 잡았다; `e2eContract` 가 `shared/protocol.ts` 선언으로 고정). 입력줄 이름표 단추(면 36 + 4 + 라벨 19.6 = 59.6)가 패널을 11.6 키워 판정이 그만큼 더한다(앱 상수는 그대로). 옛 E2E 기대(떠 있는 단추 상자 48×71.6·시상 패·맵 칩의 띠 아랫변 + 8 등)를 새 계약으로 옮겼고 문턱·개수는 낮추지 않았다.

## 알려진 한계 (받아들임, 고치지 않음)

- 360×560 위쪽 비좁음: 띠 때문에 이름표·칩이 띠 밑으로 겹친다. 8페이즈부터 두던 "작은 화면 가장자리 잘림"과 같은 취급이다. 측정값(정보 줄): HO1k 이름표 3 이 띠와 103.8×5.6px 겹침(띠는 눌림을 받지 않아 이름표는 눌린다), R-MS6k 맵 칩이 이름표 한 칸과 겹침, AW4k 시상 패 아래 스테이지 125.6 < 150, GH13k 유령 이름표가 띠 밑이라 화면 그림으로 대비를 못 잼.
- 8자 이름(첫 봇 이름이 8자 고정)은 이름표가 3줄로 감기거나 겹칠 수 있다.
- 채팅 입력줄의 [유언] 단추와 [보내기] 사이 눈에 보이는 간격이 16 → 8(깃펜의 여분 왼쪽 여백 제거, 폭 360 에서 입력칸 172 확보)로 줄었다. 실기기 확인에서 오터치가 없는지 본다.
- [내 역할] 단추 높이가 약 57 이고 헤더는 62 라 거의 꽉 찬다.
- 스크린리더는 띠(aria-live)와 단계 읽기, 아침 알림을 함께 읽을 수 있다.
- `PhaseBar`·`Timer` 부품 사용처 0(0073-8 f).

## 정하지 않은 것 (넣지 않는다 — Deferred)

- 사회자 음성 낭독(D-01): 글 + 합성 알림음만. 추가 요구가 생기면 새 결정으로.
- 첫 판 말풍선 안내·연습 판(D-06): 넣지 않는다.
- 15페이즈(심부름·목격·밤 흔적)의 사회자 줄은 예약 행(`errand`·`witness`·`trace`)에 문구만 채우면 된다. 표 구조는 14페이즈가 확정했다. → 15페이즈가 채웠다(결정 0074).
