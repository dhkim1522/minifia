# 0074 v3.0 심부름·목격 기록·밤 선택 통일·아침 흔적: 토론 전 40초 심부름, 근처 사람만 보이는 동선, 같은 모양의 밤 (0071 확장)

- 상태: 채택
- 날짜: 2026-11-07

## 배경

- 팀 모의 플레이 피드백(`docs/playtest-v2.0-feedback.md`)의 "증거가 없다"를 풀기 위해 v3.0 15페이즈는 낮에 심부름 단계를 두고, 심부름 중 본 것을 토론의 기록으로 주고, 밤을 모든 역할이 같은 모양으로 하게 하고, 아침에 흔적 하나를 공개한다(`.planning/phases/15-errand-and-trace/15-CONTEXT.md` D-01~D-10).
- 화면 값은 `15-UI-SPEC.md` 의 위임 기본값 U-1~U-18 로 정했다. 사용자가 자리를 비우며 위임했고(2026-11-07), 사용자는 돌아와 아래 0074-7 표의 한 줄씩을 바꿀 수 있다.
- `RULESET` 에는 새 스위치가 없다(D-07). 기준 커밋 대비 `shared/game/ruleset.ts` diff 는 0이다. 심부름·흔적은 기본판에서 항상 켜져 있다.
- 숫자는 `shared/game/phases.ts` 한 곳이 원천이다: `ERRAND_MS` 40000 · `ERRAND_COUNT` 3 · `ERRAND_ACT_R` 1.2 · `ERRAND_NEAR_R` 3.0 · `ERRAND_TICK_MS` 1000 · `ERRAND_VIEW_HORIZON_MS` 1500 · `ERRAND_MIN_GAP_MS` 250 · `RECORD_MAX` 6 · `MORNING_TRACE_MS` 3000. 실테스트 뒤 이 줄들만 고친다.

## 결정

0074-1. **심부름은 낮 시작 다음, 토론 앞의 40초 단계다. 마피아도 같은 목록을 받는다(D-01·D-03·D-07).**
- 새 단계 `errand`(`낮 시작 → errand → 토론`, 마감 40초, 일찍 끝내기 없음). 산 사람마다 서버가 맵 장소 후보에서 3곳을 뽑아 `me.errand.places`(순서 없는 목록)와 진행 `done` 을 보낸다. 장소 id 는 닫힌 집합 16개(`PLACE_IDS`, 재즈 바 8 + 시계탑 광장 8)이고 `MapDef.places` 가 없는 맵은 빈 목록이다.
- 처리는 `{t:"errand"}` 한 메시지다. 필드가 없고 서버가 내 위치로 판정한다(반경 `ERRAND_ACT_R` 1.2 안의 미처리 장소). 거절(단계 아님·유령·가까운 장소 없음·이미 처리·간격 초과 등)·무효는 모두 같은 응답이라 어느 이유인지, 내가 마피아인지가 응답으로 새지 않는다. 연타 방어 간격 `ERRAND_MIN_GAP_MS` 250ms 는 받아들인 요청이 아니라 간격 검사를 통과한 모든 시도에서 기록한다(성공 여부가 타이밍으로 새지 않게).
- 마피아의 목록은 시민의 것과 같은 모양의 가짜가 아니라 같은 규칙으로 뽑은 진짜 목록이고(방해 행동 없음), 처리 방식·화면·네트워크 모양이 역할과 무관하다. 마피아에게 심부름은 알리바이이자 목격 기회다.
- 심부름 단계는 채팅·동작을 받지 않는다(`CHAT_PHASES`·`emotePhases` 밖, silent). 걷기와 처리뿐이고 유령은 지도 단계에서 자유롭다. 판 통계(`STAT_PHASES`)에도 넣지 않았다. 봇은 장소를 돌며 처리한다(난수 호출 순서는 기존 시드 고정 값을 바꾸지 않게 지켰다).
- 화면(U-1~U-6): 채팅 없는 전용 아래 패널 `ErrandDock`(높이 84 + 안전 영역, 한 줄 = 진행 칩 3 + "n/3" + [처리] 알약 104×48). 맵 위에 내 장소 표지(투영 원 36, 누르기 44)·다음 장소 방향 화살표 칩 하나·발밑 근처 반경 점선 링. "다음 장소"는 클라이언트가 내 위치에서 가장 가까운 미처리 장소로 계산하고(서버 값 없음) 그것만 빛난다. 표지를 누르면 그곳으로 걷고(처리는 [처리]로만), 근처가 아닐 때 [처리]는 `aria-disabled` 불투명 .45 로 눌려도 아무 일 없다. 3곳을 마치면 [처리] 자리가 체크 + "완료"가 된다.
- 사회자 띠: `errand.act`("심부름 시간입니다. 장소 세 곳을 돌며 처리해 주세요.") · `errand.done`("심부름을 마쳤습니다. 곧 토론이 시작됩니다.") · `errand.ghost`("심부름 시간입니다. 유령은 지켜봐 주세요."). 이 분기는 역할을 읽지 않는다.
- 알림음은 새 레시피가 없다. `hostChimeOf`: 낮 시작 → 심부름은 무음(낮 시작에서 이미 울림), 심부름 → 토론에서 `ui.host` 가 한 번 울린다. [처리]는 기존 `ui.tap`.

0074-2. **심부름 중 다른 사람의 위치는 근처에 있을 때만, 서버가 근처 사람의 위치만 보낸다(D-02).**
- 위치 전송은 사건이 아니라 표본이다. errand 단계에서 알람이 1초(`ERRAND_TICK_MS`)마다 깨어(상태 저장은 표본당 한 번, 낮 한 번에 약 40회) 산 사람끼리 거리를 잰다. 근처 = 고정소수점 유클리드 거리 ≤ `ERRAND_NEAR_R` × UNIT(경계 포함, 대칭). 받는 사람마다 "나 + 내 근처 산 사람"의 `world` 프레임(`near: true`)만 간다. 멀리 있는 사람의 좌표는 보내지 않는다.
- 근처 사람의 이동 구간은 지금부터 `ERRAND_VIEW_HORIZON_MS` 1.5초로 자른다(1초 표본 사이에 끊기지 않고, 서버가 미래 경로를 길게 알려 주지 않는다). 단계 진입·이탈과 알람 따라잡기로 늦게 errand 에 닿는 경우도 같은 규칙이다. 늦게 닿은 첫 표본은 `now + 1초`로 옮기고, 이미 전체 snap 을 보냈으면 진입·이탈 snap 을 건너뛰어 snap 이 겹치지 않게 했다.
- 유령은 심부름 중 모든 사람의 위치를 본다(U-16, 거리 제한 없음). D-02 는 산 사람의 시야 제한이다. 산 사람이 자기 근처에서 벗어나면 서버가 그 사람 위치를 끊는다. 표본 상태는 방 상태에 저장한다(`Player.errandNear·errandSeen`, `RoomState.errandTickAt`).
- 클라이언트(U-17): `near: true` 프레임은 "표본에 없는 사람은 사라진 것"으로 읽는다. 새로 보이는 사람은 등장(`dur-fast` 페이드인), 빠진 사람은 이름표와 함께 퇴장(페이드아웃), 모션 줄이기는 즉시. near snap 은 월드 사본의 `moveSeqs` 를 비우지 않아(남은 좌석의 세기 유지) 걷는 중의 예측 구간과 링이 끊기지 않는다. 투영(표지·화살표·링)은 런타임 `onProject` 한 곳에서 프레임마다 DOM 에 직접 쓰고 React 상태를 거치지 않는다.
- 이름표 DOM 은 방의 사람 수만큼 있고 근처 밖은 opacity 0 이다(공개 목록이라 위치 정보가 없다). E2E 는 보이는(opacity > 0) 이름표 수로 판정한다.

0074-3. **목격 기록은 3곳을 모두 마친 사람에게만, 본인에게만, 토론 때 준다(D-04).**
- 표본마다 "내가 본 사람 B 가 어느 장소 곁에 있었는지"를 기록한다(`Player.errandSeen`). 줄 = `{seat, place}`, 시간순, 상한 `RECORD_MAX` 6. 줄의 장소는 B 에게 그 순간 가장 가까운 맵 후보 장소다(내 목록 3곳에 한정하지 않음 — 단서이지 증명이 아니다). 한 사람이 두 곳에서 보였으면 두 줄.
- 3곳을 모두 마친 산 사람만 `me.record`(`{seat, place}[]`)를 받는다. 못 마친 사람·유령·다른 단계에서는 키 자체가 없다. 마피아도 같은 규칙이다. 토론 이후 단계에도 `errandDone` 이 남아 있어 record 가 계속 실리고 밤 진입에서 지운다. 그래서 클라이언트가 [기록]·카드를 토론 단계에서만 그린다.
- 화면(U-7~U-9): 토론 헤더 [기록] 단추(기록 있을 때만)가 빛나고 띠가 부른다(`witness`: "토론 시간입니다. 기록 단추로 본 것을 확인해 주세요."). 카드는 접힌 채 시작하고, 한 번 열면 빛은 꺼져 되살아나지 않는다(열림 래치 하나). 입력칸 포커스가 가면 자동으로 접힌다. 줄 = 순서 번호 + 장소 아이콘 24 + 얼굴 28 + 닉네임, 높이 44. 마쳤지만 본 사람이 없으면 눈 아이콘 + "0" 한 칸(글 없음)이다.
- **기록 카드 겹침 규칙**: 카드는 채팅 기록 칸을 덮는 것이 설계다. 카드 윗변 ≥ 독 아랫변 + 8, 띠와 교차 0, 아랫변 ≤ 채팅 입력줄 윗변 − 8(`--mf-record-bottom` 을 입력줄에서 재어 쓴다). 입력줄·[토론 끝내기]는 가려지지 않는다. 카드가 열려 있는 동안 스테이지 이름표는 가려질 수 있다(사용자가 연 것). E2E RC3 은 이 기준으로 본다(처음 계획의 "아래 패널과 교차 0"은 360×560 에서 성립하지 않아 UI-SPEC 설계를 따라 정정했다).

0074-4. **밤 선택은 모든 역할이 같은 모양이다: 같은 메시지·같은 응답·나 포함 산 사람 전원의 같은 얼굴 목록(D-05, TRACE-01).**
- 산 사람은 마피아·경찰·의사·시민 모두 같은 `FaceList` 패널에서 "고르기"를 한다. 시민의 고르기는 효과가 없다. 거절 이유는 단계·행위자·대상 세 가지뿐이고 응답은 역할과 무관하다.
- **U-11 개정**: UI-SPEC 의 "자기를 뺀 산 사람"을 **"나 포함 산 사람 전원"**으로 고쳤다. 의사의 자기 보호가 서버 규칙이라 의사만 자기 칸을 가지면 칸 수가 역할마다 갈라진다. 의사 규칙은 바꾸지 않았다. 동료(마피아끼리)를 고르거나 자기를 고르는 것은 서버가 효과 없이 받는다(집계는 마피아를 세지 않고 `confirmedTarget` 이 걸러낸다). 얼굴 칸 이름은 "{이름} 고르기", 묶음 이름은 "밤 대상"이다.
- 마피아의 "걸어가서 접근하기" 연출·밤 걷기 메시지·`approach`·`data-ring-kind="mafia"`·`aim`·몸 윤곽 선택 표시는 모두 없앴다(`approachPoint`·`APPROACH_DIST_FX` 포함). 밤 `world` 는 산 사람 모두에게 본인 한 칸 하나다(마피아 걷기·다른 마피아 위치 없음). `canMoveIn(phase, alive)` 는 두 인자뿐이다. 마피아만 걷기 메시지를 보내면 네트워크로 역할이 샌다.
- **마피아 밤 채팅 패널은 화면에서 삭제**했다(서버 채널 `channelOf`·집계(`me.nightTally·nightSure`)·쪽지·spectate 는 유지). 되돌리는 한 곳 = `GamePanel` 의 밤 분기. 산 마피아에게 보이던 "{이름} · 확정" 알림은 칸 안 check 표시가 대신한다. 사람이 밤 채팅을 보낼 수단이 없어 `result-reveal` 흐름은 "마피아 탭에 밤 채팅 줄 없음·입력칸 없음"을 확인하도록 바꿨다(시험 전용 훅 없음, 15-10 결정).
- 밤에 동작(emote) 버튼도 모든 산 사람에게 없다(마피아 방장의 동작 칸 삭제). `[쪽지]`(마피아)·`[유언]`(그 밖) 행동 줄만 역할을 본다.
- **겉보기가 같음의 유일한 예외 = 마피아 선택 수 배지**(T-15-32 accept, 사용자가 바꿀 수 있는 기본값): 산 마피아의 얼굴 칸에는 `me.nightTally`(n ≥ 1)가 `.mv-face__count` 배지로 보인다. 마피아끼리 합의하려면 필요한 정보라 남겼다. 다른 세 역할의 화면에는 없다.
- 사회자 줄: 14 의 `night.wait` 가 `night.citizen`("밤이 되었습니다. 한 명의 이름표를 눌러 주세요.")으로, `night.mafia` 가 "없앨 사람의 이름표를 눌러 주세요."로 바뀌었다. 빛남은 마피아·시민·경찰·의사 모두 같은 좌석 오름차순의 산 사람 칸에 켠다(결정 0073-3 의 "마피아 밤은 빛나지 않는다" 개정). 밤 얼굴 목록 모양은 네 역할 시점이 `faceSig` 로 같다.

0074-5. **아침 흔적은 피해자를 고른 사람 중 한 명의 의상에서 뽑은 조각 id 하나다. 확정 증거가 아니다(D-06, TRACE-02·03).**
- 풀 = 밤 시작 때 산 사람 중 `nightPick` 이 피해자 seat 인 사람(피해자 본인 제외, seat 오름차순). 역할을 읽지 않는다. 서버가 `randInt(풀 크기)` 한 번으로 한 명을 뽑아 그 사람 의상(없으면 `coat`)의 조각을 정한다. 풀이 비면(구출·무효·처형 없는 아침 등 피해자가 없음) 흔적 키가 없고 난수도 부르지 않는다. `tick` 은 탈락자가 있는 밤 → 아침에 난수가 필요하다(서버는 항상 `cryptoRandInt`).
- `view.day.morning.trace` 는 닫힌 집합 `TRACE_PIECE_IDS` 9개 중 하나뿐이다. 좌석·의상 id·풀은 어디에도 내보내지 않는다. 의상 → 조각 표(`TRACE_OF_OUTFIT`, 의상 id 와 조각 id 가 겹치지 않음):

| 의상 | 조각 id | 이름(클라이언트 표 `TRACE_TEXT`) |
|---|---|---|
| coat | button | 단추 하나 |
| police | pin | 은빛 핀 |
| doctor | whiteCloth | 흰 천 조각 |
| mafia | blackCloth | 검은 천 조각 |
| detective | brownCloth | 갈색 천 조각 |
| reporter | pencil | 노란 연필 조각 |
| elder | grayThread | 회색 실밥 |
| hood | navyThread | 남색 실밥 |
| noir | redCloth | 붉은 천 조각 |

- 이름에 역할 연상어(경찰·의사·마피아·시민·가운·정장)와 "범인·증거·확정"을 쓰지 않는다(시험이 막는다). 카드 = 아이콘 `thread`(44 원) + 조각 이름 + 고정 보조 문구 "누구의 것인지는 모릅니다". 의상은 아무나 입을 수 있어 마피아일 수도, 우연히 같은 사람을 고른 다른 사람일 수도 있다(T-15-13 accept).
- **아침은 흔적이 있으면 +3초**(`phaseDurationMs` + `MORNING_TRACE_MS`, 최대 14초). 흔적 구간 = `phaseEndsAt − MORNING_TRACE_MS` 부터 단계 끝까지(서버 시계). 피해자 알림·유언·쪽지가 끝난 뒤 같은 자리(위 240, 좌우 16, 높이 약 88)에 카드가 이어서 나오고 띠가 "현장에 흔적이 남았습니다."로 바뀐다. 알림음은 `ui.card` 한 번(구간 시작 전 마운트에서만, 재접속·새로 고침은 소리 없음). 카드는 아침 단계가 끝나 장면 막이 덮는 순간 같이 사라지고 퇴장 전환은 만들지 않았다.

0074-6. **누설 규칙과 검사(D-08, DEPLOY-03).**

0074-8. **계획 단계에서 정한 것(각 계획 `<context>` 결정 절).**
- (15-01) 장소 id 16개는 닫힌 집합. 처리 메시지에 필드 없음, 거절·무효·간격 초과 응답 동일. 간격 기록은 간격 검사를 통과한 모든 시도에서. 계획 좌표 중 맵 규칙(걷기·간격)을 어긴 세 곳은 가까운 걷기 칸으로 옮겼다. errand 는 채팅·동작 불가. 난수는 errand 진입에서만 불리며 인자는 8·7·6(산 사람 × 3 의 배수 호출), 밤 → 아침은 탈락 시에만.
- (15-02) 위치 전송은 사건이 아니라 표본. 목격 줄 장소는 B 에게 가장 가까운 맵 후보. 근처는 대칭·산 사람끼리·경계 포함. 표본 상태는 방 상태에 저장. 마감 전 알람은 `errandTickAt` 이 이르면 그 시각에 걸린다(마감은 진입 + `ERRAND_MS` 그대로). `snapFrameFor` 는 보낼 좌석이 없는 단계에서 null.
- (15-03) U-11 개정(0074-4), 마피아 밤 채팅 서버 채널·집계 유지, `pickRecipientIds` 그대로(마피아의 pick 은 산 마피아 전원에게 state 가 가고 비마피아의 pick 은 본인 + 유령뿐 — "같은 응답"은 보낸 소켓이 받는 프레임 열이 같다는 뜻). 흔적 풀 = 피해자를 고른 산 사람, 조각 표 9개, 아침 +3초.

- **15-01**: E2E 사본의 단계 전이·장면 표(`BASIC_TRANSITIONS`·`EXPECTED_SCENE`)에도 errand 를 더했다. 모든 시각이 `ERRAND_MS` 만큼 밀리므로 봇 시드 고정 값은 시각만 `- ERRAND_MS` 로 되돌려 같은 값을 지켰다(난수 호출 순서 불변의 증명). 알람 따라잡기 시험은 허용 단계에 errand 를 더했다.
