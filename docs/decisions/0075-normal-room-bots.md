# 0075 일반 방 방장도 서버 봇으로 빈자리를 채운다

- 상태: 채택
- 날짜: 2026-11-07

## 배경

- v3.0 실테스트는 4명 이상이 필요한데, 사람이 2~3명뿐인 때가 많다. 지금은 `?test=1` 테스트 방에서만 봇을 넣을 수 있고, 테스트 방은 끊김 유예가 짧아(대기실 6초, 방장 3초) 실제 판처럼 쓰기 어렵다.
- 사용자 요청: "사람 2~3명일 때 방장이 나머지 자리를 봇으로 채워 4~5명이 같이 플레이할 수 있게".

## 결정

1. **`testBots` 메시지는 일반 방 방장도 쓴다.** 검사 순서는 방장(`NOT_HOST`) → 대기실(`WRONG_PHASE`) → 개수(`BAD_MESSAGE`)다. testMode 검사만 없어지고, 개수·자리·이름·8명 한도 규칙은 결정 0024 그대로다. 와이어 이름(`testBots`, `me.testBots`)은 배포 뒤 한 방향 계약이라 바꾸지 않는다.
2. **`me.testBots` 는 방장 본인의 대기실 view 에 항상 싣는다**(테스트 방 여부와 무관, 0 포함). 손님·게임 중 view 에는 키가 없다. `isBot`·`botPlan`·봇 id 는 여전히 어디에도 없다.
3. **화면**: 대기실 오른쪽 아래 떠 있는 버튼 묶음에 방장만 **[봇]** 버튼(안테나 달린 얼굴 아이콘)을 옷장 위에 둔다. 누르면 '봇' 시트에 `[−] N명 [+]`·`[5명 채우기]` 줄이 있다. 줄은 테스트 도구 시트와 같은 부품(`BotStepper`)이다. 사용자 선택: [봇] 도구 버튼 안, 시안 없이 진행.
4. 다른 테스트 도구(단계 넘기기·대기실 복귀·직업 지정·봇 투표 고정)와 짧은 유예는 테스트 방 전용으로 남는다.

## 결과

- 일반 방에서 사람 2명 + 봇 3명 판이 1일차 심부름 → 토론 → 투표 → 밤 → 아침 → 2일차까지 도는 것을 로컬에서 확인했다.
- 손님에게 봇은 지금처럼 이름이 '봇…' 으로 시작하는 평범한 참가자로 보인다. 공개 항목은 그대로다.
- 정식 출시 전에 봇 기능을 그대로 둘지(예: 친구 모으기 전 연습용)는 출시 마일스톤에서 다시 본다.
