# 0080 튜토리얼 "첫 사건" — 계획 단계 결정과 위임 기본값

- 상태: 채택(계획 단계 추천안 — 사용자가 돌아와 한 줄씩 바꿀 수 있다)
- 날짜: 2026-11-09 (계획 단계) · 2026-11-09 (17페이즈 완료)
- 바꾸는 것: 0078 결과 절의 "함께 진행의 서버 부분은 17 에서 다시 정한다"를 확정, 0077-2 의 대기실 기본값 문장은 유지

## 배경

0078 이 튜토리얼을 "첫 사건" 미니 에피소드로 정하고 17페이즈로 뗐다. 17-UI-SPEC 은 사용자가 승인했고(시안 캔버스 선택 포함), 17-RESEARCH 의 Assumptions A1~A12 는 사용자가 자리를 비운 사이 모두 추천안으로 진행했다. 이 문서는 계획 단계에서 그 추천안을 번호로 고정한 것이다. 17-02~17-09·17-12 계획이 아래 번호(0080-1~0080-19)로 가리킨다. 실행 중 달라진 곳과 한계는 17-10 이 이 문서에 더해 완성했다(아래 세 절).

## 결정

0080-1. (A1) 스위치 값은 `start` 메시지의 `tutorial?: boolean` 으로만 서버에 간다. 서버 기본은 꺼짐. 별도 설정 메시지·`view.tutorialOn` 방송은 없다. 스위치는 방장 화면의 로컬 상태이고 [시작] 순간의 값이 실린다(UI-SPEC T-4 를 따르고, UI Considerations #25 의 "서버가 방송한 값만 따른다" 문장은 이 결정으로 바뀐다).
0080-2. (A2) 역할은 지금처럼 beginGame 이 시작 때 배정한다(assignRoles·testRole·decideMap 난수 순서 그대로). tutorial 단계는 revealsOwnRole:false 라 view 에 역할이 없다. T-19 의 "역할은 튜토리얼이 끝난 뒤에 정해진다"는 관측 계약(튜토리얼 중 어떤 view 에도 역할 없음)으로 지킨다.
0080-3. (A3) 테스트 방(me.testMode) 방장의 스위치 초기값은 꺼짐(줄은 보인다). 일반 방은 첫 판 켜짐, 다시 하기(rematch 는 대기실을 거치지 않음)는 늘 꺼짐.
0080-4. 방장 패널 증분은 UI-SPEC 숫자 +76 을 지킨다: 스위치 줄 64 + 패널 간격 10 + 줄 위 margin-top 2 → 326/382. 앱 상수 `LOBBY_HOST_TUTORIAL_EXTRA = 76`.
0080-5. (A6) 저장 키는 T-2 문자열 `minifia.tutorial.seen` 그대로(코드베이스의 콜론 표기와 다름 — 위임 기본값 존중). 값은 "1". session.ts 의 read/write(메모리 대체)에 얹는다.
0080-6. (A12) 튜토리얼 화면 안에서는 기존 호출 빛남(.is-call)의 5회 맥박(::before 애니메이션)만 끄고 정적 테두리(::after)는 둔다. 깜빡이는 것은 FocusRing 하나다(0078-8 한 규칙, T-14 의 우체통 램프 빛은 정적으로 남음).
0080-7. (T-20, Open Q1) 혼자 하기는 history.pushState 를 쓰지 않는다. 뒤로 가기는 앱을 떠나고 다시 열면 첫 화면이다.
0080-8. (A7·A8) 새 소리 id 13개: tut.lampOff·tut.scream·tut.whoosh·tut.sting·tut.step·tut.eye·tut.link·tut.buzz·tut.stamp·tut.fanfare·tut.flip·tut.warm + voice.syl. SOUND_IDS 57→70, 효과음 50→63. tut.fanfare 는 4음(D·F·A·E) 한 레시피(옥타브 사인 없음). voice.syl 은 ui 버스·prio 2·max 2·gapMs 0. 목소리 모듈은 문구를 인자로만 받는다. 시험 페이지 묶음에 "튜토리얼" 하나를 더한다(일곱 묶음).
0080-9. (A9·T-12) 램프 꺼짐은 시안 두 곳(왼쪽·오른쪽 가장자리, 390×844 기준 높이 225) 화면 위 번짐이고 tut.lampOff 도 2번이다. WorldStage 에 투영 통과 prop 을 더하지 않는다. 장면 4 도윤의 포커스 상자는 이름표 사각형 기준 합성 상자(아래로 고정 길이)다.
0080-10. (Open Q2) view.tutorial.total = 앉은 사람(봇 제외) 수, done = 그중 끝났음을 보냈거나 연결이 끊긴 사람 수. 연결된 사람이 0명이어도 전원 완료다. 끊김이 생길 때마다 서버가 전원 완료를 다시 본다.
0080-11. 이름: 서버 전용 `RoomState.tutorialPassed?: string[]`(player id), 공개 `view.tutorial = { done, total, endsAt }`(tutorial 단계에서만, 모두 같은 값), 본인 `me.tutorialDone?: true`(보낸 본인에게만, 거짓은 키 없음 — 코드베이스의 `endDiscussion?: true` 관례). assigning 에 들어갈 때 tutorialPassed 를 지운다.
0080-12. 화면 구조: TutorialScreen 하나가 장면 1~7 을 그린다. 장면 2~6 은 실제 GameMap 에 가짜 view·로컬 WorldStore/ChatStore·로컬 send 어댑터를 주고, 장면 1·7 은 WorldStage 를 직접 쓴다(장면 1→2·6→7 사이에 3D 무대를 다시 만드는 순간은 어둠·막 아래라 보이지 않는다). 장면 8 은 첫 화면(Home)의 마무리 카드다.
0080-13. CSS 는 세 파일: `src/styles/tutorial.css`(첫 사건 화면·장면), `src/styles/tutorialEntry.css`(첫 화면 카드·마무리 카드), `src/styles/tutorialRoom.css`(방장 스위치 줄·기다림 화면). 진홍은 tutorial*.css 에서 T-18 의 두 연출 자리(.tut-opening·.tut-reveal·.tut-role 선택자)에만.
0080-14. 소리 소유: TutorialScreen 이 자기 useSound·소리 단추를 쓴다(혼자·함께 같음). RoomScreen 은 tutorial 단계에서 자막 띠·독·자기 소리 훅·알림음을 끈다(hostChimeOf 는 tutorial 진입·이탈에 거짓).
0080-15. 재접속(T-20): me.tutorialDone 이면 기다림 화면, 아니면 장면 1 부터. 끝났음을 보낸 뒤 연결 번호(epoch)가 바뀌면 화면의 로컬 끝남 표시도 비운다(서버 값만 따른다).
0080-16. 출연(T-9 보완): 좌석 0 민준(detective)·1 도윤(noir)·2 서연(elder, 피해자)·3 지호(reporter)·4 하린(hood)·5 나(coat). 좌석색은 좌석 번호에서 나오므로 T-9 의 "하린 seat-3"(서연과 같은 색)은 seat-5 가 된다. 역할 낱말이 든 의상(police·doctor·mafia)은 쓰지 않는다. 내 이름표는 "나" 한 글자 — 이름표 부품이 닉네임이 이미 "나"이면 접미 " (나)" 를 붙이지 않는다.
0080-17. 장면 4 의 [다음]은 눈 표시 + 1.5초(3.4초)에 나온다. 그때 도윤 포커스는 꺼지고 [다음]이 깜빡인다(UI-SPEC 포커스 표 "꺼지는 때: [다음] 등장"). 장면 5·7 의 [다음]은 시안대로 장면 시작부터 보인다.
0080-18. 개발용 손님 봇 스크립트(scripts/bots.mjs)는 tutorial 단계에서 끝났음을 한 번 보낸다(실제 방 부하 시험이 150초에 묶이지 않게).
0080-19. E2E 새 흐름은 tutorial-solo·tutorial-together(--only tutorial 로 둘 다). 150초 시간 초과 경로는 E2E 가 기다리지 않고 워커 시험(알람)이 맡는다. 튜토리얼 장면 3~6 fps 는 E2E 가 보고만 하고 판정은 v3.0 끝 실기기(VALIDATION 수동 항목)다.

## 위임 기본값

17-UI-SPEC 기본값 기록 T-1~T-23 이 원문이다. 이 문서가 바꾼 줄은 넷이다.

- T-9(하린 좌석색): 하린은 seat-3 이 아니라 seat-5 다(0080-16).
- T-12(램프 꺼짐): 시안 두 곳 화면 위 번짐, tut.lampOff 2번(0080-9).
- T-19(me.tutorialDone): 참일 때만 키가 있다(0080-11).
- UI Considerations #25: 스위치는 방장 로컬 상태이고 [시작] 순간의 값이 실린다(0080-1).

값을 바꿀 곳은 다음과 같다. 사용자가 돌아와 값을 바꾸고 싶으면 이 상수만 고치면 된다.

- 튜토리얼 제한 시간 150초: `shared/game/phases.ts` 의 `TUTORIAL_MS`
- 오답 도움이 나오는 오답 횟수: `src/game/tutorialScript.ts` 의 `WRONG_HINT_AFTER`
- [건너뛰기] 뒤에 마무리 카드를 보일지: `TUTORIAL_END_CARD_ON_SKIP`
- 방장 패널 증분 76: `src/game/chatUi.ts` 의 `LOBBY_HOST_TUTORIAL_EXTRA`
- 저장 키 `minifia.tutorial.seen`: `src/game/session.ts` 의 튜토리얼 읽기·쓰기

## 실행 중 달라진 곳

계획 단계 결정 0080-1~19 의 본문은 그대로이고, 실행 중 값이나 방식이 달라진 곳은 아래뿐이다.

- 17-01: 단계 `tutorial` 과 `tutorialDone` 메시지를 더하자 Record·유니온 키 목록을 박은 시험이 깨져 EXPECTED_SCENE 에 `tutorial` 행, 클라이언트 메시지 종류 목록에 `tutorialDone` 을 한 줄씩 더했다(판정은 넓히지 않았다).
- 17-02: 소리 수 고정값은 최종 70(침대 7 + 효과음 63)이다. `tut.step` 의 표 레벨을 −22 → −16 dB 로 올렸다(−22 는 50ms 잡음이 RMS 문턱 −60 dB 에 못 닿았다, 문턱은 그대로). 시작 레벨 범위(−16~−24) 안이다.
- 17-03: 정적 가드(`tutorialStaticGuard`)의 정규식이 겹 괄호 뒤의 `.role` 을 놓쳐 한 단계 겹 괄호까지 잡도록 고쳤다. 확인용으로 `npx tsx` 가 한 번 내려받아 졌고 이후 쓰지 않았다(프로젝트 의존성은 그대로).
- 17-04: [다음]의 깜빡임은 FocusRing 묶음이 아니라 `.tut-next` 자기 테두리다(같은 곳에 이중으로 깜빡이는 것을 피함). 모션 줄이기의 정지 모양은 UI-SPEC 대로 테두리 불투명 + 번짐 .5 다. 시험용 가짜 무대를 `test/helpers/fakeTutorialStage.ts` 로 뺐다.
- 17-05: 화면이 엔진 `play` 를 직접 부르지 못하게 하는 시험 때문에 소리·말 호출은 `useTutorialDirector` 훅(`playTutorialCue`·`sayTutorialLine`)을 거친다. 띠 흔들림 클래스는 `.tut-band.is-shake` 다(계획의 `--shake` 가 아님). 모션 줄이기용 도윤 자리 `tutorialSuspectStand` 를 대본 모듈에 더했다.
- 17-06: 마무리 카드의 `tut.warm` 호출도 같은 이유로 `useTutorialWarm` 훅으로 옮겼다. 동작은 같다.
- 17-07: 같은 연결에서 다음 판이 튜토리얼을 다시 거치면 지난 판의 끝남 표시가 남아 장면 1 을 건너뛰는 틈을 막았다(tutorial 단계를 벗어날 때 ref·state 를 비움). 360×560 방장은 패널 326 으로 스테이지가 172 라 world 흐름의 방장 쪽 겹침 단계를 이 크기에서 참고 행으로 돌렸다.
- 17-08: 서연이 사라진 뒤 이름표만 빈자리에 남지 않도록 `data-tutorial-gone="2"` 를 더하고 그 이름표만 `visibility: hidden` 으로 했다(계획에 없던 작은 속성 하나). 직업 카드 한 줄 설명은 두 줄로 자르지 않는다(글이 잘리지 않는 쪽).
- 17-09: 함께 진행 재접속 검사 순서를 서버 규칙(0080-10, 끊긴 사람은 끝난 것으로 센다)에 맞춰 바꿨다(손님 새로 고침 → 방장 건너뛰기). 장면 6 이름표가 좁은 폰에서 가장자리를 넘는 것은 앱 코드를 고치지 않고 참고 줄(G2k·G2s)로 남겼다. `tutorialBandChecks`·`tutorialLeakChecks` 의 인자 모양이 계획 예시와 조금 다르다.
- 17-11: 이 문서의 번호 표기를 `0080-N.` 로 맞췄다(0079 와 같음).
- 17-12: 편차 없음. 누설 시험(`leak`·`tutorialLeak`)이 view·방송·허용 경로 전체를 덮는다.
- 17-10 단계 1(로컬 전체 검증): 폰 6종 E2E 전 흐름 회귀에서 17-07 의 방장 패널 +76 이 드러낸 곳 둘을 고쳤다.
  - 390×844 맵 불러오기 실패 카드의 [다시 시도] 중심이 방장 패널(윗변 462)에 덮였다(perfbudget E1b). 가림막 아래 여백에 `--mf-panel-h` 를 더해 카드가 패널을 뺀 자리 가운데에 서게 했다(`fix(17-10)`, 제품 CSS 한 줄).
  - avatar-dress·avatar-emote 흐름은 낮은 폰의 방장 열이 두 줄로 접히면서 둘째 열 옷장이 잠긴 소리 알약 밑에 겹치고(390×664, 알약이 접히는 8초 동안), 360×560 은 방장 스테이지가 172 로 낮아 동작 판 EP4·옷장 DB1·방장 쪽 목적지 후보가 알려진 한계다. 흐름이 알약이 접힐 때까지 기다리고 360×560 방장 쪽 세 줄은 참고 행으로 돌렸다(문턱·다른 크기는 그대로, `fix(17-10)`).
  - 그 밖의 흔들림(tutorial-solo 폭 360·390 의 시간 판정 TM1·TB2, errand HS3, reconnect RC1, avatar 재시도)은 같은 크기 재실행에서 통과했고 알려진 간헐(perfbudget B2·M1, witness 시간 초과)은 판정 문턱 그대로다.

## 알려진 한계

고치지 않는다(진행에 지장 없는 작은 화면 가장자리·실기기 몫).

- 360×560 방장 대기실은 패널이 326 이라 스테이지가 172 로 낮고 오른쪽 열이 두 줄로 접혀 겹친다(UI Considerations #24). 390×664 방장은 잠긴 소리 알약이 접히는 8초 동안 둘째 열 옷장을 가린다.
- 360×560·360×640 에서 직업 카드(장면 7) 아래 줄이 [다음] 아래로 겹칠 수 있다(E2E 에서는 360×560 에서만 TC4 참고 줄로 나왔다).
- 장면 6 도윤 이름표(+ 득표 배지)가 폭 360·390·402 에서 오른쪽 가장자리를 3~29px 넘고, 눌러 포커스가 가면 맵 틀이 가로로 최대 29px 밀린다. 고치려면 `.mf-world` 를 `overflow: clip` 으로 하거나 `TUTORIAL_SPOTS` 를 안쪽으로 옮긴다(`deferred-items.md`).
- 튜토리얼 장면 3~6 fps 는 보고만 한다(390×844 headless 평균 60fps, 장면 2~6). 판정은 v3.0 끝 실기기다(0080-19).
- 장면 1→2·6→7 사이에 3D 무대를 다시 만든다(어둠·막 아래라 보이지 않는다고 본 것이고, 실기기에서 끊김이 있는지는 아직 못 봤다).
- 웅얼 목소리(`voice.syl`)와 효과음의 체감, 깜빡이는 테두리가 시선을 끄는지는 실기기에서만 알 수 있다.
- 17-09 의 시간 경쟁: `tutorial-solo` 의 오프닝 4.6초(±1초) 판정과 띠 막대 판정은 여러 흐름이 함께 도는 전체 회귀에서 한두 번 흔들렸다(같은 크기 재실행 통과).
- `test/worker/errandLeak.test.ts`·`bots.test.ts`·`v2Marker.test.tsx` 는 부하에서 가끔 한 번 실패하는 기존 간헐이다(단독 통과). perfbudget B2(점광원 4 > 3)·M1(geometries)은 13페이즈부터의 한계다.
- UI 안전 점검(`ui.safety-gate`)은 설치된 gsd-tools 에 그 명령이 없어 돌리지 못했다.
- 성능 nightload(390×844, 4배 감속, 5분 두 판): 재측정 평균 59.8fps·끊김 6/419초(5분 환산 4.3)이고 첫 측정은 끊김 9(6.4)였다. 끊김은 두 측정 모두 처형 장면에서만 났고(16페이즈도 같은 형태), 6페이즈 게이트는 낮추지 않았다. 합격 판정은 실기기다.

## 정하지 않은 것

- 실제 한국어 낭독 TTS·녹음(지금은 글자마다 짧은 음절로 웅얼거린다 — 0078 의 목소리 방향).
- 햅틱·진동은 앱 전환 때 더한다(웹에서는 새로 만들지 않는다).
- 장면 3 의 화살표(심부름 방향 표시)는 넣지 않았다. 필요하면 실테스트 뒤에 정한다.
- 투표 단계의 변론·찬반·처형 흐름은 장면 6 에 넣지 않았다(지목 한 번과 정체 공개까지). 더할지는 실테스트 뒤에 정한다.
- 첫 방문 때 튜토리얼을 자동으로 시작할지(지금은 첫 화면 큰 카드가 부르기만 하고 누르면 시작한다, 0080-5).
- 실기기 확인(v3.0 끝 실테스트 한 번): 웅얼 목소리·효과음 체감, 깜빡임이 시선을 끄는지, 처음 온 사람의 반응, 튜토리얼 장면 fps, 폭 360 의 직업 카드·이름표 가장자리, 혼자 하기·함께 진행의 흐름.
