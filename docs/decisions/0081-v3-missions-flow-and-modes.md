# 0081 v3.0 할 일 재설계: 원인→결과 하루 흐름, 등불·집 찾기·현장 조사, 방장이 고르는 기본/확장 판

- 상태: 채택(방향). 세부 값은 이 결정을 받는 페이즈의 SPEC·UI-SPEC 에서 정한다
- 날짜: 2026-11-09
- 근거: 17페이즈 UAT 피드백, 조사 문서 `docs/research-v3-missions-ux.md`
- 바꾸는 것: 0007(역할 확인 다음은 낮), 0072·0074 의 하루 순서와 낮 심부름, 0074-4(밤은 얼굴 목록), 0078-8(배경 흐림·어둠 없음). 0072 의 "판 고르기 화면 없음(D-01)"

## 배경

17페이즈 UAT 에서 사용자가 지적한 문제는 다음과 같다.
- 맵이 좁아 심부름 동안 다 근처에 있게 되므로, 목격에 의미가 약하다.
- "아무 데나 가서 처리"는 왜 하는지 당위성이 없어 억지스럽다.
- 흔적과 의심을 무슨 기준으로 찾는지 알 수 없다.
- 하이라이트가 있어도 [다음] 버튼이 눈에 들어오지 않는다.
- 배경이 모두 같은 어둠이다.

조사(관점 6개)에서 근본 원인이 나왔다. 범행은 밤인데 심부름은 낮이라 둘이 끊겨 있고, 마피아에게 낮에 할 일과 들킬 위험이 없다. 로컬 플레이에서는 다음 두 가지도 확인됐다.
- 기본 옷 `coat` 가 겹쳐서 흔적 표시가 전원에게 붙는다.
- 실제 판의 낮 조명도 남색이라 어둡게 보인다.

## 결정

0081-1. **실테스트 전에 바로 고칠 것 네 가지**(미션 방향과 무관)
  1. **옷 중복 해소**: 흔적이 한두 명으로 좁혀지게 한다(조사 4-4 #1).
  2. **낮·밤 조명 대비**: 낮은 채도를 낮게 유지한 채 명도와 색온도만 바꾼다.
  3. **튜토리얼 손보기**
     - 대상 밖을 어둡게 하는 스포트라이트. 흐림은 쓰지 않는다.
     - [다음]을 아래 가운데의 글 단추로 바꾼다.
     - 채팅 칸과 입력줄을 숨긴다.
     - 장면 5 연결선이 화면 안에서 끝나게 한다.
     - 시민 문구를 실제 판과 같게 한다.
  4. **낡은 문구 정리**: "밤 대화가 공개돼요", 밤 띠의 "이름표", "눈 0".

  0078-8 은 "배경 흐림 없음, **대상 밖 어둡게는 허용**"으로 바뀐다.

0081-2. **하루 흐름은 원인 → 결과 순서다.**
  - 처형(또는 처형 없음) → 저녁 할 일 → 밤 → 아침 증거 → 바로 토론 → 투표.
  - 첫날: 역할 확인 → 저녁 할 일 → 첫 밤 → 첫 아침부터 토론.
  - 토론이 시작되면 모두 광장 가운데로 모이고, 증거는 의심 보드(얼굴 줄 + 표시) 한 곳에 모은다(조사 4-4 #2·#3).

0081-3. **할 일은 세 가지가 한 줄로 이어진다.** 저녁 할 일이 밤의 목격을 정하고, 밤의 동선이 아침 현장의 단서가 된다.
  - **저녁 등불 당번**
    - 지금 심부름(배정, 근처 표본)을 다시 쓴다.
    - 마피아는 같은 단추로 심지를 자른다. 겉보기엔 켜지고 밤에만 꺼진다.
  - **밤 집 찾기**
    - 모든 역할이 같은 조작으로 지도에서 집을 누른다. 실시간으로 걷지 않으므로 0074-4 의 누설 문제를 피한다.
    - 아침에 발자국 수와 이웃 창문 목격이 생긴다.
  - **아침 현장 조사**
    - 단서는 나만 본다.
    - 마피아가 만진 지점은 흐려지고 "먼저 손댄 흔적"이 남는다.
    - 구출된 밤에는 미수 현장으로 쓴다.

0081-4. **맵은 단계적으로 넓힌다.**
  - 먼저: 지금 광장 + 가장자리 실내 방 4곳(지붕을 걷어 내는 방식) + 집 8채.
  - 실테스트로 효과를 확인한 뒤 소도시 블록(조사 3장 1안)으로 넓힌다.

0081-5. **처형된 사람의 정체는 계속 판 끝까지 비공개다.** 튜토리얼에서 "정체는 판이 끝나야 알아요"를 미리 보여 준다.

0081-6. **방장이 판 종류를 고른다.**
  - **기본 마피아**: 역할 → 낮 토론·투표·처형 → 밤 얼굴 고르기 → 아침 발표. 할 일과 흔적이 없다.
  - **확장판**: 0081-2·0081-3 의 흐름이다.
  - 기본값은 확장판이다. 튜토리얼은 확장판을 기준으로 한다.
  - 구현 방식: 지금 전역 상수인 `shared/game/ruleset.ts` 의 `RULESET`(12개 파일에서 읽음)을 방마다 고르는 값으로 바꾸고, 대기실 방장 패널에 선택을 더한다.
  - 0072 가 예약해 둔 "정통 판"(배지, 귓속말, 결선 등 정치 장치)은 이 선택과 별개로 남겨 둔다.
  - 이후 기능은 두 판 모두에서 시험한다.

## 정하지 않은 것

- 저녁 할 일의 시간과 개수, 등불 개수, 집 배치, 현장 단서의 종류와 표.
- 의심 보드의 표시 세트(실, 눈, 투표 손가락), 토론 모이기의 카메라.
- 판 종류의 이름. 기본/확장은 임시 이름이다.
- 튜토리얼을 실제 판의 축소판으로 다시 짜는 범위(조사 4-4 #6).
- 대질 신문 등 보조 장치는 실테스트 뒤에 정한다.

## 실행 중 달라진 곳 (18페이즈)

본문 결정은 바뀌지 않았다. 18페이즈(바로 고칠 것: 증거·조명·튜토리얼 손보기, `.planning/phases/18-quick-fixes/`)를 실행하며 위임 선택과 계획 값이 달라진 곳이다.

- **18-01 옷 해소·옷장 잠금(0081-1)**: 시작 때 겹친 옷은 서버가 풀어 `players[].look` 으로 저장한다. 그래서 기본 판에도 `look` 키가 생긴다(의상은 역할의 함수가 아니라 공개 값 L25, 누설 아님). 잠금 거절은 `BAD_MESSAGE` 로 정했다 — `worker/room.ts` 는 바뀌지 않았고 기존 분기가 보낸 소켓에만 자기 state 한 프레임을 보내므로 250ms 간격 위반과 같은 응답이라 거절 이유가 드러나지 않는다.
- **18-02·18-07 낮 조명**: UI-SPEC 시작값 다섯 곳을 허용 범위(1~3)에서 조정했다(광장 vote sky `#5c5078`→`#625e72`, 광장·바 morning moonColor `#dcd8e0`→`#e0dad8`, 바 morning sky `#7c7898`→`#7e7a96`, 바 vote sky `#3a3464`→`#3c3a48`). 바 vote moonColor 는 시작값이 없어 광장 vote 와 같은 `#d8b48a` 로 채웠다. 18-07 은 휘도를 재어 morning hemi·moon 을 맵마다 0.05π 씩 올렸다(광장 `0.95π/0.6π`→`1.05π/0.7π`, 바 `0.85π/0.4π`→`1.0π/0.55π`). 광장은 morning/night 1.71배로 문턱(1.6)을 넘었다.
- **18-07 남은 조명 문제(문턱은 낮추지 않았고 사람이 방향을 정한다)**: ① 두 맵 모두 vote(0.0044)가 night(0.0069)보다 어둡다(L4a). 따뜻한 방향광이 남색 재질에 반사돼 어둡게 렌더되는 탓이고, hemi·moon 만으로는 닿지 않아 moonColor·sky 나 재질을 만져야 한다. ② 재즈 바 morning/night 1.53배(문턱 1.6). ③ 광장 talk 가 짙은 남색 바닥이라 "낮" 인상이 약하다. 낮·밤 구분 느낌은 v3.0 실기기 확인에서 본다.
- **18-08 도윤 자리와 스포트라이트**: 장면 5 도윤 이름표가 폰 가장자리를 넘어 도윤 자리를 (1.3, −2.3)에서 **(1.3, −1.5)** 로 옮겼다(후보 (1.1, −1.9)는 360 폭에서 1px 모자랐고 (0.9, −1.5)는 연단 안쪽이라 걸을 수 없는 칸). 고정 카메라 target 은 그대로다. 스포트라이트 `.tut-dim` 의 z 값은 스크린샷 확인 결과 바꾸지 않았다. 스포트라이트 구멍은 `<mask>` 안 rect 라 `getBoundingClientRect` 가 0 이어서 E2E 가 속성과 svg 원점으로 읽는다(앱 버그 아님). 360×560 의 장면 5 이름표↔증거 카드 겹침(EV8)은 참고 행으로 남는다.
- **18-06 스포트라이트 구멍 선택자**: 장면 4 구멍은 계획의 `.mf-game__record`(띠 아래부터 화면 아래까지 늘어나는 컨테이너) 대신 카드 본체 `.mf-game__record > .mv-record` 로 잡았다(상자·카드·눈만 밝게).
- **18-09 E2E**: 옷장 잠금(AL1~AL3)·옷 유일(OU1·OU2) 판정을 더하고 마커 `data-taken` 을 AVATAR_MARKERS 에 넣었다.
- **E2E·성능 한계(그대로)**: `perfbudget` B2(점광원 4 > 3)·M1(geometries 35 > 25)은 13페이즈부터 지속되고 문턱은 그대로다. nightload 평균은 59.7fps 로 합격선(55)을 넘지만 처형 장면에 끊김이 몰려 5분당 5~7회로 합격선(5회) 근처다(17페이즈 측정에도 같은 장면에 있었다).
