# 0085 v3.0 내 캐릭터는 서버 응답이 와도 뒤로 끌려가지 않는다 — 위치 차이 대신 시각 앞섬

- 상태: 채택(구현됨 — 2026-11-12, 로컬 반영·배포 전)
- 날짜: 2026-11-12
- 근거: 18.1 실기기 재확인 중 사용자 피드백 "움직임이 밀립니다. 깔끔하게 움직여지지 않고 살짝 뒤로 움직여졌다 감"(`.planning/phases/18.1-screen-polish/18.1-UAT.md` "추가 개선 요청")
- 바꾸는 것: 0059-2·0059-3 가운데 **내 캐릭터의 예측 → 서버 구간 교체** 방식. 0059-1(탭하면 바로 걷는다)·0059-4(남은 예측하지 않는다)와 남의 새 구간 섞기는 그대로다

## 원인

- 탭하면 클라이언트는 탭 시각에 출발하는 예측 구간을 그린다(0059-1). 서버는 그 탭을 업링크 시간 `u` 뒤에 받아 **같은 길을 `u` 늦게** 출발시킨다. 그래서 응답이 도착한 순간 그리던 예측 위치는 서버 구간의 위치보다 `1.8 × u` 단위 앞에 있다.
- 0059-3 은 이 차이를 150ms 에 걸쳐 0 으로 줄였다(smoothstep). 당기는 속도의 최댓값은 초당 차이의 10배(평균의 1.5배)라 `u > 100ms` 이면 걷는 속도 1.8 단위/초를 넘는다 — **화면에서 내 캐릭터가 잠깐 뒤로 걷는다.** `u` 가 그보다 작아도 걷는 속도가 크게 줄어 멈칫한다(0059 가 잰 왕복 155ms, 업링크 약 78ms 에서 걷는 속도의 4분의 1 아래).
- 재현 시험: `test/client/worldStage.test.tsx` "밀림: 서버 응답이 업링크 150ms 만큼 늦은 구간이어도 …"(고치기 전 한 프레임에 −0.014 단위, 뒤로 약 0.9 단위/초), `test/unit/motion.test.ts` "움직임 밀림의 원인과 시각 앞섬".
- 서 있다 출발할 때와 방향을 바꿀 때 생긴다. 같은 방향으로 이어 탭하면 서버의 출발점도 그만큼 앞이라 차이가 없다.

## 결정

- **0085-1 내 캐릭터는 "서버 시각 + 앞섬"으로 그린다.** 앞섬(lead)은 서버가 내 탭을 받기까지 걸린 시간이다. 응답이 와서 예측을 서버 구간으로 바꿀 때, 끝점이 같은 서버 구간이면 `앞섬 += 서버 구간 출발 시각 − 예측 출발 시각` 으로 넘긴다. 출발 뒤 흐른 시간이 같아져 그리던 걸음이 그대로 이어진다(위치 차이 0).
- **0085-2 새 예측은 "탭 시각 + 앞섬"에 그리던 자리에서 출발한다.** 걷는 중 다시 탭해도 서버가 만들 구간과 출발점이 같다. 탭마다 업링크가 달라 남는 작은 차이(시간차 × 1.8)만 0059-3 의 150ms 섞기로 줄인다.
- **0085-3 서 있으면 앞섬을 0 으로 되돌린다.** 예측 중이 아니고 서버 구간이 서버 시각으로도 끝났을 때다. 서 있는 자리는 시각과 무관해 화면이 변하지 않는다. 새 연결(epoch 변경)에서도 0 이다.
- **0085-4 앞섬은 0 ~ 600ms 로 자른다(`OWN_LEAD_MAX_MS`).** 넘는 만큼은 예전처럼 위치 차이로 섞는다. 응답 없음 1.5초 되돌림(0059-2)은 그대로다.
- **0085-5 서버 권위는 그대로다(결정 0002).** 그리는 구간은 서버가 보낸 구간이고(길·끝점·속도), 도착 자리는 서버 끝점과 같다. 근처·목격 같은 판정과 다른 사람 화면은 서버 구간·서버 시각만 쓴다. 내 화면의 내 캐릭터만 업링크만큼 먼저 걷는다.
- **0085-6 남의 캐릭터는 바꾸지 않는다.** 남의 새 구간은 늦게 도착한 만큼 그린 자리가 뒤에 있어 섞기가 따라잡는 방향으로만 일어난다(뒤로 걷지 않는다 — `worldStage.test.tsx` "밀림 점검(남의 캐릭터)").

## 결과

- 탭해서 걷기 시작한 내 캐릭터가 응답이 올 때 뒤로 가거나 멈칫하지 않고 같은 속도로 목적지까지 간다.
- 목적지 링은 화면에서 내 캐릭터가 닿는 순간(서버 시각 + 앞섬 기준)에 사라진다.
- 코드: `src/world/motion.ts`(`OwnMoves.lead`·`settle`, `OWN_LEAD_MAX_MS`), `src/world/runtime.ts`(내 자리 그릴 시각 `ownNow`, 예측 출발 시각).

## 알려진 한계

- 실기기의 실제 업링크 시간은 재지 않았다. 원인은 코드와 재현 시험으로 확정했고, 배포본 실기기 확인은 남아 있다.
- 시계 오프셋 추정값이 pong 으로 바뀌는 순간에는 걷는 캐릭터 모두가 `1.8 × 변화량` 만큼 한 번 움직인다(수십 ms 면 0.05 단위 안팎). 이번에 바꾸지 않았다.
- 업링크가 탭마다 100ms 넘게 흔들리는 연결에서는 남는 차이를 섞는 동안 여전히 멈칫할 수 있다.
