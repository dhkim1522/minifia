## 결정

판 종류 모델

- **0086-1 판 종류는 두 값이다.** `GameMode = "basic" | "extended"`, 화면 이름은 "기본 마피아"·"확장판", 기본값은 확장판이다(0081-6).
- **0086-2 판 규칙에 할 일·증거 플래그 셋을 더한다.** `errand`(낮 심부름 단계)·`witness`(목격 기록)·`trace`(아침 밤 흔적). 기본 마피아는 셋 다 꺼짐, 확장판은 셋 다 켜짐. 정치 장치 다섯(배지·귓속말·순차 지목·결선·결전)은 두 판 모두 꺼진 그대로다.
- **0086-3 전역 규칙 상수를 없앤다.** `rulesetOf(mode)` 순수 함수 하나가 규칙을 만든다. 서버는 방 상태의 `mode` 에서, 화면은 모두에게 같은 공개 값 `view.mode` 에서 규칙을 얻는다. 옛 전역 상수를 읽는 곳은 코드 폴더에 하나도 남지 않는다(시험이 0건을 고정한다).
- **0086-4 저장된 옛 방(mode 없음)은 확장판으로 읽는다.** 배포 순간 진행 중이던 판은 지금 흐름 그대로 이어진다.

고르기와 전달

- **0086-5 고르기는 맵 고르기와 같은 방식이다.** 방장이 대기실·결과 단계에서 `{ t: "modePick", mode }` 를 보내면 서버가 방장·단계·허용 값을 판정해 방 상태에 저장하고 모두에게 방송한다. 거절은 오류 프레임 없이 최신 상태 한 프레임이다. **ROADMAP 성공 기준 1 은 "고른 값은 [시작] 때 서버로 간다"였는데 이 방식으로 바꿨다** — 참가자가 시작 전에 어떤 판인지 볼 수 있고, 다시 하기에서도 값이 유지되며, 판정이 이미 있는 맵 고르기와 같은 한 길이라 서버 규칙이 늘지 않는다.
- **0086-6 판이 진행 중에는 바꿀 수 없다.** 다시 하기는 지금 값으로 시작하고, 결과 단계에서 방장이 바꿀 수 있다.
- **0086-7 참가자는 읽기 전용 칩 하나로 본다.** 고를 수 없다.

기본 마피아 판

- **0086-8 심부름 단계에 들어가지 않는다.** 낮 발표 다음이 바로 토론이다. 목격 기록·가짜 장소·같은 옷 표시·마지막 목격이 생기지 않고, 서버가 관련 키(`me.errand`·`me.record`·`day.evidence`·아침 흔적)를 싣지 않는다(값이 빈 것이 아니라 키가 없다).
- **0086-9 화면에 [기록] 단추, 심부름 표시·진행 점, 아침 흔적 표시가 없다.** 자막 띠는 심부름을 말하지 않는다.
- **0086-10 튜토리얼은 확장판을 가르친다.** 기본 마피아를 고르면 방장의 [튜토리얼 먼저] 토글이 줄에서 사라지고, 서버도 기본 마피아 + 튜토리얼 시작을 튜토리얼 없이 처리한다. 첫 화면의 혼자 하기 튜토리얼은 그대로다.
- **0086-11 봇은 방의 판 규칙을 따른다.** 기본 마피아에서 심부름 행동이 없다.
- **0086-12 판 종류는 역할과 무관한 공개 값이다.** 누설 검사는 두 판 모두에서 돈다.

방장 전용 조작의 자리

- **0086-13 방장 전용 조작(판 종류·맵·봇·튜토리얼 먼저)은 화면 왼쪽 세로 줄에 모은다.** 참가자 공용 단추(오른쪽 열 소리·옷장)와 좌우로 나뉜다. 방장에게만 그린다(참가자 화면에는 마크업이 없다).
- **0086-14 방장 전용 단추는 램프 금빛 테두리·아이콘이다.** 공용 단추와 모양은 같고 색만 다르다. 채도는 낮게 유지한다.
- **0086-15 글은 늘리지 않는다(0051).** 단추는 아이콘뿐이고 접근성 이름만 갖는다. [판 종류] 를 누르면 두 칸(이름 + 한 줄 설명) 시트가 뜬다.
- **0086-16 시안 셋 가운데 A(원형 아이콘 단추 줄 + 왕관 표식)를 바로 구현했다.** B(단추 아래 이름 글)는 글이 늘고, C(왕관 하나 + 시트)는 한 번 더 눌러야 한다.
- **0086-17 [시작] 단추의 자리와 모양은 바꾸지 않는다.** 가장 중요한 한 단추라 줄에 넣지 않는다.

검증·배포

- **0086-18 두 판 모두 E2E 한 판 완주(봇 포함)와 누설 검사를 통과한다.** 바뀐 흐름만 돌리고 폰 6종 전체 회귀는 페이즈 끝에 한 번 로컬에서 돈다.
- **0086-19 실행이 끝나면 minifia-v3 에 배포한다.** 실기기 확인은 v3.0 끝 실테스트로 미룬다.

## 위임 기본값

사용자가 자리를 비운 동안 UI-SPEC 이 정한 값이다(`19-UI-SPEC.md` "기본값 기록" P19-0~P19-17). 한 줄씩 바꿀 수 있다.

- **P19-0·P19-1 줄의 모양**: 시안 A, 단추 지름 52(시안은 48 — 오른쪽 열이 실제로 52 라 눈높이를 맞췄다), 간격 12, 왼쪽 16, 위는 오른쪽 열과 같은 높이(띠 아래 + 12).
- **P19-2·P19-3 표식과 접기**: 왕관 표식은 한 열에 표식까지 들어갈 때만 그린다. 안 들어가면 표식을 먼저 빼고, 그래도 안 되면 오른쪽 열과 같은 규칙(`splitSideColumn`, 한 열 최소 2칸)으로 두 열로 접는다. 둘째 열은 첫 열 오른쪽 12 옆이다.
- **P19-4 [맵] 단추 아이콘**: 시안의 핀 대신 지금 고른 맵 아이콘을 그대로 쓴다(고른 값이 한눈에 보인다).
- **P19-5 테스트 방**: `[테스트]` 단추와 같은 왼쪽 위를 쓰므로 줄·칩이 48 내려간다.
- **P19-6 판 종류 시트**: 칸을 누르면 `modePick` 만 보내고 시트는 열어 둔다. 고른 표시는 서버가 방송한 값으로만 바뀐다(낙관 갱신 없음).
- **P19-7 시트 글자**: 제목 24, 칸 이름 16, 한 줄 설명 14(프로젝트의 네 크기 안). 설명은 "토론하고 투표해요" / "증거를 찾아 추리해요".
- **P19-8 튜토리얼 토글 알림**: 켜고 끌 때 위 알림 한 줄 "튜토리얼 먼저 켰어요" / "튜토리얼 껐어요".
- **P19-9 판 종류가 바뀌면 참가자에게 위 알림 한 줄** "판 종류: 확장판" / "판 종류: 기본 마피아". 방장 본인·처음 열 때·재연결 직후에는 띄우지 않는다.
- **P19-10 결과 화면의 참가자도 같은 칩을 본다.** 다음 판 종류를 알아야 한다.
- **P19-11 칩 자리**: 왼쪽 16, 위 = 띠 아래 + 20, 높이 32.
- **P19-12 방장 아래 패널에서 튜토리얼 스위치 줄(+54)을 없앤다.** 방장 패널 = 참가자 패널 = 222. 스테이지 사각형이 그만큼 커진다.
- **P19-13 결과 화면에서 판 종류를 바꿔도 이미 눌린 다시 하기 준비는 그대로다.**
- **P19-14 새 아이콘 넷**: `deck`(판 종류)·`book`(튜토리얼 먼저)·`modeBasic`·`modeExtended`(시트 칸).
- **P19-15 시트의 고른 칸은 밝은 회색 테두리 + V 배지다.** 금빛은 "방장 전용 단추"의 색이라 섞지 않는다.
- **P19-16 키보드·꾸미기 시트가 열린 동안 줄·칩을 그리지 않는다**(오른쪽 열과 같은 조건).
- **P19-17 자막 띠 문구는 바꾸지 않는다.** 기본 마피아는 심부름·증거 문장에 닿는 단계·값이 없어 이미 나오지 않는다.

## 계획 단계에서 고른 것

- **규칙은 인자다**: 서버 흐름 함수는 `rules = rulesetOf(modeOf(state))` 를 받는다. `modeOf` 는 허용 밖 값·없음이면 확장판을 돌려준다.
- **tick 의 훅 표는 규칙마다 하나**: `hooksOf(rules)` 가 진입·마감 훅 표를 만들고, 두 판의 표를 모듈을 읽을 때 한 번씩 만들어 두었다가 한 걸음마다 방의 판 종류로 고른다. 단계 표 데이터(`PHASE_DEFS`)는 그대로이고 낮 발표 다음만 `rules.errand` 로 갈린다.
- **0086-4 는 읽는 쪽 기본값으로 구현했다**: 저장된 방을 고쳐 쓰지 않는다. 저장된 값이 허용 밖이면 키째 뺀다.
- **방장 줄 접기 식**: 줄 최대 높이 = 방 높이 − 아래 패널 − 8 − (띠 아랫변 + 12), 테스트 방은 − 48. `n·52 + (n−1)·12 + 32 ≤ 최대 높이` 면 한 열 + 표식, `n·52 + (n−1)·12 ≤ 최대 높이` 면 한 열, 아니면 두 열.
- **E2E 흐름 이름은 mode 로 시작한다**: `mode-rail`(폰 6종)·`mode-pick`·`mode-basic`·`mode-leak`(390×844). `--only mode` 가 넷을 고른다.

## 실행 중 달라진 곳

- **서버(19-01)**: `ruleset.ts` 가 프로토콜 모듈에서 값도 가져온다(순환 없음). 쉬는 사람 view 도 `mode` 를 싣는다. 기본 마피아 한 판을 끝까지 걷는 서버 시험은 봇 투표만으로는 끝이 정해지지 않아 방장을 마피아로 지정하고 사람 소켓이 지목·찬반·밤 고르기를 보내도록 고정했다.
- **전역 상수 제거(19-02)**: 0건 검사의 범위를 코드 폴더 다섯(시험·스크립트 포함)의 부분 문자열로 넓혔다. `phases.ts` 는 `rulesetOf` 를 가져오지 않고 규칙을 인자로만 받는다. `docs/architecture.md`·`docs/screen-map.md` 의 옛 상수 설명을 판 규칙 설명으로 고쳤다. 기본 마피아 화면 요소의 렌더 조건은 고치지 않았다 — 키가 없으면 이미 그리지 않는다.
- **부품(19-03)**: 판 종류 시트의 면은 시안 값(`night-900`)인데 공용 시트 틀의 면은 `night-800` 이라 이 시트에만 면 색을 따로 줬다. 줄은 자식이 0개면 그리지 않는다.
- **대기실(19-04)**: [맵] 줄 단추가 연결이 끊긴 동안 눌리지 않게 되었다(다른 줄 단추와 같은 규칙). 방장을 넘겨주면 열려 있던 판 종류 시트가 닫힌다.
- **결과 화면(19-05)**: 판 종류 알림은 연출 중에도 뜬다. 결과 화면에는 재접속 띠 값이 내려오지 않아 "띠가 떠 있는 동안 알림을 띄우지 않는다"는 대기실 규칙은 넣지 않았다.
- **E2E(19-06)**: 지도 칩 자리 판정을 줄 기준으로, 칩과 이름표의 겹침을 참고 줄로 바꿨다. 옛 스위치 줄 판정을 지웠다. 접힌 줄의 둘째 열과 위 알림의 겹침은 판정하지 않고 잰 값만 남긴다(아래 알려진 한계).
- **E2E(19-07)**: 띠 금지 문구는 넷이다 — 심부름의 유령 줄 "지켜봐 주세요"는 다른 단계의 유령 줄과 같은 문장이라 뺐다. 화면(DOM)만 보던 판정에 받은 키 판정(BM1k)을 더해 "서버가 싣지 않는다"를 직접 본다. 기본 마피아 누설 흐름은 다섯 판 모두 기본 마피아로 돌았는지도 확인한다(LKm).
- **마무리(19-08)**: 전 흐름 회귀가 앱 결함 하나를 찾아 고쳤다 — 입력칸 포커스 중 맵을 눌러 키보드를 닫으면, 포커스가 풀리며 새로 그려진 방장 줄 단추를 그 탭의 뒤따르는 click 이 눌렀다(낮은 폰의 `chat-keyboard` 에서 [봇] 시트가 열림). 키보드를 닫은 탭과 같은 자리(10px)·0.5초 안의 click 을 한 번 삼킨다. 방장 패널이 참가자와 같아져 전제가 없어진 E2E 의 360×560 방장 예외 셋(`world`·`avatar-emote`·`avatar-dress`)도 없앴다.

일반 방(테스트 방 아님)은 재지 않았다. 같은 띠 아랫변에서 식으로 계산하면 최대 높이가 48 커져 360×560 확장판만 두 열 [3,1] 이고 나머지는 모두 표식 + 한 열이다. 실제 방에서 띠 문장이 두 줄이 되면 값이 다시 달라진다.

## 알려진 한계

- **360×560 방장 대기실에서 줄이 두 열로 접히면 입장 알림이 둘째 열 단추를 약 1.5초 덮는다.** 알림은 눌림을 통과시켜 단추는 눌린다. 고치지 않는다 — 가장 작은 화면의 진행에 지장 없는 겹침은 그대로 둔다는 사용자 방침이다(2026-11-12). E2E 는 그 겹침만 잰 값을 남기고 실패로 세지 않는다(첫 열·표식·한 열 줄과 알림의 겹침은 그대로 실패다).
- **짧은 폰에서는 왕관 표식이 빠진다**(360×640·390×664 확장판 대기실, 360×560). 색이 이미 "방장 전용"을 말하고 줄에는 접근성 이름이 남는다.
- **이름표가 줄·칩에 가려질 수 있다.** 줄은 스테이지 위에 뜬 오버레이다(오른쪽 열과 같은 정책). 잰 곳은 결과 360×560 과 대기실 430×932(2px) 둘이었다.
- **결과 화면의 `expanded` 조건은 지금 켜질 일이 없다.** 18.1 뒤로 결과 화면에 탭 행이 없어 기록을 늘린 상태에 화면 조작으로 닿지 않는다. 탭을 되살릴 때를 위한 조건이다(오른쪽 열의 같은 조건과 짝).
- **`MapChip` 의 줄 아닌 변형이 쓰이지 않은 채 남아 있다.** 어느 화면도 쓰지 않는다. 지우려면 표식 값 계약 시험과 변형 시험 넷을 같이 고친다.
- **판 종류별 튜토리얼이 없다.** 튜토리얼은 확장판만 가르친다.
- **아침 흔적 키는 E2E 가 프레임에서 보지 않는다**(안쪽 키). 화면 표식과 서버 시험이 맡는다.
- **E2E 한계**: `perfbudget` B2(점광원 4 > 3)·M1(지오메트리 35 > 25)은 13페이즈부터 지속(문턱 불변). 전체 회귀에서 `errand` 가 간헐적으로 흔들리고(알림음 기록 HS3·띠 문장 EA3) 다시 돌리면 통과한다(원인 미확정).
- **실기기 확인**은 v3.0 끝 실테스트로 미룬다: 방장 왼쪽 줄 색·왕관 표식·판 종류 시트·참가자 칩·기본 마피아 한 판.

## 정하지 않은 것

- 판 종류의 정식 이름("기본 마피아"·"확장판"은 지금 쓰는 이름이다).
- "정통 판"(배지·귓속말·순차 지목·결선·결전 켜기, 0072 예약분) — 이 선택과 별개로 남아 있다.
- 기본 마피아용 튜토리얼.
