# 0090 v3.0 판 하나·낮 투표·유언: 22페이즈 구현에서 위임으로 정한 선택

- 날짜: 2026-11-16
- 근거: 결정 0089-12~20, `.planning/phases/22-cleanup-single-mode/22-CONTEXT.md`(D-01~D-34), `22-UI-SPEC.md`(P22-1~P22-18), `22-RESEARCH.md`(Pitfall 4·가정 A6·열린 질문 Q1~Q5), 22-01~22-13 SUMMARY 의 "결정·선택" 줄

## 결정

방 저장·규칙

- **0090-1 옛 방은 옛 표시가 있을 때만 대기실로 되돌린다.** `normalizeStoredRoom` 이 옛 표시(`tutorial`·`errand` 단계, `lamps`·`scene`·`mode` 같은 옛 방 키, 마을 맵, 옛 플레이어 키)를 하나라도 가진 방만 `toLobbyFromLegacy` 로 되돌린다. 표시가 없는 방은 그대로 둔다. 방 DO 가 하이버네이션이라 생성자가 판 중에도 자주 다시 돌기 때문에 "진행 중인 방을 모두 되돌린다"(RESEARCH A6)를 쓰면 새 판이 깰 때마다 사라진다(D-03 문언을 D-30 으로 좁힘). `mode` 는 값을 가리지 않고 키 존재로 본다. 되돌릴 때는 방·사람 식별과 방장이 고른 값(다시 하기 허용 목록)만 남기고 쉬는 사람도 참가자로 합류시킨다. 표시 없는 옛 기본 규칙 방이 새 단계 순서로 읽힐 수 있는 틈은 알려진 한계다(배포 직전 방은 비어 있고 출시 전이라 허용).
- **0090-2 규칙은 상수 하나(`RULES`)이고 순차 지목(`pickTurn`)은 22-09 에서 켰다.** 22-07 이 판 종류를 지우며 `RULES` 단일 상수로 모았고, 낮 순서를 바꾸는 22-09 에서 `pickTurn: true` 로 켰다(그 전까지는 이 값이 꺼져 있어 동시 투표 코드와 함께 돌았다). 배지·귓속말·결선·결전은 꺼진 채 코드가 남는다. `politicsOn` 은 이 넷만 본다 — 순차 지목을 넣으면 누설 시험의 "꺼진 장치 키 0건" 구역이 조용히 통째로 건너뛰어진다.
- **0090-3 처형 없이 끝난 낮의 다음은 늘 밤이고 `afterDayOf` 한 곳이다.** 찬반 부결·지목 동점·지목 0표의 분기는 단계 표의 `next` 가 아니라 `tick.ts` 의 마감 훅이 정하고, 그 값은 `afterDayOf()` 로 모은다. 단계 id 는 새로 만들지 않고(21페이즈와 같은 방식) 순서와 의미만 바꿨다(`defense` 가 유언 자리).

찬반·기록

- **0090-4 찬반 판정식은 `찬성 × 2 > 던진 표`(= 찬성 > 반대)다.** 못 던진 사람은 분모에 없고 0표·동수는 부결이다. 옛 규칙(변론자를 뺀 유권자가 분모, 못 던진 사람도 분모)을 바꿨다(D-11). 유권자는 산 사람 전원이고 마감까지 번복할 수 있으며 모두가 일찍 던져도 10초를 채운다.
- **0090-5 찬반 중 던진 좌석(`day.voted`)과 누적 득표 기록은 싣지 않는다.** 실시간으로 싣는 것은 집계 수 `day.verdictCount{yes,no}` 뿐이다. 던진 좌석과 수가 함께 보이면 첫 투표자의 표가 추론되기 때문이다(D-26). 내 표는 `me.verdictVote` 로만 간다. `verdictCount`·`day.voted`·`day.verdict.ballots` 는 마감 뒤에도 남지 않는다.
- **0090-6 `voteLog` 는 판정에 필요한 최소만 남긴다.** 줄은 `{ n, exec{yes,no,passed}, cand{candidate?}, reason? }` 뿐이고 누가 누구를 골랐는지(`cand.votes`)는 저장하지 않는다(D-25 — 0089-18 의 "각자 기억한다"는 사람이 기억한다는 뜻이다). 처형 없음 이유 `NoExecutionReason` 은 `rejected`(찬반 부결·던진 표 0 포함)·`tie`·`noVotes` 셋이고 서버 저장용이다. 공개 경로는 `day.noExecution` 하나이며 알림 글은 이유와 무관하게 한 가지("처형 없음", P22-4)다. 찬성·반대 수는 종료 요약이 읽는다.

유언

- **0090-7 [남기기]는 `will` 메시지의 `final: true` 필드다.** 새 메시지 종류를 만들지 않았다. 처형자가 유언 단계에서 보내면 글을 저장하고 단계를 곧바로 끝낸다(처형자가 아니면 서버가 무시). 봇 처형자도 같은 길로 고정 문구(`BOT_DEFENSE_LINES`)를 `final` 로 남긴다(D-18, 입력 중 표시는 붙이지 않는다).
- **0090-8 유언 단계 채팅은 `CHAT_PHASES` 에서 `defense` 를 빼서 잠근다.** 채팅·동작·입력 중이 모두 서버에서 버려진다(`channelOf` 한 곳). 화면은 입력줄을 잠그고 동작 버튼을 그리지 않는다(`data-chat-locked`). 유언 단계가 "조용한 순간"이라는 D-16 을 같은 결과로 읽은 것이다. 이 10초에 몸동작만 살리려면 `audience` 에 동작만 허용하는 분기가 필요하다 — 사용자 결정 거리로 남긴다.
- **0090-9 유언 자동 저장은 입력 600ms 뒤와 마감 700ms 전이다.** 서버의 사람별 최소 간격(500ms)보다 길게 잡았다. 같은 글(마지막으로 보낸 값·서버 값)은 다시 보내지 않고 확인 대기를 만들지 않는 조용한 저장이다. 시간이 끝나면 서버가 마지막 저장본을 낸다(마지막 약 0.5초 입력은 잃을 수 있다, D-28). [남기기] 뒤 시트는 비활성으로 남고 단계가 넘어가 처형자가 죽으면 닫힌다.
- **0090-10 처형자의 유언은 `day.execution.will` 로 모두에게 같은 값이다.** 처형 단계 view 에서만 싣고(`ExecutionView{seat, will?}`) 비어 있으면 키가 없다. 처형자 DOM 에만 시트가 있다(`data-will-sheet="will"`). 처형·유언 view 의 키 집합은 같고 누설 검사(`willLeakChecks`)가 이를 본다.

처형·연출

- **0090-11 처형 시간표는 상수 셋의 합 한 표다.** `WILL_REVEAL_MS` 3000(유언 카드) + `EXEC_ANNOUNCE_MS` 3000(큰 글·유령 올라옴) + `EXEC_TAIL_MS` 600 = `EXECUTION_MS` 6600, 핀·콘이 꺼지는 시각 `PIN_OFF_EXEC_AT` 6000. 핀·판결 순간·소리·알림·smoke 사본이 모두 이 표에서 나온다. 채팅 기록의 유언 카드 보류 시간(`CARD_HOLD_EXEC_MS`)은 옛 2.4초가 아니라 유언 카드 시간(3.0초)에 맞춰, 같은 글이 카드 서 있는 동안 채팅에 먼저 나오지 않게 했다. 아침 길이 상한(`MORNING_MAX_MS` 16초)은 그대로 둔 안전 상한이다 — 흔적 구간이 없어져 도달하지 않지만, 시간은 참고 목표라 연출을 줄이는 근거로 쓰지 않는다.
- **0090-12 판결 순간의 어두운 막·확대·핀은 처형 시간표 창 `[0, 6.0초)` 로 유지한다(D-27).** 켜짐 조건은 처형자 존재 하나이고, 마지막 3인 결전의 득표자 처형도 같은 6.6초 표를 따른다(옛 `verdict.last` 예외는 없앴다). 소리 대본은 입력이 없다: 심장 박동 5번, 3000ms 에 의사봉·올라옴, 덕킹은 `PIN_OFF_EXEC_AT` 까지. 부결 소리(`verdict.reject`)는 지우지 않고 남기되 어떤 단계도 내지 않는다(처형 없는 판 소리 0건을 E2E 가 고정, 24 의 연출 정리에서 다시 정한다).
- **0090-13 찬반 장면은 토론 장면 그대로다(P22-3).** 따라가는 카메라, 조명 `talk`, 장면 `day` 이고 헤더는 "낮 · 찬반"이다.

유령·시험·화면

- **0090-14 유령은 `GHOST_SCALE` 0.75(`characterData.ts`)이고 훅은 `__mfGhosts = { seats, ready, scale, facing }` 이다.** 배율 상수는 `character.ts` 가 아니라 `characterData.ts` 에 둔다(`runtime.ts` 가 three 를 정적으로 부르지 않아 `character.ts` 를 값으로 import 할 수 없다). `facing` 은 캐릭터 root 의 yaw 를 소수 둘째 자리로 반올림한 값이다. 머리 높이(`headY`)도 0.75배, `GHOST_ART_H` 는 그대로다(산 사람 이름표 높이에도 쓰인다).
- **0090-15 시상(칭호)은 서버·와이어·소리·시험·E2E 판정까지 모두 지웠다(D-19, 0089-20).** 소리 id 는 54개(배경음 7 + 효과음 47)가 되었다. 사회자 웅얼 음절(`voice.syl`)은 새 튜토리얼이 쓸 소리라 남겼다.
- **0090-16 시험·E2E 정리의 선택.** 꺼진 정치 장치 흐름 여섯(`politics-badge`·`whisper`·`runoff`·`runoff-tie`·`showdown`·`showdown-tie`)은 `skipByDefault` 로 두고 새 순서로 고치지 않았다. 서버 전용 키 감시선(`SERVER_ONLY_KEYS` 의 옛 심부름 키)과 누설 허용 경로 접두는 지운 키가 어떤 프레임에도 없음을 지키는 감시선으로 일부러 남겼다. 옛 저장 방에 남은 `ballots` 채팅 레코드는 손상 레코드처럼 버려지고 옛 서버의 `ballots` 결과 프레임은 클라이언트가 무시한다. `will-flow` 는 사람 손님이 필요한 부분과 폰 6종 기하 한 페이지를 `will-flow`·`will-flow-sizes` 둘로 나눴다.
- **0090-17 폰 6종 전체 회귀·배포·실기기 확인은 22 에서 하지 않는다.** 24페이즈 끝에 한 번(0089-25). UI-SPEC 미해결 셋(360×560 찬반 투표자 스테이지 부족, 처형자 키보드 열림 시 자기 캐릭터가 안 보임, 유령 이름표와 머리 사이 틈)은 진행에 지장이 없어 알려진 한계로 둔다.

사용자가 돌아와 위 항목을 한 줄씩 바꿀 수 있다.
