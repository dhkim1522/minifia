## 결정

첫날 흐름·단계

- **0091-1 새 단계 id 는 `keyword`·`answerReveal` 둘이다.** `roleReveal.next = "keyword"`, `keyword.next = "dayAnnounce"`다. `keyword` 는 13초(`KEYWORD_MS` = 읽기 3초 `KEYWORD_READ_MS` + 쓰기 10초)이고 `MAP_PHASES`·`CHAT_PHASES` 에 넣지 않는다(걷기·채팅·몸동작 없음). 서버 `view.ts` 의 `DAY_PHASES` 에는 넣는다(D-23). `answerReveal` 은 3초(`ANSWER_REVEAL_MS`)이고 `answerReveal.next = "night"` 다. 둘째 날부터는 `morning → dayAnnounce` 그대로다. 단계 id 가 가입해야 하는 표·집합은 컴파일러가 못 잡는 `Set`·배열까지 grep 으로 나열해 모두 갱신했다(D-04).
- **0091-2 첫날 분기는 두 곳이고 `answerReveal` 은 첫날에만 낀다.** 처형 뒤 `execution.next` 와 처형 없는 낮의 `afterDayOf()` 가 첫날(day 1)에 한해 `night` 대신 `answerReveal` 로 보낸다. 첫날 처형이 없으면 "처형 없음" 큰 글 1.4초 + 정답 3초 = 4.4초 단계가 된다(D-22). 승패가 나서 `ended` 로 가면 공개 단계를 건너뛰고 결과 화면이 정답을 보여 준다.
- **0091-3 `keyword` 키 하나가 기능 스위치다.** `RoomState.keyword === undefined` 이면 `keyword`·`answerReveal` 단계를 건너뛴다(배포 순간 진행 중이던 옛 방·옛 시험 보호, D-29). 시험 setup 은 이 스위치로 키워드를 꺼 둔다(켠 판의 누설 전수는 `keywordLeak.test.ts` 가 맡는다). 키워드는 `beginGame` 에서 `decideMap` 뒤 `randInt` 두 번(장르, 단어)으로 고른다. 진입 훅에서 고르지 않는다.

키워드 선택·목록

- **0091-4 키워드 목록은 `shared/game/keywords.ts` 하나이고 초안이다.** 7장르(영화·음식·동물·장소·스포츠·물건·나라) × 장르당 30개 이상(전체 310개), 키워드마다 한국어·영어·짧은 이름 별칭, 한 글자 키워드 없음. 사용자 검토 대기(0089-23)이며 파일 상단에 그렇게 적었다. 클라이언트 번들에 들어가지 않는다(`npm run build` 뒤 표본 별칭 부재를 게이트로 확인). 장르 라벨은 view 의 `day.keyword.genre` 로, 단어는 시민 편 본인의 `me.keyword` 로만 간다.

답 판정

- **0091-5 금지어 판정은 정규화 포함·초성 열·철자 틀림 통과다(D-08).** 답을 NFKC → 글자·숫자 외 제거 → 소문자로 만든 뒤 같은 방식으로 정규화한 키워드·별칭이 포함되면 막는다. 3글자 이상 키워드는 완성형 한글의 초성열이 답의 초성열에 들어 있어도 막는다. 철자를 일부러 틀린 우회는 막지 않는다(매너). 길이 1 별칭은 무시한다.
- **0091-6 답 메시지는 `answer { text, final }` 이고 초안은 무검사·확정만 검사한다(D-07).** 서버 규칙은 `shared/game/keywordAnswer.ts` 순수 함수다. keyword 단계의 산 사람만, 정리(`sanitizeChatText`) 뒤 20자소(`ANSWER_MAX_GRAPHEMES`) 이하. `final:false` 는 본인에게만 저장·응답하는 쓰던 글이고 금지어를 보지 않는다. `final:true` 에 금지어가 있으면 거절한다. 허용된 첫 확정은 바뀌지 않는다. 빈 확정은 거절이라 보낼 수 없다.
- **0091-7 거절 응답은 시민·마피아가 구별되지 않는다.** 둘 다 같은 두 프레임 `[error:BAD_MESSAGE, state]` 이고 다른 소켓에는 프레임이 없다. 마피아 거절 때만 서버 전용 `keywordProbed` 가 켜지고(D1 의 떠보기 성공, D-09) 응답·view 에는 드러나지 않는다. 사람당 간격은 수락·거절 모두 기록하고 초안(`answerD`)·확정(`answerF`) 키를 나눠 400ms(`ANSWER_MIN_GAP_MS`), 간격 안의 요청은 오류 없이 버린다. 답 제출은 `persistAndBroadcast` 를 부르지 않는다(`storage.put("room")` 한 번 + 본인에게만 `sendViewTo`, D-10, 결정 0076).
- **0091-8 자유 채팅에는 금지어를 걸지 않는다(D-26).** 걸면 마피아의 무제한 탐색 도구가 된다. 금지어는 keyword 단계의 답에만 적용한다.

공개

- **0091-9 공개 순서는 확정 제출 낸 순서 → 마감에 쓰던 글로 나간 사람(좌석 순) → 답 없음(좌석 순)이다(D-24).** 쓰던 글은 금지어가 없을 때만 나가고 아니면 답 없음이다. 봇은 늘 답 없음이다. 목록 `day.keyword.answers` 는 keyword 단계가 끝나는 전환에서 모두에게 같게 실리고 판 내내 남는다(D-14, 둘째 날부터 `day.keyword` 는 `genre`·`answers`·`answer` 만). 정답 `day.keyword.answer` 는 `answerReveal` 진입 프레임부터 모두에게 같다(`answerOpenOf` 한 함수). 토론 시작 때 "모두의 답" 시트가 한 번 자동으로 열린다.

일찍 넘어가기

- **0091-10 개인 행동 단계는 전원이 끝나면 1.5초 뒤 넘어간다(0089-26, D-11).** 헬퍼 `maybeAdvanceEarly` 하나(`EARLY_GRACE_MS` 1.5초)가 세 곳에서 쓰인다 — 키워드(산 사람 중 사람 전원 확정, 봇 제외), 찬반(산 사람 전원 투표), 밤(산 사람 전원 `nightPick`). 마감은 원래 마감을 넘지 않게 줄이고, 단계 표 길이(`phaseDurationMs`)는 그대로 둔다. 연결이 끊긴 사람이 있으면 그 판은 정해진 시간을 다 쓴다(D-12). 토론 과반·유언 [남기기]는 그대로이고 연출 단계(처형·아침·정답 공개)는 못 넘긴다.
- **0091-11 번복 연장은 찬반에서만 한다(D-25).** 찬반은 마지막 표 뒤 1.5초로 다시 미루되 원래 마감 이내다. 밤·키워드는 전원이 끝난 첫 순간 +1.5초로 한 번만 줄이고 이후 연장하지 않는다(밤 선택은 본인에게만 가는 정보라 연장 방송이 새 신호가 되기 때문). 마감은 "마지막으로 끝낸 사람 시각 + 1.5초"라 역할과 무관하고 전환 프레임은 전원에게 같다(`nightLeak.test.ts` 가 역할만 다른 두 판의 종료 시각·프레임 열 동일을 고정, D-13). 화면은 막대가 기존 전환으로 미끄러지고 색은 `calm` 에 고정한다(`data-early`).
- **0091-12 0090-4 를 개정한다.** "모두가 일찍 던져도 10초를 채운다" 는 더 이상 맞지 않다. 찬반 판정식 `찬성 × 2 > 던진 표` 는 그대로다. 0090 의 해당 줄에 개정 표시를 달았다.

D1 판 기록

- **0091-13 판 기록은 Cloudflare D1 한 표 `games` 이고 열은 16개뿐이다(D-15, 되돌리기 비싼 선택).** 바인딩은 `DB`(이름 `minifia-v3-games`, `migrations/0001_games.sql`). 열: `id`(판 uuid, 서버 전용 상태에 둠), `ended_at`, `winner`(mafia|citizen, CHECK), `caught_day`(마피아가 처음 처형된 일차, 처형 무효 날은 건너뜀, 없으면 NULL), `first_day_caught`, `genre`, `word`, `probe_success`(= `keywordProbed`), `players`, `bots`, `has_bots`, `duration_s`, `left_count`, `note_count`, `no_answer_count`, `tutorial`. 닉네임·채팅·답 글은 저장하지 않는다. 적용된 뒤의 변경은 새 마이그레이션 파일로만 한다. 삽입은 항상 값 바인딩(`?`)이다.
- **0091-14 삽입은 ended 로 들어서는 전환에서 한 번, 실패는 삼킨다(D-16).** `afterTransition` 에서 `ctx.waitUntil(recordGame(...))` 로 `INSERT OR IGNORE` 한다. 실패는 토큰·내용 없는 짧은 로그 한 줄로 삼키고 판을 막지 않는다. `startGame` 이 서버 전용 `startedAt` 을 적는다. ended 를 거치지 않고 만료된 판은 기록하지 않는다. `INSERT OR IGNORE` 는 CHECK 위반도 조용히 버리므로 `winner` 는 승리 진영 표의 반대 표로만 만든다.
- **0091-15 통계 열의 정의.** `has_bots` 는 봇이 있거나 테스트 방이면 1이고 기본 통계에서 뺀다(D-27). `left_count` 는 ended 진입 시점에 끊겨 있는 사람 수다(D-28). `note_count`·`tutorial` 은 24 전까지 0 으로 고정이다(24 가 채움). `no_answer_count` 는 사람의 답 없음 수다.
- **0091-16 조회는 `npm run games`(`scripts/games.mjs`)다(D-17).** 허용 인자는 `--local`(기본)·`--remote`·`--all` 뿐이고, SQL 은 코드 상수라 사용자 입력이 들어가지 않는다. `--remote` 는 실행 전에 개인 계정 판정(`judgeWhoami`)을 거친다. 승률·평균 길이·첫날 잡힘 비율·떠보기 성공 비율을 한국어 한 화면으로 보이고 기록 0건이면 "아직 기록이 없어요"를 낸다.
- **0091-17 `database_id` 없는 배포는 가드가 막는다(D-19·D-32).** `wrangler.jsonc` 에는 바인딩과 `migrations_dir` 만 있고 `database_id` 가 비어 있어 `npm run deploy` 가 `check-deploy-target` 에서 멈춘다. 이것은 의도다: wrangler 의 자동 리소스 프로비저닝이 id 없이 원격 D1 을 만들 수 있다는 변경 로그 때문에(RESEARCH A2, 실행 확인 없음) 계정 확인 뒤 명시적으로 만들게 한다. 그래서 23 은 코드가 끝났어도 배포하지 않았다.

알려진 한계

- **0091-19 3글자 키워드 초성이 흔한 단어와 우연히 겹친다(RESEARCH A4).** 예: 고양이(ㄱㅇㅇ)↔가을이. D-08 문언대로 막으므로 시민이 이유 없이 거절될 수 있다. 사용자 피드백으로 초성 기준(3→4글자)을 조정한다. 강아지·냉장고·스위스 등 겹침 가능성이 낮은 단어는 남겼고 사우디·자장면은 빼면 누설이 더 커서 남겼다.
- **0091-20 마피아 떠보기 거절은 저장이 한 번 더라 처리 시간이 미세하게 길 수 있다.** 응답 모양·프레임 수는 같고, 소켓 왕복의 흔들림이 이를 압도하며 400ms 간격과 메시지 속도 제한(20/초)이 시도 횟수를 묶는다. 별도 보정은 넣지 않았다(T-23-18).
- **0091-21 입력·시간 한계.** 마감 700ms 전 전송 규칙이라 마지막 약 0.7초 입력은 잃을 수 있다. 빈 확정을 보낼 수 없어 모르는 사람이 10초를 다 쓰면 일찍 넘어가기가 늦어진다. 마감에 쓰던 글이 자동 확정되는 경로는 단위·worker 시험이 있으나 E2E 는 없다.
- **0091-22 화면 한계.** 높이 664 이하 폰에서 키보드를 열면 컴팩트 카드가 띠·소리 단추를 일부 덮는다(남은 시간은 메타 줄 n초가 다시 보인다). 토론 시작에 자동으로 열린 "모두의 답" 시트는 닫을 때까지 열려 있고 토론 입력을 가린다(자동 닫힘 없음). 둘 다 실테스트 뒤 판단한다.
- **0091-23 D1 쪽 한계.** `ctx.waitUntil` 삽입이 DO 내려감 뒤에도 끝까지 가는지는 문서만 믿고 실제 관찰은 없다(A3 — 누락 가능, 판은 안전하고 통계만 빈다). `npm run games --local` 이 `vite dev` 와 같은 로컬 D1 상태 폴더(`.wrangler/state/v3/d1`)를 보는지는 확인하지 못했다(A1, 워커 시험은 메모리 D1 이라 답하지 않는다). `left_count` 는 판 중간에 나갔다 돌아온 사람을 못 센다.
- **0091-24 확인하지 않은 것.** 첫날 "처형 없음 → 정답" 4.4초가 원하는 모양인지(A5), 밤·키워드를 연장 없이 한 번만 줄이는 것이 맞는지(A6)는 사용자 확인 거리다. 폰 6종 전체 회귀·실기기·배포·원격 D1 은 하지 않았다(24 끝, 0089-25). `basicDay` 의 "토론 끝내기 → … → 밤" 시험은 처형자가 무작위로 마지막 마피아면 판이 끝나 `night` 기대가 어긋나는 기존 간헐이 있다(단독 재실행 통과).

사용자가 돌아와 위 항목을 한 줄씩 바꿀 수 있다.
