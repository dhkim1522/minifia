# 화면 영역 지도와 자동 검사

> 게임 화면(낮 시작 ~ 아침)은 8페이즈에서 v1.0 고정 테이블을 지우고 맵 위 화면으로 바뀌었다(결정 0060, 계약서 `.planning/phases/08-day-execution-ghost/08-UI-SPEC.md`). 대기실은 v2.0 맵 로비(6페이즈, 결정 0044·0050·0055)에 7페이즈 채팅 패널이 붙었다(결정 0058, `07-UI-SPEC.md`). 숫자의 원천은 코드다: 게임 맵 화면 `src/screens/GameMap.tsx`·`GamePanel.tsx`, 채팅 높이 `src/game/chatUi.ts`, 검사 `scripts/e2e/lib.mjs`(상수 `LOG_H`·`GAME_PANEL_EXTRA`·`DEFAULT_SIZES`). 값이 바뀌면 코드를 먼저 고치고 이 문서를 맞춘다. v1.0 화면 그림은 `design/screens/v1.0/`(S-번호), v2.0 승인 보드는 `design/v2.0/screens/`.

## 게임 화면 개요

낮 시작 · 낮 토론 · 투표 · 최후 변론 · 찬반 · 처형 · 밤 · 아침은 모두 같은 맵 화면이다(아래 '게임 맵 화면'). 대기실의 층 구조를 그대로 쓰되 아래 패널의 내용만 단계마다 바뀐다. 역할 배정·역할 확인은 v2.0 3D 재즈 바 무대(`PreGame`) 위에 어두운 막을 얹은 화면이다(0062-5). 결과 화면은 11페이즈에 3D 무대 + 헤더 + 패널 구조로 바뀌었고 18.1 에서 전체 대화 하나만 남겼다(아래 '결과 화면', 결정 0069·0082). 역할 확인(`PreGame`)은 이름표 층이 없고(`visibility: hidden`, DOM 은 유지) 카드 위 끝이 소리 단추 독 아랫변 + 8 이며, 카드 글은 직업 이름 + 확정 문구 한 덩어리다(목표 줄 없음, `data-role-line` — 결정 0082).

`LOG_H` = 기록 칸 높이 68 한 값(`src/game/chatUi.ts`; 모든 폰·키보드 열림 포함, 접힌 두 줄 창 — 누르면 제자리에서 위로 늘어나고 별도 기록 시트는 없다, 18.1 결정 0082·0083-4). 접힌 높이는 방 높이·키보드로 바뀌지 않는다. 늘어난 높이는 순수 함수 `openLogHeight` 한 식이다: `clamp(LOG_H, 방 높이 − 키보드 올림 − 띠 아랫변 − 120(`OPEN_STAGE_MIN`) − 패널의 기록 칸 밖 높이, 300(`LOG_OPEN_MAX`))`. 키보드 열림 패널의 기록 칸 밖 높이는 `KB_PANEL_REST` 78.

## 대기실 (맵 로비)

숫자의 원천은 코드다: 화면 `src/screens/Lobby.tsx`·`src/components/WorldStage.tsx`, 맵·런타임 `src/world/`, 규칙 `shared/game/map.ts`·`world.ts`. 계약서는 `.planning/phases/06-world-skeleton/06-UI-SPEC.md`. v1.0 고정 테이블 로비(자리 슬라이드 · 방장 왕관 · 입장/퇴장 전이)는 06-16 에서 지웠다. 역할 배정부터는 위의 세 영역 틀이다.

캔버스 한 장이 화면 전체를 채우고(`inset: 0`, 헤더 · 패널 · 키보드로 크기가 줄지 않는다. 캔버스 높이는 처음 그릴 때 px 로 고정) 나머지가 그 위에 얹힌다. 아래 패널은 `visualViewport` 로 키보드 위에 붙는다(`lift = max(0, innerHeight − (vv.height + vv.offsetTop))`).

스테이지 사각형 = 헤더 블록 아래 끝(62) ~ 아래 패널 위 끝 = 높이 − 62 − (`LOG_H` + 154). 키보드 열림은 (높이 − K) − 62 − 146 (K = 키보드가 가리는 높이, iPhone 약 336). 카메라는 이 사각형 가운데에 내 캐릭터를 둔다. 카메라 배율은 폰 크기와 무관하게 고정(`PX_PER_UNIT` 58.2)이라 작은 폰은 보이는 맵 영역만 줄어든다.

키보드 열림 열은 기록 칸이 접힌 값(패널 146)이다. 입력칸에 포커스가 가면 칸이 식(`openLogHeight`)만큼 늘어나 스테이지가 띠 아래 120 까지 줄어들 수 있다(결정 0083-4, 늘어날 자리가 없는 작은 폰은 그대로). 키보드·늘어난 칸이 겹친 화면에서는 이름표 스택이 스테이지에 다 들지 않아도 되고, 발이 띠 아랫변~패널 윗변 안에 있으면 합격이다.

방장 아래 패널(17페이즈, 결정 0080-4): 위 표는 손님 값이다. 방장은 패널 맨 위(기록 칸 위)에 튜토리얼 스위치 줄("튜토리얼 먼저" + 스위치, 높이 44 + 패널 간격 10 = +54, 앱 상수 `LOBBY_HOST_TUTORIAL_EXTRA`, 결정 0083-3 — 17페이즈의 +76·298 을 바꿈)이 더해져 **276** 이고, 스테이지 사각형은 그만큼 줄어든다(예: 390×844 에서 560 → 506, 402×874 에서 590 → 536, 360×560 에서 276 → 222). 스위치 줄은 `data-tutorial-toggle`, 줄 전체는 `data-tutorial-host` 다.

알려진 한계 (고치지 않는다, 07-UI-SPEC UI Considerations 20):

- 방 높이 640 이하 폰(360×640 · 390×664 · 360×560)은 키보드가 열리면 스테이지가 128(캐릭터 80 + 이름표 26 + 입력 중 22) 미만이라 내 이름표 · 입력 중 칸이 잘릴 수 있다. 최악 360×560 은 12px 만 남는다. 캐릭터 몸만 보이도록 카메라가 맞춘다.
- (해결) 테이블 화면에서 패널이 아래 인물을 가리던 문제는 테이블 틀이 8페이즈에서 삭제되며 없어졌다.
