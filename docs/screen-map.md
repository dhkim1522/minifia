# 화면 영역 지도와 자동 검사

> 게임 화면(낮 시작 ~ 아침)은 8페이즈에서 v1.0 고정 테이블을 지우고 맵 위 화면으로 바뀌었다(결정 0060, 계약서 `.planning/phases/08-day-execution-ghost/08-UI-SPEC.md`). 대기실은 v2.0 맵 로비(6페이즈, 결정 0044·0050·0055)에 7페이즈 채팅 패널이 붙었다(결정 0058, `07-UI-SPEC.md`). 숫자의 원천은 코드다: 게임 맵 화면 `src/screens/GameMap.tsx`·`GamePanel.tsx`, 채팅 높이 `src/game/chatUi.ts`, 검사 `scripts/e2e/lib.mjs`(상수 `LOG_H`·`GAME_PANEL_EXTRA`·`DEFAULT_SIZES`). 값이 바뀌면 코드를 먼저 고치고 이 문서를 맞춘다. v1.0 화면 그림은 `design/screens/v1.0/`(S-번호), v2.0 승인 보드는 `design/v2.0/screens/`.

현재 v3의 공통 화면 외형과 홈·대기실은 [결정 0099](decisions/0099-unified-game-ui.md), 토론의 고정 채팅과 시간 게이지는 [결정 0098](decisions/0098-fixed-chat-and-phase-gauge.md)을 따른다. 아래의 치수는 각 단계의 배치를 설명한다.

## 게임 화면 개요

낮 시작 · 낮 토론 · 찬반 · 지목 · 유언 · 처형 · 밤 · 아침은 모두 같은 맵 화면이다(아래 '게임 맵 화면'). 대기실의 층 구조를 그대로 쓰되 아래 패널의 내용만 단계마다 바뀐다. 역할 배정·역할 확인은 v2.0 3D 재즈 바 무대(`PreGame`) 위에 어두운 막을 얹은 화면이다(0062-5). 결과 화면은 11페이즈에 3D 무대 + 헤더 + 패널 구조로 바뀌었고 18.1 에서 전체 대화 하나만 남겼다(아래 '결과 화면', 결정 0069·0082). 역할 확인(`PreGame`)은 이름표 층이 없고(`visibility: hidden`, DOM 은 유지) 카드 위 끝이 소리 단추 독 아랫변 + 8 이며, 카드 글은 직업 이름 + 확정 문구 한 덩어리다(목표 줄 없음, `data-role-line` — 결정 0082).

`LOG_H` = 기록 칸 높이 68 한 값(`src/game/chatUi.ts`; 모든 폰·키보드 열림 포함, 접힌 두 줄 창 — 누르면 제자리에서 위로 늘어나고 별도 기록 시트는 없다, 18.1 결정 0082·0083-4). 접힌 높이는 방 높이·키보드로 바뀌지 않는다. 늘어난 높이는 순수 함수 `openLogHeight` 한 식이다: `clamp(LOG_H, 방 높이 − 키보드 올림 − 띠 아랫변 − 120(`OPEN_STAGE_MIN`) − 패널의 기록 칸 밖 높이, 300(`LOG_OPEN_MAX`))`. 키보드 열림 패널의 기록 칸 밖 높이는 `KB_PANEL_REST` 78.

## 대기실 (맵 로비)

숫자의 원천은 코드다: 화면 `src/screens/Lobby.tsx`·`src/components/WorldStage.tsx`, 맵·런타임 `src/world/`, 규칙 `shared/game/map.ts`·`world.ts`. 계약서는 `.planning/phases/06-world-skeleton/06-UI-SPEC.md`. v1.0 고정 테이블 로비(자리 슬라이드 · 방장 왕관 · 입장/퇴장 전이)는 06-16 에서 지웠다. 역할 배정부터는 위의 세 영역 틀이다.

캔버스 한 장이 화면 전체를 채우고(`inset: 0`, 헤더 · 패널 · 키보드로 크기가 줄지 않는다. 캔버스 높이는 처음 그릴 때 px 로 고정) 나머지가 그 위에 얹힌다. 아래 패널은 `visualViewport` 로 키보드 위에 붙는다(`lift = max(0, innerHeight − (vv.height + vv.offsetTop))`).

스테이지 사각형 = 헤더 블록 아래 끝(62) ~ 아래 패널 위 끝 = 높이 − 62 − (`LOG_H` + 154). 키보드 열림은 (높이 − K) − 62 − 146 (K = 키보드가 가리는 높이, iPhone 약 336). 카메라는 이 사각형 가운데에 내 캐릭터를 둔다. 카메라 배율은 폰 크기와 무관하게 고정(`PX_PER_UNIT` 58.2)이라 작은 폰은 보이는 맵 영역만 줄어든다.

키보드 열림 열은 기록 칸이 접힌 값(패널 146)이다. 입력칸에 포커스가 가면 칸이 식(`openLogHeight`)만큼 늘어나 스테이지가 띠 아래 120 까지 줄어들 수 있다(결정 0083-4, 늘어날 자리가 없는 작은 폰은 그대로). 키보드·늘어난 칸이 겹친 화면에서는 이름표 스택이 스테이지에 다 들지 않아도 되고, 발이 띠 아랫변~패널 윗변 안에 있으면 합격이다.

방장 아래 패널(19페이즈, 결정 0086): 방장 패널 = 참가자 패널이다(222, 키보드 열림 146). 기록 칸 위에 따로 얹는 방장 줄(스위치 행)은 없다. 방장 스테이지 사각형도 위 표의 값 그대로다(예: 390×844 에서 560, 360×560 에서 276).

방장 줄(19페이즈 결정 0086, 22페이즈 결정 0089-12): 순서는 위 → 아래 [맵] · [봇] 이고 단추는 최대 둘이다. [맵] 은 허용 맵이 둘 이상일 때(`railMapsOn`, 꾸미기 시트의 맵 탭도 같은 조건), [봇] 은 테스트 방에서만 있다. 줄 최대 높이 = 패널 윗변 − 8 − (띠 아랫변 + 12), 테스트 방은 − 48. 단추 n 개가 `n·52 + (n−1)·12 + 32` 안에 들면 한 열 + 왕관 표식, `n·52 + (n−1)·12` 안에 들면 한 열(표식 없음), 아니면 `splitSideColumn` 으로 두 열이다(`hostRailLayout`, `src/components/v2/HostRail.tsx`). 결과 화면의 방장 줄은 [맵] 하나다. 단추가 하나뿐이면 [맵] 은 `MapChip` 의 줄 변형이다.

줄 크기 계산(식으로 낸 값 — 22페이즈에서 폰 6종 실측은 다시 하지 않았다): 대기실 테스트 방에서 줄 최대 높이는 가장 작은 360×560 에서도 164.4 이고 단추 둘의 필요 높이는 표식 포함 148(= 2·52 + 12 + 32) 이라 여섯 크기 모두 표식 + 한 열 [2] 에 든다. 일반 방은 최대 높이가 48 더 크다. 결과 화면은 단추 하나라 모든 크기에서 표식 + [1] 이다. 실제 방에서 띠 문장이 두 줄이 되면 띠 아랫변이 내려가 줄 최대 높이가 그만큼 줄어든다(표식이 먼저 빠지고 그다음 두 열로 접힌다).

입력칸 포커스 중 맵을 눌러 키보드를 닫으면(D4) 포커스가 풀리는 순간 방장 줄·오른쪽 열이 다시 그려진다. 그 탭에 뒤따르는 같은 자리(10px)·0.5초 안의 click 은 `WorldStage` 가 한 번 삼킨다 — 새로 나타난 단추가 눌리지 않는다(19-08, `chat-keyboard` 가 폰 6종에서 본다).

알려진 한계 (고치지 않는다, 07-UI-SPEC UI Considerations 20):

- 방 높이 640 이하 폰(360×640 · 390×664 · 360×560)은 키보드가 열리면 스테이지가 128(캐릭터 80 + 이름표 26 + 입력 중 22) 미만이라 내 이름표 · 입력 중 칸이 잘릴 수 있다. 최악 360×560 은 12px 만 남는다. 캐릭터 몸만 보이도록 카메라가 맞춘다.
- (해결) 테이블 화면에서 패널이 아래 인물을 가리던 문제는 테이블 틀이 8페이즈에서 삭제되며 없어졌다.
- 360×560 방장 대기실은 왼쪽 방장 줄이 두 열로 접힌다(결정 0086 — 오른쪽 열은 방장도 둘이라 더는 접히지 않는다). 접힌 줄의 둘째 열 단추(x 80~132)는 위 알림과 같은 높이에 와서 입장 알림이 약 1.5초 덮는다. 알림은 눌림을 통과시켜 단추는 눌린다. 가장 작은 화면의 진행에 지장 없는 겹침이라 고치지 않는다(E2E HR3 은 그 겹침만 잰 값을 남기고 실패로 세지 않는다 — `HOST_RAIL_KNOWN_LIMITS`).
- 방장 줄·칩은 스테이지 위에 뜬 오버레이라 이름표 끝을 가릴 수 있다(E2E 참고 줄 MS6bk·R-MS6k. 잰 곳은 결과 360×560, 대기실 430×932 의 2px).

## 첫날 실험방 (결정 0095·0096·0097)

v3 시험판과 로컬의 `?playtest=1`에서 방을 만들면 모이는 장소는 재즈 바다. 역할 카드에는 자기 역할의 복장과 준비 단추가 보인다. 본문 상단에는 단계 이름과 남은 시간, 메뉴를 둔다. 낮과 투표는 주변광을 공유하고 밤과 아침은 2.8초 동안 연결된다.

토론 중에는 자유롭게 걷는다. [단서]에서 모두의 단서와 아침 유언을 보고, [의심딱지]를 누른 뒤 가까운 사람의 이름을 누르면 캐릭터가 그 사람을 가리키고 의심딱지가 붙는다. [반응]에서 최고·손사래·깜짝을 보내거나 [채팅]을 열어 쓴다. 버튼을 여럿 눌러도 한 도구만 열린다.

역할 확인과 투표에서는 참가자가 자동으로 모이고 수동 이동이 잠긴다. [투표 요청] 뒤 첫 투표에서 얼굴을 고르거나 [오늘은 안 뽑기]를 누른다. 시민은 밤에 [아침 준비]를 누르고 경찰·의사·마피아는 자신의 대상을 고른다. 준비 여부는 자신만 확인하며, 마지막 행동을 받으면 다음 장면으로 넘어간다.

실험방 주소의 [혼자 연습하기]는 역할 준비, 단서 입력과 확인, 의심딱지, 투표 요청, 한 번의 투표, 제시어 공개, 시민의 아침 준비를 연습한다. 기본 주소의 연습은 찬반과 지목을 따로 가르친다.
