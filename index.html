설치 없이 링크 하나로 4~8명이 같은 방에 들어와요. 3D 지하 재즈 바를 걸어 다니며 떠들고, 손가락으로 지목하고, 조명이 꺼진 무대에서 변론해요. 대면 마피아의 눈치 싸움을 온라인으로 옮기는 게 목표예요.

WHY

대면 마피아의 눈치 싸움을 온라인으로

v1.0은 고정된 자리와 정해진 채팅 문구로 진행했어요. 친구들과 실제로 해 보니 대면 마피아의 재미인 수다, 묘한 정치질, 거짓말할 때 달라지는 모습이 빠져 단조로웠어요. 그래서 v2.0은 모두가 한 공간에 있는 느낌을 만드는 쪽으로 다시 설계했어요.

같은 공간

방에 들어오면 캐릭터가 생기고, 3D 맵 안을 자유롭게 걸어 다녀요. 기다리는 동안에도 모여서 놀 수 있어요.

자유 채팅과 몸짓

템플릿 대신 자유 채팅을 쓰고, 감정 표현은 캐릭터가 목 긋기·손사래·박수 같은 동작으로 직접 해요.

글보다 장면

단계는 조명으로, 표 수는 배지로, 남은 시간은 링으로 보여 줘요. 읽을 글은 한 줄 이하, 행동은 대상을 직접 눌러요.

HOW IT PLAYS

CHARACTERS & MAPS

코드로 조립한 3D 캐릭터와 맵

캐릭터는 three.js의 구·원통을 조립한 인물이에요. 외부 모델 파일이나 애니메이션 라이브러리 없이 관절 키프레임으로 걷고 동작해요. 맵·의상·역할 그림은 디자인 시스템에서 먼저 정하고 승인한 뒤 화면에 옮겼어요.

ARCHITECTURE

방 하나에 서버 하나, 판정은 모두 서버가

플레이어 폰 4~8대React 앱. 받은 상태를 그리고 행동만 보내요
WebSocket
Cloudflare Worker방 코드로 해당 방에 연결해요. 정적 파일도 같은 곳에서 배포해요
방 코드로 라우팅
Room Durable Object (방마다 하나)참가자·역할·단계·타이머·이동·투표 집계와 판정. 플레이어마다 볼 수 있는 정보만 골라서 보내요

  • 서버 권위

    단계 전환, 타이머, 판정, 캐릭터 이동까지 방 서버가 정해요. 클라이언트는 목적지와 행동만 보내고, 서버가 걸을 수 있는 경로로 바꿔 모두에게 나눠 줘요.

  • 보낼 사람은 한 곳에서 정해요

    채팅·이동·입력 중 표시를 누가 받을지는 함수 하나(audience)가 정하고, 전송도 한 길로만 나가요. 시민의 소켓에는 다른 사람의 역할이 실리지 않고, 탈락자(유령)의 채팅과 위치는 산 사람에게 가지 않아요. 단위 테스트와 E2E 누설 검사로 확인해요.

  • 비밀 투표

    찬반은 누가 무엇을 골랐는지 어떤 소켓에도 싣지 않아요. 투표를 마쳤는지와 집계 수만 공개하고, 개인 값은 집계 직후 지워요.

  • 끊겨도 이어지는 판

    참가할 때 받은 토큰으로 같은 자리에 다시 붙어요. iOS Safari처럼 화면이 꺼지면 연결이 끊기는 환경을 기본으로 보고, 끊긴 사람을 기다리지 않고 서버 타이머대로 진행해요.

  • 대기 비용과 공용 규칙

    WebSocket Hibernation으로 조용한 방의 비용을 줄였어요. 게임 규칙은 shared/에 순수 함수로 두어 서버와 브라우저가 함께 쓰고, 입력은 zod로 검증해요.

DECISIONS

주요 설계 결정

결정은 63개의 기록으로 남겼어요. 그중 방향을 정한 여섯 개예요.

0002

방마다 Durable Object 하나

방 상태와 판정을 한 객체에 모아 동시성 문제 없이 서버 권위로 진행해요.

 0044

v2.0은 "같은 공간"

v1.0 실게임 피드백으로 고정 자리·템플릿 채팅을 버리고 맵 이동·자유 채팅·동작 캐릭터로 바꿨어요.

 0047

코드로 조립한 3D 캐릭터

2D 그림 대신 맵과 같은 장면에서 그리는 조립 인물로, 의상·표정·동작을 부품처럼 바꿔요.

 0051

글은 최소, 조작은 직접

3초 규칙: 한 화면에서 읽을 글은 단계 이름과 한 줄 이하. 기획부터 디자인까지 가장 먼저 따르는 지침이에요.

 0060

처형과 유령의 정보 경계

유령은 모두의 역할을 보지만, 산 사람의 소켓과 화면에는 유령의 흔적이 전혀 남지 않게 했어요.

 0042

배포 전 계정·대상 확인

배포 스크립트가 계정, 빌드 산출물의 대상, 고정 인자를 차례로 확인하고 하나라도 어긋나면 멈춰요.

디자인 먼저

화면을 만들기 전에 디자인 시스템과 전체 화면설계서를 먼저 만들어 승인받고, 승인본을 저장소에 사본으로 두어 에이전트가 그대로 따르게 했어요.

세 갈래 테스트와 화면 E2E

순수 규칙은 Node, 화면은 happy-dom, 방 서버는 workerd 안에서 테스트해요. 배포본에는 Playwright로 폰 폭 5종 화면 검사와 정보 누설 검사를 돌려요.
